# 构建与测试

所有命令在 `apps/android/` 下执行。依赖都已在本机缓存时加 `--offline`，保证不联网。

## 工具链

放在仓库外的工具目录（默认 `%LOCALAPPDATA%\YongleToolchains\android`），不改系统 PATH：

| 目录 | 内容 | 来源 |
|---|---|---|
| `jdk\` | Temurin JDK 21 | adoptium.net 的 Windows x64 zip |
| `sdk\` | `cmdline-tools/latest`、`platform-tools`、`platforms/android-36`、`build-tools/36.0.0` | 先解压 cmdline-tools，再 `sdkmanager --sdk_root=…\sdk "platforms/android-36" "build-tools/36.0.0" "platform-tools"`（新版 sdkmanager 的包名用 `/`） |
| `gradle-home\` | Gradle 下载的发行版和依赖缓存 | 第一次构建时自动下载 |

每开一个 PowerShell 窗口先运行一次（工具在别处时加 `-Root`）：

```powershell
. .\scripts\env.ps1
```

## 构建、检查、单元测试

```powershell
.\gradlew.bat --offline check assembleDebug assembleRelease
```

- 在 ERP 项目根目录跑 `npm run check:apps -- android` 等于在这里跑 `.\gradlew.bat --offline check`，它按默认工具目录自己设好环境变量（不用先 `. .\scripts\env.ps1`），工具链缺什么会列出来；不带 `-- android` 时连 Windows 外壳一起查。持续集成（ERP 项目的 `.github/workflows/apps.yml`）在 Linux 上跑 `sh ./gradlew check`。
- `check` 包括：
  - Android Lint：警告也算错误（`warningsAsErrors`）。只有 `OldTargetApi`、`GradleDependency`、`AndroidGradlePluginVersion` 三条降成提示：它们只说“有更新的 SDK、Android Gradle 插件了”，结果只取决于检查那天外面出没出新版本、和代码无关（能联网时硬拦会让同一份代码今天过、明天不过）；照样列在报告 `app/build/reports/lint-results-debug.txt` 里，升级要装新的 SDK 或插件、真机重验。
  - javac：`-Xlint:all -Werror`，任何编译告警都算错。压下的过时提示都在代码旁写了理由。
  - Checkstyle（`config/checkstyle.xml`）：函数 80 行（不算空行）、参数 5 个、圈复杂度 20、文件 500 行、空 `catch`、不留 TODO/FIXME/HACK 注释；嵌套是 if 3 层、for 3 层、try 2 层分开限（Checkstyle 没有 ERP 那种各种块混在一起算 4 层的规则）。产品代码和测试都查。
  - `checkNoRuntimeLibraries`：两种构建的运行时依赖必须是空的。
  - JVM 单元测试。
- 单元测试（都不依赖 `Activity`，发送函数、时钟、读文件这些从参数传进去）：
  - `WebRulesTest`：网址分流、哪些加载错误盖离线页、渲染进程没了之后重开/盖离线页/等看得见再开、ERP 来源的写法、版本名合网页认 App 标记的正则。
  - `BackKeyTest`：按返回先问网页、后退还是按首页；回执只认正在等的编号、认一次就作废、没编号的不认；首页连按两次才退出；页面变化作废提示。
  - `ShareRelayTest`：清单和每份的消息写法、读好才发、每份有结果就发下一份、读不出记失败往下走、到头自己收尾、网页回绝、别的编号和序号不认、重连从清单重来、重连前读的作废、没开始的被替换、在传的算忙。
  - `ShareInboxTest`：能收的文件名、落盘名只用“序号.扩展名”（名字带 `/`、`..`、NUL 也一样）、交来的东西里混进别的类型时跳过不抛、没收下的原因怎么分（名字和类型都拿不到算读不到，否则算格式不支持）。
  - `FileSaverTest`：保存请求的编号、名字（和分享同一个清洗）、base64、20MB 上限，类型只认“类/子类”。
  - `ShellTest`：限长复制、建上级目录、落在目录里的核对、文件名清洗（只取最后一段、去控制字符、`..` 算没名字、按 UTF-8 截到 255 字节以内并留扩展名、不截断半个字符）。
  - `FileChooserTest`：accept 换成文件类型、什么时候给拍照、选择结果交回什么（去空地址、相机没回 data 算拍了、确定是空的照片不交、说不准的照常交）。
  - `LaunchScreenTest`：启动画面什么时候退场。
  - `SystemBarsTest`：系统栏图标深浅。
  - `AppUpdaterTest`：清单里的新版本能不能用、sha256 写法。
  - `InstallStatusReceiverTest`：只打开系统的安装确认页。
  - `ShellBoundaryTest`：产品源码正好是登记表里的文件、每个文件只引登记的、登记表没有循环、纯规则文件只引 JDK、构建配置不引用本目录以外的文件（上一级、盘符、绝对路径）、文件不超过 500 行。
- 版本号在 `gradle.properties`：每发一个新安装包 `appVersionCode` 加 1（应用内更新按它比新旧），`appVersionName` 给人看（只用字母、数字、`.`、`_`、`-`，网页按这个认 App 标记）。
- 产物：`app/build/outputs/apk/debug/app-debug.apk`（测试版，已用调试密钥签名）、`app/build/outputs/apk/release/app-release-unsigned.apk`（正式版，**还没签名，装不上**）。
- 换测试网址：`.\gradlew.bat --offline assembleDebug -PerpTestUrl=http://127.0.0.1:3198/`。
- 仓库在中文目录下，`gradle.properties` 里关掉了 AGP 的非 ASCII 路径检查；在中文路径和纯英文路径下都实测构建通过。

## 装到手机

```powershell
adb install -r -t app\build\outputs\apk\debug\app-debug.apk
```

vivo 等手机要先在“开发者选项”里打开“USB 安装”，装的时候手机上要点确认；不行就 `adb push` 到 `/sdcard/Download/`，在手机“文件管理”里点开安装（员工以后也是这样装）。

## 真机验证

手机开 USB 调试并授权、解锁亮屏（建议开发者选项里开“保持唤醒状态”），装好测试版（默认网址 `http://127.0.0.1:8787/`）后：

```powershell
.\scripts\verify-device.ps1            # 截图、日志、结果表 results.csv 放在 %TEMP%\yongle-android-verify
```

脚本自己用 jwebserver 起 `test-site/`、`adb reverse tcp:8787`，用 uiautomator 读屏幕上的字、点按、按返回键，再查手机“下载”文件夹里文件到底有没有。测试页的 `bridge.js` 代替 ERP 回答返回键（第二页回首页，首页回 home）。共 16 项：

打开测试网址；网页铺满、没有浏览器界面；状态栏底色跟网页顶部一致；站内跳转留在应用里；返回键按网页回执回到首页；首页按一次返回只提示不退出；2 秒内连按两次才退出；再打开回到测试首页；外部网页交给系统；回来时页面没被替换；blob 下载是否落盘（观察项）；普通下载真的存进“下载”；下载后没误盖离线页；连不上时显示“暂时无法连接 ERP”和“重试”；离线页的状态栏颜色也跟着变；点“重试”后恢复。

文件选择、分享、保存文件、ERP 里的返回层级要连真实 ERP 网页手动测，清单在 ERP 项目 `docs/路线图.md`“应用外壳”的“安卓真机待测”。

## 应用内更新

**版本清单**（`manifest.json`，UTF-8，不超过 64KB）：

```json
{ "versionCode": 2, "versionName": "0.2.0", "apkUrl": "https://…/yongle-erp-0.2.0.apk", "sha256": "64 位小写十六进制", "notes": "这次改了什么（可空）" }
```

外壳只在 `versionCode` 比自己大、`apkUrl` 是 http(s)、`sha256` 是 64 位十六进制时提示；下载后 sha256 对不上、安装包的包名或版本号和清单不符都不装；安装包最多 100MB。系统只肯装同一包名、同一签名的新包。

**本机测试**（同一台电脑的调试签名，旧版 → 新版）：

```powershell
.\scripts\update-test.ps1 -ErpUrl http://127.0.0.1:3198/ -OutDir D:\某个目录   # 打旧版和新版（版本号 +1），写清单
.\scripts\update-test.ps1 -Serve -OutDir D:\某个目录                          # 在 8787 提供清单和新版，adb reverse 到手机
```

先装旧版、打开，应弹“发现新版本”→“下载并安装”（下载框有进度、能取消）→ 系统安装页确认 → 打开后是新版（系统设置的应用信息里看版本）。8787 端口和 `verify-device.ps1` 共用，两个不要同时开。

**正式签名密钥**（等域名备案通过、发第一个正式版前做一次）：

- 由用户本人在开发机上生成和保管，放在仓库外；密码只进自己的密码管理器，另留一份离线备份。助手和别人不经手私钥和密码，下面带密钥的命令都由用户自己运行（密码在命令提示时输入，不写在命令行里）。
- 以后每个版本都用这同一把密钥签：系统只肯用同一签名的新包覆盖旧包，密钥丢了，装好的 App 不能再升级，只能逐台卸载重装（手机上没有业务数据，重装后重新登录）。
- 生成（JDK 自带的 `keytool`，`. .\scripts\env.ps1` 后就能用）：

```powershell
keytool -genkeypair -v -keystore <仓库外的位置>\yongle-erp-release.jks -alias yongle-erp -keyalg RSA -keysize 4096 -validity 10000
```

- 密钥文件和签名密码都不进仓库：`.gitignore` 已忽略 `*.jks`、`*.keystore`、`*.p12`、`*.pk8`、`*.pem`、`keystore.properties`、`signing.properties`；`gradle.properties` 是进仓库的，不能放签名密码。

**正式发布的顺序：**

1. `appVersionCode` 加 1、改 `appVersionName`；`releaseUpdateUrl` 填正式清单地址 `https://erp.nbyongle.cn/app-update/android/manifest.json`（或命令行 `-PreleaseUpdateUrl=…`）。地址只在打包时进安装包，第一个正式版不带它就发出去，装好的 App 永远不会自己检查更新。
2. 打包、对齐、签名、核对（`$out` 是仓库外的一个目录，安装包按版本起名）：

```powershell
.\gradlew.bat --offline check assembleRelease
$bt = Join-Path $env:ANDROID_HOME 'build-tools\36.0.0'
& "$bt\zipalign.exe" -f -P 16 4 app\build\outputs\apk\release\app-release-unsigned.apk "$out\aligned.apk"
& "$bt\apksigner.bat" sign --ks <仓库外的位置>\yongle-erp-release.jks --ks-key-alias yongle-erp --out "$out\yongle-erp-0.2.0.apk" "$out\aligned.apk"
& "$bt\apksigner.bat" verify --print-certs "$out\yongle-erp-0.2.0.apk"
```

3. 算安装包的 sha256（`Get-FileHash 文件 -Algorithm SHA256`，写成小写），写进清单（格式见上面“版本清单”，`apkUrl` 是 `https://erp.nbyongle.cn/app-update/android/` 加安装包名）。
4. **先**把安装包传到服务器，确认能下载、sha256 一致；**再**传版本清单。顺序反了，手机会看到新版本却下不到包。服务器上的目录和 Caddy 配置见 ERP 项目 `docs/部署与运维.md`“客户端更新包”。

注意：电脑的 8787 端口被占用时脚本直接报错（停不掉别人的服务，离线那步就测不准）；脚本会清空测试版的应用数据。

## 看真实 ERP 界面

正式地址没开通前，可以连 ERP 项目自己的虚构数据预览实例（在 ERP 项目里按它的说明启动，地址 `http://127.0.0.1:3198`，不碰真实数据），再：

```powershell
.\gradlew.bat --offline assembleDebug -PerpTestUrl=http://127.0.0.1:3198/
adb install -r -t app\build\outputs\apk\debug\app-debug.apk
adb reverse tcp:3198 tcp:3198
```

数据线要一直连着（手机经 adb reverse 访问电脑）。测完换回默认测试网址重新装，真机验证脚本才对得上。
