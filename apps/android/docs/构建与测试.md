# 构建与测试

安卓外壳的工具链、构建和检查、装到手机、真机验证、应用内更新和正式发布。代码和行为见[架构说明](架构说明.md)；更新包放服务器的目录和上传顺序见 [部署与运维](../../../docs/部署与运维.md)“客户端更新包”；要真机测的清单见 [路线图](../../../docs/路线图.md)“应用外壳发第一个正式版和真机测试”。

命令都在 `apps/android/` 下跑；依赖已缓存时加 `--offline`，不联网。

## 工具链

放在仓库外，默认 `%LOCALAPPDATA%\YongleToolchains\android`，不改系统 PATH：

| 目录 | 内容 | 怎么装 |
|---|---|---|
| `jdk\` | Temurin JDK 21 | adoptium.net 的 Windows x64 zip |
| `sdk\` | `cmdline-tools/latest`、`platform-tools`、`platforms/android-36`、`build-tools/36.0.0` | 解压 cmdline-tools 后 `sdkmanager --sdk_root=…\sdk "platforms/android-36" "build-tools/36.0.0" "platform-tools"` |
| `gradle-home\` | Gradle 发行版和依赖缓存 | 第一次构建自动下载 |

每个 PowerShell 窗口先运行 `. .\scripts\env.ps1`（工具在别处加 `-Root`）。

## 构建、检查、单元测试

```powershell
.\gradlew.bat --offline check assembleDebug assembleRelease
```

- ERP 项目根目录的 `npm run check:apps -- android` 等于这里的 `check`，自己设环境变量、列出缺的工具。持续集成（`.github/workflows/apps.yml`）在 Linux 上跑 `sh ./gradlew check`。
- `check` 包括：
  - **Lint**：警告也算错。只有 `OldTargetApi`、`GradleDependency`、`AndroidGradlePluginVersion` 降成提示——它们只说“出了新版本”，结果随外面发版变、和代码无关；照样列在 `app/build/reports/lint-results-debug.txt`，升级要装新 SDK 或插件、真机重验。
  - **javac**：`-Xlint:all -Werror`；压下的过时提示在代码旁写了理由。
  - **Checkstyle**（`config/checkstyle.xml`，产品和测试都查）：函数 80 行（不算空行）、参数 5 个、圈复杂度 20、文件 500 行、空 `catch`、TODO/FIXME/HACK 注释、`*` 引入、没用的引入；嵌套分开限：if 3 层、for 3 层、try 2 层（Checkstyle 没有 ERP 那种混算 4 层的规则）。
  - **`checkNoRuntimeLibraries`**：两种构建的运行时依赖为空。
  - **JVM 单元测试**（不依赖 `Activity`，发送函数、时钟、读文件从参数传入）：

| 测试 | 守什么 |
|---|---|
| `WebRulesTest` | 网址分流、哪些错误盖离线页、渲染进程没了之后怎么办、ERP 来源写法、版本名合网页认 App 的正则 |
| `BackKeyTest` | 问网页、后退还是按首页；回执只认正在等的编号、认一次作废、没编号不认；首页连按两次才退出；页面变化作废提示 |
| `ShareRelayTest` | 消息写法、读好才发、有结果发下一份、读不出记失败往下走、到头收尾、网页回绝、别的编号序号不认、重连从清单重来、重连前读的作废、没开始的被替换、在传的算忙 |
| `ShareInboxTest` | 能收的文件名、落盘名只用“序号.扩展名”（名字带 `/`、`..`、NUL 也一样）、混进别的类型跳过不抛、没收下的原因怎么分 |
| `FileSaverTest` | 编号、名字、base64、20MB 上限，类型只认“类/子类” |
| `ShellTest` | 限长复制、建上级目录、落在目录里的核对、文件名清洗（只取最后一段、去控制字符、`..` 算没名字、UTF-8 截到 255 字节内并留扩展名、不截半个字符） |
| `FileChooserTest` | accept 换类型、何时给拍照、交回什么（去空地址、相机没回 data 算拍了、确定空的不交、说不准的照交） |
| `LaunchScreenTest` | 启动画面何时退场 |
| `SystemBarsTest` | 图标深浅 |
| `AppUpdaterTest` | 清单里的新版本能不能用、sha256 写法 |
| `InstallStatusReceiverTest` | 只打开系统的安装确认页 |
| `ShellBoundaryTest` | 源码正好是登记表里的、只引登记的、没循环、纯规则只引 JDK、构建配置不指向本目录外（上一级、盘符、绝对路径）、文件不超过 500 行 |

- 版本号在 `gradle.properties`：每发一个新包 `appVersionCode` 加 1（更新按它比新旧）；`appVersionName` 给人看，只用字母、数字、`.`、`_`、`-`（网页按它认 App 标记）。
- 产物：`app/build/outputs/apk/debug/app-debug.apk`（测试版，调试密钥已签）；`app/build/outputs/apk/release/app-release-unsigned.apk`（正式版，**没签名装不上**）。
- 换测试网址：`.\gradlew.bat --offline assembleDebug -PerpTestUrl=http://127.0.0.1:3198/`。
- 仓库在中文目录下，`gradle.properties` 关了 AGP 的非 ASCII 路径检查；中文、英文路径下都实测能构建。

## 装到手机

```powershell
adb install -r -t app\build\outputs\apk\debug\app-debug.apk
```

vivo 等要先在开发者选项开“USB 安装”，装时手机上点确认；不行就 `adb push` 到 `/sdcard/Download/`，在“文件管理”里点开安装（员工也这样装）。

## 真机验证

手机开 USB 调试并授权、解锁亮屏（建议开“保持唤醒状态”），装好测试版（默认网址 `http://127.0.0.1:8787/`）后：

```powershell
.\scripts\verify-device.ps1    # 结果在 %TEMP%\yongle-android-verify（-OutDir 换）；-Install 先装测试版
```

- 脚本用 jwebserver 起 `test-site/`、`adb reverse tcp:8787`，用 uiautomator 读字、点按、按返回，再查“下载”里文件到底有没有；`bridge.js` 代替 ERP 回答返回键（第二页回首页，首页回 home）。
- 每项打印“通过 / 不通过 / 观察”，有不通过退出码 1；截图、日志、`results.csv` 放在结果目录。
- 8787 端口被占用就直接报错（停不掉别人的服务，离线那步测不准）；会清空测试版的应用数据。
- 共 16 项：打开测试网址；铺满、没有浏览器界面；状态栏底色跟网页顶部一致；站内跳转留在应用里；返回键按回执回首页；首页按一次只提示；2 秒内连按两次才退出；再打开回到首页；外部网页交给系统；回来时页面没被替换；blob 下载是否落盘（观察项）；普通下载存进“下载”；下载后没误盖离线页；连不上时显示“暂时无法连接 ERP”和“重试”；离线页的状态栏颜色也跟着变；点“重试”后恢复。

文件选择、分享、保存文件、ERP 里的返回层级要连真实 ERP 网页手动测（清单在路线图）。

## 应用内更新

**版本清单**（`manifest.json`，UTF-8，≤64KB）：

```json
{ "versionCode": 2, "versionName": "0.2.0", "apkUrl": "https://…/yongle-erp-0.2.0.apk", "sha256": "64 位小写十六进制", "notes": "这次改了什么（可空）" }
```

外壳怎么核对清单和安装包见[架构说明](架构说明.md)“应用内更新”。

**本机测试**（同一台电脑的调试签名，旧版 → 新版）：

```powershell
.\scripts\update-test.ps1 -ErpUrl http://127.0.0.1:3198/ -OutDir D:\某个目录   # 打旧版和新版（版本号 +1），写清单
.\scripts\update-test.ps1 -Serve -OutDir D:\某个目录                          # 在 8787 提供，adb reverse 到手机
```

装旧版、打开 → 弹“发现新版本”→“下载并安装”（有进度、能取消）→ 系统安装页确认 → 打开是新版。8787 和 `verify-device.ps1` 共用，不要同时开。

**正式签名密钥：**

- 用户本人生成，放仓库外；口令的保管和撤回见 Windows 外壳 [构建与测试](../../desktop/docs/构建与测试.md)“正式更新签名密钥”（两个外壳的口令在同一个加密文件里）。
- 每个版本都用同一把签：系统只肯用同签名的新包覆盖。密钥丢了，装好的 App 不能再升级，只能逐台卸载重装（手机上没有业务数据，重装后重新登录）。
- 生成（`env.ps1` 之后 JDK 的 `keytool` 就能用）：

```powershell
keytool -genkeypair -v -keystore <仓库外的位置>\yongle-erp-release.jks -alias yongle-erp -keyalg RSA -keysize 4096 -validity 10000
```

- `.gitignore` 挡着 `*.jks`、`*.keystore`、`*.p12`、`*.pk8`、`*.pem`、`keystore.properties`、`signing.properties`；`gradle.properties` 进仓库，不能放签名口令。

**正式发布的顺序：**

1. `appVersionCode` 加 1、改 `appVersionName`；`releaseUpdateUrl` 已填 `https://erp.nbyongle.cn/app-update/android/manifest.json`（也可 `-PreleaseUpdateUrl=…`）。
2. 打包、对齐、签名、核对（`$out` 是仓库外的目录；口令用 `--ks-pass env:<环境变量名>` 从环境变量读，不写在命令行）：

```powershell
.\gradlew.bat --offline check assembleRelease
$bt = Join-Path $env:ANDROID_HOME 'build-tools\36.0.0'
& "$bt\zipalign.exe" -f -P 16 4 app\build\outputs\apk\release\app-release-unsigned.apk "$out\aligned.apk"
& "$bt\apksigner.bat" sign --ks <仓库外的位置>\yongle-erp-release.jks --ks-key-alias yongle-erp --out "$out\yongle-erp-0.2.0.apk" "$out\aligned.apk"
& "$bt\apksigner.bat" verify --print-certs "$out\yongle-erp-0.2.0.apk"
```

3. 算 sha256（`Get-FileHash 文件 -Algorithm SHA256`，写成小写）写进清单；`apkUrl` = `https://erp.nbyongle.cn/app-update/android/` + 安装包名。
4. 上传：照部署与运维“客户端更新包”（先包后清单）。
