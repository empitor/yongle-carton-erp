# Windows 外壳文档

这里讲 Windows 外壳自己的结构、构建、测试和打包。不讲服务器上放更新包的目录和 Caddy 配置（ERP 项目 `docs/部署与运维.md`“客户端更新包”），也不记待办（ERP 项目 `docs/路线图.md`“应用外壳”：还没做的、待验证的、已知的限制）。

甬勒ERP 的 Windows 员工客户端（Rust + Tauri 2）：安装目录里只有一个程序 `甬勒ERP.exe`，它把同目录的客户端核心 `yongle_erp_core.dll` 加载进自己的进程运行，网址等设置在 `config\`、自带页面在 `pages\`；核心用独立窗口打开 ERP 网页，连不上时显示自带的离线页，点 × 收进托盘，托盘左键恢复，右键“显示”“重新载入”“检查更新”“开机自动启动”“退出”；再次启动只唤起已开的窗口。外壳和 ERP 唯一的接点是配置的网址：网页和它之间没有消息通道（ERP 项目 `docs/架构说明.md`“安卓 App 通道”只在安卓 App 里接得通），导出的文件走 WebView2 自己的下载。

它不是 ERP 的“Windows 本机安装包”：本机安装包带着 Node、服务端和数据，在本机跑 `http://127.0.0.1:3001`；这个客户端只是一个窗口，没有服务端、没有数据，只连正式域名。

- 本目录自成一体：不引用 ERP 项目和 `apps/android/` 的任何文件，单独复制出去也能构建和测试。代码标准（文件 500 行、函数 80 行、一个文件一件事、不写兜底）和 ERP 项目的 `AGENTS.md` 一致。
- 检查在 ERP 项目根目录用 `npm run check:apps -- desktop` 跑（不带 `-- desktop` 连安卓外壳一起查）。
- 安装包和签名密钥不进仓库；私钥和口令由用户本人保管，文档、代码、聊天里都不写。
- AI 实测时不运行安装包、不动装在本机的测试版（`%LOCALAPPDATA%\甬勒ERP测试`）、不改这台电脑的开机启动项：“安装验证”由人做；端到端测试会弹窗口、动鼠标，跑之前先问过用户。
