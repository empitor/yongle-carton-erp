# 构建与测试

Windows 外壳怎么装工具链、检查、测试、构建、验证安装、做应用内更新和正式发布。代码结构和行为见[架构说明](架构说明.md)；服务器上放更新包的目录和 Caddy 配置见 ERP 项目 `docs/部署与运维.md`“客户端更新包”；留给人手动验的清单在 ERP 项目 `docs/路线图.md`“应用外壳”。

所有命令在 `apps/desktop/` 下执行。

## 工具链

| 工具 | 位置和装法 |
|---|---|
| Rust stable（x86_64-pc-windows-msvc，加 clippy、rustfmt） | 仓库外的工具目录，默认 `%LOCALAPPDATA%\YongleToolchains\rust`：`rustup-init.exe -y --no-modify-path --profile minimal`，安装前设 `RUSTUP_HOME`、`CARGO_HOME` 到该目录下的 `rustup\`、`cargo\`；再 `rustup component add clippy rustfmt` |
| VS 2022 生成工具 | `winget install Microsoft.VisualStudio.2022.BuildTools`，勾“使用 C++ 的桌面开发”（`Microsoft.VisualStudio.Workload.VCTools`） |
| Node.js 24 | 系统已装；依赖 `npm ci` |

每开一个 PowerShell 窗口先运行一次（工具在别处时加 `-Root`）：

```powershell
. .\scripts\env.ps1
npm ci
```

## 检查和单元测试

```powershell
npm run check
```

依次：`cargo fmt --check` → `cargo clippy --all-targets -D warnings`（规则和口径见[架构说明](架构说明.md)“代码检查的口径”）→ `cargo test` → 边界检查。不想联网时（依赖已经下载过），给 clippy、test 两条加 `--offline`（fmt 不联网，边界检查本来就用 `--offline`）。

在 ERP 项目根目录跑 `npm run check:apps -- desktop` 就是这四步的离线版本，它按默认工具目录自己设好环境变量（不用先 `. .\scripts\env.ps1`），工具链缺什么会列出来；不带 `-- desktop` 时连安卓外壳一起查；不在 Windows 上时这个外壳不跑，报“只能在 Windows 上检查”（算没过）。持续集成（ERP 项目的 `.github/workflows/apps.yml`）在 Windows 机器上按同样的顺序跑。

- `cargo test`：核心 41 条（网址分流和同源 `blob:`、离线页的“重试”链接和外壳拦的是同一个、加载结果怎么归类（含网关报错 502–504）和接下来去哪、日志里的网址不带查询串、新窗口什么时候算显示过页面、新窗口里下载的状态和中断原因决定关不关窗口和提不提示、托盘菜单、开机自启的参数和勾选、开机自启那次运行装新版的说法、启动画面等多久、`config\app.json` 的读法和网址规矩、`pages\` 只回目录里直接放着的普通文件、更新报错的中文说明、启动出错的原因、日志的时间和换文件），启动器 3 条（按完整路径找同目录的核心 dll、找不到时报错不崩）。`pages` 有一条要建符号链接，得在 Windows 开发者模式或管理员身份下跑（GitHub 的 Windows 机器是管理员）。
- 边界检查（`tests/boundary.test.mjs`，15 项）：产品源码是登记的几个文件；只有入口用 `mod` 声明、不 include；核心里每个文件只引登记表里写的、登记表没有循环；启动器只用标准库、找的入口就是核心导出的那个；运行时依赖清单、WebView2 绑定只有一份；构建依赖、没有开发依赖、npm 只有开发用的命令行；`pages/` 每个文件都装进安装包、安装包引用的文件都在本目录；不开任何 IPC 权限（各份配置、打包覆盖项、`build.rs`、Rust 代码）；编译生成的权限清单是空的；没有插件往网页注入脚本（初始化脚本、`eval`）；文本文件不超过 500 行（末尾换行不算一行，和 ERP 根目录的检查一样）。依赖清单、插件源码用 `cargo metadata --offline` 读（`Cargo.toml` 怎么写依赖都看得见），权限清单是编译生成物，所以要先 `. .\scripts\env.ps1`、编译过一次（`npm run check` 把它排在 cargo 之后）。

## 构建

```powershell
npm run build                                              # 正式版：启动器、核心和安装包，网址 https://erp.nbyongle.cn/
node scripts/build-test.mjs http://127.0.0.1:8788/         # 测试版程序（不打安装包）
node scripts/build-test.mjs http://127.0.0.1:8788/ --installer   # 再出测试版安装包
```

`build-test.mjs`（也可 `npm run build:test -- <网址>`）的网址必须写明，写进测试版自己的配置 `src-tauri/target/test-config/`；另有 `--version x.y.z`、`--updater` 两个选项给应用内更新的本机测试用（由 `scripts/update-test.mjs` 调，见下面“应用内更新”）。

编出来的在 `src-tauri\target\release\`：启动器（cargo 编出来叫 `yongle-erp-launcher.exe`，`tauri build` 按 `mainBinaryName` 改名成 `甬勒ERP.exe`，测试版 `甬勒ERP测试.exe`）、核心 `yongle_erp_core.dll`，`config\`、`pages\` 由 tauri-build 复制在旁边，所以直接运行改过名的启动器就和装好的一样。安装包在 `src-tauri\target\release\bundle\nsis\`，按当前用户安装（不用管理员），静默安装加 `/S`。还没签名，别的电脑上会被 SmartScreen 拦一下。依赖下载过以后，打包前设 `$env:CARGO_NET_OFFLINE='true'` 就不会联网。

打包命令都带 `--no-binary-patching -- --lib`（`npm run build` 和 `build-test.mjs` 已带上）：Tauri 只编程序，`-- --lib` 让核心 dll 在同一次编译里出来、用同一份合并后的配置；主程序（启动器）里没有 Tauri，写不进安装包类型标记，所以跳过这一步。核心的更新插件没有这个标记时按清单里的 `windows-x86_64` 条目找安装包、按下载内容认出是 NSIS 安装程序，所以版本清单要写这个条目（`scripts/update-test.mjs` 就是这么写的）。

## 端到端测试

```powershell
node scripts/build-test.mjs http://127.0.0.1:8788/
node --test --test-concurrency=1 tests/shell.e2e.test.mjs
```

**会在屏幕上弹出测试版窗口、打开一次默认浏览器、真的移动鼠标拖三次，跑的时候别用这台电脑。** 直接启动测试版（WebView2 数据放临时目录、开调试端口），通过 WebView2 调试接口用真实鼠标事件点网页，用 `tests/win32.ps1` 读窗口可见状态、发 WM_CLOSE（和点 × 一样）、用真的鼠标输入拖动、给托盘图标发一次点击。是一个按顺序走的流程（后一步用前一步留下的窗口和页面），共 17 步：

冷启动先出启动画面、页面加载好后几秒内关掉并露出主窗口；打开测试网址、窗口可见；页内拖动放到接收区；从外面拖文件进来网页收到、拖到别处窗口也不去打开它；网页调不动外壳接口（几个插件和核心的命令）；站内跳转和后退；外部网页交给系统浏览器、主窗口不落到离线页；站内新窗口（含 `rel="noreferrer"`）在外壳里打开、网页自己关掉时整个窗口一起关；blob 下载、照 ERP 写法导出的送货单（Blob 加 `a.download`、中文文件名，不弹框）、普通下载都真的存进“下载”文件夹（带编号的测试文件，测完删掉）、主窗口不落到离线页；新窗口里打开的下载也存进去、不留空白窗口；点 × 收进托盘；再次启动只唤起原窗口；ERP 服务停着时落到离线页（几秒内关掉启动画面、露出主窗口，不等 8 秒的上限）、起来后点“重试”恢复；带开机自启参数启动时不出启动画面和主窗口、点托盘图标后出现。

- 跑之前关掉正在运行的测试版（包括装在 `%LOCALAPPDATA%\甬勒ERP测试` 的那个：单实例会让新启动的直接把消息交给它、自己退出）。
- 不点托盘菜单里的“开机自动启动”，不改这台电脑的开机启动项。
- **在这台开发机上，放在 ERP 项目文件夹里运行的程序加不上托盘图标**（换任何其他目录都正常，和代码无关）。所以最后一步把测试版复制到临时目录再启动（`launchCopy`）；从副本启动时调试端口连不上（原因没查清），那一步只看窗口、点托盘，不操作网页。人工验托盘菜单要用安装包装到 `%LOCALAPPDATA%` 再从那里启动。
- 拖动前把主窗口切到前台，并确认起点、终点露出来的是外壳的窗口，被挡住就报出来。

## 安装验证（启动器和安装目录）

用测试版安装包（`/S` 静默安装），每项看得见的结果：

1. **首次安装：** 安装目录是 `甬勒ERP测试.exe`、`yongle_erp_core.dll`、`config\app.json`、`pages\` 里四个文件、`uninstall.exe`；开始菜单和桌面的“甬勒ERP测试”快捷方式都指向 `甬勒ERP测试.exe`；卸载后整个目录删干净，开机自启的两项登记（如果勾过）也删掉。
2. **重复启动：** 双击快捷方式，启动器马上退出、核心一个、主窗口出来；再双击，核心还是原来那一个，窗口回到前台。
3. **覆盖安装：** 装着的测试版开着时再装一次新包：模板请正在运行的程序退出，核心 dll 被覆盖。应用内更新（被动模式带 `/UPDATE`）不删开机自启的登记，卸载才删。

## 应用内更新

**本机测试**（不发布、不上传）：

```powershell
node scripts/update-test.mjs build http://127.0.0.1:3198/ D:\某个目录   # 测试签名密钥（没有就生成，放在 %LOCALAPPDATA%\YongleToolchains\desktop-update-test\）、旧版和新版（次版本号加 1）安装包、latest.json
node scripts/update-test.mjs serve D:\某个目录                          # 在 127.0.0.1:8789 提供清单和新版安装包
```

装旧版 → 托盘“检查更新”→“发现新版本，要现在下载吗”选“是”→“现在安装吗”选“否”→ 点 × 只收进托盘、版本不变 → 托盘“退出”→ 安装器装好新版，程序不重新打开（退出就是退出）。再测一遍“现在安装吗”选“是”：马上关掉、装好、重新打开。开机自启拉起的那次运行里选“是”：问话写“装完程序回到托盘”，装好后程序在托盘里、点图标出窗口。

**版本清单**（`latest.json`，Tauri 官方格式）：

```json
{ "version": "0.2.0", "notes": "这次改了什么", "pub_date": "2026-11-17T00:00:00Z",
  "platforms": { "windows-x86_64": { "signature": "安装包 .sig 文件的全文", "url": "https://…/甬勒ERP_0.2.0_x64-setup.exe" } } }
```

**正式更新签名密钥**（发第一个正式版前做一次）：

- 由用户本人在开发机上生成和保管，放在仓库外；口令只进自己的密码管理器，另留一份离线备份。助手和别人不经手私钥和口令，生成、打包签名的命令都由用户自己运行。
- 生成：`npx tauri signer generate -w <仓库外的位置>\yongle-erp.key`，按提示设口令。私钥和口令不进仓库、不进聊天（`*.key` 不要放进项目目录，`.gitignore` 也挡着）；公钥（`.pub` 的全文）是公开的，写进 `config/app.json`。
- 这里的签名只给应用内更新核对安装包用；Windows 代码签名证书（让 SmartScreen 不拦）先不买。

**正式发布的顺序：**

1. 生成密钥（上面）。
2. 改 `src-tauri/tauri.conf.json` 的 `version`；在 `config/app.json` 填 `updateUrl`（正式清单地址 `https://erp.nbyongle.cn/app-update/windows/latest.json`）和 `updatePubkey`（公钥全文），两个要一起填；打包时设 `TAURI_SIGNING_PRIVATE_KEY`（私钥全文）、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，并把同一个公钥写进配置的 `plugins.updater.pubkey`（Tauri 签名时核对它，可用 `--config` 只在打包时加），`bundle.createUpdaterArtifacts` 设为 `true`；出安装包和同名 `.sig`。签名里会带上版本号，客户端核对它和清单一致（`requireSignedVersion`）。
3. 上传到服务器：先传安装包、确认能下载，再更新 `latest.json`（`signature` 填 `.sig` 全文，`url` 是 `https://erp.nbyongle.cn/app-update/windows/` 加安装包名，中文名上传时改成字母数字）；目录、文件名和顺序的规矩见 ERP 项目 `docs/部署与运维.md`“客户端更新包”。
4. 清单地址和公钥写在安装目录的 `config\app.json` 里，只有新安装包能换掉它：第一个正式版不带地址和公钥就发出去，装好的客户端永远不会自己检查更新，只能逐台重装。换公钥要先用旧密钥签一版带新公钥的过渡版本。
