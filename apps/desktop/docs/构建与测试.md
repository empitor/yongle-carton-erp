# 构建与测试

Windows 外壳的工具链、检查、构建、端到端测试、安装验证、应用内更新和正式发布；两个外壳共用的签名口令保管也写在这里（“正式更新签名密钥”）。代码和行为见[架构说明](架构说明.md)；更新包放服务器的目录和上传顺序见 [部署与运维](../../../docs/部署与运维.md)“客户端更新包”；留给人手动验的见 [路线图](../../../docs/路线图.md)“应用外壳发第一个正式版和真机测试”。

命令都在 `apps/desktop/` 下跑。

## 工具链

| 工具 | 装法 |
|---|---|
| Rust stable（x86_64-pc-windows-msvc，加 clippy、rustfmt） | 放仓库外，默认 `%LOCALAPPDATA%\YongleToolchains\rust`：先设 `RUSTUP_HOME`、`CARGO_HOME` 到其下 `rustup\`、`cargo\`，再 `rustup-init.exe -y --no-modify-path --profile minimal`、`rustup component add clippy rustfmt` |
| VS 2022 生成工具 | `winget install Microsoft.VisualStudio.2022.BuildTools`，勾“使用 C++ 的桌面开发”（`Microsoft.VisualStudio.Workload.VCTools`） |
| Node.js 24 | 系统已装 |

每个 PowerShell 窗口先运行（工具在别处加 `-Root`）：

```powershell
. .\scripts\env.ps1
npm ci
```

## 检查和单元测试

```powershell
npm run check
```

- 依次：`cargo fmt --check` → `cargo clippy --all-targets -D warnings`（口径见[架构说明](架构说明.md)“代码检查的口径”）→ `cargo test` → 边界检查。不联网就给 clippy、test 加 `--offline`（fmt 不联网，边界检查本来就离线）。
- ERP 项目根目录 `npm run check:apps -- desktop` 是这四步的离线版，自己设环境变量、列出缺的工具；不在 Windows 上报“只能在 Windows 上检查”（算没过）。持续集成（`.github/workflows/apps.yml`）在 Windows 机器上按同样顺序跑。
- **`cargo test`**：核心 41 条，启动器 3 条（按完整路径找同目录的核心 dll、找不到报错不崩）。核心测的是：网址分流和同源 `blob:`；离线页“重试”链接和外壳拦的是同一个；加载结果归类（含 502–504）和去哪；日志网址不带查询串；新窗口何时算显示过页面；新窗口下载的状态和中断原因决定关不关、提不提示；托盘菜单；自启参数和勾选；自启那次装新版的说法；启动画面等多久；`config\app.json` 读法和网址规矩；`pages\` 只回直接放着的普通文件；更新报错的中文；启动出错原因；日志时间和换文件。`pages` 有一条要建符号链接，得在开发者模式或管理员身份下跑（GitHub 的 Windows 机器是管理员）。
- **边界检查**（`tests/boundary.test.mjs`，16 项）：
  - 源码：产品源码是登记的几个文件；只有入口用 `mod`、不 include；核心文件只引登记的、没循环；启动器只用标准库、找的入口就是核心导出的那个。
  - 依赖：运行时依赖是登记的；WebView2 绑定只有一份；构建只依赖 tauri-build、没有开发依赖；npm 只有开发用的命令行。
  - 打包：`pages/` 每个文件都进安装包；安装包引用的文件都在本目录。
  - 安全：各份配置、打包覆盖项、`build.rs`、Rust 代码都不开 IPC 权限；编译生成的权限清单是空的；没有插件往网页注入脚本（初始化脚本、`eval`）。
  - 启动画面小窗（`splash.rs` 的 `SIZE`）装得下整段动画：按 `splash.html` 的图形和 `splash.css` 的商标大小、平移算；动画加了阴影、缩放、旋转这类会外扩的写法就报错，要跟着改这条检查。
  - 文本文件不超过 500 行（末尾换行不算，和 ERP 根目录的检查一样）。
  - 依赖和插件源码用 `cargo metadata --offline` 读；权限清单是编译生成物，所以要先 `env.ps1`、编译过一次（`npm run check` 把它排在 cargo 之后）。

## 构建

```powershell
npm run build                                                    # 正式版：启动器、核心、安装包
node scripts/build-test.mjs http://127.0.0.1:8788/               # 测试版程序（不打安装包）
node scripts/build-test.mjs http://127.0.0.1:8788/ --installer   # 再出测试版安装包
```

- `build-test.mjs`（也可 `npm run build:test -- <网址>`）网址必须写明，写进 `src-tauri/target/test-config/`；`--version x.y.z`、`--updater` 给更新测试用（由 `update-test.mjs` 调）。
- 产物在 `src-tauri\target\release\`：启动器（cargo 叫 `yongle-erp-launcher.exe`，`tauri build` 改名成 `甬勒ERP.exe` / `甬勒ERP测试.exe`）、核心 dll，`config\`、`pages\` 复制在旁边，直接运行改过名的启动器就和装好的一样。
- 安装包在 `src-tauri\target\release\bundle\nsis\`，按当前用户安装（不要管理员），静默加 `/S`。没有代码签名，别的电脑上 SmartScreen 会拦一下。
- 依赖下过以后，打包前设 `$env:CARGO_NET_OFFLINE='true'` 不联网。
- 打包都带 `--no-binary-patching -- --lib`（`npm run build`、`build-test.mjs`、`release.ps1` 已带），为什么见[架构说明](架构说明.md)“安装包怎么装”。因为没写安装包类型标记，更新插件按清单的 `windows-x86_64` 条目找包、按下载内容认出 NSIS，所以清单要写这个条目。

## 端到端测试

```powershell
node scripts/build-test.mjs http://127.0.0.1:8788/
node --test --test-concurrency=1 tests/shell.e2e.test.mjs
```

**会弹测试版窗口、开一次默认浏览器、真的移动鼠标拖三次，跑时别用这台电脑。** 直接启动测试版（WebView2 数据放临时目录、开调试端口），经调试接口用真实鼠标事件点网页；`tests/win32.ps1` 读窗口可见状态、发 WM_CLOSE（等于点 ×）、真鼠标拖动、点一次托盘。按顺序走（后一步用前一步的窗口和页面），共 17 步：

1. 冷启动先出启动画面，加载好后几秒内关掉、露出主窗口
2. 打开测试网址，窗口可见
3. 页内拖动放到接收区
4. 从外面拖文件进来网页收到；拖到别处窗口不去打开它
5. 网页调不动外壳接口（几个插件和核心命令）
6. 站内跳转和后退
7. 外部网页交给浏览器，主窗口不落离线页
8. 站内新窗口在外壳里打开、网页关掉时整个窗口关
9. 同上，带 `rel="noreferrer"`
10. blob 下载存进“下载”
11. 照 ERP 写法导出的送货单（Blob 加 `a.download`、中文名）直接存进“下载”、不弹框
12. 普通下载存进“下载”，主窗口不落离线页
13. 新窗口里打开的下载也存进去、不留空白窗口
14. 点 × 收进托盘
15. 再次启动只唤起原窗口
16. ERP 服务停着时落到离线页（几秒内关启动画面，不等 8 秒上限），起来后点“重试”恢复
17. 带自启参数启动时不出启动画面和主窗口，点托盘图标后出现

下载测试用带编号的文件，测完删掉。注意：
- 跑之前关掉正在运行的测试版，包括装在 `%LOCALAPPDATA%\甬勒ERP测试` 的（单实例会让新启动的把消息交给它、自己退出）。
- 不点托盘的“开机自动启动”，不改开机启动项。
- **这台开发机上，放在 ERP 项目文件夹里运行的程序加不上托盘图标**（别的目录正常，和代码无关）。所以最后一步复制到临时目录再启动（`launchCopy`）；副本的调试端口连不上（原因没查清），那一步只看窗口、点托盘。人工验托盘菜单要装到 `%LOCALAPPDATA%` 再启动。
- 拖动前把主窗口切到前台，确认起点、终点露出的是外壳窗口，被挡住就报出来。

## 安装验证（启动器和安装目录）

用测试版安装包（`/S`）：

1. **首次安装：** 目录里是 `甬勒ERP测试.exe`、`yongle_erp_core.dll`、`config\app.json`、`pages\` 四个文件、`uninstall.exe`；开始菜单和桌面快捷方式都指向 `甬勒ERP测试.exe`；卸载后目录删干净，勾过的两项自启登记也删掉。
2. **重复启动：** 双击快捷方式，启动器马上退出、核心一个、主窗口出来；再双击，核心还是原来那个，窗口回到前台。
3. **覆盖安装：** 测试版开着时再装：模板请程序退出，核心 dll 被覆盖。应用内更新（被动模式带 `/UPDATE`）不删自启登记，卸载才删。

## 应用内更新

**本机测试**（不发布、不上传）：

```powershell
node scripts/update-test.mjs build http://127.0.0.1:3198/ D:\某个目录   # 测试签名密钥（没有就生成，在 %LOCALAPPDATA%\YongleToolchains\desktop-update-test\）、旧版和新版（次版本号 +1）安装包、latest.json
node scripts/update-test.mjs serve D:\某个目录                          # 在 127.0.0.1:8789 提供
```

1. 装旧版 → 托盘“检查更新”→ 下载选“是”→“现在安装吗”选“否”→ 点 × 只收托盘、版本不变 → 托盘“退出”→ 装好新版，不重开。
2. 再测“现在安装吗”选“是”：马上关、装好、重开。
3. 开机自启那次运行里选“是”：问话写“装完程序回到托盘”，装好后在托盘、点图标出窗口。

**版本清单**（`latest.json`，Tauri 官方格式）：

```json
{ "version": "0.2.0", "notes": "这次改了什么", "pub_date": "2026-11-17T00:00:00Z",
  "platforms": { "windows-x86_64": { "signature": "安装包 .sig 文件的全文", "url": "https://…/yongle-erp-0.2.0-x64-setup.exe" } } }
```

**正式更新签名密钥**（两个外壳的口令保管都按这里）：

- 密钥由用户本人生成，放仓库外，另留一份离线备份。私钥和口令不进仓库、不进聊天、不显示；`*.key` 不放进项目目录（`.gitignore` 也挡着）。
- 口令经用户同意加密存在开发机上：Windows 自带的加密，只有这台电脑的这个账号能解开；文件 `signing-passwords.clixml` 和两个外壳的密钥在仓库外同一个目录，两份口令都存在里面（`release.ps1` 读其中的 `desktop` 一项）。所以发版可以由助手发起；想收回就删掉这个文件，之后每次签名要用户自己输口令。
- 生成：`npx tauri signer generate -w <仓库外的位置>\yongle-erp.key`，按提示设口令。公钥（`.pub` 全文）是公开的，写进 `config/app.json`。
- 这把密钥只给应用内更新核对安装包用；Windows 代码签名证书（让 SmartScreen 不拦）先不买。
- 换公钥要先用旧密钥签一版带新公钥的过渡版本（装好的客户端只认 `config\app.json` 里的公钥，只有新安装包能换掉它）。

**正式发布的顺序：**

1. 改 `src-tauri/tauri.conf.json` 的 `version`。`config/app.json` 的 `updateUrl`（`https://erp.nbyongle.cn/app-update/windows/latest.json`）和 `updatePubkey` 已填。
2. 运行 `.\scripts\release.ps1 -Keys <放密钥的目录> -Out <输出目录> -Notes "这次改了什么"`。它读加密的口令，把公钥临时写进打包配置的 `plugins.updater.pubkey`（Tauri 签名时核对）、开 `bundle.createUpdaterArtifacts`，打包并签名（签名带版本号，客户端核对它和清单一致）；安装包改名成 `yongle-erp-<版本>-x64-setup.exe`，写好 `latest.json`（`url` 和 `updateUrl` 同目录），都放进输出目录，不上传。不用脚本时，等价于设 `TAURI_SIGNING_PRIVATE_KEY`（私钥全文）、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，用 `--config` 只在打包时加上那两项配置，出安装包和同名 `.sig`。
3. 上传：照部署与运维“客户端更新包”（先包后清单）。
