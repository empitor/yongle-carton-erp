# 架构说明

Windows 外壳装好后的样子、代码怎么分、每个行为怎么做、安全边界、检查口径和依赖。构建、测试、打包见[构建与测试](构建与测试.md)。

## 安装后的样子

```
%LOCALAPPDATA%\甬勒ERP\           （测试版是 甬勒ERP测试\，启动器叫 甬勒ERP测试.exe）
├─ 甬勒ERP.exe            唯一的程序：快捷方式指向它，运行时的进程就是它
├─ yongle_erp_core.dll    核心：窗口、托盘、单实例、下载、开机自启、应用内更新
├─ config\app.json        ERP 网址、更新清单地址、更新公钥
├─ pages\                 自带页面：离线页 index.html、offline.css，启动画面 splash.html、splash.css
└─ uninstall.exe
```

- **启动：** 启动器按完整路径加载同目录的核心 dll，在本进程里调它导出的 `yongle_erp_run_v1`，一直跑到退出。入口名带接口版本，约定变了就换名；程序和核心版本不配时找不到入口，弹系统消息框。核心找不到、`config\app.json` 读不到或写错、窗口建不起来，也弹框说明原因（Tauri 启动出错用 panic 报，核心接住后带出来）。
- **配置和页面：** `config\`、`pages\` 运行时读，本机改了下次启动生效；但应用内更新会用新包里的覆盖，长期改要改仓库里的 `config/app.json`、`pages/` 再发版。
- **为什么只有两个文件：** Rust 没有稳定的二进制接口，多个 dll 之间只能按 C 方式互调，而且每个都要带一份 Tauri，体积翻几倍；更新又是整包替换，拆开没收益。

## 目录

核心源码在 `src-tauri/src/`：

| 文件 | 管什么 |
|---|---|
| `launcher.rs` | 启动器（`yongle-erp-launcher`，打包时按 `mainBinaryName` 改名）：收紧 dll 搜索、加载核心、调入口；只用标准库和 `SetDefaultDllDirectories`、`LoadLibraryExW`、`GetProcAddress`、`MessageBoxW`。发布版不带控制台，开发版带 |
| `lib.rs` | 核心入口 `yongle_erp_run_v1` 和装配：读配置、注册自带页面协议、插件、状态、托盘、主窗口、启动画面（开机自启时不开） |
| `window.rs` | 主窗口和新窗口：建窗口、分流放行导航和新窗口、交给浏览器、按加载结果切离线页、重试、重新载入、从托盘唤起、点 × 收进托盘 |
| `route.rs` | 网址分流规则（纯函数） |
| `loading.rs` | 主页面加载结果：挂 WebView2“导航完成”事件；“结果 → 去哪”是纯函数 |
| `popup.rs` | 新窗口收尾：网页自己关窗、只为下载开的窗口下完了，关掉整个窗口 |
| `tray.rs` | 托盘和菜单 |
| `autostart.rs` | 开机自启：插件设置、自启参数、菜单勾选 |
| `updater.rs` | “检查更新”：读清单、下载校验、问何时装、退出时装 |
| `splash.rs` | 启动画面小窗 |
| `config.rs` | 读 `config\app.json`：只认三个键；读不到、写错、多了键、网址不合规矩都报原因、不启动 |
| `pages.rs` | 自定义协议 `yl`（Windows 上是 `http://yl.localhost/`）从 `pages\` 读文件；离线页、启动画面地址 |
| `notice.rs` | 系统消息框（提示、问是/否）；程序名 |
| `report.rs` | 出错记录写日志 |

其余：

| 位置 | 放什么 |
|---|---|
| `src-tauri/installer-hooks.nsh` | 安装包钩子：装、删核心 dll（它进不了 `bundle.resources`）；卸载时删开机自启登记 |
| `src-tauri/build.rs` | 只有 `tauri_build::build()` |
| `src-tauri/tauri.conf.json` | 正式版：名字、主程序名、标识、图标、装进 `config\`、`pages\` 的文件、更新插件、NSIS（当前用户安装、简体中文、钩子） |
| `src-tauri/tauri.test.conf.json` | 测试版覆盖：名字“甬勒ERP测试”、标识、允许回环地址的 http 清单 |
| `src-tauri/Cargo.toml`、`Cargo.lock`、`clippy.toml` | 核心是 `[lib]`（`cdylib`），启动器是唯一的 `[[bin]]`（所以安装包把它当主程序）；依赖和检查上限 |
| `src-tauri/icons/` | 由 `icons-src/app-icon.svg`（白底加公司商标）用 `npx tauri icon` 生成，启动器、窗口、托盘共用 |
| `config/app.json` | 正式版配置（网址、更新地址、公钥都已填）；测试版的由 `scripts/build-test.mjs` 写进 `src-tauri/target/test-config/` |
| `pages/` | 自带页面 |
| `package.json` | 只有开发依赖 `@tauri-apps/cli` 和 `check`、`build`、`build:test`、`test:e2e` |
| `.gitignore` | 依赖、构建产物、`*.msi`、`*.pfx`、`*.p12`、`*.key` 不进仓库 |
| `scripts/` | `env.ps1` 设 Rust 环境变量；`build-test.mjs` 打测试版；`update-test.mjs` 更新的本机测试；`release.ps1` 打正式包 |
| `tests/` | 边界检查、端到端测试和它的准备代码、测试页服务、操作窗口和鼠标的小工具 |
| `test-site/` | 虚构测试页 |

**分层：** `lib.rs` 用 `mod` 声明其余文件，只往下引、没有循环；`tests/boundary.test.mjs` 的登记表守着：

```
lib ──→ autostart、config、notice、pages、report、splash、tray、updater、window
tray ─→ autostart、config、notice、report、updater、window
window → config、loading、notice、pages、popup、report、route、splash
popup ─→ loading、notice、report、route
loading → pages（只在测试里）、report、route
updater → autostart、config、notice、report
autostart → report      splash → report      route → pages
config、notice、pages、report：最底层
```

导航规则和“按加载结果导航主窗口”都在 `window.rs`：“重试”要重载主窗口，加载结果又要导航主窗口，拆开就互相引用。`loading.rs`、`popup.rs` 只挂事件、判结果，不碰主窗口。启动器不和核心共用代码，入口名两边各写一次，边界检查核对一致。

**安装包怎么装：** NSIS 模板把启动器当主程序，按 `mainBinaryName` 改名，快捷方式、装完“运行”、更新后重启都指向它；`config\`、`pages\` 按 `bundle.resources` 装、卸载时删；核心 dll 由钩子装删，钩子用模板的 `MAINBINARYSRCPATH` 找同目录的 dll。打包带 `--no-binary-patching`（启动器里没有 Tauri，写不进安装包类型标记）和 `-- --lib`（核心和启动器同一次编译出来）。

## 两个版本

| | 正式版 | 测试版 |
|---|---|---|
| 网址、更新清单、公钥 | `config/app.json` | `scripts/build-test.mjs` 按命令行和环境变量另写 |
| 标识 | `cn.nbyongle.erp.desktop` | `cn.nbyongle.erp.desktop.test` |
| 启动器、安装位置 | `甬勒ERP.exe`，`%LOCALAPPDATA%\甬勒ERP` | `甬勒ERP测试.exe`，`%LOCALAPPDATA%\甬勒ERP测试` |
| 清单协议 | 更新插件在 release 构建里只认 https（报错译成中文） | 插件另许 http（`dangerousInsecureTransportProtocol`） |

- 两版共用 `config.rs` 的规矩：ERP 网址和清单地址只收 https，回环地址（127.0.0.1、localhost、[::1]）也收 http；更新地址和公钥要么都填、要么都空（都空 = 不检查更新，托盘里也没有“检查更新”）。
- 标识不同，登录数据（WebView2 数据目录）、单实例、日志、安装位置互不影响。

## 行为和实现

**启动画面：** 冷启动先开无边框小窗放 `pages\splash.html`（Y、L 从两边靠拢 0.9 秒合成商标，1.3 秒淡出），主窗口同时后台加载 ERP。
- 小窗 360×280 只在 `splash.rs` 定义；靠拢前图形伸出 160 像素的商标框，框不裁、由小窗装下，边界检查核对。
- ERP 加载好（或确定连不上）且放够 1.5 秒后，先关小窗再露出主窗口；最多挡 8 秒。
- 结果比小窗建好还早到也不丢（先记“已就绪”，小窗建好照常收尾）；小窗建不起来就记一笔、直接露主窗口。
- 从托盘恢复、再次启动唤起不重播；启动画面放着时再次启动什么都不做。

**加载 ERP 和离线页：** 启动、重试、重新载入都直接让 WebView2 加载，外壳不自己去连（走系统代理的电脑也能用）。
- 主页面每次导航完看“导航完成”事件：连不上（连接失败、被拒、域名解析失败、超时、证书错误）或整页拿到 502/503/504（服务器升级重启时）→ 切离线页；ERP 好了 → 启动画面收尾。
- 不算连不上：页面里的接口请求、被取消的导航（拦下交给浏览器的、被新导航顶掉的）、变成下载的、别的错误页（404、500）；自带页面的结果一律不管；不管子框架。
- 从托盘或再次启动唤起时，停在离线页就再加载一次。

**网址分流**（`route`）：协议、主机、端口和 ERP 相同的留在窗口（含 ERP 自己生成的同源 `blob:`）；自带页面放行；离线页的“重试”拦下、重载 ERP；别的 http(s) 交给默认浏览器（opener 插件）；其余协议（`file:`、`javascript:`、`mailto:` 等）不打开。只管顶层导航：解析不了的网址 Tauri 会直接放行，所以主页面加载完再核一次，停在站外或解析不了的就回首页；iframe 不经过分流。

**新窗口：** 站内的开一个规则相同的外壳窗口（共用登录，带不带 `rel="noreferrer"` 都一样），站外的交给浏览器；opener 改写链接的脚本已关。网页 `window.close()` 时关整个窗口。一页没显示就变成下载的（原件是 Excel、Word 这类）：
- 下完、被取消 → 关窗口；被暂停 → 留着（下载提示在窗口里）；
- 没下下来（断网、服务器错、磁盘满、被安全检查拦）→ 记日志、弹“文件没下载下来：原因。请重试。”再关。

显示过页面的窗口，下载怎样都不关。

**拖放：** 主窗口和新窗口关掉 Tauri 的拖放接管，网页 HTML5 拖放（拖文件进上传区、排产板）照常；拖到没有接收区的地方，WebView2 会去打开 `file:///`，被分流拦下。启动画面保留接管（它没有导航规则）。

**窗口：** 主窗口 1280×800 居中、最小 960×600，屏幕放不下时缩进屏幕（`prevent_overflow`）；能 Ctrl+滚轮、Ctrl± 缩放。主窗口 `CloseRequested` 时只隐藏；网页弹出的窗口照常关。

**托盘：** 商标图标，提示“甬勒ERP”；左键松开恢复；右键“显示”“重新载入”“检查更新”（配了更新地址才有）、“开机自动启动”（勾选项）、“退出”。

**开机自动启动**（官方 `tauri-plugin-autostart`，默认不勾）：
- 勾上：在当前用户注册表 `Run` 项登记“程序路径 --autostart”（值名是 productName；命令不带引号，带空格的目录 Windows 也能逐段找到），并在 `Explorer\StartupApproved\Run` 写同名“已启用”；取消就删掉。
- 带 `--autostart` 启动：安静待在托盘，不放启动画面、不弹主窗口，主窗口后台加载好，点托盘马上出来；已开着又被拉起一次也不弹。
- 菜单勾选跟系统实际登记走（任务管理器里关了也显示没勾）。卸载（不是升级）时钩子删这两项。

**检查更新**（官方 Updater，按 `config\app.json` 的地址和公钥，每次请求最多等 2 分钟）：
- 有新版问“要现在下载吗”；下载时核对签名，并要求签名里的版本号和清单一致（`requireSignedVersion`），对不上报错不留包。
- 下好问“现在安装吗”：
  - 选“是”：马上交给安装器（被动模式），装完由安装器带着本次命令行参数经启动器重开——人点开的那次自动重开；开机自启那次重开后仍在托盘，问话写“装完程序回到托盘，点托盘图标打开”。
  - 选“否”：从托盘“退出”时再装，装完不重开（问话里写明）。
- 查或下载中再点只提示“正在检查或下载”。常见报错（连不上、清单读不出、没有 `windows-x86_64` 条目、签名不对、不是 HTTPS）译成中文。
- 安装包只在内存里：没装就关机，下次重新下载。
- 退出时没装上：弹只有“确定”的提示（原因、当前版本不受影响、包没保留、下次从托盘“检查更新”重下），然后照常退出。选“是”却没装上：不退出，包留着，下次退出再试。

**再次启动：** single-instance 插件（在核心里）：第二次启动的程序把消息交给已开的、自己退出，已开的把窗口恢复到前台。

**下载：** WebView2 自己的下载存进“下载”（`a.download` 的 `blob:` 和带 `Content-Disposition` 的都一样）。

**出错提示和记录：**
- 员工能感知的失败（新窗口打不开、交给浏览器失败、新窗口下载没下下来、检查更新、开机自启设置失败、安装没成功）弹中文系统消息框（后台线程弹，不卡窗口）。
- 失败都记日志 `%LOCALAPPDATA%\<应用标识>\logs\shell.log`（UTC），超 256 KB 改名 `shell.old.log` 重写，最多两份；开发版同时打到控制台。
- 页面没加载成功的记错误码、HTTP 状态码和网址（只留来源和路径，不带查询串和 `#` 后面——可能有客户名）；被取消和变成下载的导航不记。

## 安全边界

- 外壳不调 ERP 接口、不读登录凭据、不看页面内容，不依赖网页的 DOM、类名、事件或路由。
- **不开任何 IPC 权限：** 没有 `capabilities/`，各份配置里没有内联权限，`build.rs` 不改权限路径，Rust 里不注册命令、不加权限，`withGlobalTauri` 关闭；编译生成的 `gen/schemas/capabilities.json` 是空的 `{}`（边界检查都查）。Tauri 仍会往每个网页注入 `window.__TAURI_INTERNALS__`，但没权限时命令一律被拒（端到端测试试调几个，都被拒）。ERP 网页就靠这个对象认出 Windows 客户端（端到端测试守着它存在）；换 Tauri 版本或收紧注入前先看[外壳和网页](../../../docs/架构/外壳和网页.md)“网页怎么认出两个外壳”。
- 插件（单实例、opener、更新、开机自启）都只在 Rust 里用、不往网页注入脚本；`window.__TAURI__.插件名` 的接口脚本只在 `withGlobalTauri` 打开时才编进去。边界检查按 `Cargo.lock` 锁定的插件源码逐个查（初始化脚本、`eval` 都算注入）。
- `yl` 协议只读 `pages\` 里直接放着的几类普通文件（不跟符号链接、不读设备名），响应带 CSP `default-src 'self'; style-src 'self'`，不放脚本。`tauri.conf.json` 不写 CSP（它只管 Tauri 自带的资源协议，这里没有内嵌前端）。
- 启动器一开始就把 dll 搜索收紧到程序目录、系统目录和登记过的目录（`LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`；输入法、外壳扩展要用登记目录）；核心按完整路径加载，它的依赖另从 dll 所在目录找；都不从当前目录、PATH 找。
- 更新包必须能用 `config\app.json` 的公钥核对签名、签名里版本号和清单一致；正式版清单只认 HTTPS。`config\` 和程序在同一个用户可写的目录，能改配置的人本来也能换程序，不另设防。

## 代码检查的口径

`Cargo.toml` 的 `[lints.clippy]` 和 `clippy.toml`：
- 和 ERP 一致：函数 80 行（不算空行、注释）、参数 5 个；不用 `unwrap`、`expect`（测试里可以）。一定成功的常量网址用 `#[expect(clippy::expect_used, reason = "…")]` 写理由（`pages.rs` 私有的 `url`，只由 `offline_url`、`splash_url` 调；`window.rs` 的 `about:blank`）。
- 和 ERP 不同、只当粗筛：clippy 没有圈复杂度，`cognitive_complexity` 20 是“认知复杂度”；`excessive_nesting` 4 连函数体、闭包体一起算，比 ERP 约严一层。
- 文件 500 行由边界检查管。

## 依赖

- 运行时（Rust，都是 Tauri 官方的）：`tauri` 2.12（开 `tray-icon`）、`tauri-plugin-single-instance` 2.5、`tauri-plugin-opener` 2.7、`tauri-plugin-updater` 2、`tauri-plugin-autostart` 2（经 `auto-launch` 写注册表）。另有 `webview2-com` 0.39、`windows-core` 0.62 挂 WebView2 事件，和 wry 用的是同一份（边界检查核对 `Cargo.lock` 里各一份）；`serde_json` 1 本来随 tauri 编进来，写了 `plugins.updater` 时 `generate_context!` 要求直接依赖。启动器不用任何库。
- 构建：`tauri-build` 2.7、Rust stable（MSVC）、VS 2022 生成工具“使用 C++ 的桌面开发”、Node.js 24、`@tauri-apps/cli` 2.12.5；NSIS 用本机缓存的（没有就自动下载）。
- 运行环境：WebView2 运行库（Win10/11 自带；安装包带下载引导）。

## 已知的限制

离线页不自己重试、连着自动下载第二份时弹多文件下载的权限框、以管理员身份运行时勾选开机自启会登记到 `HKLM`（卸载删不到），都记在[路线图](../../../docs/计划/路线图.md)“应用外壳发版前看要不要做的”。
