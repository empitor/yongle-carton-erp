# 架构说明

Windows 外壳装好后是什么样、代码怎么分、每个行为怎么做、安全边界、检查口径和依赖。怎么构建、测试、打包见[构建与测试](构建与测试.md)。

## 安装后的样子

```
%LOCALAPPDATA%\甬勒ERP\           （测试版是 甬勒ERP测试\，启动器叫 甬勒ERP测试.exe）
├─ 甬勒ERP.exe            唯一的程序：开始菜单和桌面快捷方式都指向它，运行时的进程就是它
├─ yongle_erp_core.dll    客户端核心：窗口、托盘、单实例、下载、开机自启、应用内更新
├─ config\app.json        ERP 网址、更新清单地址、更新公钥
├─ pages\                 外壳自带页面：离线页 index.html、offline.css，启动画面 splash.html、splash.css
└─ uninstall.exe          卸载程序
```

启动器按完整路径加载同目录的核心 dll（依赖只从 dll 所在目录和系统目录找），在自己这个进程里调它导出的 `yongle_erp_run_v1`，一直跑到程序退出；不再另起一个程序。入口名带接口版本：入口的参数或约定改了就换名字，程序和核心不是同一版时启动器找不到入口，弹系统消息框说明。核心找不到、`config\app.json` 读不到或写错、窗口建不起来时，也弹系统消息框说明原因（Tauri 启动出错时用 panic 报原因，核心接住后把原因带出来）。

`config\app.json` 和 `pages\` 在运行时读：本机改了下次启动就生效，不用重新编译；但应用内更新会用新安装包里的那份覆盖它们，要长期改得改仓库里的 `config/app.json`、`pages/` 再发版。

代码只分成两个文件（程序和一个核心 dll），没有按功能拆成多个 dll：核心是 Rust 写的，Rust 没有稳定的二进制接口，dll 之间只能按 C 的方式互相调用；窗口、托盘都依赖 Tauri，每个 dll 都要各带一份 Tauri，体积会翻几倍；更新又是整个安装包签名替换，拆开没有收益。

## 目录

| 位置 | 放什么 |
|---|---|
| `src-tauri/src/launcher.rs` | 启动器（`yongle-erp-launcher`，打包时按 `mainBinaryName` 改名 `甬勒ERP.exe`）：收紧进程的 dll 搜索、加载核心 dll、调入口；只用标准库和 Windows 自带的 `SetDefaultDllDirectories`、`LoadLibraryExW`、`GetProcAddress`、`MessageBoxW`。发布版不带控制台，开发版带（核心的出错记录直接能看到） |
| `src-tauri/src/lib.rs` | 核心（`yongle_erp_core.dll`）的入口 `yongle_erp_run_v1` 和装配：读配置、注册自带页面的协议、插件、托管状态、建托盘和主窗口、开启动画面（开机自启时不开） |
| `src-tauri/src/window.rs` | 主窗口和网页弹出的新窗口：建窗口、按网址分流放行导航和新窗口、交给浏览器、按加载结果切离线页、“重试”、“重新载入”、从托盘唤起、点 × 收进托盘 |
| `src-tauri/src/route.rs` | 网址分流的规则（纯函数）：留在窗口、交给浏览器还是不打开 |
| `src-tauri/src/loading.rs` | 主页面的加载结果：挂 WebView2 的“导航完成”事件；“结果 → 去哪”的判断是纯函数 |
| `src-tauri/src/popup.rs` | 新窗口的收尾：网页自己关窗、只用来下载的窗口下载完，关掉整个窗口 |
| `src-tauri/src/tray.rs` | 托盘和菜单 |
| `src-tauri/src/autostart.rs` | 开机自动启动：插件设置、自启参数、菜单勾选状态 |
| `src-tauri/src/updater.rs` | 托盘“检查更新”：读清单、下载校验、问什么时候装、退出时安装 |
| `src-tauri/src/splash.rs` | 冷启动的启动画面：无边框小窗 |
| `src-tauri/src/config.rs` | 读 `config\app.json`：只认三个键，读不到、写错、多了不认识的键、网址不合规矩都报出原因、不启动 |
| `src-tauri/src/pages.rs` | 自带页面：自定义协议 `yl`（Windows 上是 `http://yl.localhost/`）从安装目录 `pages\` 读文件；离线页、启动画面的地址 |
| `src-tauri/src/notice.rs` | 系统消息框（提示、问“是 / 否”）：自己声明 Windows 的 `MessageBoxW`；程序名 |
| `src-tauri/src/report.rs` | 出错记录：写进日志文件 |
| `src-tauri/installer-hooks.nsh` | 安装包钩子：装、删核心 dll（它是 cargo 编出来的库，进不了 `bundle.resources`）；卸载时删开机自启的登记 |
| `config/app.json` | 正式版的配置（正式网址，更新地址和公钥先空着）；测试版由 `scripts/build-test.mjs` 另写一份放在 `src-tauri/target/test-config/` |
| `pages/` | 外壳自带页面，安装后在 `pages\` |
| `src-tauri/build.rs` | Tauri 规定的构建入口，只有一行 `tauri_build::build()` |
| `src-tauri/tauri.conf.json` | 正式版的名字、主程序名 `甬勒ERP`、标识、图标、安装进 `config\`、`pages\` 的文件、更新插件设置、安装包（NSIS，按当前用户安装、简体中文、钩子） |
| `src-tauri/tauri.test.conf.json` | 测试版覆盖项：名字和主程序名“甬勒ERP测试”、标识 `cn.nbyongle.erp.desktop.test`、允许本机回环地址的 http 更新清单 |
| `src-tauri/Cargo.toml`、`Cargo.lock`、`clippy.toml` | 核心是 `[lib]`（`cdylib`，编成 dll），启动器是唯一的 `[[bin]]`（所以安装包把它当主程序）；依赖、锁定版本、代码检查的规则和上限 |
| `src-tauri/icons/` | 由 `icons-src/app-icon.svg`（白底加公司商标）用 `npx tauri icon` 生成；启动器带这个图标，核心用它做窗口和托盘图标 |
| `package.json`、`package-lock.json` | 只有开发依赖 `@tauri-apps/cli` 和几条命令（`check`、`build`、`build:test`、`test:e2e`） |
| `.gitignore` | 依赖、构建产物、安装包、签名证书和私钥（`*.msi`、`*.pfx`、`*.p12`、`*.key`）不进仓库 |
| `scripts/env.ps1`、`scripts/build-test.mjs`、`scripts/update-test.mjs` | 临时设 Rust 环境变量；打测试版（网址必须写明）；应用内更新的本机测试 |
| `tests/` | 边界检查、端到端测试和它的准备代码、测试页服务、操作 Windows 窗口和鼠标的小工具 |
| `test-site/` | 虚构测试页 |

**核心里的文件怎么分层：** 入口 `lib.rs` 用 `mod` 声明其余文件，每个文件只引更底层的，没有循环；`tests/boundary.test.mjs` 的登记表写着每个文件能引哪几个：

```
lib ──→ autostart、config、notice、pages、report、splash、tray、updater、window
tray ─→ autostart、config、notice、report、updater、window
window → config、loading、notice、pages、popup、report、route、splash
popup ─→ loading、notice、report、route
loading → pages（只在测试里）、report、route
updater → autostart、config、notice、report
autostart → report      splash → report      route → pages
config、notice、pages、report：最底层，不引别的
```

导航规则和“按加载结果导航主窗口”都在 `window.rs`：“重试”要重新加载主窗口，加载结果又要导航主窗口，拆开就成了互相引用。WebView2 的事件怎么挂、结果怎么判断放在 `loading.rs`、`popup.rs`，它们不碰主窗口。启动器是另一个程序，只用标准库，和核心不共用代码（入口名两边各写一次，边界检查核对两边一致）。

**安装包怎么装这些文件：** Tauri 的 NSIS 模板把唯一的程序（启动器）当主程序，按 `mainBinaryName` 改名放进安装目录，快捷方式、安装完“运行”、更新后重启都指向它；`config\`、`pages\` 按 `bundle.resources` 装、卸载时删；核心 dll 由钩子装、删：钩子宏在模板插入它的地方才展开，用模板定义的 `MAINBINARYSRCPATH`（编出来、改过名的启动器）找同目录的 dll。打包时用 `--no-binary-patching`（Tauri 要往主程序写安装包类型标记，可启动器里没有 Tauri），`-- --lib` 让核心 dll 和启动器在同一次编译里出来。

## 两个版本

| | 正式版 | 测试版 |
|---|---|---|
| 网址、更新清单、公钥 | `config/app.json`（正式网址；更新地址和公钥先空着 = 不检查更新，托盘里也没有“检查更新”） | `scripts/build-test.mjs` 按命令行和环境变量另写一份 |
| 标识 | `cn.nbyongle.erp.desktop` | `cn.nbyongle.erp.desktop.test` |
| 启动器、安装位置 | `甬勒ERP.exe`，`%LOCALAPPDATA%\甬勒ERP` | `甬勒ERP测试.exe`，`%LOCALAPPDATA%\甬勒ERP测试` |
| 网址规矩 | `config.rs` 两版一样：ERP 网址和更新清单地址只收 https，本机回环地址（127.0.0.1、localhost、[::1]）也收 http；更新地址和公钥要么都填、要么都空。正式版另外由更新插件在 release 构建里只认 https 清单（报错译成中文） | 更新插件另外允许 http 清单（`dangerousInsecureTransportProtocol`） |

标识不同，登录数据（WebView2 数据目录）、单实例、日志、安装位置都互不影响。

## 行为和实现

| 行为 | 怎么做的 |
|---|---|
| 启动画面 | 冷启动时核心先开一个无边框小窗放 `pages\splash.html`（Y、L 两个图形从两边靠拢 0.9 秒合成商标，1.3 秒时淡出），主窗口同时在后台加载 ERP；ERP 页面加载好（或确定连不上）且放够 1.5 秒后，先关小窗再露出主窗口；最多挡 8 秒。结果来得比小窗建好还早（建小窗时主线程在转消息循环，连不上的结果很快就到）也不丢：先记下“已就绪”，小窗一建好就照常收尾。小窗建不起来就记一笔、直接露出主窗口。从托盘恢复、再次启动唤起不经过这里，不重播；启动画面放着时再次启动什么都不做，等它自己收尾 |
| 加载 ERP 和离线页 | 启动、“重试”、“重新载入”都直接让 WebView2 加载 ERP，外壳不自己去连（走系统代理上网的电脑也能用）。主页面每次导航完，WebView2 的“导航完成”事件给出结果：连不上（连接失败、被拒、域名解析失败、超时、证书错误）、整页打开拿到网关报错 502、503、504（服务器升级重启时会出现）就切到离线页，用着用着断网再点页面也一样；ERP 页面好了就让启动画面收尾。页面里的接口请求不走这个事件，拿到 502 不切页。被取消的导航（外壳拦下交给浏览器的站外链接、被新导航顶掉的）、变成下载的导航、服务器回的别的错误页（404、500 等）都不算连不上；外壳自带页面的结果一律不管，不会来回跳；只看主页面，不管子框架。从托盘或再次启动唤起窗口时，停在离线页就再加载一次 ERP |
| 网址分流 | `route`：协议、主机、端口都和 ERP 网址相同的留在窗口里（ERP 页面自己生成的同源 `blob:` 也算）；外壳自带页面放行；离线页的“重试”拦下、重新加载 ERP；别的 http(s) 交给系统默认浏览器（opener 插件）；其余协议（`file:`、`javascript:`、`mailto:` 等）不打开。只管顶层导航：网址解析不了的导航 Tauri 会直接放行，所以主页面加载完再核一次，停在站外或解析不了的网址就回 ERP 首页；页面里的 iframe 不经过分流 |
| 新窗口 | 站内的开一个规则相同的外壳窗口（共用登录，`target=_blank` 带不带 `rel="noreferrer"` 都一样），站外的交给浏览器；opener 插件改写链接的脚本已关掉。网页自己 `window.close()` 时关掉整个窗口，不留空白窗口。新窗口一页都没显示就变成了下载（原件是 Excel、Word 这类）时：下完了、被人取消了就关窗口；被人暂停了留着窗口（下载提示在窗口里）；没下下来（断网、服务器出错、磁盘满、被安全检查拦下）先记日志、弹“文件没下载下来：原因。请重试。”再关窗口。窗口里显示过页面的，下载怎样都不关窗口 |
| 拖放 | 主窗口和新窗口关掉 Tauri 自己的拖放接管，ERP 网页的 HTML5 拖放（拖文件进上传区、排产板拖动）照常；文件拖到页面上没有接收区的地方，WebView2 会去打开 `file:///`，分流按“别的协议”拦下。启动画面保留接管（它没有导航规则） |
| 窗口大小和缩放 | 主窗口 1280×800 居中、最小 960×600，屏幕放不下时缩到屏幕里（`prevent_overflow`）；和浏览器一样能用 Ctrl+滚轮、Ctrl± 缩放页面 |
| 点 × | 主窗口 `CloseRequested` 时阻止关闭、只隐藏；网页弹出的窗口照常关 |
| 托盘 | 商标图标，提示“甬勒ERP”；左键松开恢复主窗口；右键菜单“显示”“重新载入”“检查更新”（只在配了更新地址的版本里有）、“开机自动启动”（勾选项）、“退出” |
| 开机自动启动 | 官方 `tauri-plugin-autostart`，默认不勾。勾上时在当前用户的注册表 `Run` 项登记“程序路径 --autostart”（值名是 productName，即“甬勒ERP”或“甬勒ERP测试”；插件写的命令不带引号，用户目录带空格时由 Windows 按空格逐段去找程序，能启动），并在 `Explorer\StartupApproved\Run` 写同名的“已启用”；取消勾选就删掉。带 `--autostart` 启动时安静地待在托盘里：不放启动画面、不弹主窗口，主窗口在后台加载好，点托盘图标马上出来；已经开着时又被自启拉起一次也不弹窗口。人点开的、再次启动唤起窗口照旧。菜单的勾选跟着系统里实际的登记走（任务管理器里关掉了也显示没勾）。卸载（不是升级）时安装包钩子删掉这两项登记 |
| 检查更新 | Tauri 官方 Updater：按 `config\app.json` 的清单地址和公钥查（每次请求最多等 2 分钟），有新版问“要现在下载吗”（是 / 否）；下载时按公钥核对签名（另外要求签名里带的版本号和清单一致：`requireSignedVersion`），对不上就报错不留包；下载好问“现在安装吗”：选“是”马上交给安装器（被动模式），装完由安装器带着这次运行的命令行参数经启动器重新打开——人点开的那次会自动重新打开；开机自启拉起的那次（带 `--autostart`）重开后照样安静地待在托盘里，问话就写“装完程序回到托盘，点托盘图标打开”。选“否”等从托盘“退出”时再装：退出就是退出，装完不重新打开（问话里写明）。查或下载期间再点只提示“正在检查或下载”。常见报错（连不上、清单读不出、没有 `windows-x86_64` 条目、签名不对、不是 HTTPS）译成中文。点 × 仍只是收进托盘。安装包只放在内存里：没装就关机，下次要重新下载 |
| 退出时安装没成功 | 弹一个只有“确定”的提示，写明原因、现在的版本不受影响、安装包没保留（只在内存里），下次打开后从托盘“检查更新”重新下载；然后照常退出。“现在安装吗”选“是”却没装上时，程序不退出，安装包留着，下次从托盘退出时再试 |
| 再次启动 | single-instance 插件（在核心里）：第二次启动的 甬勒ERP.exe 加载核心后把消息交给已开的那个、自己退出，已开的把窗口恢复到前台 |
| 下载 | 用 WebView2 自己的下载存进“下载”文件夹（`a.download` 生成的 `blob:` 文件和服务器带 `Content-Disposition` 的文件都一样） |
| 出错提示和记录 | 员工能感知的失败（新窗口打不开、交给浏览器失败、新窗口里的下载没下下来、检查更新、开机自启设置失败、安装没成功）弹中文系统消息框（Windows 的 `MessageBoxW`，在后台线程里弹，不卡窗口）。失败都记进日志：`%LOCALAPPDATA%\<应用标识>\logs\shell.log`（UTC 时间），超过 256 KB 就改名成 `shell.old.log` 重新写，最多两份；开发版同时打到启动器的控制台。页面没加载成功的记错误码、HTTP 状态码和网址（只留来源和路径，不带查询串和 `#` 后面，那里可能有客户名这类搜索词）；被取消的导航和变成下载的导航太常见，不记 |

## 安全边界

- 外壳不调 ERP 的接口、不读登录凭据、不看页面内容，不依赖网页的 DOM、样式类名、事件或路由。
- 不开任何 IPC 权限：没有 `capabilities/`，各份配置（`tauri.conf.json`、测试版，另有平台版的话也算）里没有内联权限，`build.rs` 不改权限路径，Rust 里不注册命令、不加权限，`withGlobalTauri` 关闭；编译后 tauri-build 生成的权限清单 `gen/schemas/capabilities.json` 是空的 `{}`（边界检查都查）。Tauri 仍会往每个网页注入 `window.__TAURI_INTERNALS__`，但没有权限时插件命令一律被拒（端到端测试从网页里试调几个插件和核心的命令，都被拒）。外壳没给网页留别的标记，ERP 网页就靠这个对象认出自己在 Windows 客户端里（约定写在 ERP 项目 `docs/架构说明.md`“网页怎么认出两个外壳”），端到端测试守着它存在；换 Tauri 版本或收紧注入时要先看这一条。
- 用到的插件（单实例、opener、更新、开机自启）都只在 Rust 里用、不往网页注入脚本；opener 的改链接脚本已关。插件自带的 `window.__TAURI__.插件名` 接口脚本只在 `withGlobalTauri` 打开时才编进去。边界检查按 `Cargo.lock` 锁定的插件源码逐个查（初始化脚本、`eval` 都算注入）。
- 外壳自带页面经 `yl` 协议只读 `pages\` 里直接放着的几类普通文件（不跟符号链接、不读 Windows 设备名），响应带 CSP `default-src 'self'; style-src 'self'`，不放脚本。`tauri.conf.json` 不写 CSP：它只管 Tauri 自带的资源协议，这里没有内嵌前端。
- 启动器一开始就把进程的 dll 搜索收紧到程序目录、系统目录和进程里登记过的目录（`LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`，输入法、外壳扩展这类组件要用登记目录）；按完整路径加载核心 dll，它的依赖另外从 dll 所在目录找。都不从当前目录、PATH 找。
- 更新包必须带能用 `config\app.json` 里公钥核对的签名，签名里的版本号要和清单一致；正式版的清单只认 HTTPS。`config\` 和程序文件在同一个当前用户可写的安装目录里，能改配置的人本来也能换程序，不另设防。

## 代码检查的口径

`Cargo.toml` 的 `[lints.clippy]` 和 `clippy.toml`：函数 80 行（不算空行、注释）、参数 5 个，和 ERP 的代码检查一致；不用 `unwrap`、`expect`（对应 ERP 不用非空断言，测试里可以用），一定成功的常量网址用 `#[expect(clippy::expect_used, reason = "…")]` 写明理由（`pages.rs` 私有的 `url`，只由 `offline_url`、`splash_url` 拿两个常量文件名调；`window.rs` 的 `about:blank`）。另外两条口径和 ERP 不同，只当粗筛：clippy 没有圈复杂度，`cognitive_complexity` 20 是“认知复杂度”；`excessive_nesting` 4 连函数体、闭包体一起算，比 ERP 的嵌套 4 层大约严一层。文件 500 行由边界检查管。

## 依赖

- 运行时（Rust）：`tauri` 2.12（开 `tray-icon`）、`tauri-plugin-single-instance` 2.5、`tauri-plugin-opener` 2.7、`tauri-plugin-updater` 2、`tauri-plugin-autostart` 2（经 `auto-launch` 写注册表）都是 Tauri 官方的；`webview2-com` 0.39、`windows-core` 0.62 用来挂 WebView2 的事件，和 tauri 里 wry 用的是同一份（边界检查核对 `Cargo.lock` 里各只有一份）；`serde_json` 1 本来就随 tauri 编进来，配置里写了插件设置（`plugins.updater`）时 `generate_context!` 要求直接依赖它。启动器不用任何库。
- 构建：`tauri-build` 2.7、Rust stable（MSVC）、VS 2022 生成工具“使用 C++ 的桌面开发”、Node.js 24 和 `@tauri-apps/cli` 2.12.5；打安装包时 Tauri CLI 用本机缓存的 NSIS（没有就自动下载）。
- 运行环境：WebView2 运行库（Win10/11 自带；安装包默认带下载引导）。

## 已知的限制

离线页不自己重试、连着自动下载第二份时弹多文件下载的权限框、以管理员身份运行时勾选开机自启会登记到 `HKLM`（卸载删不到），都记在 ERP 项目 `docs/路线图.md`“应用外壳”。
