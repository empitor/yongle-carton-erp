# 子智能体须知

在这个项目里干活的智能体（Claude Code、Codex、Antigravity，主会话和子智能体都算）开工前读这份，派工说明写“先读 `.claude/子智能体须知.md`”。这里只放 `AGENTS.md` 里没有、干活时要知道的项目做法；硬规则、业务规则、一件事一条链路、文件怎么分、文档怎么维护都以 `AGENTS.md` 为准，改代码前先读它的“业务规则”和“一件事一条链路”。系统怎么搭的见 `docs/架构说明.md`（入口；各题目在 `docs/架构/` 下），下面写到的做法那里有细则。各家自己的配置说明只写在它自己的文件里（Claude Code 是 `CLAUDE.md`）。

## 给不是 Claude Code 的智能体

这个项目只有 `.claude/` 这一套环境（须知、技能、审查员定义、钩子脚本都只放在 `.claude/`、只有一份），没有另造副本。`.agents/` 和 `.codex/` 里只放各自软件需要的指路小配置。

- **技能：** Antigravity 经 `.agents/skills.json` 发现下面两个技能。Codex 用到哪个，就直接读它的 `SKILL.md`。
  - `ui-check`（`.claude/skills/ui-check/SKILL.md`）：界面改动、删除和权限相关改动，要在真实浏览器里看效果时读（起虚构数据的预览实例、截图或走流程，必要时给用户看）。
  - `release`（`.claude/skills/release/SKILL.md`）：发布新版本（检查、改版本号、整理更新记录和发布说明、提交、标备注、打标签推送、Linux 上测试和打包、GitHub 发布、上服务器核对）。**只在用户明确说要发布时**才读并照做，不要自行调用。
- **审查：** 改完 `server/`、`shared/`、`src/` 的业务代码、收尾汇报前，按项目规则查一遍。Claude Code 直接派 `erp-rules-reviewer` 子智能体；其他智能体（Codex、Antigravity 等）在发起审查时，让负责审查的智能体先读 `.claude/agents/erp-rules-reviewer.md` 照着查，并按里面的汇报格式返回。
- **钩子：** 挡板钩子和先问人的命令在三家软件里的接法和拦截范围见下面“钩子会拦什么”。

## 硬规则（AGENTS.md 之外的）

- 不读不写：`.env` 和 `.env.<后缀>`（`.env.example` 可以读）、密钥文件（`.pem`）；真实数据目录见 AGENTS.md“绝对不能做”。
- 搜索只在 `server/ shared/ src/ tests/ scripts/ docs/` 里做，不在项目根目录不带目录地搜。
- 不连 `127.0.0.1:3001`（正式实例，真实数据）。
- 任何情况下都不加载、不运行 `server/index.ts`（见 AGENTS.md“绝对不能做”）。自己写脚本加载 `server/` 下的任何文件（包括 `server/app.ts`）之前，先把 `LOCALAPPDATA`、`ERP_CONFIG_DIR`、`DB_PATH`、`ERP_BACKUP_DIR` 都指到新建的临时目录。
- 不许以项目根目录（或没写明的当前目录）为来源做复制、移动、同步；要副本只从指定的回退点拷，或只拷点名的 `server/ shared/ src/ scripts/ tests/`。带变量的复制命令先打印来源和去向，带 `$` 的写成脚本文件再跑。
- 不提交、不推送：子智能体一律不做，主会话等用户说了才做（AGENTS.md“用户说了才能做”）。不运行 `npm run build`；构建检查用下面“测试”表里的命令。

## 钩子会拦什么

三家在工具执行前调用同一个挡板 `.claude/hooks/protect-real-data.mjs`。挡板按下表取命令或路径，再应用共用规则。被拦就换写法，不要绕过。

| 软件 | 配置与生效条件 | 钩子检查的工具和参数 |
|---|---|---|
| Claude Code | `.claude/settings.json`，新会话生效 | `Bash`、`PowerShell` 取 `tool_input.command`。`Read`、`Edit`、`Write`、`MultiEdit`、`NotebookEdit`、`Glob`、`Grep` 取 `tool_input` 的 `file_path`、`notebook_path`、`path`。`Glob` 还检查 `pattern` 中第一个通配符前的路径 |
| Codex | `.codex/hooks.json`，项目须受信任，钩子首次使用或定义改动后由用户用 `/hooks` 信任 | 终端按 `Bash` 上报（本机运行 PowerShell），取 `tool_input.command`。`apply_patch` 从同一字段的补丁头检查 `Add File`、`Update File`、`Delete File`、`Move to` 的路径 |
| Antigravity | `.agents/hooks.json`，新会话生效 | `matcher` 为 `*`。`run_command` 取 `toolCall.args.CommandLine`。其余工具检查参数名以 `Path` 结尾的值和 `Cwd`（大小写不限）。`run_workflow` 还按命令文字检查 `Script` |

命中禁止项时，Claude Code 和 Codex 收到 `hookSpecificOutput.permissionDecision = deny`，Antigravity 收到顶层 `decision = deny`。允许的操作和无法识别的输入都不输出决定。输入的 `cwd` 缺失或为空时，按项目根目录解析相对路径。

- 文件工具会拦项目下的 `data/`、`backups/`，以及 `AppData\Local\ZhixuERP`、`.pem`、`.env`、`.env.<后缀>`（`.env.example` 除外）。在 Git 单独工作区里，挡板通过 Git 元数据找到主项目，同时保护两边的真实数据目录。
- 命令工具按文字做以下检查（反斜杠按正斜杠算）。
  - 以 `data/`、`backups/`、`./data/`、`./backups/` 开头的相对路径（前面是行首、空白、引号、`=`、`(`、`;`、`|`、`&`、`<`、`>`、`,`）。`src/data/` 这种不算。
  - `cd`、`pushd`、`Set-Location`、`sl` 进 `data`、`backups`。
  - 当前工作区或主项目根目录的绝对路径后接 `/data`、`/backups`。以 `./` 或 `../` 开头的路径会解析后检查是否指向这些目录，也检查等号后的路径参数。
  - `ZhixuERP` 前接 `AppData/Local`、`%LOCALAPPDATA%`、`$LOCALAPPDATA`、`${LOCALAPPDATA}`、`$env:LOCALAPPDATA`。
  - 出现 `.pem`（作 `-i` 参数给 `ssh`、`scp` 指定身份文件除外）。
  - 单独出现的 `.env`、`.env.<后缀>`（`.env.example` 除外）。
  - `npm run build`（也认 `npm.cmd` 和 `run-script`）、`scripts/build.mjs`、不带 `--outDir` 或 `--out-dir` 的 `vite build`。
- 命令里只是文字提到这些（比如 heredoc 写的文件内容里有 `data/`）也会被拦：要往文件里写这些字样时用文件工具（Claude Code 的 Write、Edit，Codex 的 `apply_patch`，Antigravity 的 `write_file`、`edit_file`）。

先问人的命令前缀包括 `git push`、`git tag`、`npm run patch-server`、`npm run package`，以及 `gh release` 的 `create`、`upload`、`edit`、`delete`。Claude Code 由 `.claude/settings.json` 的 `permissions.ask` 处理。Antigravity 的钩子从同一份清单读取 Bash 和 PowerShell 命令前缀，匹配时忽略大小写，并识别前置环境变量赋值、括号或花括号包住的命令、用 `&` 和完整路径调用的命令，命中时回顶层 `decision = ask`。Codex 在受信任项目中由 `.codex/rules/ask-before.rules` 的 `prompt` 规则处理，覆盖无后缀、`.cmd` 和 `.exe` 的命令名，改规则后重启 Codex。`tests/claude-hooks.test.mjs` 核对清单和 Codex 规则一致。提交仍须遵守 AGENTS.md“用户说了才能做”。

写完文件后，Claude Code 的 `Write`、`Edit`、`MultiEdit` 和 Codex 的 `apply_patch` 会调用 `.claude/hooks/file-size-reminder.mjs`，通过 `PostToolUse` 的 `additionalContext` 提醒。它检查 `server/ shared/ src/ tests/ scripts/` 下的代码和样式，跳过 `server/core/schema/tables/`。Claude Code 的 `Write` 直接看写后的行数，`Edit`、`MultiEdit` 在有替换新增行时检查。Codex 检查新增文件和本次补丁净增行数的文件，包括移动后的路径。相对路径在 `cwd` 为空时按项目根目录解析，也识别 Git Bash 的 `/c/...` 盘符路径。超过 300 行才提醒，超过 500 行会提示上限。Antigravity 的 `PostToolUse` 无法返回提醒文字，使用时自行留意文件长度。

## 排版

项目不用 prettier（没有配置文件）。照文件现有的写法写：单引号、行宽 100 左右。只排自己改的那几行，不要把整个文件重排一遍。

## 命令行

- Git Bash（Claude Code 的 Bash 工具）会吃掉反斜杠：带正则或反斜杠的脚本用文件工具写成文件（放草稿目录），再用 `node <文件>` 执行。
- Git Bash、PowerShell 命令的文字里不写反引号和没加引号的 `$(…)`：Git Bash 会把里面的字当命令执行，PowerShell 把反引号当转义（出过事：一句说明文字里的反引号让 `npx` 从网上下载并运行了同名的包）。要往文件里写带这些字符的文字，用文件工具。
- 项目里的文件换行不统一（有的 CRLF、有的 LF，新开的工作区检出来多是 CRLF）：用脚本按 `\n` 整段替换可能悄悄对不上，或者把文件弄成混合换行。改文件用文件工具；非用脚本不可时，先读出文件原来用哪种换行，照它写回。
- `npx` 只在项目根目录或两个外壳的工程目录里跑：在草稿目录、临时目录里它找不到本地装的工具，会去网上下载同名的包来运行。

## 后端读库、读单据、地址

细则见 `docs/架构/服务端写法.md`（“接口表”“读库”“防重复提交”）、`docs/架构/业务主线.md`“单据流转和订单进度”、`docs/架构/财务.md`“财务从哪拿业务数据”。最常踩的：

- **请求身份：** 路由的账号参数用基础模块入口的 `RequestAuth`；装配传入账号模块的实现。账号库和登录记录的归属见 [账号和权限](../docs/架构/账号和权限.md)。
- **读库：** 只用 `server/core` 的 `one`、`many`、`exists`、`count` 和生成的 `rows.<表名>`，不写 `.all() as …`；JSON 列用 `parseStoredJson` 读，不直接 `schema.parse` 库里的东西（不合结构是 `StoredDataError`、回 500）。
- **读单据内容：** 单据流转里只走 `storedContent`，别的模块用 `parseStoredJson(flowDocumentSchema(种类), …)`，不自己 `JSON.parse`；视图走 `FlowService.get`、`list`。服务端给单据加字段，同时加进 `shared/business/flow-document.ts`，并在 `shared/business/finance-source.ts` 的归类表里归类。
- **财务要业务的数据：** 在 `server/flow/finance-facts/` 加只读函数，财务调 `financeFacts`，不在财务里写读业务表的 SQL；读不出来要逐条跳过的照“读不出来的跳过”（`readOrSkip`）。库存流水的来源编码按名字引用 `movementSource`。
- **地址：** 先在接口表（`shared/<路由主人模块>/<名字>-api.ts`）写键，服务端 `route<表>(router)` 注册，前端在本模块 `*-api.ts` 里用 `call<表>()` 发、建出来的函数不导出给组件。新的写地址、助手写入命令要登记成一条业务动作，见 AGENTS.md“新增功能时一起改”（账号、助手、设置、数据管理的动作在 `shared/assistant/ui-actions-system.ts`，其余在 `shared/assistant/ui-actions.ts`）。

## 前端

细则见 `docs/架构/前端约定.md`、`docs/界面规范.md`“公共件”。

- 组件和 hook 不直接写地址发请求：请求收进本模块的接口文件（财务是 `finance/fin-api.ts` 和各页签的 `*-api.ts`），同一个写地址只由一个函数发；别的模块的数据走 `src/ui/slots.tsx` 的服务接口。
- 提示、出错、正在读取、时间、日期筛选、列表工具栏和表格、页头和“更多”这些用 `src/ui` 的公共件（清单见界面规范“公共件”），不在模块里另写；列表行上不手写点击和按键。
- 栏目名用 `shared/core/field-names.ts` 的 `fieldLabel` 等取，不在页面里手写。手机只有一个断点 `max-width: 700px`（`npm run lint:css` 会拦别的）。样式放在组件所在的模块目录，只在 `src/main.tsx` 引入。
- **代码检查：** 上限和禁止的写法见 AGENTS.md“验证”，全部规则见 `docs/架构/检查和测试.md`“代码检查”；测试文件也一样查，也受 500 行管。全项目现在是 0 处、`eslint-suppressions.json` 是空的，报一处就失败，不许往里登记；源码里写 `eslint-disable` 不起作用。自查用 `npx eslint <改的文件> --quiet`。

## 测试

- 测试怎么写的规矩见 AGENTS.md“验证”。搭环境只用共用的准备代码，不在测试文件里再抄一份；各份准备代码交出什么见 `docs/架构/检查和测试.md`“测试的准备代码”，测试只走模块入口（`moduleTests`、`viewAs`）见同一份“测试怎么跑”的“模块的入口”。另外几条：
  - 常用的准备代码（`flowFixture`、`businessFixture`、`workbenchFixture`、`maintenance-fixture`、`admin-edit-fixture`、`delete-fixture` 的 `setup`、`completionFixture`、`deliveryCorrectionSetup`）都交出 `base`：补建档写 `f.base.customer(...)`，核对单据写 `f.base.check(单据, 别的字段, 谁)`；没有准备代码的写 `businessBase(谁, store)`。只有测预览本身、过期、重发的才自己写 `flow.preview` 加 `flow.confirm`。生产任务直接保存（`task()`），不交给 `confirm`。
  - 建助手用 `tests/assistant-fixture.ts` 的 `assistantDeps`（或 `assistantFixture`），只测业务工具用 `toolsOf`、`ctxOf`，只测业务流程用 `autoConfirmAssistant`；建识别导入管理器用 `tests/order-import-fixture.ts` 的 `testImports`。
  - 要完整视图（已安排、可用、到货记录、单号）用 `FlowService` 的 `views`，改已有采购单、库存品和手工出入库用 `flow.stock.*`。
  - 财务测试要“假装业务变了”（直接造已确认的单据、改单据内容、撤销、删除、删流水、挪流水日期、改库存品）只用 `tests/business-changes-fixture.ts` 的 `businessChanges(store)`，不在测试里直接写业务表的 SQL；测“库里内容坏了、读不出来”用它的 `tamper(...)`（模拟直接改库，版本号不动）。直接调财务服务的测试不会自动补扫（只有路由和助手入口会）。财务看来源撤没撤销、删没删只走 `server/finance/source-scan.ts` 的 `sourceIs`，所以测“撤销后”的写入拦截不用先补扫；成本计算里“已撤销”只认窗口的 `stock.reversedArrivals`。
  - 不要用 `registerVersionedSqlite` 往全进程共用的登记表里加条目，真的规格也不行（生成行结构、基线快照检查、换回配置库都看这张表）；测位置规则用 `resolveHomes`，测换回把位置当参数传给 `revertConfigUpgrades`。

### 外壳实测的界限

- **手机：** 只装、只操作测试版（包名 `cn.nbyongle.erp.test`），连电脑上虚构数据的预览实例；不碰手机上别的应用（微信、相册、文件管理器、系统设置），不改手机的任何设置；系统弹出的权限、安装确认不替用户点；手机锁屏了就停下报告。测试文件只放“下载”、名字以 `yongle-test-` 开头、测完删掉；查文件只按确切的文件名，不列出整个目录。
- **Windows：** 不运行安装包，不动 `%LOCALAPPDATA%\甬勒ERP测试`，不改这台电脑的开机启动项；端到端测试会弹窗口、动鼠标、开一次默认浏览器，跑之前由主智能体问过用户。

## 浏览器查看（固定副本）

几路同时改代码时，审查和浏览器查看用一份固定副本，不用正在改的主项目。

1. 在草稿目录建副本，复制 `server shared src scripts tests public docs` 和根目录的 `package.json package-lock.json tsconfig.json vite.config.ts index.html AGENTS.md`。
2. `node_modules` 用目录联接指向主项目（PowerShell）：`New-Item -ItemType Junction -Path <副本>\node_modules -Target <项目>\node_modules`。
3. 在副本目录里后台起测试实例（命令和端口见 `.claude/skills/ui-check/SKILL.md`“起预览实例”），等输出 `READY`。同一端口只能起一个；改了 `server/`、`shared/` 要重启实例。
4. 截图、走流程、给助手排模型替身的回复，照 `.claude/skills/ui-check/SKILL.md` 做；走流程在草稿目录写一个复用 `scripts/ui-check/lib.mjs` 的脚本一次走完，不用内置浏览器一步一步点。

### 真实模型实例（会花钱，先问）

用法见 `.claude/skills/ui-check/SKILL.md`“真实模型模式”。另外：

- 不读、不打印、不复制、不打开存密钥的那个隔离目录里的任何文件；命令行里不写它的路径（`preview.mjs` 自己拼）。
- 冒烟脚本 `real-smoke.mjs --yes` **跑之前必须由主智能体问过用户**（会产生少量费用），只发脚本现造的虚构文件。改冒烟脚本自测用 `--fake-deepseek`，不用 `--yes`。

### 清理副本

**不要直接递归删除副本**：会顺着 `node_modules` 联接把主项目的依赖删掉。按这个顺序（PowerShell）：

1. 关掉副本上的测试实例。
2. 只删联接本身：`(Get-Item <副本>\node_modules).Delete()`。
3. 确认主项目依赖还在：`Test-Path <项目>\node_modules\.bin` 返回 `True`。
4. 再删副本：`Remove-Item -Recurse -Force <副本>`。
