# 宁波甬勒包装制品有限公司 · 管理系统

当前软件版本 **0.5.2**（0.5系列），Git标签 **v0.5.2**。面向外购瓦楞纸板、厂内加工纸箱的本地ERP，使用React、TypeScript、Express及SQLite。当前供本机开发测试，投产前仍需验证备份恢复、网络部署和真实业务流程。

**版本说明：** `v0.5.2`加入统一插件与工具管理、ERP页面控制、原工作区关联与多文件导入，并优化Agent执行预算、页面观察、逐步核验及统一权限校验。沿用`v0.5.1`的数据管理与长期任务恢复；本版没有新增业务数据库迁移。历史标签保持不动。详见[0.5.2发布说明](docs/发布说明-v0.5.2.md)。

## 主要功能

- 客户、供应商、产品、客户订单、采购订货与真实经营概览。
- 分批到货、原材料和成品库存、不可变出入库流水、生产任务/登记、仓库客户送货与订单履约。
- AI双模式单据识别、原件预览、可编辑草稿、专属草稿助手、人工核对和受控正式导入。
- 多文件有界并发、流式输出、API预设、独立提示词和工具管理、全局聊天附件与业务工具、本地语音输入。
- 登录、本机最高管理员直接编辑、物理删除、独立可恢复归档与审计。

## Windows本地启动

安装 **Node.js 24.15或更高24.x版本**和Git；进入项目目录执行：

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

浏览器访问 `http://127.0.0.1:3001`。日常双击“启动系统.cmd”，脚本检查健康状态后才打开网页；“停止系统.cmd”核验进程身份后停止。源码开发使用 `npm.cmd run dev`，前端端口5173，后端3001。首次全新安装通过右上角建立自己的管理员账号，不自动生成默认密码或业务示例。

检查命令：`npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build`。测试使用独立临时库，不清空实际业务库。仓库包含本地xlsx依赖包，不能删除`vendor/xlsx-0.20.3.tgz`后再安装。

本地语音模型不随Git上传。需要语音时，将自己备份的完整`vendor/models/sensevoice`目录放回；详见`vendor/models/README.md`。没有模型时不影响ERP及文字聊天。

## 数据与API设置

以下均是本机运行数据，不在Git仓库中：

| 数据 | 默认位置 |
| --- | --- |
| 业务数据库、流水与审计 | 项目下`data/erp.sqlite` |
| 登录账号、密码哈希、权限 | `data/security/users.sqlite` |
| AI原件、草稿、聊天及错误档案 | `data/ai-imports/` |
| 正式导入原件归档 | `data/import-archive/` |
| 提示词预设 / 工具启停 | `data/ai-prompts/` / `data/ai-tools/` |
| AI地址、模型和加密密钥 | `%LOCALAPPDATA%\ZhixuERP\ai\settings.sqlite` |

“AI设置 → API配置”填写自己的服务地址和密钥，连接、读取模型、选择模型、测试并保存启用。支持Chat Completions和Responses，第三方兼容性取决于服务；文件识别沿用已实现的直传或明确披露的兼容路径。密钥仅在后端处理，Windows使用当前用户DPAPI保护，不进入前端或Git。**DPAPI密文不能保证在另一台电脑或另一个Windows账号解密**，换电脑应重新配置密钥，业务资料可另行备份恢复。

程序不会自动加载`.env`，`.env.example`只说明环境变量。`PORT`可指定端口，`DB_PATH`可指定业务库；启动脚本会进入项目目录。不要为更新代码改动既有数据目录。

## 软件内 Agent 与 AI 插件

“AI 设置 → AI 插件与工具管理”和聊天窗口的插头按钮打开同一管理页签（`#ai-settings?tab=tools`）；旧`#ai-plugins`链接自动兼容跳转。页面以插件为第一层、工具为第二层，动态展示注册关系、权限、服务状态、独立开关和日志。关闭插件保留各工具原开关，重启和重新启用后按原设置恢复。业务服务、订单工作区、ERP页面控制、持久任务及隔离附件阅读复用同一个注册/调度器；支持插件和单项工具启停、参数/权限声明及当前账号操作日志。设置沿用`data/ai-tools/tools.sqlite`，没有第二套业务数据。普通账号遵守原业务权限，本机最高管理员沿用页面直接管理能力。

人工在AI导入页面识别的文件可通过`order_import.list/attach`原地关联。用户明确要求导入时，`execute/execute_many`使用最新完整预览和原正式服务，逐份报告结果；已经成功的原件不会重复入库，不复制、不重复识别。数据歧义和修订冲突仍需核对，真实原件/审计/事务/幂等校验保留。

聊天每次发送及`page.observe`按需读取当前ERP标签页的标题、表格、字段、按钮、弹窗、选中记录及反馈。原业务API优先；`page.act`提供导航、点击、输入、下拉选择、滚动、限定键盘和表单提交。控件引用绑定最新页面快照，页面变化拒绝旧引用。交互回执不是业务提交成功；需要业务核验的`page.act`必须在执行前通过outcome绑定该步module/id/完整expected；`page.verify`只按步骤自身的目标逐项核验，并要求业务版本变化。未绑定的历史步骤不猜测为已完成。

页面观察支持summary概要（默认）、region指定区域、record当前记录、full完整页面。概要省略静态菜单、只取少量表格行和下拉选项；表格通过tableIndex/offset/limit分页，控件和选项可按controlOffset/optionOffset继续读取。连续操作优先返回带baseSnapshotId的变化内容与反馈，客户端仍保存完整控件映射与有效性签名。

页面桥接绑定真实登录会话、账号、聊天请求和浏览器标签页；刷新/断流时不会盲目重放未知提交。密码、API密钥、Cookie/令牌不进入普通快照，账号认证区和密钥输入继续人工维护。只控制ERP自身DOM；未实现截图识别、像素鼠标、Windows控制、跨域iframe或原生浏览器确认框自动操作。完整观察上限180控件、5张表各32行、16000文字及100000字符总预算，截断会标记并可分页续读；没有后台持续截图。

聊天窗口边缘与四角支持独立调整宽高，保留拖动、最大化/恢复；位置和尺寸仅存本机浏览器，小屏和虚拟键盘区域会限制在屏内。详见[Agent升级与验收](docs/Agent插件与页面控制验收-2026-10-28.md)。

## 全局助手的长期任务

复杂流程通过独立注册工具 `task.plan/get/activate/finish` 保存步骤。任务、已成功操作的真实回执、剩余步骤和历史任务保存在原业务库 `assistant_threads.document`，按登录账号和会话隔离，不增加第二套订单或库存数据。

中断、非法JSON或达到本轮上限后，可发送“继续”“接着完成”或点击聊天窗口中的“核验并继续”。服务器先核对原执行回执和最新关联记录，已提交写入不重放；订单正式导入仍使用原预览、用户确认和幂等服务。重新登录/刷新后打开原会话仍可继续。要独立执行一份参数完全相同的新业务，请点击“开始新任务”，原任务会保留并可切换。

进度面板中的“已列步骤完成”仅表示服务器已有结果的列出步骤，模型结束回复不代表整体业务已完成。本机最高管理员免除重复密码审核；库存非负、版本、真实身份和事务限制保留。预算统一由`server/assistant/budget.ts`管理，默认15次模型/40次工具/8次业务写入/20次页面交互、30分钟。可用`ERP_AGENT_MODEL_CALLS`、`ERP_AGENT_TOOL_CALLS`、`ERP_AGENT_BUSINESS_WRITES`、`ERP_AGENT_PAGE_INTERACTIONS`、`ERP_AGENT_TIMEOUT_MS`配置，业务写入不能超过8、超时不能超过30分钟。前端任务面板展示当前用量、输出字符及真实/估算Token；未知计费结果的附件识别不会自动重发，需核查原工作区后决定是否重试。

当前协议为自定义JSON信封，未迁移Provider原生`tool_calls`；DSML控制文本不会被提取执行。只有服务明确拒绝`response_format/json_object`且尚未产生输出，Chat Completions才取消JSON参数重试一次；网络错误、524、非法JSON和DSML不触发该回退。聊天面板“下载协议诊断”导出本账号当前会话的白名单请求参数、响应形状、结束原因及错误类别，不包含密钥、消息正文、原件或完整模型响应。诊断保存在原库`assistant_audit`，不能用Git代替备份。

## 本机管理员数据管理

现阶段首先完善业务数据库管理，再逐步完善多人审批。当前优先级：完整增删改查 → 关联与库存正确 → 操作体验与AI → 复杂权限流程。

本机最高管理员登录后，直接拥有全部业务数据管理能力；不需开启超级或开发者模式、不需每15分钟验证密码。普通账号沿用原权限。后端必须核验真实登录角色、loopback远端及Host、无代理转发头，模型和请求正文不能伪造授权；登录和CSRF保留。正常登录会话8小时有效，退出或重启后需重新登录。

- 所有适用业务页提供“编辑｜归档｜删除”；归档列表提供“编辑｜恢复｜删除”。删除实际移除数据库记录，不是归档、取消、冲销或回收站，不要求先归档或库存归零。
- 物理删除由`server/business/database-maintenance.ts`统一处理真实外键和单据引用：必需子记录级联删除，可空引用解除，金额、实收、履约、库存前后余额同步维护，整个事务外键检查通过才提交。涉及其他独立业务记录时显示实际影响清单，不另设审批。
- 删除单据的库存处理有明确选项：保留其他库存已有数量并解除被删来源引用；或同时移除来源流水并重算。删除库存档案本身一并删除它的全部流水，不受非零库存限制。
- 归档保留数据库记录，可从归档筛选查看和恢复。未完成订单、未处理采购、未完成生产任务和非零/仍有待履行业务的库存不能归档，返回具体原因；不影响直接删除。
- 历史、已确认、完成、AI导入或已归档记录都可编辑。已确认实物单据按原ID直接更新并同步库存，不强制冲销另建更正单。采购计划数量允许低于实际收货；更换采购供应商/实物身份时解除旧实收关联，保留独立到货及真实库存。订单客户变更同步送货客户，必要时拆分共享送货单。
- 全局助手`records.delete`执行物理删除；`records.propose_lifecycle`的archive/restore分别执行归档/恢复，明确指令直接调用与页面相同服务，以真实成功回执回复。模型没有SQL、Shell或结构修改工具。
- AI导入页的归档保留文件及工作区，删除移除工作区数据库行、任务、草稿、识别失败记录和工作原件，不可恢复。正式业务独立原件/审计仍保留。旧回收数据只作为兼容归档查看恢复，正常删除不写入旧回收表。

右上角“账号 → 打开数据管理”是同一服务的批量入口。旧`/api/developer`兼容地址保留，本机最高管理员不用特殊模式。当前业务目录25；数据库迁移11移除采购计划不得低于实收的旧CHECK，原数据、外键、索引保留。详见[0.5.1发布说明](docs/发布说明-v0.5.1.md)。

## 备份、更新与恢复

先使用现有备份命令`npm.cmd run backup`备份业务库；完整迁移还需在停止程序后备份整个`data/`、本机API配置和语音资源。不要只复制正在写入的SQLite主文件而漏掉WAL。凭据另行安全保管，不能放进仓库。业务库恢复使用`npm.cmd run restore -- "备份文件绝对路径"`；其他文件恢复到原目录，先保留当前副本。

新电脑：登录有权限的GitHub账号，克隆**公开仓库**，执行`npm ci`、`npm run build`，恢复自己的离线数据备份；API密钥按需重新输入。更新现有副本：备份并停止程序，`git status`核对本地修改，`git pull --ff-only`，重新`npm ci`、构建、启动；有冲突先处理，不用强制重置。

需要稳定版本时可`git switch --detach v0.5.2`查看或测试，继续开发前创建分支。Git只保存程序代码，不能代替业务数据备份。

## 发布安全

`.gitignore`排除真实数据库、附件、密钥/个人配置、依赖、构建物、缓存、日志、备份、语音权重和历史本机验收报告。默认提示词以源码模板保存，不上传运行中的提示词SQLite。执行`node scripts/release-audit.mjs`检查真实暂存区及已有提交历史，只报告风险位置，不打印凭据。

公开MIT格式测试夹具`tests/fixtures/import/word-extractor-test01.doc`是唯一DOC例外，附来源与许可证；发布审计校验其大小、SHA256及是否纳入版本控制，其他业务文件仍禁止上传。发布验收必须从干净克隆执行`npm ci`、测试、类型检查和构建，不能只依赖原工作区的本机文件。

本机历史开发文档与原README另行保留，不随首次发布上传。当前发布范围及限制见[发布说明](docs/发布说明-v0.5.2.md)。
