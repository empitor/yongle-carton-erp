# 甬勒纸箱厂 ERP

宁波甬勒包装制品有限公司自用的纸箱厂管理系统。这一页说清它是什么、谁在用、部署在哪、用什么写的、怎么装和跑；细节从文末“从哪读起”进入。

## 是什么、谁在用

- **管的事：** 收客户文件 → 接单 → 采购订料、到货入库 → 排生产、登记完工 → 安排送货、出库 → 每月算账（应收应付、收付款、发票、凭证、成本、结账报表），都在一个系统里；另有收件箱（企业微信、飞书、钉钉机器人收文件）、单据导出（采购单、订货单、送货单的 Word/Excel）和全局 AI 助手。
- **AI：** 只接 DeepSeek 官方接口（模型 `deepseek-flash`，接口见[模块表](docs/生成/模块表.md)的 AI 接入），用来识别订单、送货单文件和当助手办日常操作；助手改业务数据一律出确认卡片、人点了才执行。不填密钥也能用全部业务功能。
- **谁在用：** 公司员工，按账号级别分管理员、业务人员、只读、财务、出纳（出纳这类纯财务账号只看得到财务和使用说明）。界面只有中文，金额只有人民币，时间按北京时间。

## 部署在哪

- **正式环境：** 腾讯云 Ubuntu 24.04 LTS x64 服务器，同机 Caddy 负责 HTTPS，域名已备案、已能从公网用 HTTPS 访问。服务只监听本机：3001 给维护（管理员经 SSH 隧道 `ssh -L 13001:127.0.0.1:3001` 进来），3002 只给同机 Caddy。服务器跑的是 0.9.5，现状见[部署](docs/运维/部署.md)“当前服务器”。
- **员工怎么打开：** 浏览器，或两个应用外壳：安卓 App（`apps/android`）、Windows 客户端（`apps/desktop`）。外壳只是打开 ERP 网址的窗口，没有服务端和数据；安装包放在服务器的更新目录里，装好以后有新版会自己提示（见[打包和客户端更新](docs/运维/打包和客户端更新.md#客户端更新包)）。
- **单机：** Windows x64 本机安装包也能单独用，数据存在本机。

当前版本 **0.9.5**（`shared/core/version.ts`）：1.0 之前的第一个正式测试版，工厂从 2026-11-23 起在正式系统上用真实数据试用。

## 技术栈

TypeScript，Node.js 24（24.15 或更高的 24.x，用 `tsx` 运行）。前端 React 19 + Vite 7；服务端 Express 5 + Node 自带的 `node:sqlite`，校验用 zod 4；前后端共用 `shared/` 里的类型、校验和计算。业务数据在一个 SQLite 业务库里，账号、AI 设置等在几个小配置库里。

## 安装使用

到 [GitHub 发布页](https://github.com/empitor/yongle-carton-erp/releases) 下载 0.9.5 的完整安装包（Windows 用 `win-x64.zip`，Linux 用 `linux-x64.tar.gz`，各附 sha256）。从 0.8.x 升级不能用补丁，只能装这个完整包，业务数据从新库开始，见[升级](docs/运维/升级.md)“0.9.0 以前的旧数据”。

**Windows：**

1. 解压到一个固定的文件夹，比如 `D:\纸箱厂ERP`，不要在压缩包里直接运行。
2. 双击 `启动系统.cmd`，浏览器自动打开 `http://127.0.0.1:3001`。用完双击 `停止系统.cmd`。
3. 第一次打开时在页面上建管理员账号（没有默认密码，也没有示例数据）。
4. 要用 AI：管理员到“设置 → API 配置”填 DeepSeek 密钥。

启动不了时：提示“已保护你的电脑”点“更多信息 → 仍要运行”；缺 DLL 装微软 [VC++ 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)；3001 端口被占用先关掉占用的程序。

**Linux 服务器：** 安装、备份、恢复、升级（含从 0.8.x 升上来要先移走旧业务库）见 `docs/运维/` 下的[部署](docs/运维/部署.md)、[升级](docs/运维/升级.md)、[备份恢复](docs/运维/备份恢复.md)。

## 从源码运行

需要 Node.js 24.15 或更高的 24.x，以及 Git。

```bash
npm.cmd ci
node scripts/ui-check/preview.mjs
```

预览实例用临时目录和虚构数据、带模型替身，打开 `http://127.0.0.1:3199`（本机管理员模式；加 `--remote` 模拟从域名访问，在 3198），不碰真实数据。

`npm.cmd run dev`（前端 5173、后端 3001，开发时自动重载）和 `启动系统.cmd` 按真实数据目录启动，只给人在自己的开发机上用；AI 和自动化脚本不运行它们，也不运行会覆盖正在用的 `dist` 的 `npm run build`（钩子会拦）。
