## 正式更正事务

入口为OperationsService.previewReceiptCorrection/correctReceipt及：

```
POST /api/purchases/:id/receipts/:receiptId/correction-preview
POST /api/purchases/:id/receipts/:receiptId/correct
```

请求绑定原到货、采购及明细身份、原单版本、采购版本、正确数量、原因、唯一requestId；提交还校验包含相关采购/库存版本及余额的previewDigest。允许只传需改变的行，未传行完整保留。正确数量可为0；纸板arrival保持整张规则，旧入口保持原单位及千分精度。

同一事务完成：校验原有效记录和原入库流水一致 → 创建正确替代到货 → 追加替代入库与原到货冲销流水 → 标记原单已冲销并连接替代记录 → 维护原批次/文件身份 → 重算累计缓存与采购版本 → 读回采购、有效到货、库存核验 → 写完整审计与幂等回执。

事务先核验最终净库存，内部先追加替代入库再冲销原入库，避免后续已领用但最终库存足够时被“临时扣回整批”误拒绝。外部只看见原子提交结果。库存不足、单位/身份变化、原流水不一致、并发版本或摘要冲突均拒绝；任何中途异常回滚替代单、流水、原单、采购、审计及回执。原订购数量和合同金额不改变。原流水从不更新或删除。

同一requestId和相同真实Actor重试只返回成功回执，不再次入库；内容或Actor改变拒绝复用。连续更正针对最新有效替代单。新到货仍沿原重复批次防护，更正合法继承原供应商批次与来源文件，不冒充新收货。

旧入口新收货开始保存数量、规格/单位和单价快照。历史记录优先使用原收货审计中的当时快照；无法证明旧单价时显示待核价，不按后来修改的合同价格伪造实际入库金额。

## AI正式工具

统一AssistantToolRegistry新增purchase.receipt.preview和purchase.receipt.correct，归入原ERP业务插件。先records.get读取真实采购、receipts及correctionLines，再预检并提交同一人工服务。执行端校验实时Actor的business:edit、工具/插件启停与原业务规则；无需超级模式或AI专属确认。显式只预览仍只生成方案。

更正服务本身读回核验采购进度、逐行累计/待到货和库存，并返回verified、数量变化和真实摘要；助手最终摘要由这些回执形成，包含原登记、正确数量、有效累计、待到货、采购进度和库存净变化。不能通过写派生字段修改履约进度，也不提供SQL/库存余额直接写入工具。

## 范围与限制

本次正式数量更正面向已关联采购的有效到货；完全无采购单到货仍沿既有流程维护。原采购/库存身份缺失或原流水不一致必须先核对，不能自动猜测关联、重建单据或改历史领料。AI真实供应商模型未联测，验收采用模型替身。本机最高管理员既有专门数据维护/物理删除能力保持原范围，普通采购数量更正使用本次追加冲销和替代的路径。

真实实例未重启；重启加载新代码时自动执行兼容迁移12。未调整软件版本或任何历史Git标签。
