# 账号与登录验收

2026-11-06。全程用临时目录和虚构账号，没有碰 `data/`、`backups/`、正式实例和 `%LOCALAPPDATA%\ZhixuERP`。

## 做了什么

| 需求 | 结果 | 位置 |
|---|---|---|
| 登录页版式 | 字段之间 12px，标签和输入框 4px，手机输入框 44px 高、字号 16px；可显示密码；短密码也只提示“用户名或密码错误” | `src/LoginScreen.tsx`、`src/design.css` |
| 切换账号 | 登录页和右上角都能切换。切换就是退出再登录，要输密码。这台设备只记用户名，可移除 | `src/AuthPanel.tsx`、`src/recent-accounts.ts` |
| 注册 | 做成“申请账号”：管理员通过并选级别后才能登录。第一个管理员仍只能在服务器本机建立 | `server/auth.ts` 的 `/apply`、`/requests/*` |
| 忘记密码 | 管理员确认后生成临时密码，24 小时有效，登录后必须先改。管理员本人走命令行 | `server/auth.ts` 的 `/forgot`、`resetPassword` |
| 右上角 | 账号菜单，显示真实级别。本机数据管理、开发者模式、超级管理员模式收进“系统维护” | `src/AuthPanel.tsx` |
| 账号管理 | 从设置页搬到 `#accounts`，列表加右侧面板，待处理申请在最上面。旧地址自动转过来 | `src/AccountManagement.tsx` |
| 密码规则 | 用户要求改成至少 8 位，要有大写和小写字母。只管新设的密码，旧密码照常登录 | `shared/password-policy.ts` |

## 和设计稿不同的地方

- 还没改掉临时密码的会话，`actor()` 直接返回空。这样所有业务接口都默认拒绝，不用逐个判断。
- 管理员重置密码也改成生成临时密码，不再手填。
- 管理员不能给自己生成临时密码，否则会把自己锁在外面。
- 能用原密码登录时，自动撤销该账号待处理的忘记密码申请。
- 会话到期时间统一用注入的时钟，原来非部署模式混用了 `Date.now()`。生产环境两者相同，行为不变。

## 没有验证

- 真实账号库升级。只用虚构的旧结构库试过，下次启动正式实例时才会真正加字段。
- 真手机。只用 Chrome 模拟过 390 宽的触屏。
- 真实服务器和 HTTPS。公网入口只在部署测试里走过 `/apply`、`/forgot`，访客地址记录正确。
- 公网安全审查还没做，新增的两个免登录接口要包括在内。
- 临时密码的“复制”按钮。公网 HTTPS 下应该可用，没有实际点过。
- 部署模式下“系统维护”里的超级管理员模式。本机实测账号是本机管理员，界面上显示的是本机数据管理；相关接口的测试通过。

## 已知取舍

- 至少 8 位比原来的 12 位弱。靠登录限频（同一地址加账号 5 次、同一地址 30 次，5 分钟）挡撞密码。
- 通过申请和发临时密码靠管理员线下确认身份，系统无法替代。
- 这台设备记住的用户名在公用电脑上别人能看到，可以点 × 移除。
