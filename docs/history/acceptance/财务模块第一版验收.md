## NEEDS_DESIGN

- 到货可能缺少结构化税率及含税口径。当前保留原单快照，允许带依据逐行补录财务口径。需明确常规暂估核价的凭据，以及实收、验收、入库数量不同时应付和原材料分别取哪一列。
- 明确先收后核销、先付后核销以及跨期撤销的预收预付分录模板和入账日期。已结账期间的原核销与凭证必须保留。
- 明确到货替代单的差额分摊，以及到货暂估发票到后按原期间或当期调差的规则。当前只登记差异，保留原凭证。
- 明确 5601、5602 的费用项目名称、编码及默认映射。主科目已预置。
- 以分计量且差额集中末行时，多条小额行可能令末行出现负分。需明确末行超过原金额时的处理。整单金额和原精确金额均可复算。
- 明确财务初始化是否允许删除已记账凭证和已结账报表快照。任务同时要求初始化清空财务业务数据和已记账档案无删除入口，需明确开发隔离环境的例外边界。

## 页面验收（2026-11-06）

新增 `src/finance/` 八个页面、导航分组、今日页“货款到期”、订单和送货详情的财务段。助手 `ui.open` 能打开财务页面，没有 `finance:view` 时拒绝。

用隔离实例和虚构数据，在 Chrome 无头模式实际操作：

- 全部页签逐个打开并核对选中项，共 40 多个界面，无错误提示，控制台无报错。
- 走通：未启用时看经营表 → 启用 → 建资金账户 → 设压货款和现结优惠 → 批量补税 → 生成凭证 → 提交、审核、记账 → 收款核销。补税后理论金额不变，实收按来源月份拆分。

测试中修复的前端问题：同页切换页签的监听被 App 的同步渲染移除；记账模板的映射对象直接渲染导致白屏，并加了页面级错误边界；账期窗口在读回现有规则前可编辑，可能盖掉刚填的内容。

未逐个点到底：银行导入、发票关联和确认、费用审批、工资导入、固定资产、结账全程、反结账、归档下载。这些后端有测试。深色模式和窄窗口没看。核销窗口只显示往来单编号，没有单号，以后可改进。
