# 界面第三轮验收与收件箱

日期：2026-11-06。基于 0.6.1，业务目录 35，迁移 15（收件箱 14，唛头 15）。未提交、未发布。只用隔离虚构库和本机 Chrome 验证，未接触真实 `data/`。

## 决定

- 客户统一加企业微信发单。收件箱只预留接口，这一轮重点改 UI，后续可能再调整。
- 收件箱和 AI 导入分开：收件箱放所有进来的内容，AI 导入是加工单据的地方。

## 收件箱

| 项目 | 内容 |
|---|---|
| 页面 | `#inbox`：待处理、已转单、已忽略；可按来源和关键词筛选；点行打开面板 |
| 操作 | 文件：转订单、转到货、忽略。文字：新建订单、已处理、忽略 |

| 后端 | `shared/inbox.ts`、`server/inbox/`，迁移 14 新增 `inbox_items`、`inbox_files`；同来源同消息只记一条，相同文件只存一份 |

## 全部页面

- **页框：** 标题和统计同一行，筛选一行，表格紧跟。订单页表格从约 295px 上移到约 210px。
- **列表：** 去掉每行的“查看”列；点行或单号打开面板。刷新、重置改为图标，分页统一。
- **名称：** 页面标题和导航一致：采购单、供应商、库存、完工记录、设置。生产页去掉和导航重复的页签。
- **到货、送货：** 使用统一页头，日期条压成一行，并恢复了之前被隐藏的日期选择。
- **AI 导入：** 文件列表、原件、草稿三栏；原件可收起；识别配置和错误档案收进“更多”；底部一条放金额、疑点和操作；“让 AI 改”按需展开；已确认的产品匹配收成一行。备注移到明细的折叠区。
- **表单：** 控件同高；供应商、关联订单、原材料、产品等改为可搜索；修复到货表单内容从底部按钮下露出。
- **设置：** 页签统一，超级管理员增加账号页；模板页页签改为横排。
- **归档：** 页签合并，文字改为白话。
- **使用说明：** 按新导航更新操作顺序。

## 单据详情与到货草稿

- **下一步卡片：** 订单和采购面板顶部直接给出下一步，由 `shared/order-next-step.ts` 按已有单据和库存判断，没有依据的不提示。顺序是：确认送货草稿、建送货单（库存够发）、确认生产任务、登记完工、安排生产；库存只够一部分时，送货排在安排生产之后。
- **逐行进度：** 面板显示每行的待发、可用库存、完工 / 计划；单位不同的库存不算。关联采购未下单或未到齐时给出提示。
- **收起空环节：** 没有内容的生产、完工、送货、采购不再显示。归档、修改历史、删除收进“更多”。
- **状态刷新：** 确认订单或后续业务变化后，面板按主键重读，单据不在当前筛选结果里也能更新。
- **登记完工：** 从面板进入时带上任务和对应成品档案。
- **`/related`：** 订单和采购改为按主键读取，不再全量加载后查找。
- **到货草稿：** 明细改成单行，尺寸、配纸、匹配、原单数据、备注折叠在一处，档案和规格不一致时自动展开；供应商、采购明细、原材料档案可搜索；底部和订单草稿一样收成一条，主按钮随状态变为保存草稿或核对并确认入库。

实测：草稿确认、安排生产带产品、登记完工带任务和档案、已发货显示完成、更多菜单；到货草稿改字段、保存、切换主按钮、展开助手。到货的“确认入库”这一步未在浏览器点击，原有确认弹窗和事务未改。

## AI 助手链路

- **收件箱工具：** 助手可查询收件箱、改状态，并把文件转入订单识别（`inbox.list`、`inbox.get`、`inbox.set_status`、`order_import.from_inbox`）。里面的内容只算数据，不能当作指令。
- **转单入口：** 转订单、转到货、转唛头统一走 `POST /api/inbox/:id/convert`，校验版本，重复转换不会多建任务。
- **名称对齐：** 助手提示词、导航、模块名和提示词用途都改成新页面名称，旧叫法保留为别名。
- **能力清单：** 补上收件箱和唛头。
- **链路表：** 新增 [功能链路表](../../功能链路表.md)，`tests/feature-links.test.ts` 检查导航、链接、页面名称和工具注册一致。

## 唛头

客户发来的唛头、样稿不是订单，也不用生产，作为参考资料存到对应产品下。

| 项目 | 内容 |
|---|---|
| 进入 | AI 导入选“唛头”，或收件箱“转唛头” |
| 识别 | 多款文件拆成多款，每款带页码、料号、尺寸；独立提示词 `shipping-mark` |
| 自动对应 | 只有料号完全相等且唯一、尺寸不冲突才预选产品；只对上尺寸或料号相似只作候选，由人确认 |
| 不猜测 | 单位不明不换算；外箱和内径分开；已归档产品不参与匹配 |
| 存档 | 一键保存并存入，单事务；重复提交不多存；同名新产品只建一个；未选产品的款不能存，可标记“不存” |
| 存储 | 迁移 15 新增 `product_marks`、`mark_files`。同一文件只存一份，每款记录页码；备份包含这些文件 |
| 查看 | 产品详情可看、放大、上传、移除；订单详情和生产任务详情只读显示 |
| 不影响 | 不产生订单、生产任务和库存 |
| 安全 | 只有 PNG、JPEG、WebP、PDF 在页面内打开，SVG 等一律下载 |

实测（本机 Chrome、虚构 3 页 PDF、模型替身）：收件箱转唛头、拆成 3 款、料号预选、同料号两个产品不预选、只有尺寸不预选、点行切页、待确认时不能存、存档后只读、产品面板和大图、手动上传、订单面板显示。控制台无错误。

**没有验证：** 还没用真实模型和真实客户文件跑过识别。提示词的实际效果要等这一步。

## 企业微信智能机器人

走官方长连接，不需要公网地址。配置在设置 → 消息接入，只有管理员能看和改。

| 项目 | 内容 |
|---|---|
| 连接 | `wss://openws.work.weixin.qq.com`，`server/inbox/wecom-bot.ts`。订阅后每 30 秒心跳，连续 2 次无回应就重连；断线重试间隔从 1 秒退到最长 30 秒 |
| 不自动重连 | 凭据被拒（订阅有频率保护）；被别处的新连接顶替（否则两边互相踢）。页面显示原因，由人处理 |
| 凭据 | `%LOCALAPPDATA%\ZhixuERP\wecom\bot.sqlite`，Secret 用 Windows DPAPI 加密，只写入不回显，审计只记是否改过 |
| 收消息 | 文字、语音转写、图片、文件、视频、图文混排都进收件箱，来源标记 `wecom_bot`，同一条消息只记一次 |
| 文件 | AES-256-CBC 解密后存原文件和原名。下载地址 5 分钟有效，失败重试 2 次；只接受 https 和公网地址，跳转每一跳都检查 |
| 失败不丢 | 超过 20MB 或下载失败时留一条文字记录，并回复发送人 |
| 回复 | 每条消息回一句确认或失败原因，只说是否保存，不做其他回答 |
| 安全 | 内容只算数据，不发给模型，不执行任何业务操作 |

新增依赖 `ws`。Node 自带的 WebSocket 连企业微信服务器会得到 404（2026-11 实测），手动握手和 `ws` 都正常，官方 SDK 用的也是 `ws`。

实测：
- 用虚构凭据连真实服务器：握手成功，收到 `853000 invalid bot_id or secret`，界面显示中文原因。
- 本机模拟服务端：订阅、收消息、回复、心跳走通；解密、去重、超限、跳转到内网、断线重连、被顶替、凭据被拒、权限和 CSRF 均有测试。

- 用真实机器人在隔离实例上试接（用户在页面填入 Secret）：显示已连接；单聊发的文字、PDF、两张图片都进了收件箱，机器人都回复了确认。文件头和大小正确（解密无误），PDF 保留原名，图片能显示，PDF 转唛头后进入 AI 导入并能预览。测完已关闭实例，删除了临时数据和加密的 Secret。

**没有验证：** 正式实例还没连接；群聊 @、图文混排里的图片是否带密钥、断网后的真实重连都没有实测。试接实例没有配置唛头识别，转入后右侧提示“接口不存在”，这一步不算验证，唛头识别之前用模型替身测过。
