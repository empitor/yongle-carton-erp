# 路线图

什么时候读：看还剩什么没做：1.0 发布前要做完的，和 1.0 上线以后要做的新东西。

只写智能体要做的、代码层面还没做的事，做完就删（怎么写相关的见 `.claude/skills/docs-writing/SKILL.md`）；做完没发布的写进 `docs/CHANGELOG.md`。1.0 之后的技术债和暂不做的相关的见 `docs/计划/技术债.md`，已知问题相关的见 `docs/计划/已知问题.md`。

现在的版本和试用情况见 `docs/运维/部署.md`“当前服务器”；试用稳定后出 1.0。

## 一、1.0 发布前要做完的

### 1. 服务器上还没做的

每件动手前先问用户；现状见 `docs/运维/部署.md`“当前服务器”。

- 备份复制到服务器外（`ERP_BACKUP_COPY_DIR`，存哪等用户定），再做一次完整的部署和备份恢复演练。
- Linux 主密钥（不进任何备份）单独加密保管。
- 真让服务崩一次，看会不会自动重启。
- SSH 22 只放维护者 IP（先确认控制台网页登录能当备用通道）。
- 在 2 核服务器上量登录核对密码的耗时，按需调 `server/accounts/hash-queue.ts` 的常量。
- 升级第 24、25 步没在服务器的 SQLite 上跑过，正式库里超长的老待送货单、老税率和口径写法有多少也没查：发布前照 `.claude/skills/release/references/升级前只读核对.md` 做。
- 拿到公安备案号后填 `ERP_POLICE_RECORD`，并在 `src/FilingLine.tsx` 补公安小徽标。

### 2. 应用外壳发版前看要不要做的

- **安卓：**
  - 切深色、改语言、开关粗体字会整页重载、丢掉没存的表单：要不要接管 `uiMode`。
  - 刘海让位：先在真机上看 WebView 给不给 `safe-area-inset-top`。
  - 没接网页录音授权，App 里助手录不了音。
  - 拍照占位用 `IS_PENDING`。
  - `compileSdk`、`targetSdk` 从 36 升到 37。
  - 更新包下载地址要不要只收 https；回前台要不要隔一段查一次新版（现在只接着装上次下好的）。
  - 别的应用读文件卡住时，后面的分享一直排队、没有超时。
  - ERP 导出以外的 `blob:` 下载存不了。
  - 分享到达时网页还在加载或停在登录页，登录前没有任何提示：要不要加一句。
- **Windows：**
  - 离线页不自动重试（要做就按递增间隔重载）。
  - 接连自动下载第二份时 WebView2 弹多文件下载权限框。
  - 托盘常驻时页面不自己刷新，服务器升级后要点“重新载入”。
  - 以管理员身份运行时勾选开机自启会登记到整台电脑，卸载删不到。

### 3. 界面

- **助手输入区（手机、电脑都改）：** 输入框改成一行高，加号、输入框、话筒、“思考”档位、发送同一高度（现在输入框最低 54px、其余 40px，电脑上提示字分两行）。`src/assistant/composer.css`、`src/assistant/ComposerInput.tsx`。
- **使用说明按账号只给各自那部分：** 业务员看“登录和账号”到“常见问题”；财务、出纳看“登录和账号”“认识页面”“财务”“AI 助手”“常见问题”；“管理员”开头的几章和“备份”只给管理员。页面（`server/system/user-manual.ts`）和助手 `guide.read`（`server/assistant/tools/guide.ts`）用同一张表；手册开头那段跟着改。
- **超长的章先给小节目录：** “财务”一章约 9300 字，`guide.read` 整章只给前 6000 字。
- **在浏览器里看一遍：** 补税率窗的选项卡片、财务抵扣窗、附件预览的当前页。
- **在预览实例上照手册点一遍：** 管理员各章；财务章的撤销核销、按单位补税率、银行流水、工资、结账到底。

### 4. 库存的全库一致性核对

写不成约束的几条，加进系统体检 `system.check`，只读只报：

- 已撤销单据名下出库加冲销等于 0；待核对、已取消的单据没有流水。
- 逐笔余额重算对得上；库存和账面价值对比。
- 采购明细的 `received_units` 缓存和按到货单现算的一致。

### 5. 助手考题和真实模型补跑（花钱，跑之前问用户）

套件是 `scripts/ui-check/real-suite.mjs`。

- **补“不该动手”的题：** 纯闲聊；“只问不办”的题加断言不出卡片。
- **冒烟的“最短的对话”问法含糊：** `scripts/ui-check/real-model.mts` 的 `chat` 让模型“回复”JSON，4 次错 2 次；改清楚再跑几次。
- **还没在真实模型上跑过的：**
  - 35 条写入场景的行级差异和最终数据核对、`--repeat`、`--rejudge`；误判的改场景再 `--rejudge`。
  - 对话层：常用 13 条直接给以后的请求次数和选对率、断线重发、附件 7 天有效期和删远端那份、不传输出上限时长回复会不会被截、备份出卡片、长期记忆自己记、接力规则和示范、排队时只来保活行能不能按 300 秒断开重发。
  - 改过的提示词：“最近 N 天”含今天往前数、查不到不拿相近的数顶替、值没给就留空或先问、点名谁就是谁、两种情况才接力。
  - 架构整理以后的全量（只抽过 10 道）。
  - 联网：先查系统再上网的问法；模型先说一句再搜时的显示；和 DeepSeek Harness 对比同一句话。
  - 订货单命令（只用替身测过）。

### 6. 记真账之前的财务几件

- **要做：** 财务事件明细子表 `fin_event_lines`（事件、行号、订单、订单明细、产品、采购明细、金额），订单的财务段、毛利、发票匹配不再拆事件快照 JSON。
- **要用户定：**
  - 部分到票的到货撤销后，撤销那个月起各月都要等红票、红冲做完才能结账（`server/finance/events/event-correction.ts`；红冲日期改到以后再结那个月，会少余量暂估那么多）。可选：撤销那个月先不冲余量暂估，或允许没开红票先红冲余量暂估。
  - 采购退货和撤销到货“数量为 0 还有余额”口径不同（`server/finance/costing/costing-compute.ts` 的 `valueRaw`）：要不要把未到票的退货改成和撤销到货一样（只留到过票、等红票的部分，其余转主营业务成本）。
  - 启用期初和成本窗口的存货期初要不要系统校验（`server/finance/base/opening.ts`）。
  - 员工借还款要不要设专用科目（现在默认 `1221`，没开员工辅助，`server/finance/expenses/expenses.ts`）。

### 7. 等用户定的两件小事

- 到货明细单价填空格报“最多四位小数”，采购明细算“没写”（`src/flow/ArrivalLineCard.tsx`）：要不要统一成没写。
- 长期记忆（在助手设置库）搬不搬进业务库：开工前给用户看升级、备份恢复、初始化怎么办的方案。

## 二、1.0 上线以后

- **评估“长期记忆被带坏”的风险**（只做评估和演示，加界限要用户同意）：外来文件、网页、消息能不能骗助手记进错的东西、会影响哪些操作。出处：Anthropic《How we contain Claude across products》（https://www.anthropic.com/research/how-we-contain-claude ）。
- **合并请求的迭代体系（上线马上建，先给用户看方案）：** 之后所有改动都走合并请求。要补：合并请求模板（怎么测、什么风险、怎么退回）、按改动挑检查、各模块的审查说明、全新上下文的 AI 审查加单独的安全审查、按风险分级定要不要人批。参考 Anthropic《How the Claude Code team does code review》（https://claude.dev/blog/solving-code-review-at-anthropic/ ）、《How the Claude Code team thinks about verification》（https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/ ）、《How Anthropic secures its AI-native software development lifecycle》（https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle ）、Cursor《Building a better Bugbot》（https://cursor.com/blog/building-bugbot ）。
- **微信登录（开工前给用户看方案）：** 没注册过的第一次登录自动建账号，用微信头像和名字；前提是微信开放平台资质（电脑扫码和 App 拉起分开申请）。要定：自动建的账号给什么权限（建议默认什么都看不到，和“申请账号、管理员审批”并成一条路）、已有账号怎么绑、头像存不存。
- **一个账号同时登录的设备数（先记下，不做）：** 最多三台，最好手机、平板、电脑各一台；现在不限（`server/accounts/login-route.ts`），也没有看在哪几台登着、把某台下线的入口（全清在 `server/accounts/auth.ts` 的 `revokeSessions`）。要定：同种设备再登录顶掉旧的还是拒绝新的、设备种类怎么认、服务器本机的管理员登录算不算。
- **聊天机器人接助手（开工前给方案，先问用企业微信还是钉钉）：** 员工单聊机器人提问、发文件、办简单的事，只对员工开。机器人账号绑 ERP 账号、没绑的不答；复用网页助手的命令、权限和审计；写入回链接到系统里确认，删除和财务写入不上机器人；先单聊只读、再写入，群聊先不做。待查：回复时限、模板卡片、每句的模型费用。
- **会话存档让客户消息自动进收件箱：** 要客户同意、公网 IP、官方 SDK，只能拉近 5 天，费用待查。
- **机器人消息的发送人姓名：** 企业微信、飞书现在显示发送人编号。
- **识别结果和原文自动核对**（LangExtract 的做法，新功能，开工前先跟用户说）：有原文的（Excel、Word、带文字层的 PDF），识别出的值在原文找不到就标“拿不准”。
- **识别那两张表用 DeepSeek 严格模式：** 可能省掉重试；走测试版地址，先用识别对比脚本实测；助手命令不用。限制见 https://api-docs.deepseek.com/guides/tool_calls 。
- **识别时附一份填好的示范：** 试能不能提高读对率。
- **手机导出时选“分享”还是“存到手机”（不急）：** 安卓 App 现在只存“下载”；选分享时什么算“已交付”开工前要定。
