# ERP 自主 Agent 架构升级验收

2026-10-28，基于0.5.2继续开发，业务目录26，数据库迁移仍11。本记录覆盖本轮架构升级和后续P0/P1补充要求。保留此前全部未提交修改；未提交、推送、打标签或发布GitHub。

## 实际根因

1. 调度器把toolCalls为空视为结束，并用问号、“请确认”等正文正则推断needsInput。两次续办检查耗尽后，即使还有可查询、可恢复的步骤也停止。
2. 任务状态依赖列出的步骤，缺少明确的执行状态；已确认事实、旧任务目标、草稿成功、页面交互及正式业务结果容易混在一起。旧导入目标还能影响后续独立查询。
3. 基础工具虽然能创建生产草稿、确认既有单据，但缺少完成生产所需的关联准备。flow.propose_confirmation确认生产任务只代表下达任务，不会自动生成生产登记、领料或成品入库。
4. 全量操作需要模型逐条找ID和版本，跨模块不能引用前序真实结果。finishedStockId、materials缺失被直接作为技术错误返回；搜索结果有多条时又一律视为身份歧义。
5. 调度和助手包装层仍残留额外审核、超级模式、重复密码及小额度限制，与当前人工接口和默认预设不一致。
6. DOM之外没有可执行的视觉后备。重复工具契约、页面快照、历史结果和任务数据也增加上下文开销。

## 调度、记忆与资源

沿用AssistantManager、AssistantTaskLedger和原JSON信封，增加status：working、needs_input、completed、blocked。问号不再参与停机判定。参数完整的已计划只读步骤可直接续办；模型仍说working或有可恢复目标时继续后台调用，连续空转才标blocked。needs_input必须包含尚未确认、需用户决定的结构化业务问题；内部ID、版本和系统查询问题不作为业务提问。

最终状态仍检查真实执行回执、待办、未知步骤及订单工作区目标。模型声明completed不能跳过未执行步骤；浏览器点击/提交回执不能单独关闭业务目标，须按每步真实记录、预期字段和执行前版本核验。草稿、交互、正式业务及已替代步骤继续分别保留。所有目标文件的正式导入成功后，旧待核验步骤才关闭。

真实用户原话、确认来源、文件顺序及confirmed/inferred/unknown/conflict参数存于原任务memory。补充生产良品率和整批领退料数量；已确认547张时，模型提出548张会在提交前被拒绝。没有100轮原话或150个决定的任意截断，容量使用服务端配置并按UTF-8字节校验。税率不证明含税，数量单位不猜换算。

独立业务目标、独立查询自动新建任务；模型可用taskControl补充语义分类。“继续”沿原任务恢复，历史任务可切换并引用真实业务结果，旧授权不会自动扩散。上下文只携带近期任务引用和必要记录ID，完整历史仍在原台账。

默认模型、工具、写入、页面交互和单次模型回复调用数均为0（持续执行）；默认超时2小时。运维可配置非零上限，超时也可设0。移除固定80步和20份历史任务限制。保留无进展、连续失败、同参数失败、真实登录变化和用户停止；每次工具执行和预算更新保存检查点。

控制模型网络、超时或协议错误默认最多恢复2次，先核验原回执，再继续剩余步骤。配置/认证失败不反复重试；收费识别未知结果及未知页面写入仍不自动重放。进程重启后保留台账，需要真实登录会话恢复，未增加无人登录的后台权限。

## 业务组合与生产完工

基础records、flow、inventory、purchase工具继续开放，可以自主组合查询、创建、修改、确认和核验。records.search describe:true从真实Zod规则返回输入结构、模板和依赖，不维护第二套字段规则。

management.execute在原工具中增加：

- selection.all直接选择真实全量范围，可筛原料/成品、归档状态等，避免模型逐条查询ID。
- commands顺序编排原DeveloperService；前序真实结果可用$ref引用，未知/前向/危险对象路径拒绝。
- 原服务每批100条的约束由服务器分批处理，外层统一事务、外键检查及根请求幂等；失败全部回滚。自动查询实际删除影响，并沿原删除引擎处理关联、库存、金额和审计。
- 尺寸单位转换保留实际尺寸，逐记录生成原字段校验所需补丁；原单位未知时拒绝猜换算。

新增复合工具flow.propose_production_completion，只编排原FlowService和OperationsService：

1. 读取所选或全部待完工任务、已完工数量、产品、真实关联采购和库存。
2. 100%良品使用当前剩余任务数量；其他情况需要实际良品/废品数量，不猜投入量或舍入。重复任务、矛盾数量、无效单位和不足库存在提交前拒绝。
3. 唯一匹配原料、成品库存；需要时按实际产品及任务单位创建成品档案。有多个相同规格候选时支持明确finishedStocks选择，不能擅自合并。
4. 可下达尚未下达的所选任务，创建生产登记，沿原完整预览和确认服务执行领料、退料及成品入库。整批先回滚预演，正式执行也在统一事务内；正式回执检查生产登记、任务和良品数。
5. 整批实际领料使用shared-proportional：按实际产量比例，以最大余数法分配整张，保证逐任务合计严格等于用户给定总量。也支持明确的逐任务distribution；总量、原料和单位必须一致。

共享分配表示实际领料的归属，不推断纸板切割布局。六型号1093只、每张2只，按型号独立取整需要548张；跨型号共享的理论下限为547张，不能据此自行宣称物理排版可行。用户明确实际领用547张并100%良品时，按该实际总量登记，不能改成548张。已确认独立取整规则或实际数量存在冲突时仍需澄清。

本机最高管理员直接使用原管理能力；普通业务账号也按原服务权限调用基础工具和生产完工。移除助手独有的库存/实物确认/批量归档超级模式门槛，以及助手预览提交的重复密码/确认门槛。未修改AuthManager、角色、权限、原业务服务或数据库规则；原冲销、历史维护、永久删除等独立权限仍由各原服务执行。只读账号不能借插件、页面或复合工具写入。

## 页面和真实视觉后备

保留当前ERP标签页的page.observe/act/verify。新增同一注册表内的browser.capture/act，使用playwright-core和本机已安装的Chrome/Edge；在“AI设置 → AI插件与工具管理”打开独立的可控ERP窗口。

- 服务端绑定实际账号、登录会话和本实例来源；直接本机连接且拒绝代理提升。HttpOnly登录凭据仅用于内部会话，模型不可读取。
- 实际PNG发送给控制模型，支持视区坐标点击、普通键盘、滚动、当前聊天附件上传及普通确认框。没有脚本、任意选择器、Shell、文件路径或外部网站工具。
- 截图遮盖账号认证区、聊天区、密码/密钥及标记的私密区域；敏感区域拒绝输入。图像/路由变化、过期帧、其他账号或会话拒绝操作。
- PNG仅在内存及当前模型请求中使用，不写入聊天业务回执。点击回执不充当业务结果；写入未知时核验后再继续。

视觉API依据：[Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype)、[Page](https://playwright.dev/docs/api/class-page)、[Locator](https://playwright.dev/docs/api/class-locator)。本轮实际验证了浏览器启动、截图、可信Canvas鼠标事件、键盘、文件输入、账号/快照保护和模型图片请求链路，并验证了管理页面连接/断开。

## 仍存在的限制

- 密码/API密钥输入、Windows窗口、系统文件/打印/另存为对话框及其他网站/浏览器不受Agent控制。凭据继续人工维护；上传仅限当前聊天已有原件。
- 视觉后备是独立ERP窗口，不复制原标签页尚未保存的表单或弹窗；原标签页仍用DOM桥接。未安装浏览器或Provider/模型不支持图片时，不能宣称视觉能力可用。
- 供应商到货识别没有独立聊天工作区协议，仍使用既有到货页面/识别服务；本轮没有付费模型与真实供应商识别端到端验收。业务数据的采购到货入库链已用真实服务验证。
- 未提供物理切割排版引擎。共享领料分配保证实际总数与整张库存一致，不证明某种原料尺寸能生产指定组合；真实规格、税价、身份或实际产量有歧义仍需业务决定。
- 自然语言规划和独立任务分类仍依赖受控匹配与模型结构化输出；模型反复不产生操作会按无进展保护停止。临时替身验收证明服务和恢复链路，不代表任意外部模型的自然语言成功率。
- 进程退出、客户端断开或登录失效后保存进度；重新登录后核验继续，没有另建跨登录无人值守调度器。需要重启ERP服务并刷新网页才能加载本轮代码。
