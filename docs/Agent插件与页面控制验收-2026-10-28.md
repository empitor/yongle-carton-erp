# 软件内 Agent、插件和页面控制验收

日期：2026-10-28。开发验收基线为0.5.1，业务目录升级25，没有业务库结构迁移。以下分阶段记录保留当时版本与发布状态；用户随后明确授权将当前成果标定并发布为0.5.2，详见发布说明-v0.5.2.md。

## 实现结果

1. 工作区是ERP业务资源。`order_import.list`查询人工或聊天创建的现有工作区；`attach`把原ID关联到当前账号的聊天任务，不复制文件、不重新识别。原UUID、哈希、草稿修订、行ID和识别记录保留。归档工作区沿用原本机管理员打开服务和权限。
2. `get/edit/match/preview/execute`继续复用ImportManager、原客户产品匹配及ImportExecutionService。允许指定本任务任一taskId操作，无须为每份文件额外执行select。明确导入指令不再被聊天专属跨轮确认限制；后台仍生成完整预览，绑定当前用户、来源哈希、修订、档案版本、摘要与期限，再经原服务提交。
3. `execute_many`最多6份，逐份执行、核验正式订单和原执行台账；返回每个文件名称、成功/失败和真实回执。第二份失败不会抹去第一份成功，继续时复用已经导入的订单。草稿被其他页面修改时旧核对版本失效，不能悄悄提交；匹配歧义、单位、金额等原校验保留。批量导入和普通业务提交共用本轮8次修改预算。
4. 五个内置插件适配同一个AssistantToolRegistry：ERP业务服务、订单工作区、ERP页面控制、持久任务、隔离附件阅读。插件声明含ID、名称、版本、描述和能力，工具含Zod参数、类别、权限和可选执行器；`registerPlugin`能添加新插件和执行器，无须重写聊天循环。插件和单项工具开关共用原tools.sqlite的版本化设置，分派前核验启停和真实权限；没有第二套客户、订单或库存库。
5. 独立`#ai-plugins`页面展示插件、能力、参数结构、权限、可用状态及本账号最近操作日志。左侧菜单和聊天插头按钮均可打开，与提示词管理分离。旧工具管理路径兼容。
6. 页面控制具备观察→操作→新快照/反馈→原业务核验的循环。每次消息和`page.observe`按需读取真实页面标题、路由、菜单/选项、表格、非敏感字段、弹窗、记录身份和反馈。`page.act`在ERP当前标签页操作真实控件；原业务工具/API存在时优先使用。
7. `page.verify`读取原业务服务，比较用户要求的目标字段，只有真实匹配才给当前任务中的页面步骤记录核验结果。它不重复点击、不写业务数据，也不声称证明未知点击的执行过程。正式导入中途重启则直接核对原导入台账，复用已提交订单，只继续剩余文件；未知收费识别继续禁止自动重发。
8. 聊天边缘和四角支持自由拉宽、拉高和组合缩放，保留拖动、键盘移动、最大化/恢复。尺寸和位置仅保存在本机浏览器；视区变化、滚动条和虚拟键盘偏移参与边界计算，恢复不会越出屏幕。附件、语音、任务和预览区域沿用原组件。

## 新增工具与插件对应

| 插件 | 新工具 | 作用 |
| --- | --- | --- |
| 订单工作区 | `order_import.list` | 原页面现有文件、状态、草稿及导入信息 |
| 订单工作区 | `order_import.attach` | 原地关联跨页面工作区，读取最新草稿与候选 |
| 订单工作区 | `order_import.execute_many` | 多文件逐份正式预览/执行/回执，支持部分成功 |
| ERP页面控制 | `page.observe` | 当前ERP标签页实际结构与内容 |
| ERP页面控制 | `page.act` | 导航、点击、输入、下拉选择、滚动、限定键盘、提交 |
| ERP页面控制 | `page.verify` | 原业务服务核验目标字段及中断页面步骤 |

原业务、导入、ui.open、任务与附件工具继续走同一调度器。插件之间通过同轮工具结果、持久任务和原业务记录ID组合，不向模型开放插件源码执行、SQL、Shell或任意HTTP请求。

扩展入口是`registry.registerPlugin(manifest, tools)`；插件作为经过开发审查的服务端模块注册，每个工具提供Schema、权限和执行器。组合根可把现有业务服务注入执行器；业务写入仍须走原业务引擎和真实Actor，不能返回模型自称成功的结果。管理页面自动从注册表读取，既有内置工具不另起第二套执行路径。未实现模块没有注册成业务工具。

## 页面桥接边界与验证

- 命令经聊天SSE送到发起本轮请求的ERP标签页；回执必须同时匹配随机命令ID、真实账号、登录会话绑定、线程、请求和浏览器clientId。另一个账号、另一次登录或另一个标签页不能提交回执。所有HTTP变更沿用CSRF。
- DOM工具只接收最新快照中的元素编号，不接收CSS选择器、JavaScript或外部URL。路由、控件和显示内容变化会拒绝旧引用；控件已移除、禁用或不适合指定操作也拒绝。
- 交互完成返回`interaction`及`businessVerified:false`。点击不等于保存，需读取反馈，再用records.get或page.verify核验。正式业务操作始终经原页面fetch/原业务服务，不直接写SQLite。未收到回执时标记未知结果，不能盲目重放。
- `page.verify`只核验当前账号当前任务中的page.act步骤；字段不匹配、记录不可访问或步骤不属于当前任务均拒绝。当前状态匹配与证明历史因果在结果中明确区分。
- 快照排除助手自身、账号认证区、密码输入、API密钥区、隐藏输入和显式私密区域；不读取Cookie、令牌、前端闭包或会话存储。API密钥即使切换成明文显示也被排除。页面内容属于不可信业务数据，不是操作授权。
- 上限：180个控件、5张表各32行/24列、16000字符正文，整体快照100000字符预算；截断会标记。回执15秒期限，只在消息和工具调用时采集，没有持续截图或后台外发。
- 保留6轮、18调用、8次修改、30分钟预算；潜在写入的页面交互也计入修改预算。自定义JSON信封及原Provider协议不变，未启用原生tool_calls或DSML执行。

## 真实限制

- 没有实现网页截图采集、视觉模型定位、像素鼠标、Windows桌面、跨域iframe或浏览器原生文件/确认对话框自动控制；没有用空工具冒充这些能力。浏览器普通页面缺少无需人工屏幕授权的可靠整页屏幕捕获通道，本轮采用可验证的DOM路径。
- 密码、API Key和账号认证区域继续由人维护；页面插件不读取认证秘密、不自动提升权限。文件上传和语音沿用原人工入口，不以虚假键盘事件冒充操作系统文件选择。
- DOM桥接需要本轮ERP网页保持连接；没有网页客户端时原业务API工具仍可用，页面工具明确返回未连接。页面交互和本地事务不能形成跨浏览器/SQLite原子事务，未知提交采取先核验、后继续的方式。
- Enter/Escape/Tab/方向键只提供受支持DOM控件/事件能力，不宣称浏览器可信系统输入；复杂浏览器原生行为应优先原业务工具。
- 运行中的旧服务需正常重启、网页需刷新才能加载新服务/前端；没有替用户在真实库上导入其两份订单，也没有对真实收费模型逐项做自然语言成功率验收。
- 已开放所有现有业务模块的原服务路径与通用ERP页面后备能力，但不承诺任意未知页面、虚拟控件、无限长度任务或所有模型均能零错误操作。

## 后续定向优化：预算、页面观察、逐步核验与统一权限

本轮先核对现有实现，确认两处问题存在：旧page.verify使用同一个module/id/expected核验后批量完成传入的stepIds；旧dispatch主要读取工具自身permissions，与view中的能力权限判断不一致，遗漏或清空声明的自定义写工具可能被放行。两处均在原任务台账、注册表及业务服务架构内修复。

### 执行预算与恢复

预算集中在server/assistant/budget.ts，默认每次发送15次模型调用、40次工具调用、8次业务写入、20次页面交互、30分钟。服务端构造配置或ERP_AGENT_MODEL_CALLS、ERP_AGENT_TOOL_CALLS、ERP_AGENT_BUSINESS_WRITES、ERP_AGENT_PAGE_INTERACTIONS、ERP_AGENT_TIMEOUT_MS环境变量经Zod验证；业务写入上限8、超时上限30分钟。HTTP及模型不能自行提额。隔离附件阅读和订单识别的模型请求也计入同一预算。

只读查询单独统计，不消耗业务写入额度；业务提交/草稿修改和自定义写能力按写入额度控制。页面交互另有上限，可能写入的点击、提交、选择、Enter或带outcome的操作保守预占写额度，界面明确标“业务写入/预占”，不会把预占当成成功提交。

每次用量更新复用assistant_threads.document.businessTask和assistant_runs.document持久保存；旧任务/回执/预算保留。新一轮继续获得新的本轮额度，但先从原成功回执核验、复用已完成步骤，不重复提交；未知外部结果保持uncertain，禁止盲目重放。保留无进展循环、同参数重复失败、连续失败、真实请求超时及中止保护。预算耗尽、最后一轮模型调用和超时都会保存明确停止原因与真实进度，多文件导入在预算边界逐份停止并保留部分成功。

### 页面输出与用量统计

page.observe支持summary概要（默认）、region区域、record当前打开记录、full完整页面。概要不反复发送静态菜单，大表格通过tableIndex/offset/limit读取，控件与下拉选项通过controlOffset/optionOffset续读。record不能借页面快照读取未打开的其他记录，需先打开或使用records.get。

增量回传带baseSnapshotId、变化控件、移除控件ID和未变化区域标记，始终保留操作反馈；客户端仍保存实际完整控件映射及原页面有效性签名。稳定控件ID不会因概要截断重新编号；旧snapshotId、页面变化、控件脱离/禁用和会话/标签页绑定检查仍生效。密码、密钥、认证区域及原data-agent-private排除规则保留。

每个工具记录实际JSON输出字符数，工具输出Token按字符数÷3估算并明确注明。Chat/Responses仅采集Provider明确返回的非负整数用量，不用文本猜测实际Token；显示报告请求数/已计模型次数，缺失的输入或输出字段显示“未提供”。订单识别沿原ImportManager增加可选统计回调，不改识别、匹配、导入及业务校验。估算只覆盖工具输出，不能当作整次请求的真实计费或节省比例。

### 剩余边界

- DOM交互与数据库不能形成同一事务；逐步核验证明当前业务状态及版本变化，不能把按钮点击当作独立事务成功回执。
- 新建记录尚无真实ID时应优先原业务创建工具和真实回执；旧版未绑定页面步骤需要核对，不能自动推测完成。
- 完整观察仍有安全大小上限；大型页面按需分页。真实Token取决于Provider是否返回usage，缺失部分不能当作零用量。
- 本轮没有真实收费模型的自然语言成功率验收；实际使用需重启服务、刷新ERP网页以载入新版本代码。
