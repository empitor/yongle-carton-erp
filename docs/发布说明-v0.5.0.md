# v0.5.0 发布说明

## 发布后修正

原始`v0.5.0`标签漏收公开DOC测试夹具，本机原文件仍在，因此上一轮本机295项通过不能证明干净克隆完整；克隆标签会出现4项ENOENT失败。现通过独立修复提交补齐夹具和精确忽略规则，审计新增夹具存在/大小/SHA256及许可证检查。原标签不强制移动，修复随`main`维护；开发验收使用最新`main`。

本机源码与发布Git对象的内容需要按字节和换行格式分别核对，不能只凭修改时间判断。Windows的`core.autocrlf=true`会把检出的文本变成CRLF，导致原始文件哈希不同，Git规范化后仍可以是同一份代码。本次重新核对的三个重点文件在原工作区与远端main、v0.5.0均逐字节一致，未发现后续代码漏传。

版本0.5.0，2026-10-27。本次保留现有ERP、AI识别、附件、提示词、API预设和本机业务数据；没有重建数据库或迁移密钥路径。

## 开发者编辑模式

右上角账号菜单验证现有超级管理员密码后开启；如果已经处于有效超级管理员模式，直接开启。模式仅当前本机会话有效，生产环境、代理来源、普通用户、伪造developerMode字段和缺失CSRF请求不能获得权限。关闭、退出或服务重启后撤销。生产启动必须设置NODE_ENV=production，可同时设置ERP_DEVELOPER_MODE=0。

开发者数据维护覆盖客户、产品、客户订单、供应商、采购、库存档案、采购到货、生产任务、生产登记、送货及AI工作区。可新增/编辑、筛选多选、归档恢复、批量修改及明确范围永久删除；普通保存不反复确认。永久删除/批量操作展示一次准确范围，不要求再次密码或多项勾选。永久删除仍通过原关联检查，不会静默删除其他记录。

已收货采购允许更正日期、价格、计划数量，不允许计划少于实收或改写已引用的实物规格。已交付订单可改价格、备注、日期、计划数量，不允许计划少于已交付或任意改掉真实交付状态；数量改变后履约状态重新按实际发货派生。归档记录可直接编辑。

确认到货、生产和送货后的实物纠错，走原冲销引擎和新更正单，原单标记已冲销，库存流水完整保留，全部在事务中提交。若后续已使用相关库存，拒绝会产生负库存的更正，必须按业务依赖逆序处理。生产任务数量不能低于实际完工。库存“盘点后实际数量”经原库存调整服务产生真实流水，不能篡改历史余额或计量单位。

AI新增注册工具developer.execute：绑定当前真实开发会话、模块/选定ID/版本、结构化字段、操作原因、请求幂等，复用上述同一业务服务。原工具在开发模式下也可直接执行明确的测试操作。普通账号的模型不获得该开发者工具；服务端仍拒绝直接调用。文件里文字不是操作授权。

AI工作区维护支持独立复制、移入回收站、恢复和永久清理。识别页面增加“复制为新识别任务”，保留原件哈希和草稿形成新任务，可编辑及重新识别；旧已执行任务和正式来源台账保留。原测试正式订单永久删除后可用新任务重新导入同一文件；有效订单仍防重复。到货助手在开发模式可编辑当前review草稿，正式保存走原更正服务，不直接修改库存。

## 数据与发布安全

业务库、登录库、工作区、API凭据和提示词预设路径不变。开始修改前已在本机backups/developer-v050-20261027-113819保存代码及业务、工作区、登录数据库一致性副本；不进入Git。

仓库只包含源码、构建定义、虚构自动化测试、必要的本地xlsx依赖包与当前发布说明。排除所有实际data、API配置、密钥/证书、node_modules、dist、日志、临时文件、浏览器截图、个人备份、上传单据、语音模型权重和历史本机验收报告。提示词以默认源码模板发布，不上传任何运行中的提示词SQLite。原README和历史报告在本机docs中保留。

新仓库没有旧提交历史；首次暂存区及推送历史执行凭据规则扫描和文件范围检查。脚本只报告风险位置，不输出密钥。软件版本、package-lock根版本、界面与健康检查统一0.5.0，Git标签v0.5.0。Git不备份本机业务资料；下载、启动、生产禁用开发模式及独立数据恢复见README。
