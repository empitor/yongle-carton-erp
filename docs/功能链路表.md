# 功能链路表

对照表：每个功能走哪个页面、哪些后端地址、哪个服务函数、助手用哪些工具。机制见[架构说明](架构说明.md)，表见[数据模型](数据模型.md)，怎么操作见[使用手册](使用手册.md)。

- **地址**都在 `/api` 下，只列主要的；`a|b` 是同一前缀下的几个。参数和回答看接口表 `shared/<模块>/*-api.ts`（财务是 `shared/finance/finance-api-*.ts`）。回文件、收原始字节、边算边推的地址不在接口表，直接用 express 注册。
- **代码里的登记：** 功能、页面、地址、工具的对应在 `shared/assistant/ui-capabilities.ts`；写地址的业务动作在 `shared/assistant/ui-actions.ts`、`ui-actions-system.ts`；工具目录在 `server/assistant/tool-catalog.ts`。`tests/feature-links.test.ts` 查登记和代码一致。**本表没有测试守着，改了功能自己对一遍。**
- **助手写入**一律出确认卡片，下表不再注明；直接执行的几类见[助手](架构/助手.md)。

**业务各行的细节：**

- **搜索和筛选只有一份：** 客户、供应商、库存品按哪些栏目搜是 `shared/business/business-metrics.ts` 的 `operationalSearchText`，产品是同文件的 `matchesProduct`，采购单列表页和接口用 `shared/business/purchase-filters.ts` 的 `matchesPurchase`（顶栏搜索在 `src/palette-items.ts` 组装关键词）。订单筛选只有 `shared/business/order-filter.ts`，列表和助手都调它，状态只认页面上的叫法。
- **前端保存：** 档案在 `src/editors/editor-api.ts`（客户编辑窗 `src/editors/CustomerEditor.tsx`、供应商编辑窗 `src/editors/SupplierEditor.tsx`、产品编辑窗 `src/editors/ProductEditor.tsx`、订单编辑窗 `src/editors/OrderEditor.tsx`；新建编号给 `undefined`，修改的版本号取打开窗口时读到的），采购单在 `src/operations/purchase-api.ts`。
- **订单税率：** 编辑窗、数据管理和 `records.propose_save` 使用订单录入结构的百分数数字 `taxRate` 与原件写法 `taxText`，由 `sales(store)` 保存。
- **归档：** 写法都是 `{ action, items: [{ id, version }] }`，做法只有 `server/core/records/archive.ts` 一份。
- **只有一个窗口的**（数据管理和各详情打开的也是它）：
  - 安排订料 `src/operations/PurchaseLaunch.tsx`：订单“下一步”、订单详情、订单多选“更多”；几张订单可合成一张或每张一张。
  - 出入库和盘点 `src/operations/MovementDialog.tsx`：库存品详情“出入库 / 盘点”。
  - 安排生产 `TaskPlanDialog`：订单“下一步”、订单或产品勾选、产品详情、生产任务页页头（按产品排，能加产品）、`#production?create=1`。
  - 登记完工 `ProductionBatchDialog`，含不挂任务的完工（`UntaskedCompletions.tsx`）。
  - 安排送货 `DeliveryPlanDialog`：订单勾选、成品库存、今日页、订单“下一步”、送货页页头（先选客户）、可发货勾选、`#warehouse?deliveries=1&createDelivery=1&order=|stock=`。
  - 更正窗口到货、送货、完工各一份内容，本机管理员多一栏。
- **订货单**回给人时由 `FlowService.views.batch` 补上到货单。
- **到货：** 登记时每行可带入库数 `stockedQuantity`，`pending:true` 存成待入库；核对时 `preview` 返回 `previewDigest`，`confirm` 带回。
- **说明编辑**的入口：单据页、仓库页、数据管理的“编辑”，成品批次的“写备注 / 编辑备注”。
- **更正：** 入口在单据页、仓库页详情“更多 → 更正到货单 / 更正送货单 / 更正完工单”，采购单详情到货记录的“更正”，AI 导入里已入库的到货单，数据管理。提交带预览的 `previewDigest` 和请求号。助手的 `production.correct` 只给超级管理员、执行要超级管理员模式，另两个要业务编辑权限；卡片就是更正前后的对比。
- **单据详情**按编号读台账记录（`readFlowRecord`），已归档的也有验收入库和流水。
- **生产、完工：** 生产任务保存即下达，没有待下达。`POST /flow/production` 新建一律 409；`ProductionForm` 只编辑待入库的完工单；`records.propose_save` 不能新建完工单。`untasked` 是不挂任务的完工，`pending:true` 只登记。
- **送货：** 超订单数量带 `allowOverdelivery` 和原因，要超级管理员模式。单据编辑窗只改已有的送货单。
- **流水分页**只收 `page`、`pageSize`，没有排序。
- **导出的文件**经 `src/documents/export-file.tsx` 的 `deliverBusinessFile` 交给插槽 `saveFile`，存好了才调 `/documents/:id/complete`；安卓 App 里存进手机“下载”（[外壳和网页](架构/外壳和网页.md)“安卓 App 通道”）。

- **正式导入**带 `expectedRevision` 和预览的 `previewDigest`；回执只有 `ImportReceipt` 十项，不含服务器路径和操作人。
- **`order_import.start`** 识别本会话的附件或文件任务（含收件箱转来、关联进来的），识别过的复用原结果、不重复收费。**`execute`** 一份或几份一张卡片，写明客户和每行产品用已有档案还是新建，新建的列出相近的已有档案。

**进件路线：**

```text
企业微信、飞书、钉钉机器人 / 手动上传 / 粘贴 → 收件箱
收件箱 → 转订单 → AI 导入（客户订单）→ 人核对 → 正式订单
       → 转到货 → AI 导入（到货单）  → 人核对 → 待入库的到货单 → 核对入库
       → 新建订单（文字或不可识别格式的文件）→ 本页打开订单编辑窗 → 正式订单并由识别导入标收件已处理
安卓 App 分享 → src/app-bridge.ts → src/import/app-share.ts → useUploadQueue 的 upload → POST /api/ai/imports/upload → AI 导入（待识别）
唛头：产品详情里直接上传，整份文件挂到产品下，不识别
```

转单和分享都只把原件放进 AI 导入，不自动识别、不发给模型。分享的消息约定见[外壳和网页](架构/外壳和网页.md)“安卓 App 通道”。

## 账号、设置、系统

`/auth` 下的接口归账号模块（`server/accounts/`），助手经装配传入的只读查询取登录记录。

账号管理、AI 设置、提示词、消息接入、工具启停的写入都要超级管理员模式（没进回 403 `super-mode`；本机管理员一直算在模式里）。没进模式时页面顶上 `src/ui/SuperModeNotice.tsx` 给入口，打开的是账号菜单里同一个“系统维护”窗口。

- **设置页谁看得到：** API 配置、提示词、高级只给超级管理员账号，读也一样（`/ai/settings`、`/ai/prompt-modules`、`/assistant/plugins`）；别的账号只有单据模板，只读和出纳没有设置。页签名单在 `src/app-shell.ts` 的 `settingsTabsOf`；助手 `ui.open` 打开这几个页签时别的账号被拒（`adminSettingsLink`）。
- **AI 设置：** 改密钥和识别设置要超级管理员模式；查余额、重新测试只要超级管理员账号。助手、AI 导入、收件箱要知道 AI 能不能用、用哪个模型，读 `GET /assistant` 的 `ai`，人人能读。两页的 AI 凭证关卡共用 `server/ai/page-guard.ts`。
- **`/assistant/tools`** 设置页不用，按账号列自己的工具，真实模型套件用。
- **数据管理：** 删除、已生效单据的说明和更正、库存品出入库打开的都是业务页面同一个窗口、走同一个地址。`/management/execute` 只办新建、修改、归档、恢复、确认、取消、撤销，删除走 `/deletions/execute`、助手走 `records.delete`；已生效单据改数量、日期会被拒；补丁里有录入结构不收的栏目，不管在第几层都拒收并说清哪一格，照读出来原样带回的放过（[架构说明](架构说明.md)“模块”的数据管理）。
- **提示词模块**三个：客户订单识别 `sales-order`（AI 导入选客户订单）、供应商到货单识别 `supplier-delivery`（AI 导入选到货单、到货页 AI 识别送货单）、小甬小勒 `assistant`（全局助手）。定义在 `shared/ai/prompt-modules.ts`；存在哪个文件见[数据模型](数据模型.md)“提示词库（第 2 版）”，默认内容由谁提供见[架构说明](架构说明.md)“模块”的 AI 接入。

## 新增功能时

加页面、写地址、助手工具时一起改这些地方（硬规则在 AGENTS.md“新增功能时一起改”；表和字段见[数据库结构版本](架构/数据库和备份.md)“改结构时一起改”），改完更新本表：

- **页面：** `shared/core/pages.ts`（页面编号、中文名、分组、查询参数）、`shared/assistant/assistant-navigation.ts`（助手页面说明，少一页编译不过）、`src/Navigation.tsx`（图标和权限条件）、`docs/使用手册.md`（“使用说明”页和助手的 `guide.read` 读的都是它）。
- **写地址（post、put、patch、delete）：** 在 `shared/assistant/ui-actions.ts`（账号、助手、设置、数据管理在 `ui-actions-system.ts`）登记一条业务动作：哪种记录、什么动词、按钮文字、服务函数、助手命令。一个写地址只属于一条动作，前端只由一个 `*-api.ts` 发；同一种记录的同一个动词已有动作就用它，不另开地址。新地址前缀登记在 `tests/module-api-owners.test.ts` 的 `apiOwners`。
- **助手工具**（人能在界面上做的，助手同一轮也要能做）：
  - 在 `server/assistant/tools/` 对应的领域文件里定义一次；名字加到 `server/assistant/tool-catalog.ts` 顺序表末尾；在 `server/assistant/plugins.ts` 的分组表补一行（查不到会报错）；在 `shared/assistant/ui-capabilities.ts` 登记（每个工具只出现一次）。
  - 说明不超过 200 字：第一句写成“短名字：什么时候用”（命令目录只印这一句；冒号前的短名字是状态行“正在……”和“没做成：……”的叫法，要读得通），后面一两句说办什么、参数各一句。命令怎么用只写在说明里，不写进提示词；权限和实现细节不写。
  - 写入一律出确认卡片：业务类有方案生成器就自动出；流程类在 `server/assistant/chat/workflow-cards.ts`（出卡片、确认后执行）或 `workflow-direct.ts`（直接执行，写明为什么不用确认）登记一处，都没登记的不执行。由注册表直接执行的只能是只读命令。卡片写明动的是哪条记录、每个变了的字段。
  - 新命令默认进命令目录；要常驻成原生工具的才加进 `server/assistant/command-directory.ts` 的 `commonCommands`（少加，每加一条每次请求多发它的参数结构）。只给超级管理员的加进 `server/assistant/tool-registry.ts` 的 `superAdminTools`。
