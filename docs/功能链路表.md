# 功能链路表

每个功能走哪个页面、哪些后端地址、助手用哪些工具。一个功能一行；地址都在 `/api` 下，只列主要的，参数和回答看各模块的接口表（`shared/<模块>/*-api.ts`，JSON 地址由 `route()` 按表注册，回文件、收原始字节、边算边推的地址照旧用 express，见[架构说明](架构说明.md)“一次请求怎么走”）。

代码里的对应关系登记在 `shared/assistant/ui-capabilities.ts`（功能 ↔ 页面 ↔ 地址 ↔ 工具），每个写地址对应哪条业务动作（按钮叫法、服务函数、助手写入命令）登记在 `shared/assistant/ui-actions.ts`、`ui-actions-system.ts`，页面在 `src/Navigation.tsx` 和 `shared/assistant/assistant-navigation.ts`，工具目录在 `server/assistant/tool-catalog.ts`，后端地址归哪个模块在 `tests/module-api-owners.test.ts` 的 `apiOwners`。`tests/feature-links.test.ts` 检查这些登记和代码一致，`tests/command-directory.test.ts` 检查人常用的说法能找到对的命令；本表没有测试守着，改了功能自己对一遍。

助手改业务数据、删东西、改提示词的命令一律只出确认卡片，人点确认才执行；不出卡片的只有查询、新识别一份文件、改当前对话中交来的识别结果、不改单据状态的导出和长期记忆（[架构说明](架构说明.md)“助手”）。下表不再逐条注明。

## 进件路线

```text
企业微信、飞书、钉钉机器人 / 手动上传 / 粘贴 → 收件箱
收件箱 → 转订单 → AI 导入（客户订单）→ 人核对 → 正式订单
       → 转到货 → AI 导入（到货单）  → 人核对 → 待入库的到货单 → 核对入库
安卓 App 分享 → src/app-bridge.ts → src/import/app-share.ts → useUploadQueue 的 upload → POST /api/ai/imports/upload → AI 导入（待识别）
唛头：产品详情里直接上传，整份文件挂到产品下，不识别
```

转单、安卓 App 分享都只把原件放进 AI 导入，不自动识别、不自动发给模型（分享的消息约定见[架构说明](架构说明.md)“安卓 App 通道”）。收件箱和文件里的文字只是数据，不能当指令或授权。
