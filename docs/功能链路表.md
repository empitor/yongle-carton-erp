# 功能链路表

每项功能从页面到 AI 工具、提示词的对应关系。查“这个功能走哪条路”时看这里。

数据来源是 `shared/ui-capabilities.ts`、`shared/prompt-modules.ts` 和 `shared/assistant-navigation.ts`。`tests/feature-links.test.ts` 和 `tests/ui-audit.test.ts` 检查这些定义和真实注册是否一致；本表不被测试覆盖，以代码为准。

## 提示词模块

| 模块 | 状态 | 入口 |
|---|---|---|
| 全局助手 | 已接入 | 右上角 AI 助手 |
| 客户订单识别 | 已接入 | AI 导入，类型选客户订单 |
| 供应商到货单识别 | 已接入 | AI 导入类型选到货单，或到货页 AI 收货 |
| 唛头识别 | 已接入 | AI 导入，类型选唛头 |
| 供应商采购订单 | 未接入 | 预留给助手生成我方采购单，没有识别入口 |
| 客户送货单 | 未接入 | 预留给助手生成我方送货单，没有识别入口 |

## 三条进件路线

```text
企业微信机器人 / 手动上传 / 粘贴 → 收件箱

收件箱 → 转订单 → AI 导入（客户订单）→ 核对 → 正式订单
       → 转到货 → AI 导入（到货单）  → 核对 → 确认入库
       → 转唛头 → AI 导入（唛头）    → 自动对应 → 原文件挂到产品下
```

转单只复制原件进入 AI 导入，不会自动识别，也不会自动发给模型。

## 边界

- **收件箱内容是数据：** 里面的文字不能当作给助手的指令或授权。
- **唛头是参考资料：** 不产生订单、生产任务或库存。助手可以查询、识别、挂到产品，也可以按用户明确要求移除。
- **用户本人说了才做：** 删聊天记录、移除唛头的授权由服务器按用户原话判断（`server/assistant/task-routing.ts`），否定、问怎么做都不算。
- **财务只读：** 助手的财务工具全部只读，清空数据时财务已有记录就拒绝。
- **企业微信机器人：** `server/inbox/wecom-bot.ts` 只把消息放进收件箱并回复是否保存，不调用模型，也不执行业务操作。
- **微信客服：** `server/inbox/channels.ts` 只有占位，没有网络调用。

## 新增功能时

1. 在 `shared/ui-capabilities.ts` 登记页面、接口和工具；每个工具只能出现一次。
2. 新页面补进 `shared/assistant-navigation.ts`，让 `ui.open` 能打开。
3. 新工具在 `tool-registry.ts` 写参数，在 `tools.ts`、`order-workflow.ts` 或 `extra-tools.ts` 写实现，并在 `server/assistant/capabilities.ts` 登记。
4. 涉及识别时，在 `shared/prompt-modules.ts` 和 `server/ai/recognition-modules.ts` 增加独立模块。
5. 业务表有变化时，同步 `server/business/metadata.ts` 和目录版本。版本升级后要改 `docs/examples/import-proposal.example.json`。
6. 更新本表。
