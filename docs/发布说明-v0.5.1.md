# v0.5.1 发布说明

2026-10-27。软件、包及锁文件版本统一为0.5.1，业务目录24，数据库迁移11。沿用当前本地ERP与原业务服务。

## 数据库管理

- 删除是真正的数据库物理删除，与归档、取消和冲销独立；已确认、历史关联、非零库存不再成为通用删除禁令。
- 客户、产品、供应商、销售/采购订单、原材料/成品库存、采购到货、生产任务/登记、客户送货及AI工作区均接入一致的管理入口。
- 删除按真实外键和单据引用处理必需子记录、解除可空引用，并事务重算金额、采购实收、履约及库存。涉及独立业务数据时显示实际影响清单。
- 删除单据时可明确选择保留其他库存已发生数量并解除来源引用，或删除来源流水后重算。删除库存档案会删除该库存品及其全部流水。
- 归档保留原记录，单独检查未完成工作与库存条件，支持恢复。正常删除不再进入回收站；旧软删除数据继续作为兼容归档保留。
- 已确认、已完成、已归档及AI导入记录可直接编辑。确认单据保持原ID更新并同步库存，订单客户更正同步送货关联，共享送货按客户拆分。
- 采购计划和实际收货分别记录，计划可低于实收；更改供应商或实物身份时解除旧到货匹配并保留独立到货及实际库存。
- 业务页面统一“编辑｜归档｜删除”，归档记录提供“编辑｜恢复｜删除”，保存及删除后即时刷新并保留具体结果提示。

## 管理员与AI助手

本机最高管理员登录后直接获得上述能力，不需要超级/开发者模式开关、重复密码、删除口令或额外安全勾选。真实登录、loopback来源、CSRF、字段类型、版本及事务检查继续生效；普通账号不自动提升权限。

全局助手通过注册工具调用与页面相同的管理服务：`records.delete`物理删除，生命周期工具的`archive/restore`分别归档/恢复，收到真实成功回执才报告成功。没有SQL、Shell或数据库结构修改工具。

AI工作区可独立归档、编辑或物理删除。旧回收格式文件可直接编辑且保持归档状态，也能不恢复而直接删除。已导入任务的工作草稿可以维护，正式订单及来源回执不会因此重复执行；工作草稿与正式订单仍是独立对象。

增加持久任务台账、恢复核验、历史任务切换及真实新任务入口。重复继续不会重放已成功写入；未知计费结果不自动重识别。增加脱敏协议诊断，保留必要结构与错误类型，不保存密钥、原文或完整模型回复；仍使用现有JSON信封协议。

## 升级与数据

1. 停止本机服务，保存现有代码改动并离线备份整个`data/`及独立API配置，避免遗漏SQLite WAL或工作区文件。
2. 更新到`v0.5.1`，使用Node.js 24.15.x，运行`npm ci`和`npm run build`。
3. 正常启动后登录并刷新页面。不要将旧运行数据覆盖为示例数据。

本版保留已有业务、账号、工作区、提示词与Provider存储路径。迁移11仅移除采购明细“实收不得高于计划”的旧CHECK，保留非负约束、ID、数据、外键及索引；迁移在事务内校验，失败回滚。升级后的数据库恢复旧程序前应使用升级前备份，不能仅通过切换源码撤销数据库迁移。

删除不可恢复；归档才有恢复操作。审计和正式原件归档是历史凭据，不会让已物理删除的业务行出现在归档列表中。
