# 0.8.4 发布说明

发布日期：2026-11-08

这一版没有改系统功能和界面，只做了两件事：给服务器升级加上发布检查，以及拆分两个过大的前端文件。数据库结构不变。

和 0.8.3 一样只发补丁，不提供新的完整安装包。全新安装先装 0.8.2 安装包，再打这个补丁，一步升到 0.8.4。完整安装包留到 0.9.0。

## 下载

- `yongle-carton-erp-v0.8.2-to-v0.8.4-linux-x64.patch.json.gz`：Linux 补丁，把原版 0.8.2 Linux 安装包直接升级到 0.8.4，已包含 0.8.3 的全部内容。
- `apply-patch.mjs`：在服务器上应用补丁的脚本。

两个文件各附 sha256 校验文件。补丁只含程序文件，不含任何业务数据、账号、密钥和语音模型。

## 部署

- **发布检查：** `npm run patch-server` 正式打补丁前，检查本机没有未提交的改动、当前提交打了 `v版本号` 标签且已推送到 GitHub，不满足就拒绝。服务器上只会跑 GitHub 上已发布的代码。
- **三方核对：** `npm run patch-server -- --check` 核对本机、GitHub、服务器三方的版本、提交和每个程序文件。
- **临时修复：** 服务器紧急故障时可用 `--hotfix "原因"` 跳过发布检查，服务器会标记为未发布，事后要补发正式版本。

## 代码整理

- `src/App.tsx` 从 2058 行减到 1189 行，`src/FlowPage.tsx` 从 2413 行减到 1440 行。客户、产品、订单编辑器移到 `src/editors/`，单据编辑器和详情移到 `src/flow/`。只搬位置，界面和行为不变。

## 升级

**从 0.8.2 升级（Linux）：** 把两个文件传到服务器，核对 sha256，然后运行：

```sh
sudo /opt/yongle-carton-erp/runtime/node/bin/node apply-patch.mjs yongle-carton-erp-v0.8.2-to-v0.8.4-linux-x64.patch.json.gz
```

脚本会先核对服务器上的文件确实是原版 0.8.2，再备份业务数据、替换文件、重启服务，启动失败会自动换回旧文件。

**已经是 0.8.3：** 这个补丁要求原版 0.8.2，不能直接打在 0.8.3 上。请在维护电脑的项目目录更新到 0.8.4 源码，用 `npm run patch-server` 升级，它会按服务器上的实际文件计算差异。

**Windows 本机版：** 直接更新源码到 0.8.4。

## 已知限制

- 补丁不能更新依赖，依赖有变化时要用完整安装包。
- 手机上的文件选择、拍照上传和语音还没在真机上试过，要等 HTTPS 域名开通。
- 第二轮审查里还没核实的财务和数据维护条目仍在[路线图](../路线图.md)。
