# 外壳和网页

什么时候读：改两个外壳（安卓、Windows）和网页之间的接点之前读，改 `src/app-bridge.ts`、备案号、保存文件、返回键时也读。

网页这头和两个应用外壳（安卓 App `apps/android`、Windows 客户端 `apps/desktop`）的约定：网页怎么认出外壳、备案号、安卓 App 通道的消息。外壳那头怎么实现见 `apps/android/docs/架构说明.md`、`apps/desktop/docs/架构说明.md`；网页和安卓外壳之间的消息约定只写在这里。两个外壳的代码标准和本项目一样；安装包和签名密钥不进仓库。

## 网页怎么认出两个外壳

- 安卓 App 看 User-Agent 末尾的 ` YongleErpAndroid/<版本>`（`src/app-bridge.ts` 的 `inAndroidApp`；App 通道、保存文件、滑到头的拉伸用它）。
- Windows 客户端没给网页留标记，靠 Tauri 往它打开的每个网页注入的 `window.__TAURI_INTERNALS__`（外壳不开任何接口权限；`apps/desktop/tests/shell.e2e.test.mjs` 守着它在）。
- “是不是在应用程序里”只有 `inShellApp` 一处，只给网页底部的备案号用（`src/FilingLine.tsx`：应用程序里不显示）。苹果手机“添加到主屏幕”打开的照普通浏览器算。

## 备案号

服务器部署设置 `ERP_ICP_RECORD`、`ERP_POLICE_RECORD`（`server/core/http/deployment.ts`，相关的见 `docs/运维/部署.md`）。登录状态接口 `GET /auth/state` 只对从域名（代理入口）进来的请求带出 `filing`，本机入口不带，所以本机实例不显示。页面在登录页最底部（`src/LoginCard.tsx`）和登录后的页脚显示：ICP 号链工信部备案查询，公安号按号里的数字链公安备案查询，都在新标签页打开；公安徽标还没放。

## 安卓 App 通道

网页这头在 `src/app-bridge.ts`。只在安卓 App 里接得通，浏览器和 Windows 外壳里没人发接通消息、行为不变。分工：系统交给外壳的事（返回键、分享进来的文件、存文件、退出）放外壳；画在页面上的东西怎么点、怎么关放网页，手机上要不一样就按手机样式分（`src/ui/phone.ts`，例：手机上点窗口背后的暗处关窗，相关的见 `docs/界面/总规矩.md`）。界面流程 `scripts/ui-check/flow-app-bridge.mjs`（`npm run test:ui -- mobile`）模拟 App 消息把下面几样走一遍。

- **接通：** App 在 User-Agent 末尾加 ` YongleErpAndroid/<版本>`，页面加载完用 `postWebMessage`（目标来源限定为 ERP）发一字不差的 `{"type":"erp-app-bridge","version":1}` 并附一个端口。网页要同时满足 UA 标记、顶层窗口、`event.source === null`、恰好一个端口才接通（不看 origin），回 `bridge-ready`。之后都走这个端口、都是 JSON 字符串，别的消息不认。又收到接通消息（页面重新加载后 App 重新接通）就关掉旧端口换新的。通道由 `src/slots.ts` 在页面启动时接上。
- **返回键：** App 发 `back {id}`，网页回 `back-result {id, result}`：
  - 先关最上面一层弹层（`src/ui/back-layers.ts` 的 `closeTopLayer`，调它自己的关闭函数，和 × 同一个；提交中不关），回 `handled`；没弹层时不在首页就回首页（普通账号“今日”、纯财务账号财务概览，`src/app-shell.ts` 的 `homePage`），回 `handled`；已在首页或没登录回 `home`，由 App 提示“再按一次返回退出”，2 秒内再按才退出。
  - App 只认正在等的那个编号、认一次就作废，`id <= 0` 不认。没接通时（点开图片原件这类不是 ERP 的页面、页面还在加载）App 能后退就后退，不能就按首页处理。
  - 弹层由组件用 `useBackLayer(close, { busy, active })` 登记（窗口、详情面板、助手窗口（先关记忆面板）、附件预览、全局搜索、各种菜单和筛选浮层），挂着就看得见。`tests/checks/back-layers-registered.test.ts` 守着渲染 `role="dialog"`、`alertdialog`、`menu` 或 `<dialog>` 的组件文件都调了它。
  - 手机上助手全屏，地址一变或点了助手里的站内链接（记录链接、助手带去某页）就收起（`src/assistant/useAssistantPanel.ts`），电脑上不变。
- **分享文件**（`src/import/app-share.ts`）：
  - App 发 `share-offer {shareId, files[{name,mime,size}]}`。网页没登录就等登录完；这个账号打不开 AI 导入（`src/app-shell.ts` 的 `pageAllowed`，纯财务账号）回 `share-rejected {shareId, message}`，App 提示、删缓存、收尾。能进时导入页读好工作区（能上传了）就回 `share-ready {shareId}`：已在导入页就等它读好；开着弹层先发 `info` 口气的提醒“收到 N 份分享的文件，关掉当前窗口后进入 AI 导入”，弹层都关了（`afterBackLayersClosed`）再跳；没弹层马上跳，跳时提醒换成“正在把分享的 N 份文件传进 AI 导入”。同一编号只回一次 `share-ready` 或 `share-rejected`；新的 `share-offer` 替换上一批。
  - 之后 App 一份一份发 `share-file {shareId, index, data(base64)}`，网页对每条回 `share-uploaded {shareId, index, duplicate}` 或 `share-failed {shareId, index, message}`（`shareId`、`index` 照抄）。编号对不上、序号越界、还没回 `share-ready`、导入页已关、格式不对、清单里这份的 `size` 超过上限（`src/import/useUploadQueue.ts` 的 `MAX_FILE_BYTES`，大于才拒，不解码）、base64 坏，都回 `share-failed` 带中文原因。收下的每份走 AI 导入同一个上传（服务端按内容去重、只存原件不识别）；每份都有结果后提示换成总结。
  - 一批办没办完由 App 自己数：第几份有了结果（或 App 自己读不出、记一条失败）就发下一份，到头收尾；App 只认当前编号、正在等的那份的回执。页面重新接通时 App 回到“已发清单、没收到 `share-ready`”，重发 `share-offer`、从第 0 份重来（服务端按内容认出同一份，不会多出任务）；这时新来的分享可以替换它，已经在传时新分享 App 直接拒。单份上限 App 在复制阶段就拒，网页是第二道。
  - 提示分工：“正在传”和传完的总结只由网页说；App 只说自己查出的错：复制时没收下的三种原因（格式不支持、超过 10MB、读不到）、在传时又来新分享、一次份数太多、`share-rejected` 带来的原因、没传上的。所以分享时网页还在加载或停在登录页，登录前看不到提示，登录后接着传。
- **保存文件：** 内存里的文件（导出的订货单、送货单，模板样张）只经 `src/ui/save-file.ts` 的 `useSaveFile()` 保存，取插槽 `saveFile`（`src/ui/slots.tsx` 定义），没填就是浏览器下载（浏览器、Windows 外壳都这样）。`src/slots.ts` 在安卓 App 里填 `src/app-save.ts` 的保存：
  - 网页发 `save-file {id, name, mime, data(base64)}`（`id` 是本页从 1 递增的正整数），App 对每条回且只回一条 `save-result {id, ok, message?}`：存进手机“下载”成功回 `ok:true`，App 自己提示“已保存到‘下载’：文件名”，网页不重复提示；`id` 不是正整数、`data` 不是合法 base64、解码后超过 20MB、名字清洗后为空、写入失败都回 `ok:false` 加中文原因。
  - 网页收到不在等的 `id` 丢掉；最多等 `APP_SAVE_TIMEOUT_MS`（60 秒）；没接通、发不出去、超时、页面重新接通、App 回 `ok:false` 都按没存成报错（超时和重新接通时说“可能没有保存，请到‘下载’里看一看”）。
  - 要改业务状态的导出（`src/documents/export-file.tsx` 的 `deliverBusinessFile`）存好了才 `completeExport`，没存成状态不变；导出窗、订货单、助手确认卡片、助手回复里的下载、模板样张都走它。
- **滑到头的拉伸**（`src/mobile/content-stretch.ts`）：App 关掉了 WebView 对整个视图的拉伸（会带着顶栏、底部导航变形），只在 App 里由网页在滑到顶、滑到底再拖时只拉伸 `<main>`（按拖的距离、越拉越难拉，最多 8%）。只认一根手指按在 `<main>` 里、又不在它里面自己能竖着滚的区域的拖动；开着登记了返回键的弹层（`hasBackLayer`）时不拉；松手 0.3 秒回弹、到点清掉样式（不靠 `transitionend`）；系统开了“减少动态效果”时松手直接复原。浏览器自己的拉伸本来只动内容，不开。
