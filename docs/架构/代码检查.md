# 代码检查

什么时候读：写测试、跑检查、交之前自查时读；检查报红想放宽、加例外之前一定读。

点名跑哪条、测试怎么写相关的见技能 `.claude/skills/testing/`。

## 全部体检

`npm run check`（`scripts/check.mjs`）按顺序跑，哪步不过就停在哪，约三分钟：类型检查 → 代码检查 → 函数只许变小 → 样式写死的值 → 没人用的代码 → 重复代码 → 完整测试 → 覆盖 → 发布检查 → 构建到临时目录。界面流程（`npm run test:ui`，含 `a11y` 组：登记在 `scripts/ui-check/a11y-known.json` 之外的无障碍违规）和两个外壳的检查不在里面。

## 检查是防火墙

通用做法（报红改代码不改检查、什么时候才能动检查、例外怎么登记、新规矩同一轮做成检查）见技能 checks-as-firewall。本项目另有一条：`eslint-suppressions.json` 不许登记（钩子会拦）。

## 检查分几类

每个检查文件开头的注释写清它拦什么，这里只分类：模块（`tests/checks/module-*.test.ts`，规则见 `docs/架构/模块规则.md`）；结构和升级（`tests/checks/schema-constraints.test.ts`，`tests/core/` 下的结构、升级样例、配置库几份）；一件事一条链路（`tests/checks/feature-links*.test.ts`、`tests/checks/page-hrefs.test.ts`）；前端、样式和叫法（`tests/checks/` 的 ui-kit、css、field-names 等，`tests/app/`、`tests/business/` 里的几份）；两边写的清单和财务口径（下面一节和 `tests/finance/`）；助手六条界限和命令目录（`tests/assistant/`）；文档、规则文件、钩子、测试套件本身（`tests/checks/` 的 doc、rule-files、claude-hooks、test-suites 等）；发布（`tests/core/patch-rollback.test.ts` 和 `tests/release/`）。另有三条命令（`npm run lint:ratchet` 见下一节）：`npm run lint:css`（样式里写死的颜色、字号、圆角、层级，手机断点只许 700）、`npm run knip`（没人用的代码）、`npm run dup`（重复代码占比不超过 `.jscpd.json` 的上限）。

## 代码检查

- **`npm run lint`**（`eslint.config.js`，约 35 秒，带类型信息所以不带缓存）：查任意类型、强行断言、非空断言、没等待的异步、`switch` 列全、空的和什么都不做的 `catch`、hook 依赖、废弃写法、危险正则、函数长度和复杂度。上限：函数 80 行、`.tsx` 组件 150 行、嵌套 4 层、参数 5 个、圈复杂度 20，函数只许变小；不写 `any`、不用任意类型的值、不强行断言、不用非空断言，异步要等待，不留空的 `catch`。测试目录一样查（只有 `no-floating-promises` 放过 `node:test` 的 `test`）。源码里写 `eslint-disable` 不起作用；`eslint-suppressions.json` 已清空、不许再登记（钩子会拦），新写和改到的代码一处都不许报。
- **`npm run lint:ratchet`**（`scripts/complexity-ratchet.mjs`）不带豁免再量函数，和基线 `scripts/complexity-baseline.json`（现在是空的）比，超线的新函数和变大的都拦。
- **项目自己补的三条**（`scripts/eslint-local-rules.mjs`）：
  - 写死的数字：只查 `server/`、`shared/`；0、1、2、100、1000、-1、数组下标、默认值放过，HTTP 状态码按位置放过（`res.status(409)`）。
  - 直接读库 `local/no-direct-db-read`：拦 `prepare(…).get/all/iterate`（先存变量再读也拦；`.run()` 不管），读库只走 `server/core/storage/sqlite/sql.ts`。
  - SQL 里写死的单据状态、种类 `local/no-flow-literals`，见 `docs/架构/服务端写法.md`“单据状态、种类的写法”。
- **按位置限制的引用：** 前端发请求的函数（`call`、`request`、`throwIfFailed`、`authorizedRequest`、`tokenRequest`、`retryWhenBusy`）只许在 `*-api.ts` 和 `src/ui` 里引。不校验回答类型的 `trustedReply` 只许 `src/ui` 用；`responseData`、`readEventStream` 另许 `settings-api.ts`、`workspace-api.ts`、`useAssistantChat.ts`。
- **zod：** `z.custom()` 必须带校验函数；对象里值为 `z.unknown()`、`z.any()` 的键要写 `.optional()`（助手工具的参数结构除外）。
- 接住的出错要写成文字用 `shared/core` 的 `errorMessage(e)`。
- **类型检查：** `tsconfig.json` 开着 `noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`、`noImplicitOverride`；`scripts/` 的 `.ts`、`.mts` 也查。新增运行时要用的脚本或目录，加进 `scripts/release-files.mjs`。

## 防两套和文档的检查

每个会写库的地址和助手写入命令是一条业务动作，登记在 `shared/assistant/ui-actions.ts`、`ui-actions-system.ts`，每条挂在 `ui-capabilities.ts` 的一项能力上（能力表管功能、页面、工具，动作表管写地址；登记哪些项相关的见技能 `.claude/skills/add-feature/`）。检查从装一遍应用取到的路由（`tests/checks/server-routes.ts`）对照，循环拼的地址也取得到，财务的写地址也都登记了。按钮叫法对不上的清单可 `node --import tsx tests/checks/feature-links-labels.test.ts` 看。

文档的检查：`tests/checks/docs-structure.test.ts`（AGENTS.md 地图和文件一一对应、门类、开头、字数、不写“先读”）、`doc-paths.test.ts`（路径和链接真有）、`doc-section-refs.test.ts`（指到的小节真有）、`docs-generated.test.ts`（生成的是最新、`docs/生成/` 下只放登记的）、`rule-files-length.test.ts`（AGENTS.md、CLAUDE.md 字数）。

## 两边写的清单对得上的检查

都从现有结构和名单取数、真算或真拼，不手抄字段表；现在对不上的登记在测试里，只许减少。

- `tests/finance/finance-source-contract.test.ts`：单据和财务的约定（`shared/business/flow/finance-source.ts`）。① 归类表 `financeFieldClasses` 每一层的栏目和单据结构一个不多一个不少；② 归“说明”的栏目改了，指纹内容不变；③ 四种来源全填的单据，归“算”的栏目改了指纹就变，不算的不变。改栏目名指纹不变由 `tests/finance/finance-fingerprint-rename.test.ts` 守。
- `tests/admin/data-management-template-fields.test.ts`：数据管理新建模板和录入结构 `inputSchemas` 栏目对得上；新建时不给填的在 `notInTemplate` 写原因。
- `tests/documents/document-fields.test.ts`、`tests/documents/document-field-names.test.ts`：单据导出的抬头、信息格、我方资料和条款字段统一登记在 `shared/documents/document-fields.ts`；核对可隐藏清单顺序与字面值、信息格清单、`splitFields` 分区与宽格占列，并用虚构数据真拼送货单、订货单和样张，核对写出的每个字段键都在登记表里且允许用于该单据种类。
- `tests/core/upgrade-step-samples.test.ts`：每个升级步骤带一份数据样例，从第 20 版快照建库、跑这一步、逐表比对。

## 首屏体积上限

`tests/release/first-screen-size.test.ts`（发布检查里，自己构建一遍，多花约 6 秒）：读 Vite 的 manifest，取入口块和顺着静态引用带进来的块（按需加载的、样式不算），gzip 9 级后加总。

- 超过上限失败；比上限小 5% 以上也失败，按报错给的数调低上限。上限只许调低，另查上限不超过实测加 3%。日期、实测数、上限只写在测试的 `FIRST_SCREEN_LIMIT`。
- 点了才用的窗口和财务段列在 `NOT_IN_FIRST_SCREEN`：按 hidden source map 查块的源文件，名单里的进了首屏就失败，哪块都找不到（改了名）也失败。

## 两个外壳的检查

不在 `npm run check` 里（要另装 JDK、安卓 SDK、Rust）。本机 `npm run check:apps`（`scripts/check-apps.mjs`，全部离线；只跑一个加 `-- android` 或 `-- desktop`；工具链在 `%LOCALAPPDATA%\YongleToolchains\`，缺什么就报、不跑）：

- 安卓：`gradlew --offline check`，即 Lint、javac 告警、Checkstyle、运行时依赖为空、单元测试。
- Windows：`cargo fmt --check` → `cargo clippy --all-targets -D warnings` → `cargo test` → 边界检查。

外壳检查只在开发机上跑；端到端和真机测试另外手动做。

## 几组手动跑的比对和验证脚本

不在 `npm run check` 里。

- **变异测试**（`npm run mutation`，配置 `stryker.config.mjs`）：每个版本发布前在金额、单位、库存、凭证上跑一次。
- **样式比对**（`scripts/ui-check/style-compare.mjs`）：改样式前 `node scripts/ui-check/style-compare.mjs baseline` 存基线（默认跑两遍，两遍间会变的记成抖动；`--once` 只跑一遍），改完 `compare`：逐元素比计算后的样式和位置大小、逐像素比截图，结果写进目录里的“对比结果.md”，有差异退出码 1；同时列出从没命中的样式规则。`diff` 只把已有结果重比，`--list` 列状态；选项 `--dir`、`--modes desktop-light,mobile-dark`、`--only 正则`、`--port`（默认 3195）。它构建到临时目录、起虚构数据的隔离实例；前后两次要同一天、同一份组件代码。
- **识别前后对比**（`scripts/ui-check/real-recognition.mjs`）：走识别导入的接口，每份跑几遍，按栏比读对没有、“拿不准”准不准、空着的是不是原件真没写，另记请求次数、token、秒数。`--start --port 3196 --label 改后 --yes` 起真实模型实例跑（花钱，先问用户），`--compare 改前目录 改后目录` 按现在的答案重新打分。
- **Linux 验证**（`scripts/linux/`，在 Linux 上用虚构数据跑，步骤相关的见 `docs/运维/打包和客户端更新.md`）：`verify-runtime.mjs` 原生依赖和几种纸张的排版冒烟；`verify-layout.mjs` 在 Windows 生成排版基准、Linux 逐格比接受、缩字、拒绝的边界；`verify-package.mjs` 在解压的发布包里用包带的 Node 跑，核对包标记、起隔离服务、建管理员、导出单据核哈希和行数、备份 → 停止 → 恢复 → 重置密码。
