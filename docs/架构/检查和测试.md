# 检查和测试

测试怎么跑、怎么写、准备代码，各项检查管什么、怎么实现。硬要求在 `AGENTS.md`“验证”；入口见[架构说明](../架构说明.md)。

全部体检 `npm run check`（`scripts/check.mjs`）：类型检查 → 代码检查 → 函数只许变小 → 样式写死的值 → 没人用的代码 → 重复代码 → 完整测试 → 覆盖 → 发布检查 → 构建到临时目录。

## 测试怎么跑

- **分组并行：** `npm test` 由 `scripts/run-tests.mjs` 分组跑（默认按 CPU 数、最多 8 组，`TEST_JOBS` 可改），按上次记下的每份文件用时装箱，所以同一份文件不一定每次在同一组。同组共用进程，改了 `process.env`、`cwd`、模块级缓存要自己恢复；怀疑互相影响用 `npm run test:isolated` 对照。测试进程的 `LOCALAPPDATA`、`ERP_CONFIG_DIR`、`XDG_CONFIG_HOME`、`DB_PATH`、`ERP_BACKUP_DIR` 都指向新建的临时目录，忘了传路径打开的也是临时空库。
- **慢测试：** 并行时单条超过 1 秒的，把所在文件单独重跑计时（`scripts/test-slow.mjs`：串行、一轮最多 6 份、最慢的先判），单独跑还超过 1 秒才算慢、拦下。1 秒按开发机定，持续集成那边只报不拦。
- **覆盖：** `npm run test:coverage` 按文件报 `server/`、`shared/` 的行覆盖，低于 80% 的拦下。
- **例外登记：** 快不了、测不到的登记在 `scripts/test-exemptions.mjs` 写原因。过期就失败：登记的文件没了、慢测试登记的那条找不到了、低覆盖的已达标；慢测试单独跑已经不慢只提示，几次都不慢再删。
- **套件：** `tests/release/` 发布检查（含要起构建、打包进程的，`npm run test:release`），`tests/serial/` 串行组（启动器验收），`tests/fixtures/` 只放数据（结构快照、配置库基线快照、公开格式样例、升级样例），其余都是主套件。运行器只认 `.test.ts`、`.test.mjs`。
- **持续集成和界面流程：** `.github/workflows/check.yml` 推送时在 Linux、Windows 各跑 `npm run check`，推到主分支或 `ci-` 开头的分支时再跑界面流程。本机界面流程 `npm run test:ui`，各组的流程登记在 `scripts/ui-check/run.mjs`。
- **模块的入口：** 测试引采购库存只许经 `server/operations/index.ts`，引单据流转只许经 `server/flow/index.ts`；要测内部件的在 `tests/module-test-entries.test.ts` 的 `moduleTests` 登记原因。单据视图按种类收窄用 `tests/read-result.ts` 的 `viewAs`。单独测某模块要先加载负责登记的模块（如测删订单先 `import '../server/import/index.js'`）。

## 测试怎么写

新写和改到的测试都照这几条：

- **简洁、精准：** 一条测试守一件事，名字写“什么情况下应该怎样”。断言结果，不断言写法：不扫源码找字，不拿抄下来的旧实现做对照，不写必然成立的断言。
- **全覆盖的口径：** 每条业务规则和助手的六条界限都有测试守着；每个写入口的权限、版本校验、防重复、审计都有；每修一个错先补一条现在会失败的。不为凑覆盖数字去测界面和装配。
- **在最低的一层测，一件事只在一处测：** 规则和计算测纯函数；服务用 `:memory:` 库；只有权限、登录、页面凭证、状态码这类请求才有的东西才起整套服务。
- **不靠真实时间：** 不真等重试、超时、心跳；时钟和等待从参数传进来，或用 `node:test` 的假计时器；性能类的数查询次数、看查询计划，不比毫秒。
- **互不影响：** 不共用进程里的状态；所有测试放一个进程、换任何顺序都要过。
- **按守的事放和起名：** 文件名写守什么，不按哪一轮起名；不超过 500 行；搭环境用下面的准备代码。
- **碰不到真实数据：** 只用 `:memory:` 或临时目录、虚构数据；不调真实模型接口（真实接口套件要先问用户）。
- **为了能测而动产品代码，** 只许把要用的东西（时钟、等待、发请求的函数）从参数传进来，不加只给测试用的开关。

## 代码检查

- **`npm run lint`**（`eslint.config.js`，约 35 秒，带类型信息所以不带缓存）：查任意类型、强行断言、非空断言、没等待的异步、`switch` 列全、空的和什么都不做的 `catch`、hook 依赖、废弃写法、危险正则、函数长度和复杂度（上限在 `AGENTS.md`“验证”）。测试目录一样查（只有 `no-floating-promises` 放过 `node:test` 的 `test`）。源码里写 `eslint-disable` 不起作用；`eslint-suppressions.json` 已清空、不许再登记。
- **`npm run lint:ratchet`**（`scripts/complexity-ratchet.mjs`）不带豁免再量函数，和基线 `scripts/complexity-baseline.json`（现在是空的）比，超线的新函数和变大的都拦。
- **项目自己补的三条**（`scripts/eslint-local-rules.mjs`）：
  - 写死的数字：只查 `server/`、`shared/`；0、1、2、100、1000、-1、数组下标、默认值放过，HTTP 状态码按位置放过（`res.status(409)`）。
  - 直接读库 `local/no-direct-db-read`：拦 `prepare(…).get/all/iterate`（先存变量再读也拦；`.run()` 不管），读库只走 `server/core/sql.ts`。
  - SQL 里写死的单据状态、种类 `local/no-flow-literals`，见[服务端通用做法](服务端写法.md)“单据状态、种类的写法”。
- **按位置限制的引用：** 前端发请求的函数（`call`、`request`、`throwIfFailed`、`authorizedRequest`、`tokenRequest`、`retryWhenBusy`）只许在 `*-api.ts` 和 `src/ui` 里引。不校验回答类型的 `trustedReply` 只许 `src/ui` 用；`responseData`、`readEventStream` 另许 `settings-api.ts`、`workspace-api.ts`、`useAssistantChat.ts`。
- **zod：** `z.custom()` 必须带校验函数；对象里值为 `z.unknown()`、`z.any()` 的键要写 `.optional()`（助手工具的参数结构除外）。
- 接住的出错要写成文字用 `shared/core` 的 `errorMessage(e)`。
- **类型检查：** `tsconfig.json` 开着 `noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`、`noImplicitOverride`；`scripts/` 的 `.ts`、`.mts` 也查。新增运行时要用的脚本或目录，加进 `scripts/release-files.mjs`。

## 首屏体积上限

`tests/release/first-screen-size.test.ts`（发布检查里，自己构建一遍，多花约 6 秒）：读 Vite 的 manifest，取入口块和顺着静态引用带进来的块（按需加载的、样式不算），gzip 9 级后加总。

- 超过上限失败；比上限小 5% 以上也失败，按报错给的数调低上限。上限只许调低，另查上限不超过实测加 3%。日期、实测数、上限只写在测试的 `FIRST_SCREEN_LIMIT`。
- 点了才用的窗口和财务段列在 `NOT_IN_FIRST_SCREEN`：按 hidden source map 查块的源文件，名单里的进了首屏就失败，哪块都找不到（改了名）也失败。

## 几组手动跑的比对和验证脚本

不在 `npm run check` 里。

- **样式比对**（`scripts/ui-check/style-compare.mjs`）：改样式前 `node scripts/ui-check/style-compare.mjs baseline` 存基线（默认跑两遍，两遍间会变的记成抖动；`--once` 只跑一遍），改完 `compare`：逐元素比计算后的样式和位置大小、逐像素比截图，结果写进目录里的“对比结果.md”，有差异退出码 1；同时列出从没命中的样式规则。`diff` 只把已有结果重比，`--list` 列状态；选项 `--dir`、`--modes desktop-light,mobile-dark`、`--only 正则`、`--port`（默认 3195）。它构建到临时目录、起虚构数据的隔离实例；前后两次要同一天、同一份组件代码。
- **识别前后对比**（`scripts/ui-check/real-recognition.mjs`）：走识别导入的接口，每份跑几遍，按栏比读对没有、“拿不准”准不准、空着的是不是原件真没写，另记请求次数、token、秒数。`--start --port 3196 --label 改后 --yes` 起真实模型实例跑（花钱，先问用户），`--compare 改前目录 改后目录` 按现在的答案重新打分。
- **Linux 验证**（`scripts/linux/`，在 Linux 上用虚构数据跑，步骤见[部署与运维](../部署与运维.md)“打包和 Linux 验证”）：`verify-runtime.mjs` 原生依赖和几种纸张的排版冒烟；`verify-layout.mjs` 在 Windows 生成排版基准、Linux 逐格比接受、缩字、拒绝的边界；`verify-package.mjs` 在解压的发布包里用包带的 Node 跑，核对包标记、起隔离服务、建管理员、导出单据核哈希和行数、备份 → 停止 → 恢复 → 重置密码。
