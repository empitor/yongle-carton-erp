# 检查和测试

各项检查和测试怎么实现、怎么跑。规矩（检查不过改代码不改检查、测试怎么写、有哪些检查守什么）在 `AGENTS.md`“验证”，这里不重复；入口见[架构说明](../架构说明.md)。

全部体检 `npm run check`（`scripts/check.mjs`）：类型检查 → 代码检查 → 函数只许变小 → 样式写死的值 → 没人用的代码 → 重复代码 → 完整测试 → 覆盖 → 发布检查 → 构建。

## 测试怎么跑

- **分组并行：** `npm test` 由 `scripts/run-tests.mjs` 分组跑（默认按 CPU 数、最多 8 组，`TEST_JOBS` 可改），按上次记下的每份文件用时装箱（`node_modules/.cache/erp-tests/timings.json`，跑完更新，所以同一份文件不一定每次在同一组）。同组共用进程；怀疑互相影响用 `npm run test:isolated` 对照。测试进程的 `LOCALAPPDATA`、`ERP_CONFIG_DIR`、`XDG_CONFIG_HOME`、`DB_PATH`、`ERP_BACKUP_DIR` 都指向新建的临时目录，忘了传路径打开的也是临时空库。
- **慢测试：** 并行时单条超过 1 秒的，把所在文件单独重跑计时（`scripts/test-slow.mjs`：串行、一轮最多 6 份、最慢的先判，没轮到的在结尾提示），单独跑还超过 1 秒才算慢、拦下。1 秒按开发机定，持续集成的机器慢好几倍，那边只报不拦。
- **覆盖：** `npm run test:coverage` 按文件报 `server/`、`shared/` 的行覆盖，低于 80% 的拦下。
- **例外登记：** 快不了、测不到的登记在 `scripts/test-exemptions.mjs` 写原因。过期就失败：登记的文件没了（`tests/test-exemptions-current.test.mjs`）、慢测试登记的那条找不到了（`npm test`）、低覆盖的已达标（`npm run test:coverage`）；慢测试单独跑已经不慢只提示，几次都不慢再删。
- **套件：** 测试连子目录一起找：`tests/release/` 发布检查（含要起构建、打包进程的，`npm run test:release`），`tests/serial/` 串行组（启动器验收），`tests/fixtures/` 只放数据（结构快照 `schema-v20.sql`、配置库基线快照 `config-db/`、公开格式样例、升级样例 `upgrade-samples/`），其余都是主套件（`scripts/run-tests.mjs` 的 `suites`，`scripts/test-related.mjs` 用同一份）。`tests/test-suites.test.mjs` 查每个像测试的文件恰好属于一个套件；运行器只认 `.test.ts`、`.test.mjs`。
- **持续集成和界面流程：** `.github/workflows/check.yml` 推送时在 Linux、Windows 各跑 `npm run check`，推到主分支或 `ci-` 开头的分支时再跑界面流程。本机界面流程 `npm run test:ui`，各组的流程登记在 `scripts/ui-check/run.mjs`，`tests/ui-check-groups.test.mjs` 查每个流程脚本恰好在一组、组表写的都存在。
- **模块的入口：** 测试引采购库存只许经 `server/operations/index.ts`，引单据流转只许经 `server/flow/index.ts`；要测内部件的登记在 `tests/module-test-entries.test.ts` 的 `moduleTests` 写原因。单据视图按种类收窄用 `tests/read-result.ts` 的 `viewAs`。单独测某模块要先加载负责登记的模块（如测删订单先 `import '../server/import/index.js'`），正式启动时全部加载。

## 代码检查

- **`npm run lint`**（`eslint server shared src scripts tests`，约 35 秒）：查什么见 `AGENTS.md`“检查是防火墙”的“写法”，另有抓真错的几条和危险正则；规则在 `eslint.config.js`。带类型信息所以不带缓存；测试目录一样查（只有 `no-floating-promises` 放过 `node:test` 的 `test`）。源码里写 `eslint-disable` 不起作用（`noInlineConfig`）。
- **`npm run lint:ratchet`**（`scripts/complexity-ratchet.mjs`）不带豁免再量函数的行数、嵌套、参数、复杂度，和基线 `scripts/complexity-baseline.json`（现在是空的）比，超线的新函数和变大的都拦。
- **项目自己补的三条**（`scripts/eslint-local-rules.mjs`，在现成规则上加按位置、按类型的判断）：
  - 写死的数字：只查 `server/`、`shared/`；0、1、2、100、1000、-1、数组下标、默认值放过，HTTP 状态码按位置放过（`res.status(409)`、`new AppError(…, 404)`）。
  - 直接读库 `local/no-direct-db-read`：拦 `prepare(…).get/all/iterate`（按类型认语句对象，先存变量再读也拦；`.run()` 不管）。
  - SQL 里写死的单据状态、种类 `local/no-flow-literals`，见[服务端通用做法](服务端写法.md)“单据状态、种类的写法”。
- **按位置限制的引用**（`no-restricted-imports`）：前端发请求的函数指 `call`、`request`、`throwIfFailed`、`authorizedRequest`、`tokenRequest`、`retryWhenBusy`；`responseData`、`readEventStream` 在 `src/ui` 以外只许 `settings-api.ts`、`workspace-api.ts`、`useAssistantChat.ts` 用；直接验证这些函数的三份测试另有定向例外。
- 接住的出错要写成文字用 `shared/core` 的 `errorMessage(e)`。
- **类型检查：** `tsconfig.json` 开着 `noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`、`noImplicitOverride`；`scripts/` 的 `.ts`、`.mts` 也查（`allowImportingTsExtensions`，脚本由 tsx 运行）。新增运行时要用的脚本或目录，加进 `scripts/release-files.mjs`。

## 防两套和文档的检查

每个会写库的地址和助手写入命令是一条业务动作，登记在 `shared/assistant/ui-actions.ts`（账号、助手、设置、数据管理在 `ui-actions-system.ts`）：记录、动词、按钮叫法、写地址、预览地址、服务函数、助手命令，每条挂在 `ui-capabilities.ts` 的一项能力上（能力表管功能、页面、工具，动作表管写地址）。路由是装一遍应用在运行时取的（`tests/server-routes.ts`），循环拼的地址也取得到；财务的写地址也都登记了。

| 测试 | 查什么 |
|---|---|
| `tests/feature-links-actions.test.ts` | 每个写地址正好属于一条动作；同一记录同一动词只一条；会写库的助手命令挂在动作上、调登记的服务 |
| `tests/feature-links-senders.test.ts` | 一个写地址前端只有一个文件发 |
| `tests/feature-links-status.test.ts` | 单据、订单、采购单、采购退货的状态只在登记的文件里改 |
| `tests/feature-links-labels.test.ts` | 带动作词的按钮字是某条动作的叫法（清单在失败输出里，或 `node --import tsx tests/feature-links-labels.test.ts`） |

## 两边写的清单对得上的检查

都从现有结构和名单取数、真算或真拼，不手抄字段表；现在对不上的登记在测试里，只许减少。

- `tests/finance-source-contract.test.ts`：单据和财务的约定（`shared/business/finance-source.ts`）。① 归类表 `financeFieldClasses` 每一层的栏目和单据结构一个不多一个不少（算进指纹的栏目里套着对象的那层也要登记）；② 到货、送货、完工单归“说明”的栏目改了，指纹内容（`financeFingerprint`）不变；③ 四种来源全填的单据，归“算”的栏目改了指纹就变，不算的不变。改栏目名指纹不变由 `tests/finance-fingerprint-rename.test.ts` 守。
- `tests/data-management-template-fields.test.ts`：数据管理新建模板和录入结构（`server/admin/managed-records.ts` 的 `inputSchemas`）栏目对得上；新建时不给填的在 `notInTemplate` 写原因。
- `tests/document-field-names.test.ts`：用虚构数据真拼送货单、订货单，写出的信息格名字排版（`shared/documents/document-layout.ts` 的 `splitFields`、`templateInfoFields`，预览和导出共用）都认得、排了的都有人写；可隐藏清单 `optionalDocumentFields` 每一格都有单据写、勾了隐藏就不再出现。
- `tests/upgrade-step-samples.test.ts`：每个升级步骤带一份升级前后的数据样例，从第 20 版快照建库、跑这一步、逐表比对；写法见 `server/core/schema/steps.ts` 和这条测试开头。

## 首屏体积上限

`tests/release/first-screen-size.test.ts`（发布检查里，自己构建一遍，多花约 6 秒）：读 Vite 的 manifest，取入口块和顺着静态引用带进来的块（按需加载的、样式不算），gzip 9 级后加总。

- 超过上限失败；比上限小 5% 以上也失败，按报错给的数调低上限。上限只许调低：另查上限不超过实测加 3%（实测和上限一起往上改拦不住，靠审查）。日期、实测数、上限只写在测试的 `FIRST_SCREEN_LIMIT`。
- 点了才用的窗口和财务段列在 `NOT_IN_FIRST_SCREEN`：同一次构建写出 hidden source map，按块的源文件查，名单里的文件进了首屏块就失败，哪块都找不到（改了名）也失败。

## 两个外壳的检查

不在 `npm run check` 里（要另装 JDK、安卓 SDK、Rust）。本机 `npm run check:apps`（`scripts/check-apps.mjs`，全部离线；只跑一个加 `-- android` 或 `-- desktop`；工具链在 `%LOCALAPPDATA%\YongleToolchains\`，找不到就报缺什么、不跑）：

- 安卓：`gradlew --offline check`，即 Lint、javac 告警、Checkstyle、运行时依赖为空、单元测试。
- Windows：`cargo fmt --check` → `cargo clippy --all-targets -D warnings` → `cargo test` → 边界检查。

持续集成是单独的 `.github/workflows/apps.yml`，只在 `apps/` 或它自己改了时跑（安卓在 Linux，Windows 外壳在 Windows）；端到端和真机测试不进持续集成。

## 几组手动跑的比对和验证脚本

不在 `npm run check` 里。

- **样式比对**（`scripts/ui-check/style-compare.mjs`；场景清单 `style-scenes.mjs`，取样式 `style-page.mjs`，比较 `style-diff.mjs`）：改样式前 `node scripts/ui-check/style-compare.mjs baseline` 存基线（默认跑两遍，两遍间会变的记成抖动；`--once` 只跑一遍），改完 `compare`：逐元素比计算后的样式和位置大小、逐像素比截图，结果写进目录里的“对比结果.md”，有差异退出码 1；同时列出从没命中的样式规则（对回 `src/` 的文件和行号）。`diff` 只把已有结果重比，`--list` 列状态；选项 `--dir`、`--modes desktop-light,mobile-dark`、`--only 正则`、`--port`（默认 3195）。自己构建到临时目录、起虚构数据的隔离实例（和 `npm run test:ui` 同一套 `scripts/ui-check/server.mts`）；前后两次要同一天、同一份组件代码。
- **识别前后对比**（`scripts/ui-check/real-recognition.mjs`；虚构文件和标准答案 `real-recognition-cases.mjs`，打分 `real-recognition-score.mjs`）：走识别导入的接口（上传 → 识别 → 读结果），每份跑几遍，按栏比读对没有、“拿不准”准不准、空着的是不是原件真没写，另记请求次数、token、秒数。`--start --port 3196 --label 改后 --yes` 起真实模型实例跑（花钱，先问用户），`--compare 改前目录 改后目录` 按现在的答案重新打分。
- **Linux 验证**（`scripts/linux/`，在 Linux 上用虚构数据跑，步骤见[部署与运维](../部署与运维.md)“打包和 Linux 验证”）：`verify-runtime.mjs` 原生依赖和几种纸张的排版冒烟；`verify-layout.mjs` 在 Windows 生成排版基准、Linux 逐格比接受、缩字、拒绝的边界（`node --import tsx scripts/linux/verify-layout.mjs 输出.json [Windows基准.json]`）；`verify-package.mjs` 在解压的发布包里用包带的 Node 跑（`--import tsx`），核对包标记、起隔离服务、建管理员、导出各种单据核哈希和行数、备份 → 停止 → 恢复 → 重置密码。
