# 数据库约定

什么时候读：加表、字段、配置库，或写读写业务库的代码之前读。

- **当前结构**以 `server/core/schema/tables/*.ts` 为准（按表的主人分文件），版本是 `server/core/schema/version.ts` 的 `SCHEMA_LATEST`。业务库默认 `data/erp.sqlite`（`DB_PATH` 可改），它所在的目录叫“数据目录”。
- 每张表的列和约束见 `docs/生成/表结构.md`；打开和升级相关的见 `docs/架构/数据库升级.md`。

## 约定

- **全部 STRICT：** 列类型只有 INTEGER、REAL、TEXT、BLOB。业务日期 `YYYY-MM-DD` 且真有这天，会计期间 `YYYY-MM`；可空的只能是 NULL 或合法值，不能是空串；JSON 列要合法，单据这类要求是对象或数组；文件摘要是 64 位小写十六进制。写法用 `server/core/schema/tables/checks.ts` 的片段。
- **枚举：** 状态、种类加枚举 CHECK，所属模块有同一份常量，`tests/checks/schema-constraints.test.ts` 比对。不列枚举的：会随功能增加的（审计的动作和对象、记录种类、防重复的种类、助手审计的工具名）和用户填的文字。故意不加的约束写在建表注释里。
- **版本号：** 可编辑的记录带 `version`（`>=1`），写入时校验。
- **大字段放最后，插入写列名，外键子列有索引：** `tests/core/schema-layout.test.ts` 查。
- **可以不填的文字：** 没给过存 NULL，给了空白存空串；按“没填”查两种都算。
- **金额、单价：** `*_cents` 是分，单价存万分之一元整数 `*_e4`，“分”是算出来的列、写不进去；没定价存 NULL，和 0 元分开；订单精确合计读时现算；采购明细、到货明细的单价在 JSON 里按填的原文存。
- **数量：** 一律存千分整数（1 只或 1 张 = 1000），换算只用 `shared/core/quantity.ts`；“个”、pcs、空都算“只”，原材料空算“张”（`shared/core/units.ts`）。库里写死单位的：库存品、订单明细、生产任务、月末存货成本；采购明细、到货明细的单位由保存服务保证。
- **编号和单号：** 被引用、会被删的表用自增编号，删了不复用，初始化后也不从头来。单号里的序号就是编号（写事务里 `nextAutoId` 取到的，相关的见 `docs/架构/数据库升级.md`）：

| 单据 | 单号 |
|---|---|
| 订单 | `ZX-下单日期-编号`（至少四位） |
| 采购单 | `CG-下单日期-编号`（至少四位） |
| 到货、生产任务、完工、送货单 | `DH`、`SC`、`DJ`、`SH` 加 `-日期-编号`（至少五位，四种共用一个序列） |
| 采购退货 | `TH-退货日期-编号`（至少四位） |
| 订货单 | 一张采购单时就是采购单号；合并的是 `DG-日期-两位序号`（按天从 1 起） |

## 派生关系

- **库存余额、成品批次：** 不存表，按流水算（批次在 `shared/business/flow/stock-batches.ts`）。
- **采购已到货：** `purchase_lines.received_units` 按有效到货单的入库数减没冲销的退货重算（`server/flow/rules/receipt-events.ts`）；基本视图读它，完整视图按到货单现算（相关的见 `docs/功能/单据流转.md`）。
- **订单进度：** 生产中、待发货、已发货由有效单据重算（`server/flow/rules/order-progress.ts`）；“部分发货”不存。
- **财务：** 往来、凭证由财务事件生成，业务单据改了按来源指纹判断（相关的见 `docs/功能/财务取数和补扫.md`）。

## 表归哪个模块

主人以 `tests/checks/module-table-owners.test.ts` 的 `tableOwnerList` 为准：`fin_` 归财务、`flow_` 归单据流转、`assistant_` 归助手，其余逐张登记。主人才能写、财务只读 `fin_` 和审计，见 `docs/架构/模块规则.md`“表只由主人写”。那里没写的细节：

- **只许一个文件写**（外加删除引擎登记的 `deletion.ts`，`singleWriterTables`）：`purchase_lines` 只由 `server/operations/ledger/ledger.ts` 写，`flow_documents` 只由 `server/flow/documents/document-store.ts` 写，`flow_sources` 只由 `server/flow/documents/sources.ts` 写。
- **只读窗口** `server/flow/finance-facts/` 里一句写的 SQL 都不许有（相关的见 `docs/功能/财务取数和补扫.md`）。
- **助手**的 SQL 只读自己的表（`assistant_` 开头和助手设置库）。
- **删除引擎**按外键找连带行时按表名只读各表。
- **外键：** 跨模块的级联只有 `import_executions.order_id → orders ON DELETE SET NULL`；别的连带处理由删除规则做（相关的见 `docs/功能/删除和初始化.md`）。
- **初始化后保留的表**以 `tests/admin/business-reset.test.ts` 的 `kept` 为准：版本记录、审计、墓碑、按天的流水号、单据模板设置、助手的全部表、财务设置和变更历史（只清启用月份）、科目（只清“用过”标记）、凭证模板。
