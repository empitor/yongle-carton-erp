# 财务事件和凭证

财务怎么拿业务数据、补扫、来源指纹、记账、成本和结账（`server/finance/`）。“财务不卡业务”“已记账凭证只能红字冲销”的规矩在 `AGENTS.md`“业务规则”，财务的表见[数据模型](../数据模型.md)，怎么用见[使用手册](../使用手册.md)“财务”。

## 财务从哪拿业务数据

财务不调用业务代码，只引单据流转导出的一个只读对象 `financeFacts`（`server/flow/finance-facts/`，`facts.ts` 组装，一组一个文件）。`server/finance/` 的 SQL 只读自己的 `fin_` 表和 `business_audit`，业务的表（连 `customers`、`orders`、`record_lifecycle`）一律不读（`tests/module-table-owners.test.ts` 的 `financeReadable`），所以业务改表、改栏目时财务不用动。

| 组 | 函数 |
|---|---|
| 往来单位 `parties` | `names(db, 种类, 编号们)` 一批编号一次查完单位名；`options(db, 种类)` 选单位的名单（不含已归档，新建的在前） |
| 来源 `sources` | `heads(db)`：已确认、已撤销的送货、到货、完工单加盘点流水的种类、编号、版本、状态、日期（不读内容）；`texts(db, 种类和编号们)` 按批读原文和单号（盘点流水的单号拼成“库存品名 规格 调整量 单位”）；`read(原文)` 不碰库，解析成财务口径（`toFinanceSource`）和算进指纹的内容（`financeFingerprint`），读不出来抛 `StoredDataError`；`arrivalReversalDates(db, 到货单们)` 撤销（更正）那天（自己的、被它替代的原单的冲回流水日期） |
| 订单 `orders` | `between(db, 起, 止)` 按下单日期，待确认、已取消不算，已归档的算（月度台账的“接单”） |
| 采购 `purchases` | `lines(db, 明细编号们)` 一次查完采购明细（采购单号、解析好的 `item`、按单价和计价方式算好的金额文字 `amount`，开票对比用）；`hasConfirmedReturn(db, 到货单)` 到票时用；退货单分两步：`returnsOfArrivals(db, 到货单们)`、`returnRows(db, 编号们)` 交表头加原文，`returnLines(一行)` 是把原文按严格结构解析成退了哪几行的纯函数（读不出来抛 `StoredDataError`，补扫时用 `readOrSkip` 逐张跳过） |
| 库存 `stock`（成本、毛利用） | 流水（日期段、某日以前、某次成本计算以后或以前登记的）、库存品结存和启用月期初、要人填金额的流水、冲销对应的原流水和原完工入库（一批一次查完）、撤销冲回过的到货、已撤销的到货单、盘点流水编号、流水最大行号、成品送货出库量。“记没记过账”是财务的判断：财务把不计成本的到货单编号作为 `exclude` 交给窗口，窗口只按编号去掉它们的入库和冲回 |

**只读怎么守：** 目录里一处写 SQL 都不许有（`tests/module-table-owners.test.ts` 的 `readOnlyPaths`）；不碰 `prepare`、`exec`、`run`、`transaction`，读库只走 `server/core` 的读函数（`eslint.config.js`）；每个函数各跑一遍库的改动数不变、只交出数据，不交出 `Store`、连接、服务对象（`tests/finance-facts-parties.test.ts`，加组、加函数不写调用就编译不过）。各组口径测试在 `tests/finance-facts-<组>.test.ts`。财务引单据流转只许 `financeFacts` 和它导出的类型名，引共用业务只许约定（`shared/business/finance-source.ts`）、几样算金额和显示用的、按名字引用的流水来源编码 `movementSource`（编码只写在 `shared/business/movement-filters.ts`）（`tests/module-narrow-refs.test.ts` 的 `narrowRefs`）。

## 补扫

- **是什么：** `server/finance/events.ts` 扫已确认、已撤销的送货、到货、完工单和盘点流水，一张单据一条财务事件（`fin_events`，快照存来源的财务口径），挂往来、生成凭证。业务办的事财务靠补扫才看到。
- **谁扫：** 服务端在读之前扫（`server/finance/catch-up.ts` 的 `catchUp`）：`router.ts` 在每个 `/api/finance` 请求认人、核凭证之后调一次，助手查财务（`assistant.ts` 的 `readFinanceTool`）也调；业务保存不调。每批一个写事务（`FinanceEvents.sync`，最多 100 条来源、100 条被删的），一次最多扫 `CATCH_UP_BATCHES`（2）批，剩下的后面的请求接着扫：`node:sqlite` 是同步的，补扫时整个服务在等，大批历史单据分到几个请求里，批之间业务请求能进来。
- **要补哪些：** `server/finance/source-scan.ts` 的 `scanSources` 在程序里对照一次 `sources.heads` 和一次财务的观察记录 `fin_source_observations`：挑出这一版没看过的（没有记录，或版本、状态不同）和看不到了的（被删了，启用前的不管），最多 100 条再用一次 `sources.texts` 读原文；语句条数不随单据多少变，没要补的不读内容（`tests/finance-read-counts-sources.test.ts`）。先只读看有没有要补的（`pending`），没有就不开写事务；财务没启用什么都不做。`pending` 包括：没扫到的来源、被删还没记的、要自动收尾的已撤销送货（`event-status.ts` 的 `deliveryReversalsPending`，和收尾 `refreshPendingDeliveryReversals` 同一段条件）、这个人这次真能记的采购退货暂估（`return-estimates.ts` 的 `ReturnEstimates`：只看还挂着暂估应付的到货的退货，按到货单向窗口圈；一次补扫只读一次，判断和记账都按 `planReturn`；只能看财务的人一张都不看）。
- **能写什么：** 系统按固定规则同步，审计记发起这次读取的人（`financeActor`，要财务查看权限）；只建事件、挂暂估往来、记“来源已删除”、已撤销送货自动收尾；采购退货暂估要财务编辑权限才记。只能看财务的账号不会因此做到别的写入。
- **读不出来的跳过：** 内容读不出来的单据、盘点流水、采购退货单逐条跳过（`server/finance/unreadable.ts` 的 `readOrSkip`：只认读这条内容时抛的 `StoredDataError`，之后的步骤出错照常抛）。跳过的按“种类:编号”加原文 sha256 记在进程里（每个库一份），内容没变不重读；第一次跳过记进出错记录（必传：`createApp` 的 `problems`，助手用 `ToolServices` 里同一个）；库里改好（版本号没变也算）下次就补上。它没有观察记录，一直算没同步：结账、正式报表照样拦，说法写明单号（`reports.ts` 的 `readiness` 带 `unsyncedSources`，来自 `catch-up.ts` 的 `unseenSourceList`）；月度台账、报表检查列“还没同步的单据”时也跳过它（`readSourceOrSkip`）。
- **补扫出错：** 别的错（程序或财务自己的数据有问题）整批回滚、记进出错记录（同一原因只记一次），读请求照常回答已进财务的数；`readiness.syncFailed` 为真，结账、正式报表照拦。要按来源单据状态核对的写入回 503（`server/finance/sync-health.ts` 的 `assertSourcesCaughtUp`，调它的就是名单，共 8 种：收付款核销、发票关联和确认、事件补资料、批量补税率、生成凭证、红字冲销并重做、核对无误）；登记收付款、不核销的确认收付款、收开票据时自动冲往来（算收付款，用户定的；挑往来照样按 `sourceIs` 排除已撤销的送货）、登记发票、改往来条款、预算照常。下次补扫成功就放开。
- **来源状态只看一处：** 财务看来源已撤销还是有效只走 `source-scan.ts` 的 `sourceIs`（SQL 条件，参数是 `lapsedStatuses` 的结果）。看的是观察记录（被更正替代的原单状态也是已撤销，建表 CHECK 保证），还没补扫进来、现在已撤销或已删的按窗口现在的状态补上，所以没扫完、坏单据被跳过时也拦得住撤销过的单据（`tests/finance-unsynced-reversal.test.ts`）。用在收付款核销、票据冲往来、发票关联和开票对比、结账检查、正式报表检查、月度台账、事件列表的“会不会重做”。单号读事件的 `source_number` 列（结账检查“启用前单据有变化”的单号向窗口读，启用前的快照是空的）。一次对照的结果按库的记号（本连接改过几行、别的连接提交过没有）记在进程里：事务外、库没写过就直接用，事务里一律现算；一次请求里补扫判断、月度台账、报表检查共用一次。
- **页面：** 前端不另发补扫，没有补扫地址。概览、月度台账、业务单据页、结账页、报表页签读 `readiness`（`src/finance/reports/unsynced.tsx`）：补扫没成功、还剩没进财务的单据时写一句；剩的不是 0 就再读，数在变少说“正在记进财务，还剩 N 张”接着读，数不动了列出单号（读不出来、跳过的）；这一轮进了新单据最后让财务页面都重读。
- **结账和正式报表：** 结账检查的“业务单据”一步数截至月底还没同步的来源（`events.ts` 的 `unseenSources`，和补扫同一条件：新确认的、内容变了的、已撤销或被替代的、盘点流水改写的、已删除没记的），加上已是事件、还没处理完的；没补扫不能结账。正式报表的资料检查（`reports.ts` 的 `readiness`）用同一口径。结账检查的“资产负债表平衡”一步只在没有卡着的事件和缺资料的单据时按现在的账算（`currentBalance`），只差同步时由“业务单据”拦；它的“去处理”打开业务单据页的“全部”（`#finance-ledger?tab=events&status=all`）。

## 单据和财务的约定

- **约定归业务管：** `shared/business/finance-source.ts`。财务口径 `financeSourceSchemas`（四种来源里财务点名读的几项，结构从 `shared/business/flow-document.ts` 取），转换 `toFinanceSource`；单据每一层（表头、明细、到货明细的纸板资料、完工领料）每个栏目的归类 `financeFieldClasses`（算 / 说明 / 不算；映射类型，业务多一个栏目、改了名都编译不过）；说明编辑能改的 `documentInfoFields` 就是表头归“说明”的那些。
- **来源指纹：** 只取归“算”的栏目，按改名表 `fingerprintRules`（键是业务栏目名、值是财务口径名，键必须正好是归“算”的那些；往下一层的栏目——一组明细、纸板资料、领料——写在 `nested`，键必须正好是这层归“算”且值是对象或对象数组的栏目；多了少了都编译不过，层的位置只写在这里）换成财务口径的名字、键排序（`financeFingerprint`，窗口的 `sources.read` 交出），`server/finance/source-fingerprint.ts` 的 `sourceHash` 只取 sha256。所以只改备注、送达这类，或送货明细的材质、楞型（不算）时不产生新事件。业务改栏目名只改改名表的键，库里已有的指纹不变；算法、算进去的栏目、财务口径名一变，已有指纹就全对不上——`tests/source-fingerprint-pinned.test.ts` 用几张固定的虚构单据（`tests/finance-source-fixture.ts`）走正式读法守着写死的 sha256。
- **来源变了：** 没入过账的直接记“已更正”；入过账的记“有差异”，由人“红字冲销并重做”；同一来源的新事件接手旧事件（`superseded`）。
- **来源被删：** 删业务记录不通知财务、不写财务的表；下次补扫发现来源没了，只走 `server/finance/event-status.ts` 的 `markSourceDeleted` 分流（审计记补扫的人）：观察记录标 `deleted`；已更正、已替代、已算成本、无金额的不动；盘点、完工直接“已更正”；送货、到货名下没有要人处理的往来就作废系统挂的暂估往来、记“已更正”，有的才记“来源已删除”（界面叫“单据已删”），由人红字冲销，或名下还有算数的凭证时“核对无误，保留凭证”（`event-handling.ts`；判断在 `event-source-obligations.ts` 的 `hasBookedObligations`，保留的照样计入毛利）。
- **读来源和快照：** 读来源内容只在 `source-scan.ts` 的 `readSource`（窗口 `sources.read` 解析，财务补单号 `withNumber`、按窗口交出的指纹内容算 `sourceHash`）；采购明细由窗口 `purchases.lines` 解析好交出。事件快照的结构和读写在 `source-snapshot.ts`（`readSnapshot`、`snapshotText`）：`doc` 只存财务口径，四种来源合在一起读（快照不记种类），旧结构多出的项读时忽略。快照和从它取出的列（往来单位、单号、理论金额、缺税率）只由 `server/finance/event-columns.ts`（`eventColumns`、`insertEvent`、`updateEventSnapshot`）同一句写，别的 SQL 不许写 `snapshot` 和这几列（`tests/finance-event-columns.test.ts`），查询读列；被接手的上一条、同步时的单据金额只存列里（`previous_event_id`、`previous_status`、`document_cents`）。

## 记账、成本和结账

- **记账日：** 单据日期所在月已结账时，凭证记在最早没结账月份的 1 号（`server/finance/periods.ts` 的 `bookingDate`、`nextOpenPeriod`），摘要注明单据日期；到期日、分期、折扣期限、账龄、压款利息一律从单据日期起算（`obligation-sql.ts` 的 `obligationBaseDate`）；按送货确认收入时，毛利的收入记在凭证所在月（`margin.ts`）。
- **理论金额：** 送货、到货的理论金额只在 `shared/business/document-value.ts` 算（按单据单价、不另加税，到货按入库数量），财务的理论收支和经营概况的“送货金额”“到货金额”都调它；算不出的单据经营概况另报张数。
- **凭证：** 待确认 → 待审核 → 已审核 → 已记账，另有已作废（`server/finance/ledger.ts`，叫法 `shared/finance/labels.ts`）。红字冲销只冲已记账的原凭证，日期不早于原凭证，一张只能有一张有效红冲；票据、资产处置、费用这类功能生成的凭证到来源页面冲。
- **往来和冲销：** 红冲的往来成对看，判断只用 `server/finance/reversal-pairs.ts` 的 `isReversed`；往来余额口径只有 `server/finance/obligation-sql.ts`（排除撤回、红冲的用同文件 `voucherReversed`、`voucherStands`）；红票分摊 `red-invoices.ts`；票据、资产处置、费用、坏账、利息、保证金的派生凭证撤回和红冲在 `derived-vouchers.ts`（登记表）。红字冲销退货、部分到票后另出的余量暂估凭证时，红字凭证记在原到货事件名下（`event_reversal`，`event-correction.ts`），不挂退货单、发票；退货冲了多少只按挂在退货单上的凭证算。
- **退货冲暂估：** 未到票就退货时按暂估单价冲减暂估（`return-estimates.ts`，同步时做，成本计算用同一算法）：窗口给全部退货单的编号和状态，财务按挂在退货单上的凭证一次算出各冲了多少（`returnBooked`），挑出已确认没冲的、已撤销冲过没恢复的，再向窗口要这几张的内容。开票对比（`invoice-matching.ts`）同理：先从事件快照取出到货明细挂的采购明细编号，再一次向窗口要。
- **取值：** 状态、种类的取值在 `stored-values.ts`，和建表 CHECK 由测试比对；收付方式、账期方式前后端共用，在 `shared/finance/finance.ts`；含税口径只在 `shared/core/domain.ts` 的 `orderTaxModes` 定义，财务从它取，旧写法“不含税”单独登记成 `legacyTaxMode`。
- **成本：** 月末加权平均（`costing*.ts`）。冲销流水找原单据只走 `costing-origins.ts` 的 `originsOf`（一批一起找）：
  - 送货、完工冲销按原成本冲回。
  - 撤销或更正到货：在冲回流水那个月按这批还挂着的暂估（原暂估减到票已转走的）红字入库冲回，不另出成本分录，总账由到货的红字冲销凭证记。冲完数量为 0 的库存品只留到过票、等红票冲的那部分（`awaitingRed`，按那个月为止进了库存的到票调差和红票算，见 `costing-invoice-adjust.ts` 的 `adjustedTotals`；以后月份才用掉的不算），其余转主营业务成本。
  - 到货那个月按记过账的那条事件入库（`costing-arrivals.ts` 的 `arrivalEvents`、`bookedArrivalEvent`，退货计价也用后者；已撤销、被替代的按最新记过账的那条）。从没记过账的作废到货，入库和冲回在哪个月都不计（`unbookedVoidArrivals` 算出编号交窗口排除）。“已撤销”只认窗口给的 `reversedArrivals`，`arrivalEvents` 用同一份、不看观察记录，所以算成本不依赖补扫扫完；启用前的到货除外，冲回仍要人选对方科目。
  - 查不到原成本的要人在“计算成本”窗口填金额、选对方科目；没被冲销的无单价到货照旧拦下。
- **结账和报表：** `closing.ts`、`reports.ts`，结账归档 `closing-archive.ts`；只有正式报表和结账因缺资料拦下。反结账重做时删掉的派生结果（成本明细、折旧明细）能重算，不拍快照（删除前快照只管源数据）。已撤销、被替代的到货名下的往来不能再关联、确认发票（`invoice-rules.ts` 的 `assertInvoiceableObligation`），开票对比也不列，撤销那个月的冲回金额才不会再变；撤销、更正过的到货红字冲销的默认日期取撤销（更正）那天（事件列表的 `correction_date`，那个月已结账的按 `bookingDate`）：原单都给，替代单只在更正带出来、还没记过账的那一次给。

## 代码在哪

- **写入、审计、分页：** `financeWrite(store, actor, { action, input, result }, 写入)`（防重复走 `onceByRequest`；不带请求号的补扫只用其中的事务 `financeTransaction`），`financeAudit(store, actor, { action, entity, id, before, after })`，`pageSql(db, { schema, sql, values, order }, 查询)`。
- **路由和接口表：** `shared/finance/finance-api.ts`（回文件和收字节的不进表），凭证和科目的正文规则在 `shared/finance/finance.ts`；`router.ts` 用 `route<FinanceApi>(router, '/finance')`，地址按页面分在 `routes.ts`（设置、凭证账簿、业务单据、概览台账、共用的导出和上传）、`routes-cash.ts`（应收应付、资金发票）、`routes-period.ts`（费用资产工资、报表结账）。
- **选往来单位：** 财务的下拉读自己的 `GET /api/finance/parties`（`parties.ts` 的 `options`，名单来自窗口，不列已归档）；写往来、发票、票据、保证金、收付款时取单位名用 `server/finance/core.ts` 的 `requirePartyName`（找不到报“往来单位不存在。”）。出纳这类纯财务账号也能用，不借业务的 `/customers`、`/suppliers`。
- **助手：** 财务工具全部只读、金额换成元，读之前和页面一样先补扫（`server/finance/assistant.ts`）。
