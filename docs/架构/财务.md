# 财务事件和凭证

财务怎么拿业务数据、补扫、来源指纹、记账、成本和结账（`server/finance/`）。“财务不卡业务”“已记账凭证只能红字冲销”在 `AGENTS.md`“业务规则”；财务的表见[数据模型](../数据模型.md)；怎么用见[使用手册](../使用手册.md)“财务”。

## 财务从哪拿业务数据

财务不调用业务代码，只引单据流转导出的只读对象 `financeFacts`（`server/flow/finance-facts/`，一组一个文件）。财务的 SQL 只读自己的 `fin_` 表和 `business_audit`，业务的表（连 `customers`、`orders`、`record_lifecycle`）一律不读，所以业务改表、改栏目时财务不用动。

| 组 | 交出什么 |
|---|---|
| 往来单位 `parties` | `names` 一批编号一次查完单位名；`options` 选单位的名单（不含已归档，新建的在前） |
| 来源 `sources` | `heads`：已确认、已撤销的送货、到货、完工单加盘点流水的种类、编号、版本、状态、日期（不读内容）；`texts` 按批读原文和单号（盘点流水的单号拼成“库存品名 规格 调整量 单位”）；`read(原文)` 不碰库，解析成财务口径和算进指纹的内容，读不出来抛 `StoredDataError`；`arrivalReversalDates` 撤销（更正）那天 |
| 订单 `orders` | `between` 按下单日期，待确认、已取消不算，已归档的算（月度台账的“接单”） |
| 采购 `purchases` | `lines` 一次查完采购明细（采购单号、解析好的内容、算好的金额文字，开票对比用）；`hasConfirmedReturn` 到票时用；退货单交表头加原文，`returnLines` 是把原文解析成退了哪几行的纯函数 |
| 库存 `stock`（成本、毛利用） | 各种流水、库存品结存和启用月期初、要人填金额的流水、冲销对应的原流水和原完工入库（一批一次查完）、撤销冲回过的到货、已撤销的到货单、盘点流水编号、流水最大行号、成品送货出库量。“记没记过账”是财务的判断：财务把不计成本的到货单编号作为 `exclude` 交给窗口 |

**只读怎么守：** 目录里一处写 SQL 都不许有；不碰 `prepare`、`exec`、`run`、`transaction`，读库只走 `server/core` 的读函数；每个函数跑一遍库的改动数不变、只交出数据，不交出 `Store`、连接、服务对象（`tests/finance-facts-parties.test.ts`，加函数不写调用就编译不过）。财务引单据流转只许 `financeFacts` 和它的类型名，引共用业务只许约定、几样算金额和显示用的、按名字引用的流水来源编码 `movementSource`（`tests/module-narrow-refs.test.ts` 的 `narrowRefs`）。

## 补扫

- **是什么：** `server/finance/events.ts` 扫已确认、已撤销的送货、到货、完工单和盘点流水，一张单据一条财务事件（`fin_events`，快照存来源的财务口径），挂往来、生成凭证。业务办的事财务靠补扫才看到。
- **谁扫：** 服务端在读之前扫（`server/finance/catch-up.ts` 的 `catchUp`）：每个 `/api/finance` 请求认人、核凭证之后调一次，助手查财务也调；业务保存不调。每批一个写事务（最多 100 条来源、100 条被删的），一次最多扫 `CATCH_UP_BATCHES`（2）批，剩下的后面的请求接着扫。因为 `node:sqlite` 是同步的，补扫时整个服务在等，所以大批历史单据分到几个请求里扫。
- **要补哪些：** `server/finance/source-scan.ts` 的 `scanSources` 对照一次 `sources.heads` 和一次观察记录 `fin_source_observations`，挑出这一版没看过的（没有记录，或版本、状态不同）和看不到了的（被删了，启用前的不管），最多 100 条再读原文；语句条数不随单据多少变，没要补的不读内容。先只读看有没有要补的（`pending`），没有就不开写事务；财务没启用什么都不做。`pending` 包括：没扫到的来源、被删还没记的、要自动收尾的已撤销送货、这个人这次真能记的采购退货暂估（只看还挂着暂估应付的到货的退货；只能看财务的人一张都不看）。
- **能写什么：** 系统按固定规则同步，审计记发起这次读取的人（要财务查看权限）；只建事件、挂暂估往来、记“来源已删除”、已撤销送货自动收尾；采购退货暂估要财务编辑权限才记。
- **读不出来的跳过：** 内容读不出来的单据、盘点流水、采购退货单逐条跳过（`server/finance/unreadable.ts` 的 `readOrSkip`，只认读内容时抛的 `StoredDataError`）。跳过的按“种类:编号”加原文 sha256 记在进程里，内容没变不重读；第一次跳过记进出错记录；库里改好（版本号没变也算）下次就补上。它一直算没同步：结账、正式报表照样拦，说法写明单号；月度台账、报表检查列“还没同步的单据”时也跳过它。
- **补扫出错：** 别的错整批回滚、记进出错记录（同一原因只记一次），下次补扫成功就放开。这期间：
  - 照常：读请求（回答已进财务的数）；登记收付款、不核销的确认收付款、收开票据时自动冲往来（算收付款，用户定的）、登记发票、改往来条款、预算。
  - 拦下：结账、正式报表；要按来源状态核对的写入回 503（`server/finance/sync-health.ts` 的 `assertSourcesCaughtUp`，调它的就是名单：收付款核销、发票关联和确认、事件补资料、批量补税率、生成凭证、红字冲销并重做、核对无误）。
- **来源状态只看一处：** 财务看来源已撤销还是有效只走 `source-scan.ts` 的 `sourceIs`。看的是观察记录（被更正替代的原单也是已撤销），还没补扫进来、现在已撤销或已删的按窗口现在的状态补上，所以没扫完、坏单据被跳过时也拦得住撤销过的单据。用在收付款核销、票据冲往来、发票关联和开票对比、结账检查、正式报表检查、月度台账、事件列表的“会不会重做”。一次对照的结果按库的记号记在进程里，事务外、库没写过就直接用；一次请求里补扫判断、月度台账、报表检查共用一次。
- **页面：** 前端不另发补扫，没有补扫地址。概览、月度台账、业务单据页、结账页、报表页签读 `readiness`：补扫没成功、还剩没进财务的单据时写一句；剩的不是 0 就再读，数在变少说“正在记进财务，还剩 N 张”，数不动了列出单号；这一轮进了新单据最后让财务页面都重读。
- **结账和正式报表：** 结账检查的“业务单据”一步数截至月底还没同步的来源（和补扫同一条件），加上已是事件、还没处理完的；没补扫不能结账。正式报表的资料检查用同一口径。“资产负债表平衡”一步只在没有卡着的事件和缺资料的单据时按现在的账算，只差同步时由“业务单据”拦；它的“去处理”打开业务单据页的“全部”（`#finance-ledger?tab=events&status=all`）。

## 单据和财务的约定

- **约定归业务管：** `shared/business/finance-source.ts`：财务口径 `financeSourceSchemas`（四种来源里财务点名读的几项）、转换 `toFinanceSource`、单据每一层每个栏目的归类 `financeFieldClasses`（算 / 说明 / 不算；业务多一个栏目、改了名都编译不过）。说明编辑能改的就是表头归“说明”的那些。
- **来源指纹：** 只取归“算”的栏目，按改名表 `fingerprintRules`（业务栏目名 → 财务口径名；往下一层的写在 `nested`；多了少了都编译不过）换名、键排序，再取 sha256。所以只改备注、送达，或送货明细的材质、楞型时不产生新事件。业务改栏目名只改改名表的键，已有指纹不变；算法、算进去的栏目、财务口径名一变，已有指纹就全对不上（`tests/source-fingerprint-pinned.test.ts` 守着写死的 sha256）。
- **来源变了：** 没入过账的直接记“已更正”；入过账的记“有差异”，由人“红字冲销并重做”；同一来源的新事件接手旧事件（`superseded`）。
- **来源被删：** 删业务记录不通知财务。下次补扫发现来源没了，只走 `server/finance/event-status.ts` 的 `markSourceDeleted` 分流：观察记录标 `deleted`；已更正、已替代、已算成本、无金额的不动；盘点、完工直接“已更正”；送货、到货名下没有要人处理的往来就作废系统挂的暂估往来、记“已更正”，有的才记“来源已删除”（界面叫“单据已删”），由人红字冲销，或名下还有算数的凭证时“核对无误，保留凭证”（保留的照样计入毛利）。
- **快照：** 事件快照的结构和读写在 `source-snapshot.ts`：只存财务口径，四种来源合在一起读，旧结构多出的项读时忽略。快照和从它取出的列（往来单位、单号、理论金额、缺税率）只由 `server/finance/event-columns.ts` 写（`tests/finance-event-columns.test.ts`），查询读列；被接手的上一条、同步时的单据金额只存列里。

## 记账、成本和结账

- **记账日：** 单据日期所在月已结账时，凭证记在最早没结账月份的 1 号（`server/finance/periods.ts` 的 `bookingDate`），摘要注明单据日期。到期日、分期、折扣期限、账龄、压款利息一律从单据日期起算。按送货确认收入时，毛利的收入记在凭证所在月。
- **理论金额：** 送货、到货的理论金额只在 `shared/business/document-value.ts` 算（按单据单价、不另加税，到货按入库数量），财务的理论收支和经营概况都调它；算不出的单据经营概况另报张数。
- **凭证：** 待确认 → 待审核 → 已审核 → 已记账，另有已作废（`server/finance/ledger.ts`）。红字冲销只冲已记账的原凭证，日期不早于原凭证，一张只能有一张有效红冲；票据、资产处置、费用这类功能生成的凭证到来源页面冲。
- **往来和冲销：** 往来余额口径只有 `server/finance/obligation-sql.ts`；红冲的往来成对看，判断只用 `reversal-pairs.ts` 的 `isReversed`；票据、资产处置、费用、坏账、利息、保证金的派生凭证撤回和红冲登记在 `derived-vouchers.ts`。红字冲销退货、部分到票后另出的余量暂估凭证时，红字凭证记在原到货事件名下，不挂退货单、发票；退货冲了多少只按挂在退货单上的凭证算。
- **退货冲暂估：** 未到票就退货时按暂估单价冲减暂估（`return-estimates.ts`，同步时做，成本计算用同一算法）：按挂在退货单上的凭证算出各冲了多少，挑出已确认没冲的、已撤销冲过没恢复的，再向窗口要这几张的内容。
- **取值：** 状态、种类的取值在 `stored-values.ts`，和建表 CHECK 由测试比对；收付方式、账期方式在 `shared/finance/finance.ts`；含税口径只在 `shared/core/domain.ts` 的 `orderTaxModes`，旧写法“不含税”单独登记成 `legacyTaxMode`。
- **成本：** 月末加权平均（`costing*.ts`）。冲销流水找原单据只走 `costing-origins.ts` 的 `originsOf`。
  - 送货、完工冲销按原成本冲回。
  - 撤销或更正到货：在冲回流水那个月按这批还挂着的暂估（原暂估减去到票已转走的）红字入库冲回，不另出成本分录，总账由到货的红字冲销凭证记。冲完数量为 0 的库存品只留到过票、等红票冲的那部分（按那个月为止进了库存的到票调差和红票算，`costing-invoice-adjust.ts`），其余转主营业务成本。
  - 到货那个月按记过账的那条事件入库（已撤销、被替代的按最新记过账的那条）；从没记过账的作废到货，入库和冲回在哪个月都不计。“已撤销”只认窗口给的单据状态，所以算成本不依赖补扫扫完；启用前的到货冲回仍要人选对方科目。
  - 查不到原成本的要人在“计算成本”窗口填金额、选对方科目；没被冲销的无单价到货照旧拦下。
- **结账和报表：** `closing.ts`、`reports.ts`；只有正式报表和结账因缺资料拦下。反结账重做时删掉的派生结果（成本明细、折旧明细）能重算，不拍快照。已撤销、被替代的到货名下的往来不能再关联、确认发票，开票对比也不列，撤销那个月的冲回金额才不会再变。撤销、更正过的到货红字冲销的默认日期取撤销那天（那个月已结账的按 `bookingDate`）：原单都给，替代单只在更正带出来、还没记过账的那一次给。

## 代码在哪

- **写入、审计、分页：** `financeWrite(store, actor, { action, input, result }, 写入)`（防重复走 `onceByRequest`；补扫只用其中的事务 `financeTransaction`）、`financeAudit`、`pageSql`。
- **路由和接口表：** 接口表在 `shared/finance/`，凭证和科目的正文规则在 `shared/finance/finance.ts`；`router.ts` 用 `route<FinanceApi>(router, '/finance')`，地址按页面分在 `routes.ts`、`routes-cash.ts`、`routes-period.ts`。
- **选往来单位：** 财务的下拉读自己的 `GET /api/finance/parties`（名单来自窗口，不列已归档），写往来、发票、票据、保证金、收付款时取单位名用 `requirePartyName`（找不到报“往来单位不存在。”）。出纳也能用，不借业务的 `/customers`、`/suppliers`。
- **助手：** 财务工具全部只读、金额换成元，读之前先补扫（`server/finance/assistant.ts`）。
