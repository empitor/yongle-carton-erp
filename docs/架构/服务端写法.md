# 服务端通用做法

服务端写代码时各只有一种做法的几件事：接口表、读库、单据状态和种类的写法、防重复提交、事务保存点、先预览再确认、审计。请求从前端到服务的整条路见[架构说明](../架构说明.md)“一次请求怎么走”；写入要守的权限、版本、事务、幂等、审计规矩见 `AGENTS.md`“业务规则”。

- **接口表：** 一个模块的地址、请求、回答写成一张类型表 `shared/<路由主人模块>/<名字>-api.ts`，样板 `shared/business/records-api.ts`。键写 `'方法 /地址'`（不带 `/api`，路径参数 `:name`）；`query`（值只能是 string、number、boolean）和 `body`（写接口必有）照服务端的 zod 规则写 `z.input<typeof …>`（规则放共用代码，样板 `shared/business/record-queries.ts`）；`response` 只放 JSON 原样来回的值（时间用 ISO 字符串，用 type 不用 interface）。同一地址按参数回不同形状的各占一个键（`'GET /orders?withMetrics=1'`）。工具类型在 `shared/core/api-table.ts`。
  - 服务端用 `server/core/route.ts` 的 `route<表>(router)` 注册（挂在前缀下写 `route<表>(router, '/前缀')`，键照样写完整地址）：返回值按表查，`param('名字')` 只能取键里有的，`query`、`body` 是 `unknown`、进服务先 zod 校验；找不到 `notFound('说明')`（404、`not-found`），新建 201 给 `{ status: 201 }`，只回状态码或 `{ message }` 的拒绝用 `refuse`，无内容成功回 `done`，响应只经 `reply`（`cache`、`cookie`、`clearCookie`）。服务按种类回不同类型的用映射对象分派（`server/business/service.ts` 的 `savers`），不用断言。
  - 前端在本模块 `*-api.ts` 用 `src/ui/call.ts` 的 `call<表>()` 建函数（不导出给组件），读写都带页面凭证，403 换新凭证重发一次，不做运行时校验；AI 导入、AI 设置、提示词带 `X-ERP-AI-Token` 走 `tokenRequest` 按表发。对不上编译不过（`tests/api-table.test.ts`）；`module-api-owners`、`feature-links-senders`、`feature-links-actions`、`frontend-request` 都认 `call()` 和 `route()`。
  - 回文件、收原始字节、边算边推和 `/health` 仍用 express 直接写。
  - 现有接口表：基础 `shared/core/account-api.ts`、`diagnostics-api.ts`、`guide-api.ts`；AI 接入 `shared/ai/ai-settings-api.ts`、`prompt-api.ts`；采购库存 `shared/business/operations-api.ts`（查询规则 `operations-requests.ts`，基本视图 `operations-views.ts`）；删除归档 `deletion-api.ts`、`lifecycle-api.ts`；业务汇总 `records-api.ts`、`mark-api.ts`、`workbench-api.ts`；单据流转 `flow-api.ts`、`stock-flow-api.ts`（完整视图 `stock-flow-views.ts`；另有 `flow-requests.ts`、`flow-results.ts`、`flow-views.ts`、`flow-correction-views.ts`）；财务 `shared/finance/finance-api.ts`；单据导出 `shared/documents/documents-api.ts`；识别导入 `shared/import/imports-api.ts`、`inbox-api.ts`；数据管理 `shared/admin/data-management-api.ts`；助手 `shared/assistant/assistant-api.ts`。
- **读库：** 只用 `server/core/sql.ts` 的 `one`、`many`（按结构 `parse`）、`exists`、`count`（`local/no-direct-db-read` 拦直接 `prepare(…).get/all/iterate`）。读出来不合结构抛 `StoredDataError`：回 500、`stored-data`，说“库里有数据和程序要求的样子对不上……”，具体哪句 SQL、哪一列进出错记录。JSON 列用 `parseStoredJson(结构, 文本, 哪张表哪一列哪一行)` 读，写前按同一份严格结构核对（各列结构见[数据模型](../数据模型.md)“约定”）。整行结构用 `rows.<表名>`（`npm run schema:dump` 由建表生成在 `server/core/schema/rows.ts` 和 `rows/`，`tests/schema-evolution.test.ts` 守着一致）；只取几列写 `rows.x.pick({…}).extend({…})`，LEFT JOIN 可空列 `.nullable()`，聚合列自己写 `z.number()`，枚举列用现成常量收窄；可空的附加字段用 `server/core/record-fields.ts` 的 `given`；整数 PRAGMA 用 `pragmaInteger`。一万行多校验约 15 毫秒。
- **单据状态、种类的写法：** 状态按名字引用 `shared/business/physical-flow.ts` 的 `flowStatus`（`draft`、`confirmed`、`cancelled`、`reversed`）；归档标记、审计里的种类用 `flowEntity(种类)`（SQL 里写 `'${flowEntityPrefix}'||kind`）；流水来源用 `movementSource`；财务的来源种类只在 `shared/core/finance-sources.ts`（共用-财务引不到共用-业务）。SQL 里不写死这些值，传参数或由常量拼。归档编号用 `Store` 的 `archivedIds`、`archivedAmong`（只有库连接时用 `archivedIdsIn`、`archivedAmongIn`），不另写 `record_lifecycle` 的 SQL。`local/no-flow-literals` 拦 SQL 里写死的状态、种类和 `flow_`（样例 `tests/eslint-flow-literals.test.mjs`），单据流转、建表 `server/core/schema/`、财务 `server/finance/` 不在范围内。
- **防重复提交：** 只用 `server/core/requests.ts`：`operationRequest(种类, 请求号, 账号, 内容, 会话?)` 生成请求，`onceByRequest(store, 请求, 写入, 结果结构)` 在一个保存点里查、办、记，出错整段回滚；同号同内容返回上次结果（按结果结构核对，对不上 500），内容不同 409 `REQUEST_REUSED`。请求号按账号分开（主键是种类、账号、请求号）。查和办分不开的用 `replayRequest`、`saveRequest`。带请求号的写地址请求号必填（单据保存也是）；单据导出的请求号就是导出记录编号，别人用同号 409。
- **事务保存点：** 只用 `server/core/savepoint.ts`：`inSavepoint(db, 函数)` 可嵌套，出错回滚再抛；`rehearse(db, 函数)` 预演后一律撤回（助手卡片的试执行、更正预览）。函数必须同步，返回 Promise 就回滚报错。不在别处手写 `SAVEPOINT`。
- **先预览再确认：** 核对入库出库、更正、删除、初始化、登记完工、识别导入、重算到期日都这样：预览返回按当前数据算的摘要（`server/core/preview-digest.ts` 的 `previewDigest`，键排序后取哈希），提交带回，服务端在写入的同一事务里重算比对（`assertPreviewCurrent`），不一样回 409 `preview-changed`“预览以后数据已变化，请重新预览。”（格式和类别 `PREVIEW_CHANGED` 在 `shared/core/preview-digest.ts`）。不存预览、不绑会话、不过期。删除窗（`src/recordkit/deletion-retry.ts`）、更正窗、核对窗遇到它自动重新预览。删除只在会连带别的记录时要带摘要，初始化只在有已结账期间时要；字段名：删除 `deletionDigest`、初始化 `financeDigest`、到期日 `digest`，其余 `previewDigest`。
- **审计：** `audit(store, 账号, { action, entity, id, document })`，来源取账号上的 `Actor.source`：页面、助手、数据管理、系统四种（`shared/core/audit-sources.ts`）。登录会话是页面；助手在 `AssistantManager.chat`、`execute`，数据管理在 `DataManagementService.execute` 和 `/api/management/reset`、`/workspaces` 用 `viaEntry` 换成自己的来源；服务里不写来源。“系统”现在没有写入方。
