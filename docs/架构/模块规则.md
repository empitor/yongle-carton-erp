# 模块规则

什么时候读：写任何代码之前读“写代码的本项目补充”；加文件、目录、跨模块引用（还有新表、新的后端地址前缀、按需加载的入口）之前整份读。

写代码的通用规矩见技能 code-discipline，模块的通用做法（怎么划、五条规则、分层、低层要用高层的东西、例外）见技能 module-boundaries；这里只写本项目的。服务端、共用、前端按同一套模块分目录，`tests/checks/` 的模块检查会拦。模块、允许的依赖、层（`layers`）、管什么（`what`）、分层说明（`layerNote`）登记在 `tests/checks/module-map.ts`，改完跑 `npm run docs:gen`；改规则时同步改本份。有哪些模块、各管什么、谁能用谁、哪条检查拦哪条规则见 `docs/生成/模块表.md`。

## 写代码的本项目补充

- 同一件事在界面、助手、数据管理里走同一个服务函数、同一个界面入口；发现已经有两套的，合成一套。
- 表结构的升级走编号的升级步骤（相关的见技能 `.claude/skills/schema-change/`），不在业务代码里写兼容。
- 状态、单位、类别这类业务取值用现成的常量和词表（如 `shared/core/units.ts` 和各模块的词表文件），不直接写字面值。
- 外来的代码和工具改了的，在 `THIRD_PARTY_NOTICES.md` 注明出处和改了什么。
- `tests/checks/file-size.test.ts` 拦超过 500 行的文件，写完超过 300 行有钩子提醒；函数长度、嵌套这些上限相关的见 `docs/架构/代码检查.md`“代码检查”。
- `apps/` 下的两个外壳也照这几条和技能 code-discipline，测试照技能 `.claude/skills/testing/`。

## 五条规则

- **只往下用：** 前端模块能用的共用代码不超过服务端对应的模块（例外：前端数据管理也放着 AI 接入的模型和提示词设置页、识别导入的消息接入设置页，所以还能用共用-AI、共用-识别）。分了层的模块现在一处越层都没有，检查不许有。
- **只走接口（技能里叫出口文件）：** 别的模块只经它的 `index.ts` 引用（按需加载的页面走 `pages.ts`），`scripts/`、`vite.config.ts` 也一样；动态加载连 `new URL(…, import.meta.url)` 也算，目标要能看出来。
- **没有循环：** server、shared、src 合起来算。
- **前端拿别的模块的数据走服务接口：** 服务接口在 `src/ui/slots.tsx` 定义、由那个模块实现；模块之间的事件只用 `src/ui/events.ts` 的 `emit`、`listen`。
- **表只由主人写：** 表归哪个模块见 `docs/架构/数据库约定.md`“表归哪个模块”；库存流水走 `server/operations/ledger/ledger.ts`；没有逆着读的例外；财务更严，SQL 只读自己的 `fin_` 表和 `business_audit`，业务数据（连基础的客户、订单、记录状态）经单据流转的只读窗口 `financeFacts` 拿。写的例外只有建表和升级代码（`server/core/schema/`）。新表、新的后端地址前缀都要在测试里登记。

依赖方向上另有几条：财务用单据流转只许经只读窗口 `financeFacts`，不调业务服务、不读业务的表；业务不调财务。数据管理 → 识别导入只引类型。前端的依赖顺序和服务端不同：单据导出排在业务下面（业务页面嵌它的导出窗），只用共用-基础、共用-单据，助手也直接用它；前端管理还用共用-AI、共用-识别，前端助手不用共用-识别；前端基础、助手和管理可请求账号接口，前端基础用 `/auth/state` 读取登录状态和更新页面凭证。

## 模块里的分层

分了层的模块，入口 `index.ts`、`pages.ts` 不登记进层；样式类名的层按写出它的最低一层目录算。哪几个模块分层、各分几层、每层放什么见 `docs/生成/模块表.md`“模块里的分层”。

## 低层要用高层的东西

| 做法 | 本项目怎么做、例子 |
|---|---|
| 调用方传入 | 装配把请求身份接口 `RequestAuth` 传给路由；每日清理各项由 `server/index.ts` 传给 `scheduleDailyCleanup`；归档的读状态、打标记、审计由各模块给 `changeArchive`；改已有采购单、库存品时，单据流转先算好单据事实和要连带改单据的函数，传给采购库存的 `savePurchase`、`saveItem`，在同一保存点里调 |
| 登记 | 删除和初始化规则（`server/core/records/deletion-rules.ts`）；能归档、能记墓碑的记录种类（`registerRecordKinds`）；配置库规格和默认位置（`registerVersionedSqlite`）。登记用的模块名类型是 `server/core/records/kinds/module-names.ts` 的 `ModuleName` |
| 插槽 | `src/ui/slots.tsx` 定义，`src/slots.ts` 装配：详情里的财务段（没有 `finance:view` 不渲染也不下载）；到货页的“AI 识别送货单”；保存文件 `saveFile`（安卓 App 里交给 App 存） |
| 服务接口 | `src/ui/slots.tsx` 定义，各模块 `services.ts` 实现：今日页的收件箱和到期应收应付；识别导入里复制识别文件 |
| 事件 | `src/ui/events.ts` 的 `emit`、`listen`：数据变了刷新列表；打开助手 |
| 按需加载 | 整页和跨模块按需打开的窗口走模块的 `pages.ts`，整页汇总在 `src/lazy-pages.ts`；只用一小段的另立入口，登记在 `tests/checks/module-map.ts` 的 `lazyEntries` 写理由；本模块内点了才开的窗口直接 `lazy()`、包 `Suspense` 显示“正在打开…”。例子：财务段 `src/finance/related-pages.ts`；订单编辑窗 `src/editors/pages.ts`；删除窗、更正到货单窗、客户供应商产品编辑窗。这些不许进首屏（`docs/架构/代码检查.md`“首屏体积上限”） |
