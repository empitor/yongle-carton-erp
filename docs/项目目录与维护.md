# 项目目录与维护

当前源码版本0.5.3。以下按实际入口和用途分类，不以文件名或没有静态import直接判定废弃。

## 运行入口

| 路径 | 用途 |
|---|---|
| src/main.tsx、App.tsx | 前端入口、业务页面装配、登录和共享界面状态 |
| src/Navigation.tsx、shared/assistant-navigation.ts | 人工与AI共用导航、旧链接兼容 |
| src/ui、BusinessRecords.tsx | 实际列表、分页、空状态和业务记录操作 |
| server/index.ts、app.ts | 真实HTTP服务、账号、业务与AI服务装配 |
| server/db.ts | 正式业务数据和有序迁移 |
| server/business、operations、flow | 原业务服务、库存、生产与送货、删除归档和审计 |
| shared | 共用字段、金额/单位、业务目录、页面/工具协议和校验 |
| server/assistant | 唯一Agent调度器、注册表、持久任务、插件、DOM和本机浏览器桥接 |
| server/ai、import | Provider与密钥、提示词、隔离解析、原件、草稿和正式导入准备 |
| server/speech、src/speech | 可选本地语音输入；不要求分发模型权重 |
| public/theme-init.js、src/*.css | 首屏主题及运行样式，不能按无业务import删除 |

## 构建、测试与开发

- package.json与package-lock.json管理依赖。所有现有运行依赖均有运行/Worker用途；@types、TypeScript、Vite、tsx、concurrently和Prettier属于开发与构建依赖。
- npm test同时发现tests/*.test.ts和tests/*.test.mjs，包含启动器验收。tests/fixtures中的公开DOC及许可证是必要格式测试资源，不是用户订单原件。
- tsconfig启用未使用局部符号/参数检查，防止旧界面代码和废弃导入继续积累；导出接口和保留的兼容签名不因没有当前消费者被删除。
- scripts/build.mjs先类型检查再构建，并管理构建临时目录；scripts/start-system.mjs与启动/停止CMD保留健康检查、运行锁及端口保护。
- scripts/release-audit.mjs检查真正暂存内容及Git历史的凭据/运行数据风险；不能代替业务资料备份。
- vendor/xlsx-0.20.3.tgz由锁文件的本地依赖引用，npm ci必须携带。vendor/models/README.md保留语音模型恢复说明，模型本体留在本机。
- 可选.github/workflows/checks.yml是本机CI草案，按现有忽略规则不上传；执行同样检查的命令已经包含在npm脚本和本轮干净克隆验收中。

## 特别保留的兼容与动态入口

| 文件/接口 | 保留原因 |
|---|---|
| src/AssistantCapabilities.tsx | 旧组件导入兼容，重导出同一个AssistantPlugins，并非第二套管理实现 |
| src/useAssistantSpeech.ts | 旧Hook路径兼容，逻辑仅在src/speech/useAssistantSpeech.ts |
| scripts/speech-smoke.cjs、speech-e2e.ts | 已有语音自检命令兼容，转发到scripts/speech下的唯一实现 |
| server/import/parse-worker.mjs | 通过子进程路径动态启动；负责附件文字提取、兼容文件读取和安全隔离 |
| scripts/ocr-image.ps1、parse-file.ts | 隔离解析器旧格式/安全测试与兼容接口仍引用；当前订单AI的既有无OCR路径不因保留此文件而启用OCR |
| server/ai/default-prompts、recognition-modules.ts | 动态提示词模块和默认预设，不按普通页面import数量判断 |
| 旧developer、AI插件、仓库送货等路由 | 与原服务共用兼容入口，不是第二套数据库/业务引擎 |
| 所有既有数据库迁移 | 旧数据库升级仍需要，不能因当前库已执行而删除 |
| 插件声明、业务目录及未有普通调用者的导出类型 | 插件注册、校验、未来扩展或测试契约的一部分 |

## 本机数据与可再生输出

data、backups、用户配置目录及vendor/models内的实际模型受到保护；项目整理不清空数据库、不调用管理初始化、不删除原件、正式归档、审计或凭据。

node_modules、dist、.build-tmp-*、.playwright-cli和测试日志可由标准安装/构建/测试重新生成。旧验收克隆、历史输出、包备份和临时文件不得仅凭目录名删除；先检查Git状态、动态引用、来源、活动进程和可恢复性。

本轮本机旧缓存的物理删除受执行策略限制而保留，均被.gitignore排除，不会进入GitHub。work/outputs中的历史原件式样本、包备份、数据库及用途未完全确定的脚本也继续留在本机。正式源码的清洁验证以干净克隆为准。
