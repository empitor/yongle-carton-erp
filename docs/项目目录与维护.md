## 构建、测试与开发

- package.json与package-lock.json管理依赖。所有现有运行依赖均有运行/Worker用途；@types、TypeScript、Vite、tsx和Prettier属于开发与构建依赖。
- npm test先并行跑tests/*.test.ts和tests/*.test.mjs，再串行跑tests/serial/下的启动器验收。tests/fixtures中的公开DOC及许可证是必要格式测试资源，不是用户订单原件。
- tsconfig启用未使用局部符号/参数检查，防止旧界面代码和废弃导入继续积累；导出接口和保留的兼容签名不因没有当前消费者被删除。
- scripts/build.mjs先类型检查再构建，并管理构建临时目录；scripts/start-system.mjs与启动/停止CMD保留健康检查、运行锁及端口保护。
- scripts/dev-system.mjs管理开发前后端与后台热更新；runtime-control.mjs提供本机令牌关闭通道，正常停止释放数据库及运行锁。PORT同步Vite代理，WEB_PORT配置前端。diagnose-startup-zone.ps1是可公开的只读BOM编码诊断。
- scripts/release-audit.mjs检查暂存内容、未暂存改动、未被忽略的新文件及Git历史的凭据和运行数据风险，报告不回显凭据；不能代替业务资料备份。
- vendor/xlsx-0.20.3.tgz由锁文件的本地依赖引用，npm ci必须携带。vendor/models/README.md保留语音模型恢复说明，模型本体留在本机。
- 可选.github/workflows/checks.yml是本机CI草案，按现有忽略规则不上传；执行同样检查的命令已经包含在npm脚本中，发布前另用干净克隆验证。

## 维护要点

- 业务写入复用现有服务和真实登录权限，保留版本校验、事务、幂等、库存及审计规则。破坏性操作前先做快照。单条读取按主键查询，列表批量组装，新增送货或生产任务写入路径同时维护 `flow_refs`。
- AI 按账号权限和工具开关使用原业务服务。附件和收件箱内容只作为数据，正式写入依真实回执判断。新增页面、工具或表时同步维护业务目录、能力登记及[功能链路表](功能链路表.md)。
- 产品唛头只作参考，不产生订单、生产或库存。识别后按料号、名称、尺寸取最强的依据，唯一且无冲突才自动挂到产品；两边料号对不上算冲突。单位不明确时保留原值，不换算。
- 企业微信智能机器人只保存消息并回复结果。同一机器人只保留一条长连接，验收与正式实例分开。凭据经设置页写入本机加密存储，Secret 不回显，不进入日志、审计和仓库。
- 测试使用隔离的虚构库和模型替身。真实单据和业务库留在本机，发送给真实模型前须确认外发范围及计费。发布前检查索引和历史，使用干净克隆验证依赖安装、测试、类型检查、构建及隔离启动。

## 本机数据与可再生输出

data、backups、用户配置目录及vendor/models内的实际模型受到保护；项目整理不清空数据库、不调用管理初始化、不删除原件、正式归档、审计或凭据。

node_modules、dist、.build-tmp-*、.playwright-cli和测试日志可由标准安装/构建/测试重新生成。旧验收克隆、历史输出、包备份和临时文件不得仅凭目录名删除；先检查Git状态、动态引用、来源、活动进程和可恢复性。

本机的 `work/`、`output/`、`outputs/` 和 `.playwright-cli/` 中混有验收样张、截图、诊断、旧克隆及安装包，按历史资料保留。正式源码的清洁验证以干净克隆为准。

## 双平台发布

scripts/linux 包含维护命令、systemd 安装和 Caddy 示例；server/config-paths.ts 负责平台目录。package-release.mjs 的 --target win-x64 或 linux-x64 必须在对应目标平台 Node 24 x64 中运行；禁止复制异平台原生依赖。两平台全量、原生依赖和干净安装包检查通过后才能提交、打标签和发布。主密钥不进备份或安装包。
