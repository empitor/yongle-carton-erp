# 界面规范

所有用户能碰到的界面（列表、详情、编辑窗、确认窗、页签、手机版、助手卡片）都按这份做。设计系统的硬规则（字号、圆角、颜色、主按钮、不说“草稿”、一个窗口只交互一次、要在真实浏览器里看过）见 AGENTS.md“界面”，这里不重抄。

## 叫法（词表）

- **建、改：** 一律“新建××”“编辑”；按钮和窗口标题写“编辑××”（编辑说明、编辑备注、编辑到期日、编辑到货安排、编辑到货单），不写“改××”；还没有内容时写“写××”（写备注）。
- **单据名：** 一律“××单”：送货单、到货单、完工单（页面叫“完工记录”），不说“完工登记”“生产登记”。指一张单据（卡片、提示、报错）用 `shared/business/physical-flow.ts` 的 `flowDocNames`，页面和列表名用 `flowNames`。
- **业务动作：** 确认订单、安排订料（生成采购单）、导出订货单（导出并标记已订货）、登记到货、登记没有采购单的到货（多送、样品）、核对入库（AI 导入到货面板的主按钮也叫它，核对窗里的确定按钮叫“确认入库”）、安排生产、登记完工（没有任务的叫“不挂任务的完工”）、安排送货、导出送货单（导出并出库）、不导出直接出库、确认送达、采购退货、出入库 / 盘点。安排订料、安排生产、登记完工、安排送货、出入库 / 盘点各只有一个窗口。
- **撤回：** 取消（还没生效的单据）；撤销（已生效的到货、送货、完工、生产任务、采购退货）；更正到货单 / 更正送货单 / 更正完工单（改已生效单据的数量等：撤销原单、出新单号的替代单，详情写“更正自 ××”“已更正为 ××”）；已生效单据的“编辑”只改说明（备注、时间、地址联系人、操作人）；财务凭证叫红字冲销；删除；归档 / 恢复。识别结果的“撤回修改”只退回识别结果上一次修改，和业务的“撤销”不是一回事。
- **其他固定叫法：** 到货明细没有采购单写“无采购单”；能发的货今日待办和送货页都叫“可发货”；面积单位一律“m²”。
- **档案的状态：** 客户、产品、供应商只有“归档 / 恢复”，报错和下拉里说“已归档”，不说“已停用”；“停用”只用于账号、助手工具和提示词条目。采购单还没导出订货单叫“待订货”。
- **时间：** 一律按北京时间显示，只用 `src/ui/time.ts` 的 `beijingTime`（全写 2026/11/14 08:05:03，列表紧凑处用短写 11/14 08:05），不在页面里自己格式化。
- **列表：** 搜索、筛选、清除筛选、清除选择；分段统一“待处理 / 全部 / 已归档”。
- **名字一致：** 页面名、页签名、手机底部导航名和侧栏一样；同一种状态全站一套叫法（单据 `shared/business/physical-flow.ts` 的 `flowStatusText`，订单 `shared/core/domain.ts` 的 `orderDisplayStatus`，采购单 `shared/business/labels.ts` 的 `purchaseStatusLabel`，状态颜色 `src/recordkit/record-meta.ts` 的 `businessStatusTone`）。
- **待核对的单据：** 待送货、待入库、待确认，不说“草稿”；识别文件同样按“待识别”“待核对”说。生产任务没有待核对这一步，安排即下达。
- **不露：** 内部编号、英文值、字段代码、开发口径的话。财务页可以用会计词，但同一件事只用一个词。
- **库存：** 一种货叫“库存品”（分开说“原材料库存品”“成品库存品”），仓库和页面按“原材料库存”“成品库存”；不说“库存档案”“原材料档案”。删除时库存数量不动而留下的流水叫“系统维护”流水，不说“数据库维护”“手工调整”。流水按方向叫“入库流水”“出库流水”，两种都有才叫“出入库流水”。
- **订货单：** 订货批次在界面上叫“订货单”。
- **量词：** 生产任务用“张任务”，和纸板的“张”放一起时不只写“N 张”。
- **退料、退回：** 领了没用完退回仓库叫“退料”（净耗用 = 领用 − 退料）；采购退货里退给供应商的叫“退回”。
- **推算的数带“估计”：** 比如成品批次的“估计还剩”；说明推算口径的小字常显。
- **关联记录与修改历史：** 详情“更多”里那一项和打开的窗口同名，不说“关联与历史”。
- **单价、金额：** 单价至少两位、最多四位小数，尾零去掉（2.7600 写 2.76）；只用 `shared/core/precision.ts` 的 `plainPrice`，带计价方式的用 `shared/business/display-text.ts` 的 `priceText`（按面积写“元/m²”）。金额两位小数加千分位。不在页面里自己拼。还没定价写“单价待定”（`shared/business/display-text.ts` 的 `UNPRICED_TEXT`，订货单打印和预览也用它）。计价方式只有“按平方米”“按张”，栏目叫“计价方式”，不说“计价依据”。订单的“金额结算”两个选项叫“精确到分，不自动舍入”“明确采用整单四舍五入到分”，只在 `shared/core/domain.ts` 的 `roundingPolicyLabels` 写一份，没存的显示“未填写”。
- **财务：** 没有到期日的叫“没有账期”；收付款类型只用短名（收客户款、付供应商款、其他收入、其他支出、内部转账）；保证金、优惠按钱的进出叫“收到保证金”“付出保证金”“收到优惠”“给出优惠”，不说“押金”；没有单号的记录写“叫法 月-日 金额”。叫法都在 `shared/finance/labels.ts`。财务事件页的核对按钮叫“核对无误”，送货、到货“有差异”的按钮叫“红字冲销并重做”。被冲销的原往来标“已冲销”（中性色），冲销那笔标“红字冲销”；红色只给“红字”标签、“红字冲销”状态和负数金额。
- **删除：** 影响清单、库存说明、“库存怎么处理”两个选项的叫法只在 `shared/business/deletion-words.ts` 写一份，排版在 `src/recordkit/deletion-impact.ts`，页面删除窗口和助手确认卡片共用。删除窗口的标题和主按钮写明连带删掉几张什么单据；删完的页面提示说清删了哪一条、连带几条。
- **报错：** 校验没过按界面叫法说是哪一格，中文冒号、整句（“客户：请选择客户；明细第1项的产品：请选择产品”），只经 `shared/core/user-errors.ts` 的 `userError`。网络断开一律说“连不上服务器，请检查网络后再试。”。做不了的事：不是超级管理员账号直接说“要用超级管理员账号，当前账号没有这个权限”，不叫人去“系统维护”；超级管理员没进模式的才提示去账号菜单“系统维护”。超级管理员模式的横幅和“系统维护”窗口用同一句，只在 `src/admin/MaintenancePanel.tsx` 的 `superModeScope` 写一份；没进模式时要改共用设置的页面顶上用 `SuperModeNotice`（说明一行、“进入超级管理员模式”按钮另起一行），写按钮不出现。服务器正忙一律说“服务器正忙，请稍后再试。”（`shared/core/server-busy.ts`），页面先自动再试一次。先预览再确认的窗口被拒时一律说“预览以后数据已变化，请重新预览。”，核对窗、更正窗在原窗口里换成最新的再让人核对，不弹第二个窗。

## 按钮和入口

- **主按钮：** 一个区域（页头、详情头部、窗口底栏、选择条）最多一个实心主按钮，就是当前状态的下一步，随状态变；没有下一步就不放，不拿“编辑”“新建库存品”凑数。唯一例外：产品的勾选条和详情里“安排生产”和“新建订单”并列实心（`RecordAction.emphasis`，只用在这里）。
- **位置：** 页头和窗口底栏在最右；详情头部在最左（主、次，然后“更多”）。
- **次要和“更多”：** 次要最多一两个。“更多”上面是低频业务动作和管理类（归档 / 恢复、关联记录与修改历史、更正××单），分隔线下面是红色危险项（取消、撤销、删除）；危险项只出现在“更多”和确认窗里。`ActionBar` 和页头（`PageHeading`）会自动把多的主操作降为次要、多的次要（详情两个、页头一个）和危险项挪进“更多”。
- **一件事一个主入口：** 所在对象详情的主按钮，或所在页面页头的主按钮。别的入口只留“能带内容进去”的（从选中的记录开单、选择条批量操作、待办列表行的动作）；不带内容又重复的入口不做。
- **不放刷新按钮**（数据会自动刷新）；没有权限的操作、对当前账号走不通的链接不显示。
- **功能不丢：** 不为了少按钮去掉功能，拿不准常不常用的收进“更多”。
- **改了按钮文字或结构：** 同时改 `scripts/ui-check/flow-*.mjs` 和断言文字的测试，并查 `shared/assistant/ui-capabilities.ts`、`shared/assistant/assistant-navigation.ts`、`server/assistant/` 有没有依赖旧文字。

## 列表

- **页头：** 标题、一行统计（统计只在这里出现一次）、右侧从左到右一个“更多”、最多一个次要、一个主按钮。页头按钮文字不带变量（月份写在旁边的期间框和确认窗标题里）。
- **工具栏一行：** 搜索 + 一个分段 + 最多一个关键下拉 + 筛选弹层（其余条件收进去，按钮上显示生效个数）。排序点表头。
- **说明：** `ListSummary` 的 `hint` 是口径说明，收起；`note` 是会改变读数意思的说明，常显。拿不准就问：不看这句会不会把数读错。
- **金额合计算不出来**（有一行单价没填）时显示“—”加一句次要说明，不显示 0.00、不只算能算的几行。
- **默认视图**显示要处理的东西，不默认“当日”空列表；日期条只留在排产板这种本来是日程的地方。
- **列优先级：** 详情面板、助手停靠或窗口变窄时，按表格区域宽度收列（规则在 `src/ui/list-layout-5.css`“列表的列优先级”，做法见[架构说明](架构说明.md)“前端约定”）。单号或名称、状态、金额这类关键列不收；收看着像关键的列，要能在详情里看到同样的信息。宽屏定死宽度的列要在 `@container list-table (max-width: 899px)` 里放开。
- **行里不放按钮**，点行开详情。例外：待办列表（今日、待到货、可发货）每行一个动作，直接打开对应窗口，办完回到原处。
- **勾选后**用 `SelectionBar`：固定在屏幕底部，“已选 N 项”、一个正向主操作、最多一个次要、“更多”（批量归档、批量删除）、“清除选择”。归档能恢复，不用红色。
- **空状态：** 一句话说为什么空 + 一个能解决的动作。

## 详情

- 一张单只有一个详情，不做“面板 + 弹窗”两层；列表面板、归档页、从别的详情点开的窗口用同一份。窗口里的到货单“采购退货”只显示、不出“撤销退货”，“到货记录”里也不出“更正到货单”（一个窗口只交互一次）。
- **头部：** 类型、编号或名称、`StatusChip`（待办 `neutral`、进行中 `accent`、完成 `success`、取消 `warning`、撤销或作废 `danger`，都要有底色）、一行最关键的上下文（送货单写“客户 · N 种产品”）；操作用 `ActionBar`。
- **正文顺序：** 要注意的提示（`Hint`）→ 进度（只出现一次）→ 明细（数字列右对齐，补充信息写 `<small>`）→ 基本信息（`Facts`）→ 关联单据（都能点开）→ 历史。“下一步”只写一句为什么，不放按钮。
- 单据之间能互相跳：订单 ↔ 生产任务 ↔ 完工 ↔ 送货，采购单 ↔ 到货。
- 一节里多条同类记录、字段又多时（如成品批次），一条一块浅底圆角块上下排，不用多列表格。
- 空值显示“—”；单号、日期、“现存 1,050 只”这类短内容加 `nowrap`，不从中间断开；撤销、更正后原日期照常显示，后面写“ · 已撤销”“ · 已更正”。单据的“经办人”有确认人写确认人，没有才写登记人。
- 修改历史每条显示中性色小标签写来源：页面、助手、数据管理、系统（服务器给 `sourceLabel`，词表 `shared/core/audit-sources.ts`）。

## 编辑窗和确认窗

- 外壳 `ManagementDialog`；手机上 `sm`、`md` 自动变底部弹层，`lg`、`xl` 全屏。所有窗口都有底栏。
- 只摊开必填和常用字段，低频的收进折叠的“更多信息”；节标题用大白话（“生产什么”“什么时候做”）。
- 不在编辑窗里手选状态，用底栏按钮表达（保存 / 保存并确认）。默认值不伪装成真值（单价留空，不填 0）；说明最多一句 `hint`；改不了的字段在 `hint` 写原因。
- **字段：** `FormField` 的 `label` 简短，必填用 `required`，错误放 `error`；数量和单位一起用 `.form-inline`；明细字段少用 `.line-table`，多用 `.line-card`。表格行里的输入框，读屏名称用列名加第几行（“第 1 行单价”）。点了底部按钮后有报错时，`required-guide.ts` 标红还空着的必填项、滚到第一个并聚焦。
- **底栏：** `EditorFooter`，左边一句说明，右边“取消”+ 主按钮，最多再加一个次要，低频的放底栏“更多”。退出按钮通常写“取消”。到货、完工和送货的取消确认窗中，退出按钮写“不取消”；主按钮写这一步的结果（保存订单、安排送货、确认删除）；危险确认红色实心（`danger-solid`）；会动库存或连带删单据的删除窗口默认焦点在“取消”。
- 不用浏览器原生 `confirm`：用 `ConfirmDialog`，异步流程里用 `useConfirm()`。撤销、取消的确认窗不列关联记录，这一步会怎样在顶上说明里讲清。
- 从单个对象进来的窗口只显示这个对象，要多选时给“再加一张”。
- 叠在页面上、有自己关闭按钮的一层（窗口、详情面板、侧边菜单、浮层、菜单），用 `src/ui` 的 `useBackLayer` 登记它的关闭函数，安卓 App 的返回键才能一层一层关（做法见[架构说明](架构说明.md)“安卓 App 通道”）；用 `ManagementDialog`、`DetailPanel`、`FilterPopover`、`MoreMenu` 的已经登记好了。`tests/back-layers-registered.test.ts` 查渲染 `role="dialog"`、`role="menu"` 的组件都登记了。
- 办完就关窗口，结果用页面提示（`src/ui/events.ts` 的 `notify('…')`）；不保存后再弹详情，能一步做完的不拆两步。没办成：错误显示在窗口里（`FormMessage`）；窗口已经要关或是从别处弹出的，用 `notify(原因, 'error')` 发红色页面提示，不能“点了没反应”。只是提醒接下来会怎样、要人做什么（不是办成了）的用 `notify(文字, 'info')`：颜色和停留时长同办成了，图标是 i、不带对勾。

## 助手确认卡片

- 助手改数据都出卡片。删除卡片标题写“删除 + 叫法 + 单号或名称”，库存品按仓库叫“删除原材料库存 …”“删除成品库存 …”。删除、清空的确认按钮红色实心，写“确认删除”“确认清空”，其他写“确认执行”；旁边是“不执行”（作废这张卡片）。卡片标题写要做的事、用本词表的叫法（如核对入库、不导出直接出库、撤销送货、盘点调整），不用执行结果那句“已……”，也不写事务、回滚这类开发口径。卡片内容（第一行动的是哪条，下面逐项改前 → 改后、库存前后）由服务器写好（`server/assistant/tools/card-summary.ts`），页面原样列出，不在前端拿改前改后去猜。
- 每条回复下面固定一行写这一轮实际做了什么：“只查询，没有改动”“待确认：…”“已执行：…”“没做成：…”（`src/assistant/plan-card.ts` 的 `factLines`）；没做成的只写是哪一步，原因由助手自己说。“已执行”里助手记住、改过的长期记忆每条后面一个“忘掉”（`src/assistant/AssistantExecuted.tsx`），别的已执行的事不放按钮。卡片执行没成、结果不明时写“执行没有成功 · 这张卡片不会再执行”“已经发出去，结果不明 · 先查一下再决定”。
- 小字按服务器给的标记写要不要密码、超级管理员模式、是不是只能在服务器本机，不写“二次确认”“高风险操作”；密码框标签和页面删除窗口一样。执行回执写“已执行：方案标题”，不露工具名；执行过的卡片只在标题下写一次“已执行”，不再放按钮。
- 方案被别处改过、确认被拒时，同一个核对区换成服务器上最新的一版，看过再点，不弹新窗口。说法集中在 `src/assistant/plan-card.ts`。

## 页签、手机、质感

- 两到四项的切换用分段控件（`.record-view-tabs`），页内页签全站一套样式。超过四项：手机上改下拉或横向滑动，电脑上放不下折成两行，不截掉最后一项。
- **多窄算手机：** 全站只有一个标准，窗口宽 700 及以下按手机版式，701 起按电脑版式（平板、窄窗口也是电脑版式，页面要在 701 宽排得下）。样式写 `@media (max-width: 700px)`（反过来 `min-width: 701px`），代码里判断手机用 `src/ui/phone.ts`。701～899 之间不另立断点；700 以下再收一档（如 480）、900 以上的窄屏电脑和大屏多一栏可以有。`npm run lint:css` 守着（`stylelint.config.mjs`）。
- **手机（390 宽）：** 列表是紧凑行（第一列做标题，其余“字段名 值”小字，两三行高，`src/mobile/MobileNav.tsx` 自动处理）；空格子由脚本标 `m-hide`，不手写；地址、备注、加工要求这类长字段在 td 上标 `m-long`；不按列序号隐藏。组合输入、表格式输入不溢出，没有竖排文字和横向滚动。一套导航：底部栏 + 页内一排切换。筛选默认收起。顶栏（搜索、新建、账号）往下滚时跟手往上收起、内容淡出，往回滚跟手露出，停在半路松手吸附（`src/mobile/topbar-collapse.ts`，只动位移和透明度）；所以别的东西不要贴着顶栏下沿定位。弹层开着时页面提示条挪到顶上、让出一个标题栏的高度，不压住弹层的标题栏和底栏。
- **悬浮的小甬小勒不挡内容：** 电脑上只有真的压住详情面板时，或贴在屏幕右边压住表格、按钮时，才缩到屏幕边只露一条（贴在左边的不缩），鼠标移上或聚焦时探出（`src/assistant/floating-assistant.ts` 的 `yieldPeek`、`yieldReveal`）；助手入口按“收起方式”二选一（悬浮小人或顶栏按钮），不同时出现。
- **质感：** 精致版式层统一（AGENTS.md“界面”）：不框套框；图标按钮平时透明；输入框浅灰填充，聚焦变白有光圈；禁用的输入框更浅的底、虚线边（`src/ui/buttons-4.css`“禁用的输入框”）；弹窗背后变暗、缩放淡入；动画跟随系统“减少动态效果”关闭。键盘能操作，焦点可见。

## 样式变量

- 颜色、字号、圆角、层级（`z-index`）只写 `src/ui/tokens.css` 里的变量，别处一个色值、像素字号、像素圆角、层级数字都不写；`npm run lint:css`（stylelint，`stylelint.config.mjs`）守着，也在 `npm run check` 里。用变量调出来的（`color-mix(… var(--x) …)`）不算写死。
- 字号六档 `--text-xs/sm/md/lg/xl/2xl`（12/13/14/16/20/24）；圆角 `--r-control` 8、`--r-panel` 12、`--r-pill` 胶囊、`--r-inner` 6、`--r-small` 4、`--r-circle` 圆；层级按用途起名（`--z-topbar`、`--z-overlay`、`--z-toast` 等，从低到高列在一处）。单据样张（`--paper-*`，照纸面、不跟主题变）、打印（`--print-*`）、小甬小勒（`--yl-*`，紫色只给 `--yl-star`）各有一组。新值先在 `tokens.css` 起名，深色模式要的一起写。
- 间距八档 `--space-3xs` 到 `--space-2xl`（2/4/6/8/12/16/20/24，负值写法 `calc(-1 * var(--space-…))`），在档上的已改用变量，不在档上的 259 处及何时进 `stylelint` 见[路线图](路线图.md)。
