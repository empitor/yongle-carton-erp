# 排查

什么时候读：排查问题（员工说保存不了、启动被拒绝、看日志）、处理账号和密码、接消息机器人、整理项目时判断什么不能删。

## 排查问题

- **问助手：** 员工说点了没反应、保存不了，可以让助手查最近出错和被拒的请求（服务端和页面上报的，留 30 天；普通账号只看自己的，超级管理员看全部）、按人按时间的修改记录、后台任务；超级管理员还能看运行日志、登录记录和程序代码（只读）。
- **日志在哪：** 业务库目录下的 `logs/`：`run.log` 运行日志（满 2MB 轮换成 `run.log.1`），`problems.sqlite` 出错记录。Linux 还可以 `journalctl -u yongle-carton-erp`。
- **“数据没有保存：有内容不符合数据规则，请联系维护人员。”**：数据库规则（状态取值、真实日期、单位只收“只”“张”、金额不为负等）挡住了写入，什么都没存——程序本该先拦，是程序问题。日志里以 `[数据规则]` 开头的一行写明入口和哪条规则（不带写入的值），交给开发。
- **启动被拒绝（数据都不动）：**

| 启动窗口的提示 | 原因和做法 |
|---|---|
| 这是 0.9.0 以前的旧业务数据库 | 按 `docs/运维/升级.md`“0.9.0 以前的旧数据”移走旧库 |
| 数据库比当前程序新 | 多半是回滚只换回了程序。换回新程序，或用补丁前的完整备份恢复 |
| 这个文件不是本系统的业务数据库 | `DB_PATH` 指错了 |
| 业务数据库的版本记录不完整 | 库被改坏了，用最近的完整备份恢复 |
| 业务数据库的表结构和当前程序对不上 | 版本是当前版、表结构却不一样（直接改了建表或被数据库工具改过），提示列出差在哪几张表。正式数据用最近的完整备份恢复；开发库移走再启动建新库。升级走完后对不上也一样，整次升级退回 |
| 某个配置库比当前程序新 | 多半是回滚只换回了程序。停服务后运行 `revert-config-upgrades`，或换回新程序 |
| 某个配置库从第 a 版升级到第 b 版失败，已整体退回 | 文件没动。换回旧版程序继续用，提示交给维护人员 |
| 某个配置库升级停在某一步：这一步自己结束了事务，升级没有做完 | 程序问题，唯一文件可能已改动的情况：库是半截的，升级前备份已改名成 `-before-unfinished-`，以后打开都拒绝。照提示的“处理办法”和 `docs/运维/备份恢复.md` 表中“升级没做完留下的备份”那行做，提示交给维护人员 |
| 某个配置库要从第 a 版升级到第 b 版，升级前备份没有做成 | 没开始升级、文件没动。查那个目录的磁盘空间和读写权限后再启动 |
| 某个配置库比基线（第 N 版）旧，要删掉重建，但文件删不掉 | 关掉占用它的程序再启动 |

## 账号

- 第一次使用在登录页建管理员（服务器上走维护通道）。
- 员工忘记密码在登录页提交，管理员在“账号管理”确认后发临时密码。
- 管理员忘记密码：在服务器本机运行 `npm.cmd run reset-password -- "用户名"`（Linux `erp.sh reset-password 用户名`），生成 24 小时有效的临时密码，旧登录立即失效，登录后先改。

## 消息机器人

企业微信、飞书、钉钉都用长连接，不用公网地址，服务器能出站访问就行：`openws.work.weixin.qq.com`、`open.feishu.cn`（和它给的长连接地址）、`api.dingtalk.com`（和它给的 Stream 地址，回复发到 `*.dingtalk.com`）。三家可同时开，在“设置 → 消息接入”各一张卡片，填好点“保存并连接”，显示“已连接”才收得到。

- **企业微信：** ① 管理后台建智能机器人，API 模式选“使用长连接”；② 复制 Bot ID、获取 Secret；③ 设好哪些人能用；④ ERP 卡片填好、点“保存并连接”；⑤ 单聊发文字、图片、文件试一下。
- **飞书：** ① 开发者后台建“企业自建应用”；② 加应用能力“机器人”；③ 开通权限“读取用户发给机器人的单聊消息”（`im:message.p2p_msg:readonly`）、“接收群聊中 @ 机器人消息事件”（`im:message.group_at_msg:readonly`）、“获取与发送单聊、群组消息”（`im:message`，下载文件和回复要它）；④ “凭证与基础信息”复制 App ID、App Secret；⑤ 先在 ERP 卡片填好、点“保存并连接”（飞书要求长连接在线才能保存下一步）；⑥ “事件与回调”订阅方式选“使用长连接接收事件”；⑦ 添加事件“接收消息”（`im.message.receive_v1`）；⑧ 建版本、设可用范围、发布；⑨ 单聊发文件试一下。
- **钉钉：** ① 开发者后台建“企业内部应用”；② “凭证与基础信息”复制 Client ID、Client Secret；③ 加应用能力“机器人”，接收模式选“Stream 模式”，发布机器人；④ 开通“企业内机器人发送消息权限”（`qyapi_robot_sendmsg`，下载文件要它）；⑤ 设可见范围并发布；⑥ ERP 卡片填好、点“保存并连接”；⑦ 单聊发文件试一下。
- **同一个应用只连一处：** 企业微信后连的顶掉先连的、不会抢回；飞书、钉钉把消息随机发给其中一处，更难发现。测试实例别和正式实例连同一个应用，切换时先断旧的再连新的。
- **卡片上的状态：**

| 状态 | 意思和做法 |
|---|---|
| 已连接 | 收得到 |
| 连接中、连接断开，正在重试 | 网络断了、对方限流或临时出错，程序按退避自己重试（红字“××暂时连不上（错误码 N），正在重试”）；一直不好再查服务器出站网络 |
| 连接被拒绝 | 凭据或后台配置不对，不再重试，红字写原因（如“钉钉拒绝连接（错误码 401）：请检查 Client ID 和 Client Secret。”），改对后点“保存并重新连接” |
| 红字“已保存的 Secret 在这台机器上解不开……请重新填写 Secret。” | 换了服务器、平台或服务账号，重填一次 |
| 已被其他连接顶替 | 只有企业微信有：同一个机器人在别处连上了 |

- 系统关着时收不到消息，官方没说之后会不会补发。

## 项目里不能随手删的

- 数据目录、备份目录、用户配置目录受保护：整理项目时不清库、不初始化、不删原件、归档、审计和凭据。
- `node_modules`、`dist`、`.build-tmp-*`、`.playwright-cli` 和测试日志能由安装、构建、测试重新生成。
- 本机的 `work/`、`output/`、`outputs/` 混有验收样张、截图、旧克隆和安装包，不能只凭目录名删，先查 Git 状态、引用和来源。
