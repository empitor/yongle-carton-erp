# 部署

什么时候读：部署（装 Windows 本机或 Linux 服务器、改部署设置、HTTPS 和维护通道、凭据），或查服务器现状。

结构升级和备份的程序机制相关的见 `docs/架构/数据库升级.md`，登录限频相关的见 `docs/架构/账号和权限.md`。

正式部署只用腾讯云 Ubuntu 24.04 LTS x64 服务器，同机 Caddy 负责 HTTPS；Windows 只作本机使用。两个平台各有安装包，内置 Node.js 24 和原生依赖。

维护命令：Windows 在安装目录双击 `维护命令行.cmd` 后运行 `npm.cmd run …`（源码目录直接用终端）；Linux 用服务账号运行 `scripts/linux/erp.sh`（命令清单见 `docs/运维/备份恢复.md`）。

## 本机（Windows）

- 启动：双击 `启动系统.cmd`，窗口保持打开（源码目录先构建再启动）。停止：双击 `停止系统.cmd`，或原窗口 `Ctrl+C`。
- 地址 `http://127.0.0.1:3001`，端口用 `PORT` 改。要 Node.js 24.15 以上的 24.x。
- 一个数据库只能起一个实例（锁文件 `data/erp.sqlite.running`，异常退出留下的下次自动清理）。
- 数据位置：安装目录的 `data\`（数据目录）放业务库和五个配置库：账号库、AI 识别工作区（连原件）、提示词库、助手工具设置库、出错记录库（运行日志也在这里）；`backups\` 放备份。`%LOCALAPPDATA%\ZhixuERP\`（配置目录）放另两个配置库：AI 设置库（DeepSeek 密钥）、机器人设置库（机器人凭据），用当前 Windows 账号加密，换电脑或账号要重填。

## Linux 服务器部署

### 安装

全新安装用 `yongle-carton-erp-v<版本>-linux-x64.tar.gz`（现在是 0.9.5），不要复制 Windows 的 `runtime` 或 `node_modules`。先装中文字体（单据排版靠它量字宽，缺了启动会拒绝）：

```sh
sudo apt-get update
sudo apt-get install -y fonts-noto-cjk fontconfig
sudo fc-cache -f
fc-match 'Noto Serif CJK SC'
```

程序解压到 `/opt/yongle-carton-erp`（root 所有，服务账号只读）；数据、备份、凭据在 `/var/lib/yongle-carton-erp/` 下的 `data`、`backups`、`config`。

```sh
sudo sh /opt/yongle-carton-erp/scripts/linux/install-service.sh
sudo editor /etc/yongle-carton-erp/erp.env
sudo systemctl start yongle-carton-erp
sudo journalctl -u yongle-carton-erp -f
```

安装脚本建系统账号 `yongle-erp`，装 systemd 服务并开机自启（崩溃 5 秒后重启，日志进 journald）；不自动首次启动、不覆盖已有配置、不改防火墙。停止、重启用 `systemctl stop|restart yongle-carton-erp`。

### 部署设置

写在 `/etc/yongle-carton-erp/erp.env`（示例 `scripts/linux/erp.env.example`）。**API 密钥和机器人 Secret 不写这里**，在网页设置页填。

| 配置 | 用途和默认值 |
|---|---|
| `ERP_DEPLOYMENT` | `1` 启用部署；省略或 `0` 是本机模式 |
| `PORT` | 本机维护端口，默认 `3001` |
| `ERP_PROXY_PORT` | 给同机 Caddy 的回环端口，部署时默认 `3002`，不能和维护端口相同 |
| `ERP_ALLOWED_HOSTS` | 允许的域名，逗号分隔，部署时必填；非标准 HTTPS 端口要同时写进 Host 和 Origin |
| `ERP_ALLOWED_ORIGINS` | 允许的 HTTPS 写请求来源，默认允许域名逐个加 `https://` |
| `ERP_BACKUP_COPY_DIR` | 每日完整备份另复制到的绝对路径，默认关；要在 systemd 的 `ReadWritePaths` 放行并给服务账号权限 |
| `ERP_BACKUP_COPY_KEEP` | 复制目录里自动备份留几份，默认全留 |
| `ERP_ICP_RECORD` | ICP 备案号原样写（如 `浙ICP备…号`）；从域名打开的网页最底部显示，链到工信部查询。不填不显示 |
| `ERP_POLICE_RECORD` | 公安备案号原样写（如 `浙公网安备 …号`）；同样显示，按号里的数字链到公安查询。不填不显示 |
| `DB_PATH`、`ERP_BACKUP_DIR`、`ERP_CONFIG_DIR` | 业务库、备份根目录、凭据目录。AI 工作区、原件、提示词、日志跟着业务库目录 |

### HTTPS 和维护通道

- 3001（维护）、3002（只给同机 Caddy）都只听本机回环。Caddy 配置照 `scripts/linux/Caddyfile.example`（代理会覆盖 `X-ERP-Client-IP`，不信访客伪造的头），改完先 `caddy validate --config /etc/caddy/Caddyfile` 再重载。示例限了请求体 21MB（程序最大上传 20MB，改上限两处一起改）和读超时（不设写超时，助手要长时间边算边推）。Caddy 前面还有别的代理时，先核对它看到的对端是不是真实访客。
- 防火墙只对员工开 80/443；3001、3002 不开；SSH 22 只放维护者 IP（改规则前确认控制台网页登录能当备用通道）。
- 维护和首次建管理员走 SSH 隧道（隧道不要听 0.0.0.0，维护端口不能当公网代理的上游）：

```sh
ssh -L 13001:127.0.0.1:3001 operator@your-server
```

  然后本机打开 `http://127.0.0.1:13001`；维护电脑同时开着本机 ERP 时改用 `http://localhost:13001`（Cookie 只按主机名区分，否则两边互相顶掉登录）。
- 从域名进来的登录 Cookie 带 `__Host-` 前缀和 Secure（本机和维护通道叫 `erp_session`），部署入口加 HSTS，域名访问的健康检查只回 `ok`；部署时关掉服务器上的浏览器，员工网页里的页面控制照常。

### 从公网和从维护通道能做的事

- **只有维护通道能做**（从服务器本机回环登录的管理员才算“本机管理员”，从域名进来进了超级管理员模式也不算）：首次建管理员、初始化业务数据、数据管理（直接改档案、采购单、库存品、待核对的单据和生产任务；已生效的到货、送货、完工单只能编辑说明或更正，相关的见 `docs/功能/单据更正.md`）、AI 导入里改已导入的识别结果、复制成新文件和永久删除识别文件、助手的一键清空和数据管理命令。这些不可逆或绕过业务校验，有意不对公网开。
- **从公网也能删：** 没核对的单据有编辑权限就能删；已核对的单据和客户、产品、订单、供应商、采购单、库存品，要超级管理员先进超级管理员模式（账号菜单“系统维护”，输本人密码，15 分钟），确认时再输一次，删前自动快照、写审计。助手删除同样。少了“只能本机删”这道门，账号密码要管好。
- **从公网改共用设置也要先进超级管理员模式：** 管理账号，改 AI 设置（密钥和识别设置）、提示词、机器人凭据、助手工具开关；看、查余额、重新测试不用。
- **登录限频和排队：** 同一账号名从公网 15 分钟输错 20 次就锁（跨地址累计），维护通道照常能登。核对密码同时只算 2 个，排不上回“服务器正忙，请稍后再试。”（页面自动再试一次、不算输错）；维护通道登录和已登录的人验密码排在从域名登录的前面。排队常量在 `server/accounts/hash-queue.ts`（按开发机估的）。

### 凭据和主密钥

- 凭据目录默认：Windows `%LOCALAPPDATA%\ZhixuERP`；Linux `$XDG_CONFIG_HOME/zhixu-erp`（没设就是 `~/.config/zhixu-erp`），部署时由 `ERP_CONFIG_DIR` 指定。
- Windows 用当前账号的 DPAPI 加密。Linux 用 AES-256-GCM，第一次自动生成 32 字节的 `credentials/master.key`；凭据根目录和密钥目录要属于服务账号、权限 0700，密钥文件 0600、不能是链接，不对就拒绝启动（不退回明文）。不要用 `chmod 777` 解决。
- **主密钥不进任何备份，要单独加密保管。** 备份里的凭据库是密文，丢了主密钥只能到设置页重填。Windows 的凭据不能跨平台解密，迁到 Linux 后要在服务器页面重填 DeepSeek 密钥和机器人 Secret。
