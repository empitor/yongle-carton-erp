# 打包和客户端更新

什么时候读：打 Windows 或 Linux 安装包、在 Linux 上验包和跑测试、往服务器放安卓和 Windows 客户端的更新包。

## 打包和 Linux 验证

两个包用同一个脚本，必须在各自平台的 Node 24 x64 上打（`--target win-x64` 或 `linux-x64`），不能复制别的平台的原生依赖；主密钥不进安装包。程序文件清单在 `scripts/release-files.mjs`（运行时要用的新脚本或目录要加进去），发布扫描规则在 `scripts/release-scan.mjs`，整包和补丁共用。

- **Windows 包：** 开发机上 `npm run package -- --out <项目外的目录>`；检查也在开发机上跑（`npm run check`）。
- **Linux 包和 Linux 上的测试：** 在服务器的打包目录 `/home/ubuntu/build/` 里做，和 `/opt` 里正在运行的程序、`/var/lib` 下的数据分开，用程序自带的 Node，全部是临时目录里的虚构数据。自己的检查不放在 GitHub 上跑（那边的机器慢，靠时间的测试会误报）。服务器比开发机慢，设 `CI=1` 让慢测试只报不拦；代码检查、类型这些和平台无关的只在开发机上跑（服务器内存小，不在上面跑）：

  源码从开发机送过去（服务器在国内，连 GitHub 时通时断）：开发机上 `git bundle create v<版本>.bundle v<版本>`，`scp` 到服务器的 `/home/ubuntu/build/`；提交号和 GitHub 上的标签是同一个。

```sh
export PATH=/opt/yongle-carton-erp/runtime/node/bin:$PATH
cd /home/ubuntu/build
git clone --branch v<版本> v<版本>.bundle src-v<版本>
cd src-v<版本>
export LOCALAPPDATA="$(mktemp -d)" CI=1
export ERP_CONFIG_DIR="$LOCALAPPDATA/config" DB_PATH="$LOCALAPPDATA/unused.sqlite" ERP_BACKUP_DIR="$LOCALAPPDATA/backups"
npm ci
npm test
npm run test:release
npm run package -- --target linux-x64 --out /home/ubuntu/build/out
```

- **装之前验包：** 核对 sha256，解压到单独的目录，在里面用包里的 Node 跑 `runtime/node/bin/node --import tsx scripts/linux/verify-runtime.mjs`（运行环境、原生依赖、字体、单据排版）。`scripts/linux/verify-package.mjs`（干净目录启动、建管理员、登录、导出、备份恢复）跟不上程序了，修好之前只能跑到“启动、建管理员、登录”，见 `docs/计划/已知问题.md`。

## 客户端更新包

安卓 App 和 Windows 客户端（`apps/`）的“检查更新”先读服务器上的版本清单，再下载安装包。两者放在同一域名下的固定目录，由 Caddy 直接当静态文件发，不经 ERP、不用登录：

| 地址 | 是什么 |
|---|---|
| `https://erp.nbyongle.cn/app-update/android/manifest.json` | 安卓版本清单（格式见 `apps/android/docs/构建与测试.md`“应用内更新”） |
| `https://erp.nbyongle.cn/app-update/android/<安装包>.apk` | 安卓安装包 |
| `https://erp.nbyongle.cn/app-update/windows/latest.json` | Windows 版本清单（Tauri 格式，见 `apps/desktop/docs/构建与测试.md`“应用内更新”） |
| `https://erp.nbyongle.cn/app-update/windows/<安装包>.exe` | Windows 安装包 |

- **服务器目录：** `/srv/yongle-erp-app-update/android/`、`/srv/yongle-erp-app-update/windows/`，属于维护账号、Caddy 能读（目录 0755、文件 0644）；不在 ERP 的安装和数据目录里，升级、备份恢复都不碰。文件名只用字母、数字、`.`、`-`、`_`（Windows 打包出的中文名上传时改掉，清单写改后的名字）。没有文件时 `/app-update/` 回 404，不交给 ERP。
- **Caddy：** 写法只在 `scripts/linux/Caddyfile.example` 的 `/app-update/` 一段（清单不让缓存），服务器上已照它配好；以后改完先 `caddy validate` 再重载。
- **发新版的顺序：** **先**传安装包、确认能从域名下载且 sha256 一致，**再**传清单（反了客户端会看到新版却下不到）。打包、签名、清单写法见两个外壳各自 `构建与测试.md`“正式发布的顺序”。
- **客户端里的地址：** 打包时写进安装包，都已填好：更新清单地址（安卓 `releaseUpdateUrl`，Windows `config/app.json` 的 `updateUrl`、`updatePubkey`；没填就发出去的客户端永远不会自己更新），正式版打开的 ERP 地址（安卓 `apps/android/app/build.gradle.kts` 的 `releaseUrl`、Windows 的 `erpUrl`）。第一个正式版 0.1.0 已于 2026-11-21 放进更新目录：安卓 `https://erp.nbyongle.cn/app-update/android/yongle-erp-0.1.0.apk`，Windows `https://erp.nbyongle.cn/app-update/windows/yongle-erp-0.1.0-x64-setup.exe`；第一次手动下载安装，之后客户端自己提示更新。
