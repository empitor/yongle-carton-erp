# 路线图

只写还没做的事。做完就删；做完还没发布的写进[更新日志](CHANGELOG.md)。

发布前按[升级到 0.9.0](部署与运维.md#升级到-090)核对操作步骤。

## 下一步

- **财务复核：** 请懂账的人核对科目名称、报表行项目、附加税率、小规模征收率优惠和相关法规条款。另有两个待定：启用期初和成本窗口的存货期初要手工保持一致，要不要系统校验；员工借还款沿用 `1221` 不分员工核算，要不要设专用科目。
- **用真实业务跑一遍（等域名备案通过后做）：** 真实客户订单已在隔离环境走过识别、导入、生产、送货、导出，但没在正式系统长期用过。备份后录入真实客户和产品，走完 机器人收文件 → 收件箱 → AI 识别 → 订单 → 生产 → 送货，记下卡住和别扭的地方再修。真实供应商单据见“待验证”。
- **页面地址参数登记：** 页面名登记在 `shared/assistant/assistant-navigation.ts` 的 `erpPages`，地址参数（`#inbox?item=`、`#ai-import?workspace=`、`#orders?order=` 等）没登记，改名会悄悄失效；要登记在同一处、由测试比对。
- **库存的全库一致性核对：** “已撤销单据名下的出库加冲销等于 0，待核对和已取消的单据没有流水”、逐笔余额重算对不上、库存和账面价值对比，写不成约束，做成系统体检（`system.check`，现在只查完整性、断开的关联和负库存）里的一项（参考 ERPNext 的自查报表，只借思路）。
- **恢复备份时 `_extra/` 的配置库不按版本拒绝：** AI 配置、机器人配置恢复时本来就不覆盖本机，却会因为版本比程序旧或新让整份备份被拒（`server/core/backup-check.ts` 的 `validateConfigDatabase`）；改成只查完整性，守着“比程序新就拒绝”的测试一起改。
- **配置库加第一个升级步骤之前要处理：** 升级前的 `.bak` 复制在拿写锁之前做、也不自动清理；账号库的 `.bak` 里会话没清；补丁回滚只换回程序时，旧程序会因配置库“比程序新”起不来；恢复时没登记位置的配置库只查完整性、不提示，可以让恢复命令列出“只查了完整性的文件”。
- **应用外壳（路线已定、未开工）：** 先加网页清单和图标，能安装到桌面；安卓用 Capacitor 打 APK，放 `apps/android/`；电脑用 Tauri 打包，带开机自启和托盘图标，放 `apps/desktop/`；安装包和签名密钥不进仓库。不做企业微信相关的（消息机器人用哪家，动手前先问用户）。
- **代码审查留下的低优先项：** 反结账后对当期计提和成本重算的保护；切换“正常 / 已归档”和关闭新建窗口时同步 URL。
- **企业微信机器人接入 AI 助手**（用户说先不动；开工前先拿接入方案给用户看）：员工在企业微信里单聊机器人，提问、发文件、办简单的事，不用登录 ERP；客户的文件仍由员工转给机器人。放开的对象只限员工。
  - 思路：企业微信 userid 绑定 ERP 账号，没绑定的不回答，权限沿用账号；每个员工一段连续会话，说“换个话题”重开；复用网页助手的命令、权限和审计；回复转成手机上几行文字，用 stream 边想边出；查询直接答，写入回一个链接到系统里确认（要等备案后域名开放），删除和财务写入不上机器人；员工发文件后说“转订单”接上收件箱和导入。
  - 顺序：先单聊、先只读，再做写入；群聊先不做（回答全群可见，权限不好管）。
  - 待查：企业微信回复有没有时限、带按钮的模板卡片能不能用；每问一句都调一次模型，有费用。

## 时机到了再做

- **识别结果和原文自动核对**（LangExtract 的做法）：Excel、Word、带文字层的 PDF 这类有原文的，识别出来的值在原文里找不到就自动标“拿不准”。是新功能，开工前先跟用户说。
- **DeepSeek 的严格模式用在识别那两张表上**：能让交回的表一定合结构，可能省掉不合格重试；要走测试版地址，先用识别对比脚本实测再定。助手的命令不用（要求全部必填，改动大收益小）。

## 公网开放前必须做

服务器现状见[部署与运维](部署与运维.md#当前服务器)。

备案通过后按顺序做：

1. 腾讯云控制台防火墙确认开放 80/443（证书申请和 HTTP 跳转都要 80）。
2. `sudo systemctl enable --now caddy`，看 `journalctl -u caddy` 里证书申请成功。
3. 电脑、手机分别访问 `https://` 域名：登录、上传文件、手机语音。
4. SSH 22 限定为维护者 IP（先确认控制台网页登录能用作备用通道）；3001/3002 保持不开放。

还没做：

- 验证服务崩溃后自动重启。
- 用到的机器人（企业微信、飞书、钉钉）在服务器页面“设置 → 消息接入”重新填应用编号和 Secret（模型密钥已填；Linux 主密钥要单独保管）。
- 切换机器人时先停本机那一家的连接，再开服务器的。
- 配置备份复制到服务器之外，做一次完整的部署和备份恢复演练。
- 用真实网络和多人同时使用试一次（压测只测过单请求）。
- 服务器上的 Caddy 配置照新的 `scripts/linux/Caddyfile.example` 补上请求体上限和读超时，`caddy validate` 过了再重载（示例在开发机上没能校验）。
- 在服务器上量一次登录核对密码的耗时，按需要调 `server/core/hash-queue.ts` 的几个常量（现在按开发机一次约 30–60 毫秒估的，2 核服务器没量过）。

## 服务器部署之后

- **微信客服或会话存档：** 让客户的消息自动进收件箱。微信客服已否决（折叠、不像好友）；会话存档要客户同意、公网 IP、官方 SDK，费用待查，只能拉近 5 天。
- **发送人姓名：** 企业微信、飞书机器人收到的消息只显示发送人编号，钉钉有昵称。

**范围很小的风险：**

- 助手执行的初始化在外层事务里：外层回滚时业务数据恢复，但已删掉的 AI 识别工作区文件回不来。
- 助手读到的精确单价是四位小数，回复里可能说“1.5000 元”。
- 财务概览“需要处理”里缺价格和缺数量在服务端（`server/finance/monthly.ts` `missingPrice`）合算成一个总数，没有分开数。
- 启动时先打开（空的话新建）业务库再检查配置库；配置库被拒时数据目录里会多出一个空的业务库，不动旧数据（只调 `server/index.ts` 打开顺序修不全：助手工具设置库与识别工作区库建的时候就要 store，要先按登记清单核对全部配置库再开业务库）。
- 管理员改了已算成本月份流水的数量，成本不自动调整，会提示先重做上月成本。
- 助手按批导入时，前一份刚建的产品没有尺寸，后一份同名的会被拦下问。
- 采购、到货明细的计价方式默认“按平方米”，新建原材料库存品名称默认“瓦楞纸板”，是预填的猜测。
- 完工单冲销按原成本冲回原材料和成品，原来分摊进生产成本的制造费用留在 `400101`。
- 按送货确认收入时，销售蓝票不生成凭证，也不检查累计开票是否超过送货金额。
- 开票确认收入时，同一笔应收挂了几张发票、只部分红冲其中一张，应收会暂时偏少。
- 未到票就退货、退货冲减了暂估，之后先到票、再撤销该退货单时，暂估不会恢复。
- 在已结账月份物理删除盘点流水或完工单（删除时选“流水一起删”）后，下次成本计算报“期初数量和上月月末成本对不上”（`server/finance/costing-compute.ts`）。
- 开票确认收入时，毛利的收入按单据日期、成本按出库月份，和总账按开票月份记的收入可能不在同一个月（按送货确认收入时已对齐）。
- 送货页“可发货”的待发数没扣已经排在待送货单上的数量（可用量已扣）。
- 订单编辑窗开着时业务数据变了会重建表单、冲掉正在填的内容（`src/records/RecordEditors.tsx` `OrderEditor` 的 `key` 带了版本号）。
- 库里一条坏的账期约定或保证金退回记录会让整个对应列表读不出来、整页回 500（`StoredDataError`）。
- 没启用财务时打开“凭证账簿 → 账簿”页签报错（“账簿期间必须在财务启用之后。”）。
- 未提交的红字凭证详情里仍显示“编辑”按钮，但服务端一定会拒绝编辑。
- 首个管理员（只在本机建）核对密码排不上队时，账号已建好、要重新登录一次。
- 库里一张单据内容对不上结构（只有直接改库才会出现）时，财务同步整批停在这张上；今日看板、经营概况、财务概览读到坏单据或坏的事件快照也整页回 500。要改成跳过这一条并在出错记录里标出来。
- 财务事件快照的结构照抄单据结构：以后单据改了字段类型，旧快照会整批读不出来，改单据结构时要同时定快照怎么办。
- 财务的期末明细和防重复重放的结果按结构输出，多出的键会被悄悄去掉。
- 每个财务请求查两次会话，可以合成一次。
- 财务的上传（银行流水、发票原件、工资表）和原件下载没有走 HTTP 的测试。
- **跨月冲销或更正到货单，成本计算会卡死或记重（要先定口径再改，启用财务记真实账之前必须修）：** 冲销流水的日期是冲销当天；冲销流水找原单据只走 `server/finance/costing-origins.ts` 的 `originOf`，到货冲销只在“到货和冲销在同一个月”时成对抵消（`reversalOrigin`）。上月的到货在本月冲销或更正时：① 上月成本还没算、上月没结账、或上月反结账后重做，算上月成本都报“原材料到货财务资料未完成”（`costing-compute.ts` 的 `arrivalEventOf` 取的是现在的事件，已不是 `generated`），单据已作废补不了资料，之后各月的成本和结账全部卡住；② 本月算成本时这笔冲销被当成普通出库，要人选对方科目并再贷一次 1403，和红字暂估凭证重复，库存成本表和总账对不上；③ 跨期补登的到货（日期在上月、上月成本算完后才登记）在本月冲销，本月成本同样算不出。要定的口径：作废的到货在到货那个月、冲销那个月各怎么计（数量要和上月月末对得上）。改完补跨月的测试，现在没有测试守着跨月的行为。

- 撤销采购退货的助手卡片上有一行“采购退货 TH-…：有改动但列不出明细”（采购退货状态在修改历史的词表里没有叫法）。
