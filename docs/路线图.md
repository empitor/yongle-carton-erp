### 6. 开始记真账之前要定、要做的财务几件

- **财务事件明细子表 `fin_event_lines`（要做）：** 事件、行号、订单、订单明细、产品、采购明细、金额。现在订单的财务段、毛利、发票匹配要拆事件快照的 JSON 查，量大会慢；记真账以后再改代价大。
- **部分到票的到货撤销后，要等红票才能结撤销那个月（要用户定）：** 撤销后补扫出的“有差异”按原到货日期拦结账，红字冲销又要先开红票（`server/finance/event-correction.ts`），所以撤销那个月起各月都要等红票、红冲做完（全额到票也一样）。红冲按默认日期（撤销那天；那个月已经结账就是最早没结账那个月的月初）记时账都对得上；只有把红冲日期改到以后再结撤销那个月，才会带着差额（少了余量暂估那么多）结账。可选：撤销那个月先不冲余量暂估；或允许没开红票先红冲余量暂估（同时解开等红票）。
- **采购退货和撤销到货的“数量为 0 还有余额”口径不同（要用户定）：** 撤销到货后数量为 0 时，只留到过票、等红票的那部分，其余转主营业务成本；未到票的退货，同月有到票调差或红票冲减就整笔结清，没有就整笔留着等红票、均价差也挂着（`server/finance/costing-compute.ts` 的 `valueRaw`）。同种料同月两者都有时，退货那笔会提前转成本、红票到了再结回来。要不要改成和撤销到货一样。
- **启用期初和成本窗口的存货期初要不要系统校验（要用户定）：** 现在两边各录各的，要手工保持一致（`server/finance/opening.ts` 只核总账期初和辅助明细、借贷平衡）。
- **员工借还款要不要设专用科目（要用户定）：** 现在默认用 `1221`；预置的 `1221` 没开员工辅助，员工姓名和工号只写进凭证摘要和审计（`server/finance/expenses.ts`）。

### 7. 等用户定的两件小事

- **到货明细的空白单价：** 采购明细的单价只填空格算“没写”，到货明细却报“单价最多四位小数”（界面只把留空的转成空值，填了空格照样被拒，`src/flow/ArrivalLineCard.tsx`）；要不要统一成没写。
- **长期记忆搬不搬进业务库：** 现在长期记忆和按账号的设置在助手设置库（单独的配置库，走自己的升级步骤，业务初始化不清，见[数据模型](数据模型.md)“其他数据库”）。搬不搬、搬了以后升级、备份恢复、初始化怎么办，开工前先给用户看方案。

  - 同一条待处理收件在两个标签页同时点“新建订单”并各自保存时，会建出两张订单，且后一次标记 `converted/order` 在服务端按目标状态相同直接返回成功（`server/inbox/service.ts`），两个窗口都提示成功。
  - 启动时先开（空就新建）业务库再查配置库；配置库被拒时会多出一个空业务库，旧数据不动。只调 `server/index.ts` 的顺序修不全：助手工具设置库、识别工作区库建时就要 store，要先按登记清单核完全部配置库再开业务库。
  - `import:restore` 权限只在级别里发给管理员（`server/accounts/account-db.ts` 的 `levelGrant`），全项目没人检查。先查清“恢复导入”现在靠什么权限把关：有别的就删这个名字，没有就让它真查。
  - 首个管理员（只在本机建）核对密码排不上队时，账号已建好、要再登一次。
- *财务：*
  - 已结账月份的正式报表也要先等业务单据同步进财务：结账后才确认或撤销、日期在已结账月份的单据没同步前，那个月起的正式报表出不来、快照也读不了。打开财务和助手查财务前服务端都先补扫，大批单据要几个请求才扫完。
  - 完工单冲销按原成本冲回原材料和成品，分摊进生产成本的制造费用留在 `400101`。
  - 按送货确认收入时，销售蓝票不生成凭证，也不查累计开票是否超过送货金额。
  - 开票确认收入时：一笔应收挂几张发票、只部分红冲一张，应收暂时偏少；毛利的收入按单据日期、成本按出库月份，可能和总账按开票月份记的收入不在同一个月。
  - 未到票就退货冲了暂估，之后先到票再撤销退货，暂估不恢复。
  - 在已结账月份物理删除盘点流水或完工单（选“流水一起删”）后，下次算成本报“期初数量和上月月末成本对不上”（`server/finance/costing-compute.ts`）。
  - 单价为 0 的有效到货（财务事件“无金额”）算成本时被拦，报“原材料到货财务资料未完成”，补不了。
  - 财务概览“需要处理”的缺价格、缺数量在服务端合成一个数（`server/finance/monthly.ts` `missingPrice`）。
  - 一条坏的账期约定或保证金退回记录让整个列表整页 500（`StoredDataError`）。
  - 单据内容对不上结构（只有直接改库才会）时，财务补扫逐条跳过并记出错记录；但今日看板、经营概况读到坏单据、财务各页读到坏事件快照仍整页 500，要改成跳过并记出错记录。
  - 没启用财务时开“凭证账簿 → 账簿”报“账簿期间必须在财务启用之后。”。
  - 未提交的红字凭证详情仍显示“编辑”，服务端一定拒绝。
  - 期末明细和防重复重放的结果按结构输出，多出的键被悄悄去掉。
  - 每个财务请求查两次会话，可合成一次。
  - 财务的上传（银行流水、发票原件、工资表）和原件下载没有走 HTTP 的测试。
  - 记真账之前要定的几件见第一节“开始记真账之前要定、要做的财务几件”。

## 暂不做

- 财务写入、账号管理和设置不开放给助手。
