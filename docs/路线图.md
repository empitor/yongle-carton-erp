## 上服务器前必须做

详情见[部署与运维](部署与运维.md)。

- 公网安全审查要包括不用登录的 `/api/auth/apply` 和 `/api/auth/forgot`

已定：Ubuntu 24.04 LTS x64，维护人通过指定 IP 的 SSH 和维护端口隧道管理，员工只用 HTTPS 网页。Windows Server 保留备选。

代码改造已完成，下面是到服务器上才能做的：

- 办域名和备案（如需要），装证书
- 在服务器上安装 systemd 服务，验证开机自启和崩溃重启；Windows 备选仍使用计划任务
- 用 Caddy 或 IIS 配好反向代理并实际跑通 HTTPS，确认防火墙向员工仅开放 80/443，SSH 限定来源 IP
- 机器人 Secret 在服务器页面重新填写（模型 API 密钥已在服务器填好；Linux 主密钥须单独保管）
- 切换机器人时先停本机连接，再开服务器连接，不要同时连同一个机器人
- 配置备份复制到服务器之外，并做一次完整的部署和备份恢复演练
- 用真实网络和多人同时使用试一次（压测只测过单请求）
- 确认反向代理的压缩生效（步骤见部署文档）

## 待决定

- 财务派生凭证的撤回：票据、资产处置、报销、坏账、利息、保证金生成的凭证在凭证页不能作废，来源模块也没有撤回按钮。是否做成草稿可撤回、已记账可红冲。定了之后保证金余额要一起排除作废凭证
- 是否需要外币（财务第一版只有人民币）
- 工资、个税、社保是否要算（第一版只导入汇总）
- 是否对接税局（第一版不直连，只留接口）
- 收件箱聊天内容的保留期限，并告知相关人员
- 是否要让 AI 回答员工的业务问题（机器人现在只收件）

## 暂不做

- 模拟点击控制微信或企业微信：有封号风险，只有用户明确决定要试点时才考虑。
- 破解客户端、读取本地聊天数据：不做。

## 业务研究

- 物理切割、跨型号共用纸板、实际投入和废品归属：现在的领料分配不等于排版事实，要作为明确的业务模型研究。
