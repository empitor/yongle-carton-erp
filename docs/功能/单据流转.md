# 单据流转

什么时候读：改到货、生产任务、完工、送货单据（存、读、归档、登记到货、安排送货、登记完工）或订单进度时。

单据怎么存和读、归档、登记到货、完工、送货、订单进度怎么算。已生效单据的更正、编辑说明、撤销相关的见 `docs/功能/单据更正.md`；库存流水和库存品相关的见 `docs/功能/库存.md`；先预览再确认、防重复提交这些通用做法相关的见 `docs/架构/服务端写法.md`。

## 单据

- **单据：** 到货、生产任务、完工、送货单都存 `flow_documents`，只由 `server/flow/documents/document-store.ts` 写（5 个镜像列由 `flowColumns` 从 `document` 算），同时维护关联索引 `flow_refs`。
  - `document` 列是 `shared/business/flow/flow-document.ts` 的严格结构（每种单据一份，多键、类型不对、缺必填都报错），只存单据内容，不存行上的列和派生字段。
  - 读库里的内容只经 `server/flow/documents/read.ts` 的 `storedContent`；别的服务端模块写 `parseStoredJson(flowDocumentSchema(种类), row.document, …)`。写前按同一份结构核对，不过按服务端错误报（500“保存失败，请检查服务日志后重试”）。要视图走 `FlowService.get(id, kind?)`、`list(kind)`；收视图再写回用 `viewContent`。
  - 服务端写的字段分生命周期记录（`lifecycleFields`）和抄下来的快照。快照每一项跟哪个引用登记在 `shared/business/flow/flow-snapshot.ts`（缺一项编译不过）。重新保存单据的路径（三种更正、改已下达的任务、管理员连带的整份替换和拆单）都过 `keepSnapshot(原单, 新单)`：引用没变的留原单的，换了的按新的取（单据内容的存法相关的见 `docs/生成/表结构.md`）。
  - 有效只看 `status` 是 `confirmed`；`draft` 界面叫待送货、待入库。生产任务没有 `draft`，新建就是已下达（建表也拦）。核对入库、出库先预览再确认（`server/flow/rules/preview.ts`、`confirm.ts`）；前端的核对请求只有 `src/flow/flow-api.ts` 的 `previewFlow`、`confirmPreview`。
- **归档：** 单据、档案、识别文件的归档恢复只有 `server/core/records/archive.ts` 的 `changeArchive` 一种做法（批量、逐条事务、版本校验、审计），各处只给 `ArchiveTarget`；业务库记录用 `recordArchiveTarget(store, { load, blocked, after? })`。什么时候不能归档：单据 `server/flow/documents/archive.ts`，档案 `server/lifecycle/lifecycle.ts`，识别文件 `server/import/workspace-files.ts`。连已归档一起看要超级管理员模式。能归档、能记墓碑的记录种类由主人模块登记（`registerRecordKinds`），写前核对；加一种只要登记，不改表。
- **读单据和回答结构：** 按编号读一批用 `read.ts` 的 `storedDocuments`。单据视图、保存、排期、登记到货、批量登记完工的结果都按结构核对；只读接口的回答结构在 `shared/business/flow/flow-views.ts`。到货记录没关联采购单的行，页面写“无采购单”。仓库台账 `GET /flow/daily` 带 `doc`（到货单、送货单编号）时只组装这一张、连已归档的（找不到或种类不对 404，生产任务被拒）；不带时不含已归档的。

## 到货

- **采购已到货：** `purchase_lines.received_units` 是缓存，由 `server/flow/rules/receipt-events.ts` 按有效到货单减没冲销的退货重算，只算相关采购单。基本视图读缓存，完整视图现算。
- **登记到货：** 只有 `server/flow/arrival/register-arrival.ts` 的 `registerArrival` 一个入口（`POST /api/order-batches/:id/receive`、助手 `order_batch.receive`）：按订货单分到各条采购明细，每行可另给入库数量（不给等于合格数）；采购单还没订货单时同一事务里补建。挂采购明细的到货单只能这样存，通用保存只收不挂采购单的货。AI 识别的送货单带 `pending` 存成待入库。

## 生产和完工

- **完工：** 登记完工只有 `server/flow/production/batch-completion.ts` 的 `ProductionCompletion` 一个入口（页面、助手共用；挂任务和不挂任务的一起登记，按产量分领料）；`POST /api/flow/production` 新建一律拒绝，数据管理也不能新建完工单。可先登记成待入库再逐张核对；每张任务还能登记的 = 计划 − 已入库 − 已登记待入库。
- **生产任务完工了多少：** 只在 `shared/business/flow/task-progress.ts` 算，服务端和登记完工都调它，前端只管显示。要合计的数（订单明细已发、任务已完工和待入库、待送货单占用的库存）在 SQL 里直接取那几列，不整份解析单据。
- **计划日：** 生产任务和送货单的计划日由表级 CHECK 保证；录入没给时用单据日期。

## 送货

- **送货：** 新建只有“安排送货”一个窗口（`src/warehouse/DeliveryPlanDialog.tsx`）；超订单数量要写原因、要超级管理员模式。
  - 税率、含税口径由 `shared/core/tax-rate.ts` 的 `orderTaxSnapshot` 按明细、整单的顺序各取第一个有的（认不出的原话也算有）。税率有规范值时 `0 < 税率 < 1` 保留 `%`、其余抄不带百分号的数字；规范税率为空时只抄认不出的税率原话（不抄“口径：”行）。口径没选、原话里有“口径：…”的，连“口径：”一起抄，财务一律记资料待补。更正沿用同一订单明细的行时保留原送货快照。
  - 能发哪些、同一份库存按交期先后怎么分只在 `shared/business/flow/warehouse-delivery.ts`；排出送货单、按客户默认厂区预选收货厂区并带出收货信息（可拆给别的厂区）、几个客户等同一种货、送不了的原因、超订单的行只在 `shared/business/flow/delivery-plan.ts`。安排送货窗、仓库页“可发货”、助手 `delivery.plan` 都调它们。
  - 待送货单每次保存都按所选厂区（没选取默认厂区）重新取收货信息（`server/flow/rules/validate-delivery.ts` 的 `deliveryDestination`），客户改了厂区资料时也当场跟着换（`site-edits.ts` 的 `followSiteEdits`，相关的见 `docs/功能/客户产品订单.md`“客户厂区”）；出库、更正、说明编辑都沿用单上存的那份。
  - 待送货 → 导出送货单并出库（单据导出调 `FlowService.shipDelivery`，导出和交付跨零点时带上出库日），或“不导出直接出库” → 确认送达（只记送达日，不动库存）。出库那天就是单据日期，财务按它归月。

## 订单进度

- **订单进度：** 生产中、待发货、已发货由 `server/flow/rules/order-progress.ts` 的 `updateOrders` 按有效单据重算，本机管理员改订单后也只由它重算。规则：明细全发完是已发货；有已下达的生产任务时，未发完的每个产品都做够是待发货、否则生产中；没任务但发过货是待发货；都没有是已确认。没出过库的待确认、已取消是人定的，不被覆盖；人能点的状态动作（确认、退回待确认、取消、恢复）在 `server/orders/order-status.ts`。“部分发货”不存、显示时派生。
  - `sales(store)` 的 `order`、`orders`、`ordersByIds` 返回普通 `Order`。订单服务的 `trackedOrder`、`trackOrders` 返回 `TrackedOrder`，一批订单分别查一次单据流转的 `shippedByLine` 和采购库存的 `materialByOrder`。仓库送货台账直接用 `shippedByLine`。
  - 订单算不算数、还能不能送、是不是已结束只在 `shared/core/domain.ts` 判断（`effectiveOrder`、`deliverableOrder`、`closedOrder`，SQL 用 `uncountedOrderStatuses`）；详情的状态按钮按 `shared/business/operations/record-status.ts` 出现；下一步提示 `shared/business/overview/order-next-step.ts`；今日页分组 `server/overview/workbench.ts` 的 `buildToday`。
