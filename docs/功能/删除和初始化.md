# 删除和初始化

什么时候读：改物理删除（删除预览和执行、谁能删、删除规则登记、库存怎么处理）或初始化业务数据时。

日常是归档（相关的见 `docs/功能/单据流转.md`），这里只讲物理删除和初始化。“删除和初始化前调用 `snapshotBeforeDestructive`”这条业务规则相关的见 `docs/业务规则.md`。

## 删除和初始化

- **一条路：** 物理删除只有删除归档模块的 `server/lifecycle/database-maintenance.ts`：页面 `/api/deletions/preview`、`/execute`，本机数据管理（打开同一个删除窗、发同一个地址），助手 `records.delete` 都走它。
  - 先预览影响清单，提交时核对同一范围摘要（会连带别的记录时必须带）。删前 `snapshotBeforeDestructive`（初始化也用：把业务库一致地复制到数据目录的 `snapshots/`，5 分钟内没写过就复用上一份，拍不成报 507、本次不执行），写审计和墓碑。
  - 不另拍快照的删除只有 `deleteAfterSnapshot`，要拿本库的快照凭证 `TakenSnapshot`（同一操作里已拍过快照的调用方才有，比如本机管理员改订单连带删整张送货单）。
  - 客户编辑里去掉厂区也算破坏性操作：订单服务删之前拍快照（`TakenSnapshot.take(store, 'customer-site-delete')`），助手试执行卡片时不拍。
- **谁能删（`deletionAccess`）：** 本机管理员都能删；不在本机时，还没核对的到货、完工、送货单有业务编辑权限就能删，其余要超级管理员模式加本人密码。拒绝分 401 `authentication`、403 `permission`（不是超级管理员账号）、403 `super-mode`（没进模式）。
- **规则登记：** `server/core/records/deletion-rules.ts`，各模块在自己的 `deletion.ts` 登记（财务只登记初始化）。删除只改业务的表，被删的来源由财务下次补扫发现（相关的见 `docs/功能/财务取数和补扫.md`“来源被删”）。
  - 引擎先按外键找连带的行（能置空的置空，不能的跟着删），再跑各模块的规划规则；镜像列置空时同一句清掉 `document` 里的字段。
  - 要删、要改的表没人登记，预览就拒绝；删订单时没有模块登记“删订单前配合”（识别导入给导入记录打标记），也拒绝。
- **库存怎么处理：** 一起改回（`recalculate`），或库存不动（`preserve`：被删单据的流水改成“系统维护”流水留着，留修订记录）。叫法、选项文字只在 `shared/business/lifecycle/deletion-words.ts`；清单排版 `src/recordkit/deletion-impact.ts`，删除窗和助手卡片共用。
- **初始化：** `server/admin/business-reset.ts` 按 `registerReset` 登记的顺序让各模块清自己的表。客户产品订单先清唛头，单据和成品库存清完后再清档案，保留哪些表写在 `tests/admin/business-reset.test.ts`。

助手删除卡片怎么出相关的见 `docs/功能/助手卡片和界限.md`。
