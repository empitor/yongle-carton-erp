# 识别导入

什么时候读：改机器人和收件箱、把原件交给 DeepSeek 识别、核对后正式导入（`server/import/`、`server/inbox/`）时。

页面和地址相关的见 `docs/功能/功能链路-识别导入.md`，表相关的见 `docs/生成/表结构.md`。

- **进件：** 企业微信、飞书、钉钉机器人（`server/inbox/bots/`）只把消息存进收件箱、回复存没存，不调模型、不办业务。
  - `manager.ts` 按设置库启停三家，某家改了设置只重连那一家；`connection.ts` 管一家的长连接：只有明确的凭据或配置错误、Secret 解不开才停下记成“连接被拒绝”，限流、对方临时出错、断网都退避重试。
  - 给人看的原因都是我们写的中文，对方的英文原文只进服务器日志。下载文件只连公网地址。同一家同一编号的消息不重复收。
  - 待处理、已忽略的收件 180 天后由每日清理删掉，已处理的（含转成单据的）留着。
  - 人点“转订单 / 转到货”才复制进 AI 导入工作区；上传、转单都不自动发给模型。文字消息和不能自动识别的文件点“新建订单”在收件箱页直接打开按需加载的订单编辑窗（`src/editors/pages.ts`），传入原文和原文件地址，存好后由识别导入自己标“已转订单”，人留在收件箱页。识别类型切换只走 `server/import/workspace-store.ts` 的 `setMode`（关联的到货单已确认或取消就锁定）；在用、归档两张列表只由同文件的 `workspaceLists()` 拼（页面、数据管理、助手共用）；识别状态的叫法只在 `shared/import/import-words.ts`。
- **原文件直接发给 DeepSeek**（`server/import/source-file.ts`）：图片原图内联；表格、PDF、Word 原样上传到 DeepSeek 文件接口（1 小时过期），按文件编号引用，用完即删。本机不读文件内容、不做文字识别，外发前只做安全检查（`server/core/files/attachment-validation.ts`）：扩展名按自己的表查；查宏、Office 每个 XML 部件的 DOCTYPE 和实体、加密、压缩炸弹、PDF 脚本、图片尺寸。手机竖拍照片解码宽高和文件头对调照收，其余尺寸不一致报“图片实际尺寸与文件头不一致。”，解码不了报“图像内容损坏，无法解码。”。发请求只经 `server/ai/transport.ts`，排队在 `server/ai/work-queue.ts`。
- **识别是让模型填表：** 表就是一个工具的参数，请求点名必须调它（`completeChatForm`，不开思考）。订单的表在 `shared/import/order-form.ts`（栏目和叫法就是识别结果页的录入表），到货的在 `server/import/receipt-form.ts`。
  - 税率让模型照抄原件，`readTaxRate` 识别明确的 0–100 百分数（最多两位小数，可带百分号）。小于 1 的非零小数必须带百分号。未认出的税率留空并提醒核对，原话随订单保存；人在识别结果改税率时保留识别出的原写法。
  - 每栏只填原件上写了的，没写的留空，拿不准的列进“拿不准”；缺哪些、哪些待核对由程序算。提示词只有设置里的识别规则加一句固定口径（`server/import/prompts.ts`）。交回的表不合格自动再试一次。
  - 原件没写整单交期而每行都有时，整单交期取最晚一行、标待核对。改过的格子记谁改的：助手改的备注“助手改的：……”，人改的“人工修改：……”。
- **核对后导入：** 订单走 `server/import/import-execution.ts` 的 `ImportExecutionService`（完整预览、绑定版本和身份、事务、幂等、审计）。
  - 已归档的、已导入过的识别文件不能导入，只在 `server/import/import-plan.ts` 的 `assertImportable` 拦（页面和助手共用）。
  - 客户、产品匹配只在 `shared/import/import-matching.ts`：对不上唯一一个只给候选、不猜；产品候选只列当前客户的产品和没定客户的通用产品。会新建哪些客户、产品由导入方案列出（带相近的已有档案，新客户和新产品在计划订单里留空不填占位编号），人在预览或助手卡片上确认；同名要新建的行要人勾选；执行时同一事务先建客户再建产品，新建产品一律归当前订单客户。
  - 到货单识别结果存在原件记录里（`flow_sources`，`server/import/receipt-ai.ts`）；核对窗选了订货单的按 `registerArrival` 存成待入库，不挂采购单的走通用保存。
- **工作区库：** 识别结果按 `server/import/workspace-document.ts` 严格读写；导入回执只回 `ImportReceipt` 十项，不带服务器路径和操作人。一份对不上结构的工作区不挡启动和列表：列表回 `unreadable` 单独列出，删除、清空只靠编号和版本，照样能删。上传、看原件、识别（边算边推）用 express 直接写，其余按接口表注册。
- **唛头不识别：** 整份文件直接挂到产品下（`server/sales/product-marks.ts`），只是参考资料，不产生订单、生产或库存。
- **怎么建：** `ImportManager` 构造时选项一次给全、都必填（`WorkspaceOptions`）：工作区目录、原件归档目录、AI 设置、订单识别的提示词管理器、业务库、到货识别。查导入记录、核对选的客户产品还在不在、到货单锁没锁都由它拿业务库自己接好。正式导入 `ImportExecutionService` 把原件存进识别导入的归档目录；装配建一份，页面和助手共用。机器人和收件箱由 `server/inbox` 的 `inboxBots` 一起建。
