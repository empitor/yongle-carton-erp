# 财务记账和结账

什么时候读：改财务的记账日、理论金额、凭证和红字冲销、往来、成本、结账和报表，或要找财务代码在哪时。

财务（`server/finance/`）记账、成本和结账怎么做，代码按子目录怎么分。财务怎么拿业务数据、补扫、来源指纹相关的见 `docs/功能/财务取数和补扫.md`；“财务不卡业务”“已记账凭证只能红字冲销”相关的见 `docs/业务规则.md`。

## 记账、成本和结账

- **记账日：** 单据日期所在月已结账时，凭证记在最早没结账月份的 1 号（`server/finance/base/periods.ts` 的 `bookingDate`），摘要注明单据日期。到期日、分期、折扣期限、账龄、压款利息一律从单据日期起算。按送货确认收入时，毛利的收入记在凭证所在月。
- **理论金额：** 送货、到货的理论金额只在 `shared/business/flow/document-value.ts` 算（按单据单价、不另加税，到货按入库数量），财务的理论收支和经营概况都调它；算不出的单据经营概况另报张数。
- **凭证：** 待确认 → 待审核 → 已审核 → 已记账，另有已作废（`server/finance/ledger/ledger.ts`）。红字冲销只冲已记账的原凭证，日期不早于原凭证，一张只能有一张有效红冲；票据、资产处置、费用这类功能生成的凭证到来源页面冲。
- **往来和冲销：** 往来余额口径只有 `server/finance/parties/obligation-sql.ts`；红冲的往来成对看，判断只用 `base/reversal-pairs.ts` 的 `isReversed`；票据、资产处置、费用、坏账、利息、保证金的派生凭证撤回和红冲登记在 `ledger/derived-vouchers.ts`。红字冲销退货、部分到票后另出的余量暂估凭证时，红字凭证记在原到货事件名下，不挂退货单、发票；退货冲了多少只按挂在退货单上的凭证算。
- **退货冲暂估：** 未到票就退货时按暂估单价冲减暂估（`events/return-estimates.ts`，同步时做，成本计算用同一算法）：按挂在退货单上的凭证算出各冲了多少，挑出已确认没冲的、已撤销冲过没恢复的，再向窗口要这几张的内容。
- **取值：** 状态、种类的取值在 `base/stored-values.ts`，和建表 CHECK 由测试比对；收付方式、账期方式在 `shared/finance/finance.ts`；含税口径只在 `shared/core/domain.ts` 的 `orderTaxModes`，旧写法“不含税”单独登记成 `legacyTaxMode`。财务怎么认税率只在 `shared/finance/tax-rates.ts`，服务端（补扫、往来条款、补税率校验）和财务页面（补税率窗口、来源单据详情）都引它：百分数文字 `percentage`；人填的和往来默认的用 `taxRateProblem`、`partyTaxRate`（最多六位小数，0.5 就是 0.5%）；单据抄来的用 `documentTaxRate`（照订单认法 `readTaxRate`、只认半角，老快照的全角、中间带空格的算没写清）；按这一行税率从哪来判断用 `financeTaxRateReady`。补税率窗口照它预填：认得出的填好，认不出的框空着、下面写“没认出来：…”（和来源详情税率格同一句 `unreadRateText`）；口径认不出时下拉空着，下面同样写原话（“口径：”前缀由 `shared/core/tax-rate.ts` 的 `snapshotModeOriginal` 去掉）；金额框显示去掉末尾多余的 0、至少两位，人没改就交原来的精确金额（`src/finance/flow/ResolveTax.tsx` 的 `resolveLine`）。“税率超出范围。”只在 `server/finance/base/amounts.ts` 的 `TAX_RATE_RANGE_MESSAGE`，算金额和补税率校验共用。
- **成本：** 月末加权平均（`costing/costing*.ts`）。冲销流水找原单据只走 `costing/costing-origins.ts` 的 `originsOf`。
  - 送货、完工冲销按原成本冲回。
  - 撤销或更正到货：在冲回流水那个月按这批还挂着的暂估（原暂估减去到票已转走的）红字入库冲回，不另出成本分录，总账由到货的红字冲销凭证记。冲完数量为 0 的库存品只留到过票、等红票冲的那部分（按那个月为止进了库存的到票调差和红票算，`costing/costing-invoice-adjust.ts`），其余转主营业务成本。
  - 到货那个月按记过账的那条事件入库（已撤销、被替代的按最新记过账的那条）；从没记过账的作废到货，入库和冲回在哪个月都不计。“已撤销”只认窗口给的单据状态，所以算成本不依赖补扫扫完；启用前的到货冲回仍要人选对方科目。
  - 查不到原成本的要人在“计算成本”窗口填金额、选对方科目；没被冲销的无单价到货照旧拦下。
- **结账和报表：** `reports/closing.ts`、`reports/reports.ts`；只有正式报表和结账因缺资料拦下。反结账重做时删掉的派生结果（成本明细、折旧明细）能重算，不拍快照。已撤销、被替代的到货名下的往来不能再关联、确认发票，开票对比也不列，撤销那个月的冲回金额才不会再变。撤销、更正过的到货红字冲销的默认日期取撤销那天（那个月已结账的按 `bookingDate`）：原单都给，替代单只在更正带出来、还没记过账的那一次给。

结账检查的“业务单据”一步、补扫没扫完时拦什么相关的见 `docs/功能/财务取数和补扫.md`“补扫”。

## 代码在哪

- **写入、审计、分页：** `base/core.ts` 的 `financeWrite(store, actor, { action, input, result }, 写入)`（防重复走 `onceByRequest`；补扫只用其中的事务 `financeTransaction`）、`financeAudit`，`base/query.ts` 的 `pageSql`。
- **路由和接口表：** 接口表在 `shared/finance/`，凭证和科目的正文规则在 `shared/finance/finance.ts`；根目录 `router.ts` 用 `route<FinanceApi>(router, '/finance')`，地址按页面分在 `routes.ts`、`routes-cash.ts`、`routes-period.ts`；`index.ts` 为对外唯一入口，`reset.ts` 登记初始化清表。
- **选往来单位：** 财务的下拉读自己的 `GET /api/finance/parties`（名单来自窗口，不列已归档），写往来、发票、票据、保证金、收付款时取单位名用 `requirePartyName`（找不到报“往来单位不存在。”）。出纳也能用，不借业务的 `/customers`、`/suppliers`。
- **助手：** 财务工具全部只读、金额换成元，读之前先补扫（`server/finance/assistant.ts`）。
