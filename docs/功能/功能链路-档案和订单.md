# 功能链路：档案和订单

什么时候读：加改今日概况、关联记录，客户、产品、订单、供应商、采购单（改状态、归档恢复、删除、唛头、多选开单）的页面、地址、助手工具时，查它走哪些页面、地址、服务函数、工具。

表的写法（地址缩写、页面和工具列）相关的见 `.claude/skills/add-feature/SKILL.md`“功能链路表”。

| 功能 | 页面 | 后端地址 | 助手工具 |
|---|---|---|---|
| 今日与经营概况 | `#dashboard` | `GET /business/today`、`/dashboard`（`server/overview/workbench-router.ts`） | `overview.get`、`ui.open` |
| 关联记录与修改历史 | 详情“更多 → 关联记录与修改历史”（`src/recordkit/RecordContext.tsx`）；订单、采购单详情的关联单据 | `GET /business/:module/:id/context`、`/business/:entity/:id/related`（出纳不能用） | `history.records` |
| 客户、产品、订单、供应商、采购单 | `#customers`、`#products`、`#orders`、`#suppliers`、`#purchases` | `/customers`、`/products`、`/orders`（`server/orders/records-router.ts`，保存走 `createBusinessService`）、订单编辑窗换客户前读的 `GET /orders/:id/sole-products`；`/suppliers`（`server/operations/router.ts`）；`/purchases`（`server/flow/stock-router.ts`，保存走 `FlowService.stock.savePurchase`） | `records.search`、`records.get`、`records.summarize`、`records.propose_save` |
| 订单、采购单改状态（确认、退回、取消、恢复） | 详情按钮，哪个状态出哪个查 `shared/business/operations/record-status.ts` | `POST /orders/:id/confirm\|revert\|cancel\|reinstate`、`/purchases/:id/` 同四个（`changePurchaseStatus`）；整张保存的 `PUT` 不改状态 | `records.propose_save`（写 `status`，取消带 `reason`） |
| 归档、恢复 | 详情“更多”；`#trash` | `POST /{customers\|products\|orders\|suppliers\|purchases\|stock_items}/batch`（`server/lifecycle/lifecycle-router.ts`）、`/flow/batch`、`/ai/imports/batch` | `records.propose_lifecycle`、`records.propose_batch_lifecycle` |
| 删除单据和档案 | 详情“更多 → 删除”、列表批量删除、数据管理（`src/recordkit/DatabaseDeleteDialog.tsx`） | `POST /deletions/preview`、`/deletions/execute`（`server/lifecycle/deletion-router.ts`） | `records.delete`（一条或多条一张卡片） |
| 产品唛头（客户产品订单） | 产品详情 | `/products/:id/marks`、`POST /products/:id/marks/upload`、`/marks/:id`（`PUT` 改说明、`DELETE`）、`/marks/:id/file` | `marks.list`、`marks.add`、`marks.remove` |
| 多选批量开单 | 订单、成品、产品、原材料多选；`#orders?create=1`、`#purchases?create=1`、`#production?create=1` 带预填 | `POST /flow/task`、`/flow/delivery`、`/purchases` | `production.plan`、`delivery.plan`，再 `records.propose_save` 逐张 |

**各行的细节：**

- **搜索和筛选只有一份：** 客户、供应商、库存品按哪些栏目搜是 `shared/business/operations/business-metrics.ts` 的 `operationalSearchText`，产品是同文件的 `matchesProduct`，采购单列表页和接口用 `shared/business/operations/purchase-filters.ts` 的 `matchesPurchase`（顶栏搜索在 `src/palette-items.ts` 组装关键词）。订单筛选只有 `shared/business/orders/order-filter.ts`，列表和助手都调它，状态只认页面上的叫法。
- **前端保存：** 档案在 `src/editors/editor-api.ts`（客户编辑窗 `src/editors/CustomerEditor.tsx`、供应商编辑窗 `src/editors/SupplierEditor.tsx`、产品编辑窗 `src/editors/ProductEditor.tsx`、订单编辑窗 `src/editors/OrderEditor.tsx`；新建编号给 `undefined`，修改的版本号取打开窗口时读到的），采购单在 `src/operations/purchase-api.ts`。
- **客户厂区：** 客户编辑窗与 `records.propose_save` 一并提交 `sites`；修改省略时沿用原厂区，提交数组时替换整组。客户详情和数据管理复用客户读写接口。
- **订单税率：** 编辑窗、数据管理和 `records.propose_save` 使用订单录入结构的百分数数字 `taxRate` 与原件写法 `taxText`，由 `sales(store)` 保存。
- **归档：** 写法都是 `{ action, items: [{ id, version }] }`，做法只有 `server/core/records/archive.ts` 一份。
