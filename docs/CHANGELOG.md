# 更新日志

## 0.9.0 · 2026-11-15

**从 0.8.4 升级只能用整包，业务数据从空库开始：** 旧业务库和识别工作区先移走；账号、AI 设置、提示词、助手工具设置、机器人设置一律重建，升级后要重新建管理员和各个账号、重填 DeepSeek 密钥和机器人设置。步骤见[部署与运维的升级说明](部署与运维.md#升级到-090)。

### 助手

- AI 只接 DeepSeek：设置页只填一个密钥，别家服务商、自定义地址和多套预设都去掉了。
- **改数据一律先出确认卡片：** 新建、修改、删除、导入、挂唛头、删聊天记录、改提示词、导出并出库或订货、备份，都要你在卡片上点“确认执行”才做，点“不执行”就作废；确认或不执行以后助手接着把剩下的办完。卡片写清动的是哪一条（单号或名称、客户或供应商），改前改后逐项列全，会新建什么、连带改到哪些单据、库存从多少变成多少；导入卡片写明客户和每行产品用已有档案还是新建，要新建的客户、产品后面列出相近的已有档案。卡片逐项写中文，不露英文键名和内部编号；要新建的单子不写单号（建好后助手报）。一张卡片只执行一次，执行没成或结果不明的不会再执行。
- 卡片出来以后数据变了，确认时说清哪条记录变了，助手按最新数据重新出一张。一句话给几种产品安排生产是一张卡片，确认后几张任务一起建出来。
- 每条回复下面一行如实写这一轮实际做了什么（只查询，没有改动 / 待确认 / 已执行 / 没做成）；助手的话不再被系统改写或换成固定说法。
- 改用 DeepSeek 原生工具调用加思考，输入框旁能选思考档位，按账号记住。常用的 13 条命令直接给、其余按目录用到再查，提示词也精简了：实测每次请求的输入从约 3.1 万 token 降到约 0.75 万。
- 助手的工具分 13 组，“设置 → 高级”里能整组或单个停用。
- 小甬先说结论和下一步，小勒先说数字和依据。两人只在系统里查和办事，联系客户、供应商、同事会提醒你找谁、问什么，不说“我去联系”，也不答应过后再报。
- 同一个会话里记得前面查过、做过的事；会话太长（约 20 万 token）时自动让模型把早的部分整理成要点。
- 和 DeepSeek 的连接中途断了、长时间没反应时自动重发，最多 5 次，半截话不会当成回答；程序中途重启后会话接得上，做到哪一步都记着。一句话里问模型和办的步骤各最多 30 次，到了上限由助手说明做到哪、还差什么。
- 长期记忆：助手从对话里自己记，不用点确认；记了什么写在那条回复下面“已记住：……”，点“忘掉”就删、那句划掉标“（已忘掉）”；像密码、密钥的不记，会说明没有记。每个账号一份，在“更多 → 记忆”里看、改、删，自动记忆能关。
- 聊天里带的文档在 DeepSeek 那边最多留 7 天；删掉附件、清空或删除会话时 DeepSeek 上那份一起删；那边的文件提前失效时自动从原件重传。
- 输入框在电脑上按回车发送、Shift+回车换行；中文输入法选字时的回车只上屏、不发送；手机上回车是换行。
- 语音输入改用 DeepSeek 识别，不用再下载本机语音模型，录音改用浏览器新的采集方式（AudioWorklet）；回复下面可以点“读出来”。
- 能联网搜索和读网页，一次可以搜几个词；回答下面列出“来源”，读过全文的排在前面。处理中那一行写着正在做什么（在搜什么、在读哪个网页、在准备确认卡片），回答前先说的那句话会留着。
- 能帮着排查问题：查按人按时间的修改记录、最近出错和被拒的请求、后台任务；超级管理员还能让它看运行日志、登录记录和程序代码（只读）。查使用说明能按关键词找到小节。
- 问合计时直接给总只数和按客户分的只数；讲应收应付用中文叫法（还欠、预收款、没有账期等）。
- 能查成品批次、恢复已归档的到货单，登记完工也能登记不挂任务的。能更正到货单、送货单、完工单（更正完工单只给超级管理员），一步出卡片，卡片就是更正前后的对比（每行原来和更正后多少、库存、订单已发或任务已入库、金额），不点确认不改；能改它们的说明（备注、时间、地址联系人、操作人、批次备注），和详情的“编辑”一样，不出替代单。
- 删除和页面同一个删除服务、同一套规则：一张卡片删 1 到 100 条，列出会删、会保留的，可以改“库存怎么处理”；删已核对的要超级管理员模式加本人密码；出卡片后其中有一条被改了或不在了，整张作废、一条都不删。
- 数据管理命令一次办一件事（多条一起改时列出编号），不再支持按条件批量选和多步引用；出入库走库存的出入库命令。
- 识别文件按“待识别”“待核对”说，不说“草稿”；识别文件的卡片写清每份的识别状态，说法和 AI 导入页一样。
- 收件箱转进 AI 导入的、或关联进当前对话的订单文件，可以直接在对话里让助手识别。识别过的不重新识别、不重复收费；上次识别被中断或失败的，要明确说重试才重来；回复下面那行照实写这次有没有真的识别。
- 回复过程中的进度和正在写的字最多每 250 毫秒刷新一次，换步骤和最后一段不丢。
- AI 设置已在别处改过时，提示刷新页面后再操作；保存失败时提示管理员看服务器日志里写的原因。

### 识别导入

- 飞书、钉钉机器人也能把消息和文件送进收件箱：“设置 → 消息接入”里三家各填各的、各自显示连接状态，可以同时开。对方限流或临时出错时自动重试；凭据不对、或换了服务器后存的 Secret 解不开，卡片上写“连接被拒绝”和中文原因。
- 收件箱里待处理、已忽略的消息收到 180 天后自动清掉，已处理的（包括转成单据的）留着。
- AI 导入只识别客户订单和供应商送货单。唛头不再识别，在产品详情里直接上传、能预览，也可以让助手挂到产品下。
- 识别时原文件（图片、PDF、Word、Excel）原样发给 DeepSeek，本机不解析文件、不做文字识别。
- 订单识别、到货识别改成让模型按录单的那张表填，提示词从两万多字缩到几百字，实测订单识别每次的输入少约七成；设置里的识别规则只写各家原件的写法习惯。
- 原件没写订单日期也能识别出来，标出缺失等人补；原件没写整单交期、每行都有交期时，整单交期取最晚的一行并提示核对。
- 这位客户以前订过、名称和规格都一样的老产品自动选上，不用逐个确认。
- 助手改过的识别结果格子下边线是紫色、标着“助手改的”，和人改的分得开。
- 识别结果页去掉“标为已核对”，不露内部编号；“产品资料可以后补”只在确实缺的时候提示；“数量或单价改过”的提醒合成一条。
- 识别文件的归档、恢复、删除在 AI 导入页和数据管理里是同一套；已归档的不能导入，先恢复。列表标出读不出来的文件数量，可在“更多 → 历史与归档”查看并由本机管理员永久删除。
- 单价没填、不是数、超过四位小数、超过 1000000 元上限各有各的提示；识别订单时“个”一律当“只”。
- 排队中的订单文件写“等待识别”，列表、右侧标签、助手说法一致。识别读到一半网断了，提示改成中文。
- 手机竖拍的照片（带方向标记）能作为附件或识别原件发送。
- 上传的 Word、Excel 里任何一个部件带 XML 实体都拒收；带宏和带实体分开说原因。修了：附件扩展名写成 `constructor`、`__proto__` 这类名字时能绕过类型检查，现在一律拒收。
- 修了：机器人下载附件超出大小上限取消后，不再冒出未捕获异常。
- 正式导入的回执不再带服务器上的文件路径和操作人。

### 到货、采购和生产

- 到货计划去掉了：到货安排只在订货单上，在“待到货”里点“登记到货”一步入库，合格的没全部入库时可以填实际入库数。有采购单的货只能这样登记；多送、样品在到货页“更多”里“登记没有采购单的到货”。AI 识别的送货单在核对时选是哪份订货单。今日页“今天要到”按订货单的截止日列，逾期没到的标红。
- 已生效的到货单、送货单（含客户已签收的）、完工单只有三条路：“编辑”只改说明（备注、时间、地址联系人、操作人），库存和金额不变；“更正到货单 / 更正送货单 / 更正完工单”撤销原单、另出新单号的替代单，详情写“更正自 / 已更正为”，库存按差额追加流水，出库日和送达记录照旧，送货没改的行沿用出库时的单价（更正完工单要超级管理员模式）；整张没发生用撤销。“直接编辑（管理员）”“按原单重新填写”、到货统计更正都去掉了；数据管理里改已生效单据也只能编辑说明或更正。各处点更正、编辑进的都是同一个窗口，办完只关这个窗口、详情留着；打开后单据被别人改了，窗口里按最新的重新预览。
- 更正的边界：替代单被删后原单变“已撤销”；到货更正后每行都是 0 时提示撤销该到货单；已归档的单据先恢复才能更正。
- 安排订料、安排送货、安排生产、登记完工、手工出入库和盘点各只有一个窗口。安排订料：订单详情和订单列表多选进的是同一个，几张订单时选合成一张采购单还是每张一张。出入库和盘点：库存页和数据管理里的库存品点的都是“出入库 / 盘点”。
- 安排送货能改收货地址、联系人，超过订单数量要在安排时写原因（要超级管理员模式）。送货页“可发货”勾几张订单时，同一份库存按交期先后分，不再按勾选先后。
- 安排生产保存就是正式任务，没有“确认下达”这一步；生产任务页页头能按产品排、在窗口里加产品。登记了待入库完工单的任务显示“生产中”。
- 登记完工可以“先登记，稍后核对入库”；还能登记的数量扣掉已登记待入库的；打样、补做在登记完工窗口的“不挂任务的完工”里登记。
- 开工后的生产任务由本机管理员编辑时，只在把计划数改到少于“已入库加待核对入库”时拒绝，提示里写明两样各多少。
- 订单、采购单的确认、退回、取消、恢复各是一个动作，取消要写原因。
- 订单的预估成本每项最多两位小数、不超过 1000000 元（填的时候就拦），“01”这种前面补零的不收。订单明细换了产品，产品名称跟着新产品档案走。
- 采购单里没选库存纸板的行，长和宽必填，表单上直接标出来；材质、楞型照旧可以不填。
- 几张采购单合成订货单导出时订货单号不再撞号，预览不占号；同一组采购单先后导出两份时，后一份提示作废。
- 同一种货只有一个库存品：成品一个产品一个、跟着产品资料走；原材料规格一样的不能建第二个。完工、到货自动入对应的库存品，没有就新建、归档的自动恢复。用过的库存品不能改种类、成品不能换产品。
- 成品库存按每次完工分“批次”，显示估计还剩多少，能写、改批次备注。
- 订单明细的规格和产品现在的对不上时，送货拦下并写出哪一项不一样，今日页把订单列进“要核对订单”。
- 数量单位由数据库把住：产品、成品、订单、生产只收“只”，原材料、到货只收“张”。
- 单价全站一个写法：至少两位、最多四位小数；产品参考单价留空是没定价，填 0 是 0 元。
- 到货记录里没关联采购单的行写“无采购单”。
- 送货单导出的“材质 / 配纸”“楞型”两列印出产品的材质、楞型（已出库及更正留下的行照出库时的，待送货照产品现在的）。
- 已取消的待入库到货单详情不再写“核对时算”；生产任务详情的完工进度写明另有多少已登记、待核对入库。
- 修了：删除已入库的单据（库存一起改回）以后，别人已经打开的核对入库、登记完工窗口还能带着删除前的数据确认；现在提示数据变了、要重新看。
- 修了：登记完工时领料、退料数量写错现在提示输入不对，不再报服务器错误。

### 财务

- 红字冲销成对显示：原来那笔标“已冲销”，下面挨着负数的“红字冲销”，重做后的标“重记”；对账单同样排在一起。
- 对账单列出预收、预付；“按单位”多了“预收款”和“还欠”两列，还欠和同一天对账单的期末一致，超授信按还欠算。
- 只改备注、地址、确认送达这类不影响金额的，财务不当成单据变了，不再出“有差异”卡结账。
- 还没入过账的送货、到货被撤销或更正，财务里直接是“已更正”，不用再点红字冲销。
- 送货、到货单被删后：没入过账的自动“已更正”，盘点流水、完工单被删直接“已更正”；入过账的标“单据已删”，点“红字冲销”，或在“更多 → 核对无误，保留凭证”（保留的照样计入毛利）。
- 已撤销的送货在“待撤销核销”期间又改了日期，撤销核销后照样自动收尾，不用再点一次红字冲销。
- 金额为 0 的送货、到货（赠品、整批拒收）不用补税率，不卡结账。
- 未到票就退货时，退货当时按这批到货的暂估单价冲减暂估，到票时只转回剩下的，不用再手填对应暂估；退货撤销时冲减跟着加回来；已到票后再退的仍走红字发票。
- 当月入库又在当月被冲销的原材料到货单（含无单价的），计算成本时原入库和冲销成对抵消，不再报“原材料到货财务资料未完成”或要求手选对方科目；没被冲销的无单价到货照旧拦下。
- 压款利息只算已经过去的逾期天数，确认时选算到哪天，一个月可以确认几次、接着上次算。
- 费用、保证金、票据、资产处置、坏账、压款利息生成的凭证，在各自详情的“更多”里撤回或红字冲销。
- 结账检查多一步“启用前单据的变动”，列出单号，核对无误后放行，不拦结账。
- 单据日期所在月份已经结账的（补录、结账后才补税率），生成凭证记到最早没结账月份的 1 号、摘要注明单据日期，不再卡住以后每个月的结账；到期日、分期、账龄和压款利息仍按单据日期算；按送货确认收入时，这张单子的毛利算在凭证所在的月份。已结账月份的单据也能补税率。
- 收付款、保证金、优惠的叫法和单号写法全站统一（如“收客户款 11-12 100.00”“收到保证金”）；账龄、收付计划、到期提醒的口径对齐，没有账期的单独一档。
- 财务概览“记账口径”的估算提示只列确实存在的项（待补税率、缺价格或数量）；缺数量或单位的写“缺数量或单位”，待补条目叫“缺价格或数量、没算进理论金额的单据”。
- 保存手工凭证时只填一条分录，提示“至少填写两条分录。”；对账单清空日期时只提示“请填写明确日期，不能用空值自动推断”。
- 修了：银行余额调节表导出里“银行未达账”的“往来单位”一列是空的，现在写流水上的对方户名。
- 修了：到货单解除采购明细以后，财务“改了什么”里“对应采购单”的变化列不出来。

### 界面

- “使用说明”页显示的就是使用手册，按章节看，手机上也能看。
- 几个人同时用时，别人改的东西不用手动刷新：导航上的数字每 15 秒更新一次，从别的窗口切回来时眼前的列表马上重新取。
- 外观（浅色、深色、跟随系统）在账号菜单里切换，手机上也能切；跟随系统时系统切换深浅立即跟着变；同一浏览器的几个标签页外观同步。浅色主题的警示色调深了。
- 只读账号也能在详情“更多”里打开“关联记录与修改历史”，订单、采购单详情里也看得到关联单据；出纳照旧看不到业务记录。只读账号的设置页不显示“提示词”页签。
- 打开详情时列表按优先级收起次要列，不再横向滚动；悬浮小人只在真的压住详情或表格时才缩成一条贴边。
- 到货、送货详情的按钮在单据页和仓库页一样，取消要填原因，归档后提示去“已归档”里恢复。
- 删除只有一套：页面、本机数据管理和助手走同一个删除服务，页面和数据管理打开的是同一个删除窗，从域名访问也按同样规则；一次可删一条或多条。删除窗口看得懂：一句汇总加“会删除 / 保留，只解除关联”两节，库存品、流水用固定叫法，不露英文表名和编号；删除按钮红底白字；删完提示删了哪条、连带几条。预览失效时自动重查影响清单，查到后提示重新核对。
- 修改历史逐项写“字段：改之前 → 改之后”，每条标出从哪改的：页面、助手、数据管理、系统。
- 数据管理不露内部编号和英文代码，关联字段改成能搜索的选择器，出错写在那一格下面；编辑、删除、更正窗不再叠在列表窗口上。
- 叫法统一：库存品、关联记录与修改历史、没有账期、保证金、压款利息、退料；按钮写“编辑××”（编辑备注、编辑说明、编辑到期日、编辑到货安排）；识别结果的“撤销修改”改叫“撤回修改”；AI 导入到货面板的主按钮叫“核对入库”；完工的单据叫“完工单”、页面叫“完工记录”；今日待办和送货页都叫“可发货”；面积写“m²”；客户、产品、供应商被归档时报错说“已归档”。
- 提示统一：保存时没填对的全站一个写法；网断时说“连不上服务器，请检查网络后再试。”；没登录时点写操作说“请先登录账号。”；先预览再确认的地方（核对入库出库、更正、登记完工、正式导入、初始化、重算到期日），预览后数据被别人改了一律说“预览以后数据已变化，请重新预览。”。核对入库出库、登记完工、正式导入的预览不再过期，换了浏览器窗口也能确认。
- 要超级管理员模式的事被拒时分两类说：别的账号直接说没有权限，没进模式的超级管理员提示去“系统维护”。单据归档被拦时按账号说清能不能删。
- 经营概况的“已发货订单金额”“有效到货金额”改成“送货金额”“到货金额”：按送货、到货日期和单据上的单价算，不另加税，到货按实际入库数量，和财务月度台账的理论收入、支出是同一个数；算不出金额的单子另报张数。今日页“统计日期”换成和列表筛选一样的日期选择。
- 系统里的时间一律按北京时间显示（修改记录、收件箱、识别失败、账号申请、机器人最近一条等）。
- 地址里日期写坏时按页面默认范围显示；输入未知的页面名时转到 `#dashboard`。
- 手机上：有弹层时底部提示挪到顶上；详情标题放不下就换行；顶栏菜单角标、搜索框、底部导航选中色和排产板卡片单号不再挤或错。
- 列表筛选弹层在滚动页面或列表时自动收起；归档页“查看”选择器的标签不再竖排换行；窄一些的屏幕上财务页签不折行。
- 其他细节：送货、到货详情的“财务”不再卡片套卡片，只有理论金额时写出理论金额；送货单的“预览 Word 排版”在导出窗口里原地换成纸面；订货单“移出采购单”在修改历史里有中文名；取消完工确认窗的退出按钮写“不取消”；计提工资、折旧没东西要记时如实说没有生成凭证；新建资金账户类型和科目对不上时说清是不匹配；核销表里撤销核销那行写“撤销核销”；批量归档失败的原因不再重复。
- 出纳账号的页面报错也能上报到出错记录。
- 修了：校验出错的说明里碰到 `toString`、`constructor` 这类词时，提示里冒出一段程序代码。

### 部署和数据

- 业务库结构定成第 20 版，所有表加了数据规则约束；万一被约束挡住，用户看到中文提示，日志里有 `[数据规则]` 开头的一行。以后改结构按编号小步升级，升级前自动拍快照，失败整体退回。
- 业务库版本是当前版、表结构却和程序对不上时（直接改了建表、被数据库工具改过），启动时拒绝并列出差在哪，数据不动；升级走完结构对不上的整次退回。
- 编号不再复用：删掉的单号不给新单据，初始化后接着排。
- 导出文件保留 180 天（过期只删文件，记录留着）；防重复提交记录保留 90 天；每天自动清理一次并把空出的磁盘空间还回去。
- 备份更严：清单记每个库的版本，恢复前先逐个校验，旧格式和直接复制出来的库一律拒绝。手动备份只用 `npm run backup`（只备份业务库的命令去掉了）。
- 去掉了开发者编辑模式。
- 从域名访问时，管理账号，改 AI 设置、提示词、消息接入、助手工具开关，都要先进超级管理员模式（页面顶上有入口，没进时这些页只能看）。
- 登录更难被猜：IPv6 按 /64 网段算，同一账号从公网换着地址输错也有总上限（15 分钟 20 次），提示写明几分钟后再试；从域名访问的登录 Cookie 加了 `__Host-` 前缀，升级后要重新登录一次。很多人同时登录时排队核对密码，偶尔提示“服务器正忙，请稍后再试。”（页面已自动再试过一次，不算输错）；维护通道和已登录的人验密码排在前面。从域名访问的健康检查只回 ok；Caddy 示例配置加了请求体上限和读超时。
- 发布包不再带语音模型和相关下载说明；附带第三方声明 `THIRD_PARTY_NOTICES.md`（助手的会话压缩移植自 DeepSeek Harness，MIT）。

### 内部整理

程序按单向依赖拆成模块，模块之间只走公开接口，样式按模块组织，跨模块重复的常量、类型合成一份；前后端共用接口表（服务端 `route()` 注册、前端 `call()` 发），服务端读库只走 `server/core/sql.ts` 并按结构校验，单据内容按严格结构读写；结构定版前删掉了没人用的表、列和取值。

`npm run check` 十步都拦（类型、代码、函数只许变小、样式、没人用的代码、重复代码、测试、覆盖、发布检查、构建），代码检查的存量登记清到 0（`eslint-suppressions.json` 为空、函数复杂度基线 0 项），慢测试和覆盖率不达标也拦下。新加属性测试（fast-check）、变异测试（Stryker，`npm run mutation`，不进 check）和无障碍检查（axe，界面流程的 `a11y` 组）；测试按业务规则组织并共用准备代码。

持续集成支持在 `ci-` 分支运行界面流程，覆盖率不达标时显示未覆盖行；补充助手经营概况的日期筛选测试，修正上传识别和订单地址筛选的界面测试，并更新变异测试工具的间接开发依赖。

共用 HTTP 测试服务由夹具统一关闭空闲连接，避免覆盖率运行中请求撞上保活超时。

升级办法见 `docs/部署与运维.md`。
