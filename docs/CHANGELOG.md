### 手机 App（安卓）

- 返回键按层级走：开着窗口、详情、筛选、“更多”“新建”菜单时先关最上面一层（和点 × 一样，正在提交时不关），没有窗口时从别的页面一次回到“今日”（纯财务账号回财务概览），在“今日”时由 App 提示“再按一次返回退出”；点开图片原件后按返回能回到 ERP。浏览器和电脑客户端不受影响。
- 往下翻页时顶部搜索栏跟着收起，往回翻时露出来；滑到顶、滑到底时只有中间内容拉伸回弹，顶栏和底部导航不再跟着变形；在列表、输入框里滚动时不会带着整页变形，系统开了“减少动态效果”时不回弹。
- 在文件管理、相册、微信里用“分享”或“用其他应用打开”选甬勒ERP，文件自动上传进 AI 导入，显示待识别，不自动识别；页面中途重新加载也不会多出重复的任务。开着窗口时收到分享先提示，关掉窗口再进 AI 导入；超过 10MB、格式不支持、读不到的文件分开提示原因；纯财务账号分享文件会提示进不了 AI 导入。
- 导出的订货单、送货单存进手机“下载”，存好了才改状态（订货单变待到货、送货单出库）；没存成时窗口里说原因，状态不变。
- 在助手里点了记录链接或被助手带去别的页面时，助手自动收起，露出要去的页面。
- 应用内更新：下载能取消、有进度。

### 订单、采购、到货和送货

- 采购单每行必须选计价方式：接口、助手漏说时不再默认“按张”，报“明细第1项的计价方式：请选择按平方米还是按张”，助手没听到按什么计价会先问。出错提示里的“计价依据”统一叫“计价方式”。
- 到货明细没写计价方式时不再默认“按平方米”：挂了采购明细的按采购明细上的计价方式；没挂的照常登记入库，计价方式留空、金额待定，经营概况不计入到货金额、另计张数，财务按缺价格等人补（更正到货单里补上）。登记到货、助手、数据管理导入、更正到货单都一样；页面上新加的到货明细和数据管理新建到货单也不再预填“按平方米”，显示“待确认”。
- 挂了采购明细的到货行没写单价时，用采购明细上的单价（计价方式也没写或和采购明细一样时才带；写了不一样的计价方式又没写单价的仍留空，不换算）。登记到货、AI 识别、助手、数据管理、更正到货单都一样，这类行在经营概况和财务里有了金额，不再按缺价格等人补。
- 更正到货单、送货单、完工单和改已下达的生产任务时，替代单上的客户名、供应商名、产品名和送货的品名、规格、单价照原单上的，档案后来改了名也不跟着变；只有更正时换了供应商、产品、订单明细或采购明细才按换上的取。更正送货单时删掉一行又按同一条订单明细加回来，也照原单那一行出库时的。
- 今日页的“本月接单”“本月发货”和经营概况所选日期内的订单数、金额、状态分布、预估毛利、采购单数、采购金额算上已归档的订单、送货单和采购单（以前发完货一归档就从这些数里少掉，和财务月度台账对不上），张数里有已归档的写“含已归档 N 张”；待办、最近的订单和采购单、标“实时”的数照旧不算已归档的。助手的经营概况同一个口径。
- 一张生产任务同时给几张订单做时，其中改回待确认的那张不再算进要做的数（以前会让另一张一直停在“生产中”）。
- 送货单没填收货地址、联系人、电话时，导出的送货单上那一格印“未记录”，不再拿客户档案的顶上（安排送货时这三项照旧按客户档案预填）。
- 到货单、送货单的详情在到货页、送货页、归档页和从订单、采购单点开的窗口里都一样了：已归档的也能看验收 / 入库、入库流水、出库流水和每行进度，从采购单点开的到货单也有“到货记录”；明细排在基本信息前面；送货单标题下写“客户 · N 种产品”；经办人统一写确认人，没有才写登记人。从采购单点开的到货单窗口里，采购退货只能看，撤销退货到到货页办。
- 订单和订单明细的含税口径改成下拉（含税、未税、未明确）；库里原来写的别的说法照原样显示，编辑时要改选；确认、取消订单不受影响。
- 没定价的单价、金额统一叫“单价待定”（采购单列表和详情、采购明细合计、经营概况、修改历史、助手的更正卡片、订货单打印和预览的单价、金额和合计）。
- 金额结算的两个选项各处统一叫“精确到分，不自动舍入”“明确采用整单四舍五入到分”（订单编辑窗、数据管理、修改历史、AI 导入），“金额规则”统一叫“金额结算”；单价有不足一分的尾数时提示“请在金额结算里选‘明确采用整单四舍五入到分’”。
- 库存品、采购明细按厘米填超过上限时，提示和产品一样带换算：“厘米尺寸不能超过1000cm（等于10000mm）”。
- 搜索：客户、产品、供应商、库存品的下拉按关键字搜，和各自的页面同一套，不再在编号、版本、建立和修改时间这些看不见的栏目里搜（产品也不再按尺寸、料号、价格搜，和产品页一样只按名称、材质、楞型、要求）；顶栏搜索（Ctrl+K）搜客户也按备注搜，搜供应商也按地址、备注搜；供应商、采购单、库存品列表搜索时，中间有栏目没填也能按“名称 联系人”这样跨栏的整句搜到。

### 数据管理

- 修了：新建采购单的明细、新建到货单明细的纸板资料里有“种类”“产品”两格，填了保存成功却被悄悄丢掉。现在这两格去掉了。
- 修了：新建订单的单价有不足一分的尾数时建不成，提示让选的“金额结算”找不到。现在新建订单有这一格（初始“精确到分，不自动舍入”）；编辑库里没存金额结算的订单，这一格显示“未填写”，不动它就不写。
- 保存时（数据管理窗口和助手的数据管理命令）内容里有系统不收的栏目，不管在明细还是纸板资料里，都报错说清是哪一格、不保存，不再“保存成功却少了东西”；报错全是中文，不露字段代码。照读出来的原样带回的系统算出来的栏目（已发数量、金额这类）不算改，改了才拦（“是系统算出来的，不能改”）。已生效的单据整条带回、只改备注能存；改了明细、日期提示用“更正××单”。
- 新建模板补齐栏目（含到货明细的验收合格、拒收、入库），单据状态下拉按页面上的叫法。

### 财务

- 财务页面、订单和单据详情里的财务段、今日到期和助手查财务之前，服务器先把还没记进财务的业务单据同步进来，看到的都是最新的；页面不再另发同步请求。单据很多时页面写“正在把业务单据记进财务，还剩 N 张”。有单据内容坏了、读不出来时，别的单据照常同步、页面照常能看，结账和出正式报表会被拦下并写明是哪张单据；在库里改好后下次打开财务自动补上。同步本身出问题时，只拦要核对业务单据的财务操作（核销、关联发票、红冲、生成凭证这类），登记收付款、收到票据自动冲应收、改往来条款这些照常；概览、业务单据、月度台账、结账页、报表页签用红色提示说明。
- 修了：送货、到货单记过账以后被撤销、更正、改了内容或删除，财务还没同步时照样能结账。现在正式报表和结账用同一个口径，所有还没同步进财务的单据（新确认、撤销、更正、改过、删掉的）都算进“业务单据”一步拦下；结账页这一步的“去处理”直接打开业务单据页的“全部”，要处理的单据都列在那里。
- 删除业务单据、库存流水不再同时改财务的记录，财务出错也不会让删除失败；被删的单据由财务下次同步时发现、标成“来源已删除”，同步之前结账照样拦。
- 财务月度台账、财务概览的“接单”不再算待确认的订单，和今日页一样。
- 修了：出纳账号开收付款单时，往来单位下拉里选不到客户和供应商。现在出纳也能选；名单读不出来时页面底部会提示原因。
- 修了：上个月的到货在这个月撤销或更正，算成本会卡住（报“原材料到货财务资料未完成”）或把原材料多扣一次。现在到货那个月照常算，撤销（更正）那个月按原来的暂估把这批冲出库存，不用再选科目；冲完数量是 0 的，到过票、还等红票冲的金额先留着，其余转进主营业务成本；没记过账就作废的到货两个月都不算。
- 撤销或被更正替代的到货不能再关联发票（提示里写出到货单号和怎么处理），开票对比里也不再列；给撤销、更正过的到货做红字冲销时，日期默认是撤销（更正）那天。
- 修了：先撤销采购退货、再撤销到货时，红字冲销凭证被算到退货单名下，成本少加回退货撤销的那笔、原材料总账和库存对不上。

### 升级和维护

- 业务库升级到第 22 版（启动时自动做）：财务事件的几项常用内容单独成列（第 21 步，已有的按快照回填），归档标记、永久删除记录两张小表重建一次、记录种类不再写死在表里（第 22 步），数据原样保留。
- 账号、长期记忆和按账号的设置、提示词、AI 设置、机器人设置、AI 识别工作区、出错记录这几个配置库，以后程序改了它们的结构，启动时先在库旁边的 `snapshots/` 留一份升级前备份，再一步步升级，数据留着，不再整个清空重建；升级出错整个退回、文件不动，提示写明是哪个库、哪一步、备份在哪。0.9.0 以前留下的旧库照旧重建。
- 补丁回滚先把配置库换回升级前的样子，再按业务库决定要不要恢复，旧程序不会因为配置库“比程序新”起不来；换不回时服务保持停止，按打印的步骤手动换回。换回以后新程序运行期间改的配置不在库里（换下来的文件留着），所有人要重新登录。`erp.env` 的 `ERP_CONFIG_DIR` 不是绝对路径时补丁直接拒绝。
- 新维护命令 `revert-config-upgrades`（Linux `erp.sh revert-config-upgrades`，Windows `npm.cmd run revert-config-upgrades`）：把比程序新的配置库换回升级前备份，Windows 整包换回旧版本后要手动运行。
- 恢复备份：配置库比程序旧但在 0.9.0 以后的不再拒绝，恢复后启动时升级；`_extra/` 里的 AI 配置、机器人配置不论版本只查完整性；恢复完列出“只查了完整性的文件”。

### 内部整理（页面和功能不变）

- 架构整理第 1 到 4 阶段：立了模块分层的规矩和检查（前端业务四层、共用业务规则三层只往下用，现在一处越层都没有）；运行日志、登录记录、读程序代码、使用手册搬进新的“系统资料”模块，删除引擎和档案归档恢复分成“删除归档”模块，单据导出前端、使用说明页各成前端模块；采购库存不再回头问单据流转，带单据内容的采购单、库存品、订货单的入口和地址归单据流转，采购库存、单据流转的服务端按层分子目录；财务和业务之间只留一个只读窗口（`server/flow/finance-facts/`），财务只读自己的表，单据和财务的约定归业务一处管，来源指纹按财务口径算。
- 一件事只定义一处：栏目叫法收成登记表（`shared/core/field-names.ts`）；权限名、单据种类和状态、计价方式、附件上限、识别原件格式、财务的收付方式和税率口径等改成引用同一份，写错编译不过；单据快照栏目、安排送货的方案、订单的三个状态判断、客户搜索、助手的读数据和工具定义各收成一份，有检查守着。
- 界面公共件合一：列表表格（`src/ui/DataTable.tsx`）、列表工具栏、页头和详情的主 / 次 / 更多按钮（`src/ui/Actions.tsx`）、出错提示（`FormMessage`）和“正在读取”、PDF 预览（`src/ui/pdf.ts`）、导出窗（`src/documents/ExportDialog.tsx`）各只留一份，有检查拦别处再手写；业务公共件的样式搬回各自目录，逐个元素比对过样子没变。
- 配置库有了基线版本、编号的升级步骤和基线结构快照，检查核对步骤不缺、从基线升上来和新建的一样、每步带数据样例；补丁脚本拆出纯逻辑和回滚两个文件。
- 检查和测试：测试运行器连子目录找测试，检查保证每个测试文件、每个界面流程脚本都会被跑到；首屏脚本体积有了只许调低的上限；守结构的检查失败时直接写该怎么改；财务测试的造数收进 `tests/business-changes-fixture.ts`；界面流程脚本可以用 `--port` 指定起始端口。
- 应用外壳：安卓、Windows 外壳按职责拆成小文件，返回键、分享、保存文件等逻辑有单元测试，安卓 Lint 警告也算错、安装包去掉了误带的 Kotlin 标准库，Windows 去掉了往网页注入脚本的对话框插件、加了日志文件；两个外壳的检查用 `npm run check:apps` 一次跑完，并单独接进持续集成。
