### 手机 App

- 在安卓 App 里按返回键按层级走：开着窗口、详情、筛选、“更多”“新建”菜单时先关最上面一层（和点 × 一样，正在提交时不关），没有窗口时从别的页面一次回到“今日”（纯财务账号回财务概览），在“今日”时由 App 提示“再按一次返回退出”；点开图片原件后按返回能回到 ERP。浏览器和 Windows 版不受影响。
- 手机上往下翻页时顶部搜索栏跟着收起，往回翻时露出来；在安卓 App 里滑到顶、滑到底时只有中间内容拉伸回弹，顶栏和底部导航不再跟着变形；在列表、输入框里滚动时不会带着整页变形，系统开了“减少动态效果”时不回弹。

- 安卓 App 里导出的订货单、送货单存进手机“下载”，存好了才改状态（订货单变待到货、送货单出库）；没存成时窗口里说原因，状态不变。
- 手机上在助手里点了记录链接或被助手带去别的页面时，助手自动收起，露出要去的页面。
- 安卓 App 的应用内更新：下载能取消、有进度。
- 页面提示多了一种“提醒”口气（图标是 i），用来说接下来会怎样；开着窗口时提示条挪到窗口标题栏下面，不压住标题和关闭按钮。

- 修了：新建订单的单价有不足一分的尾数时建不成，提示让选的“金额结算”找不到。现在新建订单有这一格（初始“精确到分，不自动舍入”）；编辑库里没存金额结算的订单，这一格显示“未填写”，不动它就不写。
- 保存时（数据管理窗口和助手的数据管理命令）内容里有系统不收的栏目，不管在明细还是纸板资料里，都报错说清是哪一格、不保存，不再“保存成功却少了东西”；报错全是中文，不露字段代码。照读出来的原样带回的系统算出来的栏目（已发数量、金额这类）不算改，改了才拦（“是系统算出来的，不能改”）。已生效的单据整条带回、只改备注能存；改了明细、日期提示用“更正××单”。

### 财务

- 正式报表和结账用同一个口径：还没同步进财务的业务单据（新确认、撤销、更正、改过、删掉的）也拦正式报表。打开报表页签时先同步，没同步上的页面写“有 N 张业务单据还没同步进财务”。
- 财务页面、订单和单据详情里的财务段、今日到期和助手查财务之前，服务端先把还没记进财务的业务单据同步进来，看到的都是最新的。有单据内容坏了、读不出来时，别的单据照常同步、页面照常能看，结账和出正式报表会被拦下并写明是哪张单据；在库里改好后下次打开财务自动补上。
- 财务月度台账、财务概览的“接单”不再算待确认的订单，和今日页一样。
- 修了：送货、到货单记过账以后被撤销、更正、改了内容或删除，财务还没同步时照样能结账。现在结账检查把所有还没同步进财务的单据都算进“业务单据”一步拦下；打开结账页会先同步，概览、业务单据、月度台账、结账页同步没成功时页面上会写出原因，启用财务后同步没成功会用红色提示说出原因。结账页“业务单据”一步的“去处理”直接打开业务单据页的“全部”，要处理的单据都列在那里。
- 修了：出纳账号开收付款单时，往来单位下拉里选不到客户和供应商。现在出纳也能选；名单读不出来时页面底部会提示原因。
- 修了：上个月的到货在这个月撤销或更正，算成本会卡住（报“原材料到货财务资料未完成”）或把原材料多扣一次。现在到货那个月照常算，撤销（更正）那个月按原来的暂估把这批冲出库存，不用再选科目；冲完数量是 0 的，到过票、还等红票冲的金额先留着，其余转进主营业务成本；没记过账就作废的到货两个月都不算。
- 撤销或被更正替代的到货不能再关联发票（提示里写出到货单号和怎么处理），开票对比里也不再列；给撤销、更正过的到货做红字冲销时，日期默认是撤销（更正）那天。
- 修了：先撤销采购退货、再撤销到货时，红字冲销凭证被算到退货单名下，成本少加回退货撤销的那笔、原材料总账和库存对不上。
- 删除业务单据、库存流水不再同时改财务的记录，财务出错也不会让删除失败；被删的单据由财务下次同步时发现、标成“来源已删除”，同步之前结账照样拦。

### 升级和维护

- 账号、长期记忆和按账号的设置、提示词、AI 设置、机器人设置、AI 识别工作区、出错记录这几个配置库，以后程序改了它们的结构，启动时先在库旁边的 `snapshots/` 留一份升级前备份，再一步步升级，数据留着，不再整个清空重建；升级出错整个退回、文件不动，提示写明是哪个库、哪一步、备份在哪。0.9.0 以前留下的旧库照旧重建。
- 补丁回滚先把配置库换回升级前的样子，再按业务库决定要不要恢复，旧程序不会因为配置库“比程序新”起不来；换不回时服务保持停止，按打印的步骤手动换回。换回以后新程序运行期间改的配置不在库里（换下来的文件留着），所有人要重新登录。`erp.env` 的 `ERP_CONFIG_DIR` 不是绝对路径时补丁直接拒绝。
- 新维护命令 `revert-config-upgrades`（Linux `erp.sh revert-config-upgrades`，Windows `npm.cmd run revert-config-upgrades`）：把比程序新的配置库换回升级前备份，Windows 整包换回旧版本后要手动运行。
- 业务库升级到第 22 版（启动时自动做）：归档标记、永久删除记录两张小表重建一次，记录种类不再写死在表里，数据原样保留。
- 恢复备份：配置库比程序旧但在 0.9.0 以后的不再拒绝，恢复后启动时升级；`_extra/` 里的 AI 配置、机器人配置不论版本只查完整性；恢复完列出“只查了完整性的文件”。

### 内部整理

- 架构整理第三步“财务和业务之间只留一个只读窗口”的开头：单据和财务之间的约定（财务读哪些栏目、哪些栏目算进来源指纹、说明字段）归到业务这边一个文件，业务改单据栏目时编译就报错；财务事件快照只存财务用得到的几项，已有的来源指纹不变；业务这边开了只读窗口（`server/flow/finance-facts/`），财务读往来单位改走它，有检查保证窗口里不写库、财务只经窗口用单据流转；财务事件的上一条、往来单位、单号、金额、缺税率从快照里提出来单独成列（业务库第 21 步升级，启动时自动做，已有的事件按快照回填），财务查这些不再拆快照的 JSON；财务测试“假装业务变了”的造数收进一个工具（`tests/business-changes-fixture.ts`），不再直接写业务的表。
- 安卓外壳按职责拆成小文件，返回键、分享、保存文件的逻辑都有单元测试，Lint 警告也算错，安装包去掉了误带的 Kotlin 标准库；Windows 外壳同样按职责拆分，去掉了往网页注入脚本的对话框插件，加了日志文件和边界检查。两个外壳的检查用 `npm run check:apps` 一次跑完，并单独接进持续集成。
- 架构整理第一步“立规矩”，页面和功能不变：前端业务四层、共用业务规则三层只往下用，代码和样式都有检查，现有越层的列成只许减少的清单；财务和业务的单据字段约定、数据管理模板和录入栏目、单据导出的格子名、升级步骤的数据样例都有检查对着；首屏脚本体积有了只许调低的上限；删了两条没人用的样式。
- 架构整理第二步“修毛病”的第一批：订单“算不算数、还能不能送、是不是已结束”三个判断各收成一份，订单、采购单详情的状态按钮直接按状态规则出现；客户搜索三处共用一份；权限名列成固定名单，写错编译不过（服务端当前操作人身上的权限也一样），账号库读权限时按名单核对；几十处手抄的清单、数字、叫法改成引用同一份（单据种类、各种状态、计价方式、附件上限、识别原件格式等，财务的收付方式、账期方式和税率口径挪到前后端共用）。
