## 0.8.1 · 2026-11-07

### 双平台与部署

- 新增 Linux AES-256-GCM 凭据保护和严格权限检查，Windows DPAPI 兼容旧密文；主密钥不进业务备份。
- 新增 Linux 配置目录、可指定备份目录、systemd、Caddy 示例和维护命令；工作区随业务库目录存放。

- Linux 安装 fonts-noto-cjk，缺字体拒绝启动；新增目录、加密、平台识别和原生权限测试。

### 单据导出

- **固定版式：** 订货单和送货单改成像印好的联单一样的固定表格。每张纸铺满，明细行数固定，货少只填前几行，其余空行留表格线。每张能放几行在“设置 → 单据模板”的预览上方写明（送货单 241×93 每张 6 行、241×140 每张 11 行、A5 横向每张 11 行；订货单 A4 纵向每张 24 行、A4 横向每张 14 行。行数只随纸张、方向、字号、明细列及模板固定资料和条款变化，不随单据联系人、地址或备注长度变化）。
- **续页：** 明细超过一张时按同一版式续页，每张都重复抬头、单号、客户或供应商信息、备注和签字栏，页脚写“第几张 / 共几张”。合计只写在最后一张，前面几张写“合计金额（见最后一张）”。
- **新版式：** 抬头一行：左边商标和公司名，标题在整张纸正中，右边红色单号和日期；我方联系人和地址印在页脚一行，“测试样张 / 计划单 非正式”印在页眉；客户或供应商信息写成“标签：内容”并排的格子，送货单两行放下；明细表数字右对齐，合计和备注收在表里；交货、验收、付款和税费说明编号列在表下；签字栏带横线。
- **默认纸张：** 新的默认送货单模板用针式三等分 241×93 mm（每张 6 行），另可选 241×140 mm 二等分、A5 横向和 A4；默认订货单模板用 A4 竖版（每张 24 行）。送货单右侧竖排印联次说明（默认“第一联 存根 第二联 客户 第三联 回单”），在模板里可改可清空。
- **大写金额：** 订货单合计独占整行，同时印人民币大写和原记录小写金额，不依赖金额列的位置或显隐。分以下还有数、金额待核价时只印小写，不四舍五入。
- **长文字：** 某一格放不下一行时，这一格的字自动缩小（最小 7 磅），保持每张行数不变；信息格和备注区也按固定区域缩字。最小字号仍放不下时，拒绝导出并提示单号、明细行号和字段，建议缩短内容或换更大纸张；Word 和 Excel 共用判断，不截断、不减行、不自动撑出半张单据。
- **明细字段恢复默认：** 设置 → 单据模板的“明细字段与顺序”旁加了“恢复默认”，把这个模板的明细列和顺序改回默认，其他设置不动；点保存才生效，已经是默认时按钮置灰。
- **模板设置：** 新增纸张、联次说明、是否显示商标三项。已经保存过的模板不迁移、不改：没设纸张的送货单模板按 241×140，订货单保持保存时的方向；要用新默认值，到 设置 → 单据模板 里选。多模板和默认模板照旧。
- **Excel 版：** 版式和 Word 一致，每张一块、块之间分页，明细金额是带千分位的数字，可以继续求和；合计整行为展示文本，保留单据原合计，不按页重算。针式联单不是 Excel 的标准纸型，打印时在打印机里选联单纸；Word 版自带准确纸张尺寸。

## 0.8.0 · 2026-11-07

用真实订单文件把全部链路测了一遍，修掉测出来的问题；助手换成小甬和小勒两个角色，工具重新整理；做了两轮代码审查，修了权限、订单状态、财务和库存几处缺陷；清理了旧样式。详见[发布说明](releases/发布说明-v0.8.0.md)。

### 订单、生产和送货

- **待发货要做够：** 订单每个没发完的产品，已完工数量够订单数量才算待发货。排 100 做完 100、订单要 1000，还是生产中。同一产品写了几行的合起来算；一张生产任务同时挂几张订单、又不知道各分多少时，这几张单合起来做够才算。任务单位和订单单位不同（箱和只）不换算，不算这张单的生产量，订单详情里会说明。
- **部分发货：** 发了一部分的订单显示和筛选为“部分发货”，全部发完才是“已发货”。
- **升级时重算老订单：** 第一次用 0.8.0 启动时，按新规则把全部订单的状态核对一遍，只改状态不对的，改了哪些记在审计里；跑过就不再跑。
- **今日页：** 做好一批就进“可安排送货”，不用等全部做完。还没做够、又没有正在做的同单位任务时，今日页和订单下一步都提醒接着排产，下一步预填还缺的数量。
- **送货单：** 页面上能给真实订单建送货单了。以前订单规格写 `66*25*7.5cm`、成品档案写 `66 × 25 × 7.5 cm` 就提示“无可关联订单”。完工入库的成品也因为同样的原因送不了货，已一并修好。
- **重算和快照：** 删除完工单或解绑生产任务后，订单状态会重算。订单换客户拆分送货单时，已确认送货单的价格和金额快照不再丢失。
- **流水修订：** 解除采购关联、删除后保留库存、拆分送货单这几处改写库存流水，都留了修订记录。
- **采购进度：** 按明细行判断，不再把张和公斤加在一起。
- **旧到货单：** 同一物料出现多行时，按流水顺序一一读取实际入库量，不再每行重复显示总数；对不上的保留“入库待核对”。记明入库 0 的行不参与配对，不会把同物料的另一行带成待核对。
- **导出：** 送货单金额不再打印 `4000.0000000`；合计显示 `5,100.00`，规格不再重复，客户联系信息不再填地址，没记录时间时不印“时间未记录”。订单金额显示成 `1,490.00`。

### AI 导入、识别和自动对应

- **识别不再莫名失败：** 模型回显多余字段、返回空对象、少括号、一次回两段 JSON，或者服务商在正文前夹安全判定和思考过程，都会自动清理或重试一次，仍不行才报错。网络、限流和取消不重试。
- **疑点：** 只列模型自己拿不准的内容和原件没写的必填项。以前一份合同三十多条，真问题看不见。
- **客户自动对应：** 只差“有限公司”、括号、盖章字样的直接并入已有档案；错别字、少字列为候选问一下，不再静默新建重复客户。名字里的数字不同（1 厂和 2 厂）不算相近。同名既有归档也有在用的，对应在用那个。
- **产品自动对应：** 同名同尺寸直接对应，一边没写单位但数字一样也算，加工要求写法不同不影响。只差括号里的说明也算同一个；只是名称包含的（“纸箱1”和“纸箱10”、“纸箱”和“纸箱加厚”）列为候选，要人确认。尺寸相同、名字完全不同的不拦新建。
- **批量导入：** 后一份能认出前一份刚建的产品。客户和产品的选择自动保存，导入按钮不再无故变灰。导入后的页面不再显示“待确认”和“相同采购单号”，已办完的文件不再计入“待核对”和左侧角标。
- **唛头自动挂到产品：** 识别出料号、名称、尺寸后按最强的依据对应产品，唯一就把原文件挂到产品下；对不上或有多个候选才让人选。两边都有料号又对不上时，即使名称相同也不自动挂。产品详情显示原文件链接和缩略图，能预览、翻页、新窗口打开和下载。聊天发唛头、收件箱转唛头都能走通。
- **唛头细节：** 纯括号料号不会因为去括号后都是空串而被当成相近；同名不同料号的新产品不再并成一个；到货识别不再复用同一文件的唛头识别结果。
- **识别外发：** 聊天里识别唛头和到货单，用的是发这条消息时确认的模型；中途换了配置就停下，要重新确认。

### 助手：小甬和小勒

- **两个角色：** 纸箱精灵换成 YL 两个小人：小甬（Y）和小勒（L），站在一起就是商标。小甬管收件箱、导入、客户、产品、唛头、订单、送货和今日总览，小勒管采购、到货、库存、生产和财务；问到哪块，对应的人出面回答，也可以点名。分工只决定谁出面，不限制工具，也不改变权限。
- **动作：** 传箱子、说悄悄话、击掌、互相顶、一起够小星、轮流蹦；AI 处理中两人轮流点头，窗口收起时做完会击掌、回复冒气泡；贴边时上下错开，只探出头。深色模式跟随主题，系统设置“减少动效”时完全不动。手机底部“助手”图标也换成了它们。
- **新工具：** 系统维护（`system.status`、`system.check`、`system.backup`、`management.reset_preview`，仅本机最高管理员；恢复备份要停机，仍用 `npm run restore`）、唛头直接挂和移除（`marks.add`、`marks.remove`，识别改名为 `marks.recognize`、`marks.attach`）、收件箱手动添加（`inbox.add`）、聊天里识别供应商送货单（`arrival.recognize`，用户说了验收结果才入库）、聊天记录（`chat.list`、`chat.delete`）。
- **去掉过时工具：** 旧的采购分批到货 `purchase.propose_receipt` 不再给模型，由 `arrival.receive` 代替。本机管理员不再同时看到两个永久删除工具。每次调用带的工具说明从约 83,000 字压到约 23,000 字，参数信息不丢。
- **删聊天和移除唛头要用户本人说：** 按分句判断，“不要删”“不删除”“取消删除”“暂时保留，不清空”“怎么删”都不算授权；“能不能删”要下一句确认；“确认不执行”这类不是整句肯定的话不算确认；“把聊天记录删了，告诉我怎么恢复”仍算明确要删。模型的决定、文件和网页里的文字都不算。只删自己账号的会话，删之前留备份。
- **助手清空数据：** 财务里已有记录时拒绝，请到“系统维护”页面操作，助手不替财务写入。
- **回答更可靠：** 财务金额统一换成元再给模型（已付、已关联、信用额度也算，编号不算），不会再把 7692.60 元说成“76.9 万”。选填项不追问；校验不通过时不能编数字；问情况的话不被上一件事打断；说产品名前半截也能点名；做完不再提示“尚有事项待处理”；同一个问题不再问两遍；工具失败后已换办法查到结果时，不再报已解决的错误；隔了几句再说“好的”不会保存提示词；到货识别的内部提示不再显示给用户。
- **聊天窗口：** 下方的任务进度条和每条消息的工具记录只在开发者模式显示。
- **提示词：** 分成两层，回复格式和不能改变的规则留在代码里，业务规则拆成按主题的条目，可以在 设置 → 提示词 里改。没改过的默认提示词自动升级；改过的不覆盖，只补上缺少的条目。新增 `finance.monthly` 查理论和实际盈亏，财务没启用也能查。

### 财务

- **红字发票：** 可以在页面上确认（以前确认按钮一直是灰的）；全额红冲后释放开票额度，可以重新开票；部分红冲按各关联累计分摊，合计正好等于红票额。部分红冲且原票已有凭证时，确认窗口里填对方科目。发票状态显示中文。
- **12 月结转：** 先结转月末损益，再结转年度利润。以前 12 月一点就报错。
- **手工凭证：** 应收、应付这类科目可以选客户、供应商等辅助项，修改时保留。以前这些科目手工凭证存不了。
- **删除凭证：** 接口不再一直等待响应，会直接提示凭证编号要保留、请改用作废。
- **清空数据：** 连同往来条款、资金账户和银行导入模板一起清，新客户不会串到旧客户的账期。

### 账号、权限和安全

- **AI 设置只有管理员能改：** 密钥、模型和预设，别的账号只看到提示。导入工作区和提示词的写操作要业务编辑权限。以前任何登录账号都能改。
- **登录页：** 重排间距，可以显示密码，能切换账号（只记用户名）。新增“申请账号”（管理员通过并选级别后才能登录）和“忘记密码”（管理员确认后生成 24 小时有效的临时密码，登录后必须先改）。新设的密码改为至少 8 位、要有大小写字母，已有密码照常能登录。
- **账号菜单：** 右上角显示真实级别；账号管理搬到左下角单独页面，有待处理申请时显示数量；本机数据管理、开发者模式、超级管理员模式收进“系统维护”。管理员重置密码改为生成临时密码。
- **防刷：** 同名排队的账号申请不能被别人覆盖，同一地址最多占 3 个名额；登录限频表不再无限增长。
- **企业微信下载：** 文件下载和每次跳转都连接已校验的公网 IP，避免域名两次解析之间被改指向内网。文件名不超过下游识别的 180 字。
- **发布扫描：** 同时检查未暂存改动和未被忽略的新文件，补查企业微信机器人 Secret 和 `.env.*`，报告不回显凭据。

### 可靠性和维护

- **删除前快照：** 移除唛头、开发者删除、管理员改订单之前都会留快照。以前这几处漏了，或者开了事务才调用，快照实际没拍。带唛头的产品现在能永久删除，唛头一起清掉。
- **恢复备份：** 中途清空或切换文件失败时自动退回原数据；回退失败会给出原数据副本位置；迁移版本缺号的备份拒绝恢复。
- **读取：** 查看关联记录、单条采购和供应商时只组装有关数据，不再读取全库。
- **打包和部署：** 打包先做类型检查，构建和打包用项目内临时目录；计划任务脚本固定工作目录。

新增财务模块、收件箱和企业微信机器人、产品唛头，支持服务器部署，提供解压即用的安装包。详见[发布说明](releases/发布说明-v0.7.0.md)。

### 财务

- 财务概览：对照理论盈亏（送货单减到货单）和实际盈亏（实收减实付），两者互不影响；点金额看明细，看实收来自哪个月的单子。
- 月度台账：当月接单、送货、到货、收付逐条可查，单张或按单位批量补税率，不改原单。
- 缺税率不卡业务，只有正式报表和结账才要求补完。
- 应收应付：往来单、压货款、收付计划、到期提醒、现结优惠、账龄、对账单、账期设置、保证金、压款利息。
- 资金发票：收付款的录入、确认、核销和撤销，资金账户，银行流水导入和匹配，承兑票据，发票，税务底稿。
- 费用资产工资：费用报销、固定资产折旧、工资导入、库存成本、毛利。
- 凭证账簿：制单、审核、记账、红字冲销，财务事件，总账、明细账、余额表，修改记录。
- 报表结账：资产负债表、利润表、现金流量表、试算平衡、结账清单、反结账、预算。
- 财务导出全部改成给人看的 Excel：中文表头、金额按元、带期间的文件名；结账归档打包成一个 zip。
- 今日页提醒货款到期，订单和送货详情显示财务状况。账号新增财务、出纳两级。

### 收件箱和机器人

- 新增收件箱，集中处理手动上传、粘贴和企业微信智能机器人转来的消息，可转入 AI 导入或忽略。
- 接入企业微信智能机器人：发给机器人的文字、图片、文件自动进收件箱并回复是否保存。凭据在“设置 → 消息接入”填写。
- AI 助手可查询收件箱、改状态并转入订单识别。

### 产品和单据

- 新增产品唛头：AI 导入可识别唛头文件，按款对应到产品并存入档案；产品、订单、生产任务详情可查看。
- 订单、采购详情顶部显示下一步，逐行看待发、可用库存和生产进度。
- AI 导入页重做：文件列表、原件、草稿三栏。收件箱文字可带入新建订单。

### 界面

- 全部列表页统一：标题和统计同行，按钮同高，页面名称和导航一致。
- 单据表单的选择项改为可搜索，选项很多时提示用关键词缩小。
- 产品表单一屏放下；API 配置按三步排列；提示词、插件与工具页改紧凑布局。
- 重新设计纸箱精灵。修复全站下拉框文字被切掉、到货表单内容露出、生产页窄窗口撑宽整页。
- 主脚本从 873 KB 降到 526 KB，大页面按需加载。没有财务权限的账号打开财务地址时给出明确提示。

### 部署和可靠性

- 支持部署到 Windows Server：公网和本机维护分两个端口，公网入口校验域名和来源，Cookie 加 Secure，登录状态重启不丢；提供计划任务脚本、日志轮转和备份异地复制。不配置时本机使用不受影响。
- 新增解压即用的 Windows 安装包，内置 Node.js，`npm run package` 生成。
- 启动时有待执行的迁移，先自动保存业务库快照；快照失败就不迁移。
- 登录限流按“IP + 账号”，办公室共用公网 IP 时一个人输错不影响同事。
- 财务和今日页在大数据量下提速；带哈希的静态文件设置长缓存。
- 升级 `ws` 到 8.22.1，修复安全公告。

### 开发

- 新增 `npm run test:ui`，用隔离实例和虚构数据在无头 Chrome 里走财务主要流程。
- 启动器测试移到 `tests/serial/`，解决全量测试偶发进程退出。
- 文档按用途重新整理，历史验收归档到 `docs/history/`。
