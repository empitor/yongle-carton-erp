# 部署与运维

本机运行沿用现有启动方式。Windows Server 使用单实例部署，同机反向代理负责 HTTPS。

## 日常运维（本机）

### 启动和停止

- 启动：双击 `启动系统.cmd`。发布包直接启动；源码目录会先构建，再启动服务并打开浏览器，窗口要保持打开。
- 停止：双击 `停止系统.cmd`，或在原窗口按 `Ctrl+C`。
- 地址：`http://127.0.0.1:3001`。端口用环境变量 `PORT` 改。
- 环境：Node.js 24.15 或更高的 24.x。

同一个数据库只能有一个实例，由 `data/erp.sqlite.running` 锁定。进程异常退出留下的锁，下次启动会自动清理。

### 更新版本

1. 备份：`npm.cmd run backup`
2. 停止服务
3. 取新代码（如需要）并安装依赖：`npm.cmd ci`
4. 启动。数据库迁移会自动执行。

### 备份和恢复

| 类型 | 说明 |
|---|---|
| 手动完整备份 | `npm.cmd run backup`，生成 `backups/full-时间/`，运行中可执行 |
| 自动备份 | 服务运行时每天一次，`backups/auto-时间/`，保留最近 14 份 |
| 删除前快照 | 物理删除和初始化前自动保存，`data/snapshots/`，保留最近 20 份；只含业务库 |
| 升级前快照 | 启动检测到待执行迁移时保存到 `data/snapshots/upgrade-*.sqlite`。只含业务库，单独留存，生成失败时启动中止 |

- 备份包含业务库、账号、AI 工作区和原件、归档、提示词、AI 配置和机器人配置（后两者是加密内容）。
- **恢复：** 先停止服务，再执行 `npm.cmd run restore -- "备份目录绝对路径"`。恢复前的 `data/` 另存为 `data.before-restore-时间`。本机 AI 配置不会自动覆盖。
- **请定期把备份复制到其他磁盘。** 同一块硬盘坏了，备份也一起没了。
- 自动备份失败时今日页会提示。

### 账号

- 首次使用在登录页创建管理员。
- 忘记密码：`npm.cmd run reset-password -- "用户名"`，生成一次性临时密码，旧登录立即失效。

### 企业微信机器人

- 在 设置 → 消息接入 填 Bot ID 和 Secret。后台要把 API 模式设为“长连接”，不需要公网地址。
- 同一个机器人只能连一处。测试实例和正式实例不要同时连，后连上的会把先连的顶掉，且不会自动抢回。
- 软件关着时收不到消息。官方没有说明之后是否补发，所以部署前电脑要常开。

## Windows Server 部署

```text
员工浏览器 → HTTPS 反向代理（Caddy 或 IIS）→ 127.0.0.1:3002
维护人 → 远程桌面 → 服务器本机浏览器 → 127.0.0.1:3001
```

### 安装和配置

1. 在 Windows Server 安装 Node.js 24.15 或更新的 24.x，使用 `node --version` 验证。准备专用普通 Windows 账号，授予“作为批处理作业登录”，登录一次建立其用户配置目录。管理员通过受限远程桌面维护系统。
2. 把已审阅的代码版本取到服务器的独立发布目录。给服务账号授予程序目录的读取、执行权限，并对发布目录下的 `data`、`backups` 和外置日志目录授予写入权限。在发布目录执行 `npm.cmd ci`。将构建输出先放到新目录，成功后将该产物放入尚未运行的新发布目录的 `dist`。

   ```powershell
   npx.cmd tsc --noEmit
   $stage = Join-Path ([IO.Path]::GetTempPath()) ('erp-dist-' + [guid]::NewGuid())
   npx.cmd vite build --outDir $stage --emptyOutDir
   ```

3. 在项目目录之外创建部署 JSON，只允许管理员写入，授予服务账号读取权限。以下为虚构域名示例。

   ```json
   {
     "ERP_DEPLOYMENT": "1",
     "PORT": "3001",
     "ERP_PROXY_PORT": "3002",
     "ERP_ALLOWED_HOSTS": "erp.example.invalid",
     "ERP_ALLOWED_ORIGINS": "https://erp.example.invalid"
   }
   ```

   | 配置 | 用途和默认值 |
   |---|---|
   | `ERP_DEPLOYMENT` | `1` 启用部署，省略或 `0` 保持本机模式 |
   | `PORT` | 本机维护端口，默认 `3001` |
   | `ERP_PROXY_PORT` | 同机 HTTPS 代理的后端回环端口，部署时默认 `3002`，须和维护端口不同 |
   | `ERP_ALLOWED_HOSTS` | 部署入口允许的域名，逗号分隔，部署时必填。非标准 HTTPS 端口须同时写在 Host 和 Origin |
   | `ERP_ALLOWED_ORIGINS` | 允许的 HTTPS 写请求来源，逗号分隔，默认由允许域名逐个加上 `https://` |
   | `ERP_BACKUP_COPY_DIR` | 每日完整备份的额外复制目录，默认关闭。使用绝对路径，网络盘使用 UNC 路径 |
   | `ERP_BACKUP_COPY_KEEP` | 目标目录中自动备份的保留份数，默认保留所有，选填正整数 |

   直接运行服务器时可用同名环境变量。计划任务从指定 JSON 加载这些设置，并设置 `NODE_ENV=production`。备份复制使用 ERP 独占目录，位于业务数据和本地备份目录之外，计划任务账号须具有该位置的权限。目标断开时本地备份仍生成，失败显示在今日页，后续定时检查会重试最近一份。

4. 以 Windows 管理员身份打开 PowerShell，先预演。确认路径和名称后，在上线窗口移除 `-WhatIf` 注册任务，按提示输入专用账号凭据。首次启动可在计划任务控制台手动运行。任务开机启动，失败后每隔一分钟重试，最多三次，禁止重叠运行。日志写入指定目录的 `erp.log`，约 10 MiB 轮转，保留七份轮转日志。

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\install-deployment-task.ps1 `
     -ConfigFile 'C:\ERPConfig\deployment.json' -LogDirectory 'D:\ERPLogs' -WhatIf
   ```

5. 在服务器浏览器打开 `http://127.0.0.1:3001`。空库在此建立首个管理员，随后按职责创建员工账号。恢复的库沿用已有账号。确认计划任务使用正确的 Windows 用户配置目录和 `%LOCALAPPDATA%\ZhixuERP`。DPAPI 将 AI 密钥和机器人 Secret 绑定到原 Windows 账号和机器，换机器或账号时在页面重新输入。启动日志会提示已保存的密钥解密失败。机器人先停用旧电脑的长连接，再启用服务器端；同一机器人只保留一处连接。

### HTTPS 反向代理

代理必须把公网请求送往 `127.0.0.1:3002`，保留原 Host，并用 TCP 对端地址覆盖 `X-ERP-Client-IP`。ERP 用该地址限流，忽略访客提供的 `X-Forwarded-For`。维护端口是本机信任边界，严禁作为任何代理规则的上游。

**Caddy** 使用已配置证书或可从 443 完成验证的证书签发方式。示例从文件读取证书，证书由维护人续期。若只对外开放 443，关闭 Caddy 自动添加的 HTTP 跳转监听。参见 [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

```caddyfile
{
    auto_https disable_redirects
}
erp.example.invalid {
    tls C:/ERPConfig/erp-fullchain.pem C:/ERPConfig/erp-key.pem
    encode /assets/* gzip
    reverse_proxy 127.0.0.1:3002 {
        header_up X-ERP-Client-IP {remote_host}
    }
}
```

**IIS** 安装 URL Rewrite 和 ARR，在服务器级启用 ARR Proxy，并设置 `system.webServer/proxy` 的 `preserveHostHeader=True`。为专用站点添加仅 443 的 HTTPS 绑定和证书，绑定目标域名。服务器级 URL Rewrite 的允许变量列表添加 `HTTP_X_ERP_CLIENT_IP`。专用站点 `web.config` 的 `system.webServer` 内添加以下规则。参见 [IIS 请求头和服务器变量](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/setting-http-request-headers-and-iis-server-variables)。

```xml
<urlCompression doStaticCompression="false" doDynamicCompression="false" />
<rewrite>
  <rules>
    <rule name="ERP HTTPS to loopback" stopProcessing="true">
      <match url="(.*)" />
      <conditions>
        <add input="{HTTPS}" pattern="^ON$" />
      </conditions>
      <serverVariables>
        <set name="HTTP_X_ERP_CLIENT_IP" value="{REMOTE_ADDR}" replace="true" />
      </serverVariables>
      <action type="Rewrite" url="http://127.0.0.1:3002/{R:1}" appendQueryString="true" />
    </rule>
  </rules>
</rewrite>
```

在 IIS 安装“静态内容压缩”和“动态内容压缩”角色服务。ARR 转发的资源可能按动态内容处理。将以下配置放在站点 `web.config` 的 `configuration` 下，与 `system.webServer` 并列，只为资源路径启用压缩。若站点级配置被锁定，由 IIS 管理员在服务器配置中为该站点和路径设置。参见 [Caddy 响应压缩](https://caddyserver.com/docs/caddyfile/directives/encode) 和 [IIS URL 压缩](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/urlcompression)。

```xml
<location path="assets">
  <system.webServer>
    <urlCompression doStaticCompression="true" doDynamicCompression="true" />
  </system.webServer>
</location>
```

部署后，从首页源码找实际的主 JS 路径，用 GET 请求检查响应头。把示例路径换成该版本的文件名。

```powershell
curl.exe -fsS -D - -o NUL -H "Accept-Encoding: gzip" "https://erp.example.invalid/assets/index-XXXXXXXX.js"
curl.exe -fsS -D - -o NUL "https://erp.example.invalid/"
```

主脚本应有 `Content-Encoding: gzip` 和 `Cache-Control: public, max-age=31536000, immutable`。确认压缩在代理上生效，未声明支持 gzip 的客户端仍能正常访问。首页和前端路由回退的 HTML 应有 `Cache-Control: no-cache`，重载时会重新验证版本。普通静态文件保持默认缓存，API 和财务文件继续使用各自的缓存策略。Windows 部署示例使用 Vite 默认八字符资源哈希。

服务器前还有其他网络代理时，先核对同机代理看到的 TCP 对端地址是否就是预期访客。部署入口设置 Secure Cookie、HSTS，保留现有 CSP、防嵌入和防 MIME 嗅探响应头。远程管理员需重新验证才能进入临时超级管理员模式。本机维护能力仍由维护端口提供。部署进程关闭服务器浏览器和本机语音识别，员工当前网页的页面控制保留。

### 防火墙与验收

- Windows 防火墙和云安全组只对员工开放 TCP 443。RDP 仅允许维护者固定来源 IP 或指定管理网。确认管理控制台的备用进入方式。
- 公网访问正确域名并确认 HTTPS、Secure Cookie、HSTS。测试未知 Host、非法 Origin、伪造或缺失访客头，以及普通、只读、财务账号的权限。
- 通过公网管理员检查永久删除、初始化等本机能力受到拦截。远程桌面内用维护地址验证本机管理员功能。
- 在隔离的部署演练实例验证计划任务开机启动、失败重试、轮转、重启会话和证书续期。验证每日备份复制与异机恢复。

### 升级、恢复和回滚

1. 在维护窗口前，用旧版本执行 `npm.cmd run backup`，确认完整备份含校验清单，另存到独立介质。准备新发布目录和构建产物。
2. 维护窗口内先禁用旧计划任务的触发，再在旧发布目录设置维护端口 `PORT`，运行 `npm.cmd run stop` 并确认已退出。把备份恢复到新发布目录，或在停服后迁入数据目录。更新计划任务的工作目录、配置和启动路径。ERP 在启动锁内先保存待升级业务库的快照，之后执行迁移。日志提示快照失败时，排查目录权限和磁盘空间再启动。
3. 检查登录、历史单据、库存、财务和附件。完整恢复需在停服目录运行 `npm.cmd run restore -- "完整备份绝对路径"`。恢复会核验清单并另存原数据。恢复后重新登录，跨机器时重新填写 DPAPI 凭据。
4. 需要回滚时先停新实例，使用旧程序和升级前的完整备份。单独的升级快照只含业务库，适合在隔离目录检查或补救。若新版已经产生业务写入，先备份新版数据并核对差额，再决定如何保留这些写入。数据库只允许一个实例访问。
