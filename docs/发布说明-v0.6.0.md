# 0.6.0：业务工作台、单据模板与Windows运行维护

日期：2026-10-30。软件版本0.6.0，业务目录33，数据库迁移12。历史标签保持原样。

本版汇总0.5.3发布后的业务、UI、单据及助手升级，并完成PowerShell7兼容性修正。

## 业务与界面

- 工作台读取真实采购、生产、送货待办；详情直接关联生产任务、领料完工、到货、送货及实际库存。
- 订单采用表格明细，保留逐行交期、税费及金额精度；客户/产品/供应商可快捷建档，草稿不丢失。
- 仓库统一五个入口及日期台账，计划与实际分开，历史独立凭据兼容读取、不虚构入库。
- 实收、合格、不合格和实际入库明确区分；到货正式更正保留原单、冲销、替代及审计。
- 销售/采购状态与履约进度独立，由有效单据统一派生；历史未知数量和价格保留待核对。

## 正式单据与AI

- 采购与送货Word/Excel共用服务、字段映射和A4排版；送货只导出本批，保留价格、料号、订单号快照。
- 采购预览/生成不改状态，完整下载和交付回执核验后才联动已订货；重复交付幂等。
- AI设置第四页签统一多模板、默认选择、字段显隐/排序、字体及虚构测试样张；历史文件保留模板快照。
- 61个注册工具与人工入口覆盖同步维护；提示词编辑、客户复用、批量导入续办及生产整批完工完善。
- 助手默认停靠顶栏，保留可选悬浮入口、拖动、缩放及原权限/工具启停；不调用收费模型进行发布验收。

## PowerShell与启动关闭

- Windows原生PowerShell7可以作为日常终端；Node.js要求24.15.0或更高24.x版本。
- 保留Windows PowerShell5.1：DPAPI沿原显式调用，旧WinRT OCR不做不兼容的可执行文件替换；当前图片业务仍走原无OCR路径。
- 新增只监听本机回环的运行控制通道，使用独立随机令牌和实际PID核验。关闭先等待HTTP及数据库资源释放，再返回回执、移除本实例运行文件并正常退出。
- 正常停止不再使用Windows的强制SIGTERM，因此启动窗口不会把合法停止误报为启动失败。
- 开发启动器统一管理Vite与后台，源码修改仍自动重启后台；npm stop同时结束前后端，启动失败保留失败退出码。
- 停止CMD保留npm原始退出码。PORT同时配置后台和开发代理，WEB_PORT可配置前端端口。
- 中文诊断脚本提供UTF-8 BOM版本；Node/JSON继续UTF-8，不批量转换源码编码。
- 运行令牌、锁文件、真实数据库、原件、模型、截图和本机日志不进入Git或Release。

## 升级

1. 先备份整个data和本机AI配置，并在原服务窗口按Ctrl+C停止旧版。运行中的0.5.x没有新关闭通道，新版停止命令会明确提示，不会强制终止旧实例。
2. 正常拉取代码，执行npm.cmd ci、npm.cmd run build，再使用启动系统.cmd或npm.cmd start。
3. 不清空数据库。相对已发布0.5.3，程序会按原迁移顺序升至12；迁移12校正到货累计缓存和差异审计，保留原库存流水。迁移前备份仍需保留。
4. 新电脑自行恢复业务资料、本机AI配置及可选语音模型；DPAPI沿原Windows用户范围保护，不能把其他用户的密钥文件当作通用凭据分发。

本轮未停止或升级真实运行实例。原生Office打印分页、真实模型自然语言表现及正式生产部署仍按各自流程验收。
