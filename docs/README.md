# 文档目录

每份文档讲什么、按什么顺序读。系统是什么、部署在哪、怎么跑见根目录 [README](../README.md)；文档写在哪、怎么写的规矩见 `AGENTS.md`“文档怎么维护”。

## 读的顺序

没有上下文、要改代码的人和 AI 按这个顺序读：

1. 根目录 [README](../README.md)：系统是什么、谁用、部署在哪、技术栈、本机怎么跑。
2. 本页。
3. 根目录 `AGENTS.md`：硬规则（不能做的、要问用户的、业务规则、一件事一条链路、模块规则、文件怎么分、新增功能时一起改、验证）。只放在开发机上，不随仓库公开。
4. [架构说明](架构说明.md)：先读“总览”和“一张订单的数据怎么走”，再读“模块”；要改哪块再读对应的机制一节。
5. 按要改的东西再读：涉及表读[数据模型](数据模型.md)，涉及页面和接口读[功能链路表](功能链路表.md)，涉及界面读[界面规范](界面规范.md)；现在做到哪、还剩什么读[路线图](路线图.md)。

## 每份讲什么

| 文档 | 讲什么 |
|---|---|
| [架构说明](架构说明.md) | 系统怎么搭的：模块和谁能用谁、目录、一张订单的数据怎么走、一次请求怎么走、关键机制（库存流水、单据流转、财务、识别导入、助手、删除初始化、结构升级、账号权限）、检查和测试、前端约定、安卓 App 通道 |
| [数据模型](数据模型.md) | 业务库的表和字段、表归哪个模块、约束、派生关系、各配置库（是第几版、存在哪）、JSON 列的约定 |
| [功能链路表](功能链路表.md) | 每个功能对应的页面、接口地址、服务函数、助手工具 |
| [使用手册](使用手册.md) | 给用软件的人：每个功能在哪、点什么、会发生什么。程序里的“使用说明”页和助手读的都是它 |
| [界面规范](界面规范.md) | 界面规矩、叫法词表、公共件、样式变量 |
| [部署与运维](部署与运维.md) | 服务器部署、整包和补丁升级、客户端更新包、备份恢复、日常维护和排查、打包和 Linux 验证 |
| [路线图](路线图.md) | 只写还没做的：发布前要做的、等备案的、待验证、已知问题、暂不做；做完就删 |
| [更新日志](CHANGELOG.md) | 只有一节：开发中叫“未发布”，做完还没发布的写在这里；发布时改成版本号和日期，内容就是发布说明；以前的版本看 Git 标签和 GitHub 发布 |
| `brand/` | 商标原图（改商标时 `src/ui/BrandLogo.tsx`、`public/favicon.svg` 一起改） |
