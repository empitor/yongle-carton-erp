## 修复范围

| 原问题 | 0.6.0处理 |
| --- | --- |
| 停止CMD被pause覆盖退出码 | 保存原ERRORLEVEL并在pause后返回；失败不伪报成功 |
| Windows SIGTERM强制终止、遗留运行锁、启动器误报失败 | 新增本机回环控制通道，随机令牌与实际PID双重核验；HTTP及数据库等资源关闭后才返回成功，正常退出0，移除本实例运行文件 |
| npm stop只关闭开发后台 | 开发启动器统一管理后台与Vite，正常停止同时关闭前后端，保留源码热更新 |
| 自定义PORT后Vite仍代理3001 | PORT同步后台与代理，WEB_PORT配置前端；均校验1至65535 |
| 中文诊断无BOM导致5.1解析失败 | 可公开诊断scripts/diagnose-startup-zone.ps1使用UTF-8 BOM、动态项目目录、显式中文输出编码；本机旧work脚本仅修编码，不上传本机路径 |
| powershell.exe能否全部改为pwsh.exe | 原DPAPI及旧WinRT调用保留5.1；不为终端升级改写密钥存储或恢复OCR业务路径 |

本机控制通道不是业务HTTP接口，不注册AI工具、不改变Actor/角色、数据库结构或业务权限。连接只到127.0.0.1，令牌不进入命令行和一般日志；错误令牌、错误PID、无效/缺失控制凭据及关闭失败均拒绝返回成功。不退回强杀其他进程。运行.control和.running由Git忽略及发布扫描双重排除。

原0.5.x没有正常关闭通道；升级前在原启动窗口Ctrl+C停止。新版停止命令遇到旧实例会提示原窗口停止，不能据此宣称旧实例已经关闭。
