## 设计方向

名称：“单据流转台”。界面只回答三件事：什么卡住了、这张单到哪一步了、下一步能不能当场做。

- **履约链：** 所有订单用同一组节点表达进度（`订─料─产─送`）。“库”“账”暂未显示：完工和成品入库是同一单据，财务模块还不存在，没有依据的环节不显示。
- **账本式密度：** 表格行高 36px，数字右对齐且等宽，1440×900 下一屏约 20 行。
- **不打断的详情：** 点行在右侧打开面板，列表保持可见，↑↓ 切换相邻记录，Esc 关闭。
- **视觉：** 暖灰中性色、靛墨操作色，牛皮纸色只用于品牌点缀，紫色只表示 AI 内容。字号 6 级，圆角 2 种。

## 实现方式

- `src/design.css` 最后加载，覆盖语义变量和外壳样式，旧页面先跟着换肤。旧 CSS 的清理见文末“收尾”。
- 保留哈希路由和 `data-agent-*` 属性，AI 的 `ui.open`、`page.observe` 继续可用。
- 未引入路由库、数据层、UI 库，新增公共组件：`ui/DetailPanel`、`ui/Chain`、`ui/Combobox`。

### 旧 CSS 清理

只做可证明不影响结果的删除，脚本从真实构建取层叠顺序：

- 删除选择器里必需的类名在源码中不存在的规则（164 条规则，189 个选择器）。
- 删除被后面同一选择器、同一条件的同名属性覆盖的声明（401 条）。
- 删除变空的规则和 4 个没人引用的 CSS 变量。
- 合并层叠相邻的文件：`theme.css` 并入 `styles.css`，`ui-audit.css`、`ui-upgrade.css` 并入 `design.css`。

结果：约 10200 行降到 8800 行，构建产物 156KB 降到 134.5KB。

比对方法：用本机 Chrome 在 61 个页面状态（浅色、深色、1000、1440、1920 宽度，含面板和弹窗）上记录每个元素的全部计算样式和截图。清理前后 61 个状态的截图字节完全相同；计算样式的差异只有 `--kraft-soft`、`--success-soft` 两个已删除的未引用变量。同一基线跑两次时 59 个状态完全一致，另外 2 个收件箱状态只有元素路径不同，计算样式没有变化。

没有覆盖的状态（悬停、拖动中、罕见错误提示）靠删除规则本身的安全性保证，未逐一比对。

## 未完成

- 生产任务、完工记录、到货、送货列表仍是全量读取加前端分页，因为这些页面的状态筛选和全文搜索都在前端，且 `FlowPage` 打开时一次读取 8 个接口。`Ctrl+K` 全局搜索也要读全量才能搜客户 PO。数据量大时这几处会先变慢。
- 分页在服务端是“先算完整筛选结果再切片”，减少的是传输和渲染量，不是数据库读取量。
- 助手停靠时，1440 宽屏下订单表可用宽度约 860px，金额之后的列要横向滚动，关闭助手恢复。
- 页面打印只打当前页（最多 50 行）。
- CSS 还有不同选择器之间的互相覆盖，无法用静态规则证明安全，需要按页面逐步重写。
